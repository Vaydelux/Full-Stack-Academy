# Subscribe and resume

> Unpublished instructor manuscript. This topic is not available in the public Academy reader and has not passed Node 24/production browser qualification.

## Learning outcomes

Trace the authenticated actor, tenant boundary, relevant state transition, and failure path. Implement or describe a minimal correction and reproduce a positive case plus a negative case with synthetic data.

## Context

A phone loses connectivity while consuming an activity feed.

This scenario connects directly to a real full-stack engineering concern: security, consistency, user experience and the cost of retries must be considered together.

## Step 1 — Explain the model

## Step 2 — Find the failure

On reconnect the client silently starts at the latest event, dropping updates that arrived while offline.

**Adversarial exercise:** Describe the smallest reproducible request or event sequence that exposes this failure. Record what data must remain private, what state must remain durable, and what a reconnecting client is allowed to replay.

## Misconception

A finite in-memory replay buffer is not durable event recovery after a server restart.

## Applied engineering walkthrough

A resume cursor identifies a position in retained history. Replay can restore missed events only while the required history is available. If the cursor predates retention, a fresh authoritative snapshot is required. Subscribe and snapshot coordination must avoid a gap between the two.

### Diagnose the concrete failure

Publish several synthetic events and reconnect from a known cursor. Verify only later events are replayed. Advance beyond retention and check the explicit snapshot-required outcome. Test a cursor belonging to a different stream independently.

### Independent exercise and evidence

Design snapshot-plus-cursor synchronization with deduplication and a bounded replay window. Record received IDs and the gap recovery decision. Do not claim durable replay from in-memory history.
