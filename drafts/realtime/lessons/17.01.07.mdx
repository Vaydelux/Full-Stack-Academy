## Misconception

In-memory deduplication is not a substitute for idempotent database effects.

## Applied engineering walkthrough

Deduplication by event ID prevents repeated display of the same logical event. Resource revisions protect against older distinct events overwriting newer state. An unbounded seen-ID set grows forever; bound it using the stream retention or snapshot contract. External effects need durable idempotency.

### Diagnose the concrete failure

Deliver the same synthetic event twice and assert one rendered item. Deliver an older distinct revision and verify current state is unchanged. Rebuild from a snapshot and check the deduplication window is reset consistently.

### Independent exercise and evidence

Design a reducer with stable event IDs, resource version checks and bounded history. Record event input order, output items and final revision.
