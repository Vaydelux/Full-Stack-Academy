# Optimistic edits

> Unpublished instructor manuscript. This topic is not available in the public Academy reader and has not passed Node 24/production browser qualification.

## Learning outcomes

Trace the authenticated actor, tenant boundary, relevant state transition, and failure path. Implement or describe a minimal correction and reproduce a positive case plus a negative case with synthetic data.

## Context

A learner edits a shared note while the network is slow.

This scenario connects directly to a real full-stack engineering concern: security, consistency, user experience and the cost of retries must be considered together.

## Step 1 — Explain the model

Show a pending optimistic state, keep the base version and roll back or surface conflicts when the response rejects.

**Design exercise:** Draw the actor → browser/client → API or transport → authoritative store → other clients path. Label which inputs are controlled by callers and which authorization and version decisions must be enforced server-side.

## Step 2 — Find the failure

The client assumes the server accepted the edit and never resolves failed writes.

**Adversarial exercise:** Describe the smallest reproducible request or event sequence that exposes this failure. Record what data must remain private, what state must remain durable, and what a reconnecting client is allowed to replay.

## Step 3 — Correct and test

Show a pending optimistic state, keep the base version and roll back or surface conflicts when the response rejects.

**Acceptance target:** Save a versioned note and then replay an edit with an outdated version to observe a conflict.

## Misconception

Optimistic UI is not automatically a conflict-free collaboration algorithm.

## Applied engineering walkthrough

An optimistic edit gives immediate feedback while a write remains unconfirmed. Preserve the prior confirmed state and the user's draft independently. A success response must identify the committed revision; a timeout can be ambiguous, and a stale write needs explicit conflict handling.

### Diagnose the concrete failure

Edit a versioned synthetic note and hold the response. Observe the optimistic display, then return a rejection and verify the draft is retained for recovery. Repeat with a committed response and confirm the accepted revision.

### Independent exercise and evidence

Design a pending-edit state machine with committed, rejected, conflicting and uncertain outcomes. Record the visible text, confirmed revision and retained draft for each transition.
