## Misconception

Obscure document IDs cannot replace permissions on each operation.

## Applied engineering walkthrough

Sharing requires both resource membership and action authorization. A viewer can read but should not edit; a nonmember cannot gain access just by knowing a document ID. A share token, if supported, must have a defined capability, expiry and revocation contract.

### Diagnose the concrete failure

Use an owner, viewer and foreign tenant identity in the local fixture. Verify the permitted read and owner edit, then deny a viewer edit and foreign read. Inspect the final revision to ensure denied writes changed nothing.

### Independent exercise and evidence

Build a matrix for owner, editor, viewer and nonmember across read, edit and share actions. Record the actual server policy and denied outcomes; test revocation on existing connections separately.
