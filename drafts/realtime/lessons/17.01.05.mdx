# Presence state

## Context

Several users open the same shared work item.

This scenario connects directly to a real full-stack engineering concern: security, consistency, user experience and the cost of retries must be considered together.

## Step 1 — Explain the model

Model presence as ephemeral heartbeat state with TTL and per-document authorization; remove sessions on disconnect.

## Misconception

Presence describes liveness, not verified read receipts or durable membership.

## Applied engineering walkthrough

Presence is ephemeral evidence that a client recently participated, not a durable membership record. Heartbeats extend a bounded lease; multiple tabs can represent several connections for one identity. Expiration and disconnect cleanup should not remove another active session.

### Diagnose the concrete failure

Use the controlled clock to heartbeat two authorized users, advance time to the expiry boundary and inspect the active list. Test duplicate heartbeats and a foreign tenant query. Compare online state with durable membership.

### Independent exercise and evidence

Design a presence model distinguishing user and connection identity. Specify heartbeat interval, expiry and privacy-safe display fields. Record clock transitions and visible members; never use presence as permission.
