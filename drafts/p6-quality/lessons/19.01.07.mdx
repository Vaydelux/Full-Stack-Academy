# Coverage interpretation

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A dashboard reports 100% line coverage.

## Step 1 — Mental model

Coverage measures execution, not strength of assertions; mutation exposes weak checks.

## Step 2 — Guided practice

In a disposable lab copy replace the rejection result with a success. Run the negative test.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** The mutation is caught by an assertion.

**Negative:** A suite that merely executes the denial branch misses it.

Run the complementary local module model and inspect `reserve` in `examples/p6-quality/labs.mjs`. Add an assertion for the relevant boundary. This command does not execute the external tools described above.

```bash
node --test --test-name-pattern="19[.]01" examples/p6-quality/labs.test.mjs
```

## Qualification boundary

Pure inventory model; no real database or browser is tested.

## Applied engineering walkthrough

Line coverage measures execution, not whether a test notices wrong behavior. A test can visit the rejection branch without asserting its result. Branch coverage and mutation testing offer complementary signals, but none independently certifies correctness.

### Diagnose the concrete failure

Run the original negative test, then change a disposable copy to accept overselling. Confirm the test fails for the expected assertion rather than a syntax error. Restore the source and confirm the green case.

### Independent exercise and evidence

Review a coverage report alongside an invariant checklist. Choose one unprotected branch and add a meaningful assertion. Record the mutant, expected failure and restored result.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.

## Knowledge check

1. Which public behavior or invariant is being protected?
2. Which negative case falsifies the unsafe implementation?
3. Which real runtime or manual check is still required?

**Assessment:** Submit the exact synthetic input, expected and observed outputs, a negative result, and the untested boundaries. Mark unavailable external checks not-run.
