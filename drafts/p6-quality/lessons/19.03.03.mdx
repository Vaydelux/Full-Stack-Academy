# API integration tests

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A protected API route is invoked over HTTP.

## Step 1 — Mental model

Integration covers routing, middleware, serialization and auth, not just a function call.

## Step 2 — Guided practice

Use an installed local API on an ephemeral loopback port; send anonymous, owner and foreign-tenant requests.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** Owner receives 200 and the documented DTO.

**Negative:** Anonymous receives 401; foreign tenant receives the specified 404.

Run the complementary local module model and inspect `scopedRead` in `examples/p6-quality/labs.mjs`. Add an assertion for the relevant boundary. This command does not execute the external tools described above.

## Qualification boundary

Synthetic row/actor model; no Nest DI, network server, PostgreSQL or RLS execution.

## Applied engineering walkthrough

API integration tests traverse real routing, middleware, authorization and serialization on the intended adapter. Direct controller calls bypass some of those boundaries. Bind a disposable listener to loopback on an ephemeral port, use bounded client deadlines and close it afterward.

### Diagnose the concrete failure

Send anonymous, authorized and foreign-tenant requests to the installed local API. Assert the documented 401, 200 and 404 outcomes respectively, including exact allowed fields and no foreign data. Inspect persisted state for denied writes.

### Independent exercise and evidence

Design an HTTP acceptance matrix covering malformed input, missing session, denied scope and success. Record actual status, response contract and cleanup rather than equating a service mock with API evidence.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.
