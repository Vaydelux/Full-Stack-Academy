# RLS and tenant boundary tests

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A multi-tenant service depends on database RLS.

## Step 1 — Mental model

RLS must be tested with restricted non-owner/non-BYPASSRLS roles, not merely UI filters.

## Step 2 — Guided practice

Use scopedRead as a contract, then run a P5 RLS qualification with real restricted role and transaction-local claims.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** Owner sees the intended record.

**Negative:** Missing and foreign context cannot expose data.

Run the complementary local module model and inspect `scopedRead` in `examples/p6-quality/labs.mjs`. Add an assertion for the relevant boundary. This command does not execute the external tools described above.

```bash
node --test --test-name-pattern="19[.]03" examples/p6-quality/labs.test.mjs
```

## Qualification boundary

Synthetic row/actor model; no Nest DI, network server, PostgreSQL or RLS execution.

## Applied engineering walkthrough

RLS is evaluated by PostgreSQL under an actual role and policy context. Table owners and bypass roles can produce misleading positive results. An in-memory scoped-read model can express the expected contract but does not prove SQL policy enforcement.

### Diagnose the concrete failure

Run an authorized disposable RLS test with a non-bypass role and two known tenant records. Assert the permitted record exists and the other is excluded. Check missing context and attempted foreign mutation. Use actual authenticated requests separately from simulated claims.

### Independent exercise and evidence

Design a CRUD policy matrix covering SELECT, INSERT, UPDATE and DELETE under permitted and denied identities. Record effective role, exact row IDs and actual SQL outcomes.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.
