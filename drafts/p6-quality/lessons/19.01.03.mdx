# Fixtures and factories

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

Two tests share a mutable cart object.

## Step 1 — Mental model

Factories produce fresh objects with explicit defaults and overrides.

## Step 2 — Guided practice

Create a factory returning stock 3 and quantity 1; mutate one instance and assert a second remains unchanged.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** Independent fixtures have identical initial state.

**Negative:** Shared object mutation causes order-dependent tests.

Run the complementary local module model and inspect `reserve` in `examples/p6-quality/labs.mjs`. Add an assertion for the relevant boundary. This command does not execute the external tools described above.

```bash
node --test --test-name-pattern="19[.]01" examples/p6-quality/labs.test.mjs
```

## Qualification boundary

Pure inventory model; no real database or browser is tested.

## Applied engineering walkthrough

Fixtures supply known data; factories create independent instances with controlled variation. A shared mutable object can cause order-dependent failures, especially with concurrent tests. Cloning shallowly may retain nested references, so define ownership of nested data.

### Diagnose the concrete failure

Construct two carts with identical starting stock and separate nested items. Mutate one and assert the second is unchanged. Run the cases in a different order and confirm the result does not depend on prior mutation.

### Independent exercise and evidence

Build a factory accepting explicit overrides and deterministic identifiers. Include a nested mutation negative case and document cleanup for real database fixtures. Record initial and final values.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.
