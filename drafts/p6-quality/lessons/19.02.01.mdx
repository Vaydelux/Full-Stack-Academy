# Vitest and Testing Library

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A settings form shows loading and saved status.

## Step 1 — Mental model

Vitest runs tests; Testing Library encourages testing from the user's perspective.

## Step 2 — Guided practice

Run latestRequest; in an installed React fixture click Save with user-event and await the visible saved message.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** Loading changes to visible success.

**Negative:** Rejected requests show accessible errors, not only mock invocations.

## Qualification boundary

Plain JavaScript UI state model; installed React/Vitest/Testing Library/MSW and real browsers require separate tests.

## Applied engineering walkthrough

Vitest runs test code and assertions; Testing Library exposes DOM behavior through user-oriented queries. Neither a pure request model nor a DOM emulator automatically proves browser layout or networking. Match the test environment to the behavior and await asynchronous UI changes.

### Diagnose the concrete failure

In an installed React fixture, render the settings form, operate Save with user-event, and hold the request promise. Assert the visible pending state, resolve the request, then await the saved message. Repeat with a rejection and verify the error is presented.

### Independent exercise and evidence

Design separate component tests for loading, success and failure, plus a real browser smoke case. Record DOM assertions rather than only a mock's call count; preserve the existing latest-request model.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.
