# Secret handling

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A build log accidentally exposes a credential.

## Step 1 — Mental model

Secrets require least-privilege access and isolation from untrusted code; masking alone is insufficient.

## Step 2 — Guided practice

Design a fake secret and sanitized log fixture; review hypothetical PR job permissions without enabling Actions.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** Fake marker never reaches output.

**Negative:** Giving untrusted code a deployment secret fails.

## Qualification boundary

Synthetic CI evidence only; no hosted workflow, branch protection change or cryptographic provenance.

## Applied engineering walkthrough

Build automation separates untrusted changes from privileged deployment operations. Secrets should be available only to the approved job and environment that needs them. Masking logs is defense in depth, not permission to echo credentials. Review permissions and artifact trust boundaries before executing third-party code.

### Diagnose the concrete failure

Use a fake secret marker in a local diagnostic fixture and inspect sanitized output. Review a hypothetical pull request job with no deployment credentials, then identify why providing them would violate the boundary. Do not alter the actual workflow settings.

### Independent exercise and evidence

Design a permission matrix for read-only test jobs, artifact publication and approved deployment. Record the secret owner, scope and review results using synthetic values only.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.
