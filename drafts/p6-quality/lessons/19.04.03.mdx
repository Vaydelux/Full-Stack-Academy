# Database load testing

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A query slows when a connection pool saturates.

## Step 1 — Mental model

Distinguish pool waiting, query execution, locks and resource pressure.

## Step 2 — Guided practice

In disposable DB benchmark a fixed query at two bounded concurrency levels; record p95 and errors, inspect EXPLAIN.

## Applied engineering walkthrough

Database load testing separates pool acquisition, network and query execution time. More concurrency can increase queueing rather than throughput. Query plan measurements must use comparable parameters and data distributions; discarded failures bias results.

### Diagnose the concrete failure

Against a dedicated database, run one fixed query at two bounded concurrency levels. Record completed operations, errors, acquisition wait and execution plans. Stop if resource use exceeds the agreed disposable budget.

### Independent exercise and evidence

Design a controlled experiment varying only pool concurrency while holding dataset, query and duration constant. Record p95 and throughput with failure counts; a synthetic latency array cannot qualify PostgreSQL.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.
