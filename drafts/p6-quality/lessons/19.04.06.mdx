# Security test automation

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A protected route accidentally exposes a secret field.

## Step 1 — Mental model

Security regressions specify an abuse case and observable denial.

## Step 2 — Guided practice

Extend scopedRead with a foreign tenant and private field; separately test the real HTTP boundary and dependency audit.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** Allowed responses omit secrets.

**Negative:** Leaked fields or unauthorized records fail.

Run the complementary local module model and inspect `latencyReport` in `examples/p6-quality/labs.mjs`. Add an assertion for the relevant boundary. This command does not execute the external tools described above.

```bash
node --test --test-name-pattern="19[.]04" examples/p6-quality/labs.test.mjs
```

## Qualification boundary

Metrics model uses supplied samples; no real load generation, chaos or database benchmark.

## Applied engineering walkthrough

Automated security checks should falsify concrete controls. Dependency scanning, DTO leakage tests and authorization acceptance each examine different risks. A passing static scan cannot establish real resource isolation or safe runtime behavior.

### Diagnose the concrete failure

Use scopedRead with an allowed and foreign actor plus a row containing a fake private field. Assert the permitted projection and foreign denial. Plan actual HTTP and database checks for the same invariant and review dependency findings independently.

### Independent exercise and evidence

Create a security regression matrix mapping each control to a positive and negative test. Record commit-bound results and missing runtime evidence; do not report an automated scan as a penetration test.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.

## Knowledge check

1. Which public behavior or invariant is being protected?
2. Which negative case falsifies the unsafe implementation?
3. Which real runtime or manual check is still required?

**Assessment:** Submit the exact synthetic input, expected and observed outputs, a negative result, and the untested boundaries. Mark unavailable external checks not-run.
