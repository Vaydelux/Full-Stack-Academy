# Nest test modules

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A Nest service depends on a repository provider.

## Step 1 — Mental model

Testing modules construct dependency graphs; overrides replace a specific provider boundary.

## Step 2 — Guided practice

In installed Nest build Test.createTestingModule with a feature module, override its repository, compile and resolve the service.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** The intended repository is injected.

**Negative:** Omitting the provider produces a resolution error.

Run the complementary local module model and inspect `scopedRead` in `examples/p6-quality/labs.mjs`. Add an assertion for the relevant boundary. This command does not execute the external tools described above.


## Qualification boundary

Synthetic row/actor model; no Nest DI, network server, PostgreSQL or RLS execution.

## Applied engineering walkthrough

A Nest testing module resolves actual dependency-injection tokens and provider visibility. An override replaces a registered dependency for the test, not every instance constructed manually. A compiled test module is useful container evidence but does not establish HTTP adapter behavior.

### Diagnose the concrete failure

Compile an installed feature module with an overridden repository, resolve the service and verify the fake result. Remove the provider registration in a disposable copy and expect a resolution failure. Close the testing module after the test.

### Independent exercise and evidence

Design an integration test that imports the production feature module and overrides only its external repository. Record the exact token, resolution result and lifecycle cleanup.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.
