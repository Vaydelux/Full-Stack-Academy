# Linux filesystem and permissions

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

## Context

A Linux service stores a secret and writable data.

## Step 1 — Mental model

Ownership and permissions grant only necessary access; avoid broad chmod fixes.

## Step 2 — Guided practice

In a disposable directory create a fake secret; compare owner-only with world-readable permissions.

## Step 3 — Acceptance

## Applied engineering walkthrough

Linux permissions describe access for an owner, group and others; directory traversal permissions also affect whether a file is reachable. A service identity should have read access to its configuration and write access only where required. Restrictive file modes are not proof that privileged administrators cannot read a secret.

### Diagnose the concrete failure

Create a synthetic secret in an isolated temporary directory and compare its owner, group and mode before and after restricting access. Under a separate authorized test identity, verify access is denied when the environment permits. Never change permissions on system files or real secrets.

### Independent exercise and evidence

Design a service filesystem layout with read-only application code, writable data and restricted configuration. Record effective identities, directory permissions and observed denial; distinguish mode inspection from a real access test.
