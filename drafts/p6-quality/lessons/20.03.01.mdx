# Environments and approvals

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A build has no environment approval.

## Step 1 — Mental model

Authorization is independent of successful code checks.

## Step 2 — Guided practice

Call releaseDecision with approved=false then true, holding other evidence valid.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** All true conditions promote the candidate.

**Negative:** Missing approval holds previous version.

## Qualification boundary

Boolean release decision model, not deployment, migration, traffic switching or verified rollback.

## Applied engineering walkthrough

An environment approval is authorization for a specific candidate, target and risk context, not a generic yes. Deployment decisions should bind immutable artifact identity, reviewer and required evidence. Promotion to staging and production may have distinct requirements.

### Diagnose the concrete failure

Use releaseDecision with every required condition satisfied except approval. Verify the held decision, then supply approval and check the intended promotion. Test an incompatible candidate even when approved.

### Independent exercise and evidence

Design a release approval record with environment, artifact digest, evidence links and authorized reviewer. Record the synthetic decision outcomes without altering real environment settings.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.
