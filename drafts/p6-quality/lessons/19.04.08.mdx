# Lab measurable API SLO

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A team defines a measurable API SLO.

## Step 1 — Mental model

Specify the population, window, measurement method and targets before sampling.

## Step 2 — Guided practice

Make 100 synthetic samples, one failure and p95 below 100ms; add two failures and re-evaluate.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** First set meets p95 100ms and error rate 1%.

**Negative:** Changed set fails; this is not real production SLA proof.

Run the complementary local module model and inspect `latencyReport` in `examples/p6-quality/labs.mjs`. Add an assertion for the relevant boundary. This command does not execute the external tools described above.

node --test --test-name-pattern="19[.]04" examples/p6-quality/labs.test.mjs

## Qualification boundary

Metrics model uses supplied samples; no real load generation, chaos or database benchmark.

## Applied engineering walkthrough

An API SLO combines a precisely defined population and measurable targets over a window. Synthetic latency and error samples teach gate arithmetic, not actual service availability. Define whether failures and timeouts enter the denominator and which latency samples qualify.

### Diagnose the concrete failure

Run the supplied hundred-sample model with one error and the stated p95 threshold, then introduce additional errors and verify the changed result fails. Exercise an empty observation set and ensure it cannot pass as healthy.

### Independent exercise and evidence

Design a disposable API workload with a latency target, success-rate target and minimum sample count. Record actual observations and distinguish test acceptance from a production SLO or contractual SLA.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.
