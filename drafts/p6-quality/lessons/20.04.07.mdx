# Terraform state and secrets

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

Terraform state may retain a credential.

## Step 1 — Mental model

State maps configuration to resources and may hold sensitive values even when marked sensitive.

## Step 2 — Guided practice

Create synthetic state-like JSON with a fake marker; check Git exclusion and restricted local access.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** Marker not committed; state access policy documented.

## Qualification boundary

Synthetic topology policy; no OS/firewall/TLS/DNS/IaC or restore enforcement tested.

## Applied engineering walkthrough

Terraform-compatible state maps resource configuration to actual resource identities and may contain sensitive values even when outputs are marked sensitive. Restrict access, encrypt storage appropriately and coordinate concurrent state changes with supported locking. Do not commit state or secret-bearing plan artifacts.

### Diagnose the concrete failure

Use a fake state JSON document containing a synthetic marker. Verify it is excluded from the intended Git paths and that local access is restricted. Inspect any generated plan separately for the same marker. Do not read or expose real infrastructure state.

### Independent exercise and evidence

Design a state ownership and backup policy with access, encryption, locking and recovery procedures. Record synthetic checks and identify the real backend acceptance required before infrastructure changes.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.
