# Feature flags

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A feature is exposed to a small cohort.

## Step 1 — Mental model

Feature flags separate deployment from exposure; defaults and stable cohort identity matter.

## Step 2 — Guided practice

Design deterministic assignment and default-off behavior; model incompatible flag contract as held.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** Same subject stays in the same cohort.

**Negative:** Flag-service failure must not unexpectedly enable exposure.

Run the complementary local module model and inspect `releaseDecision` in `examples/p6-quality/labs.mjs`. Add an assertion for the relevant boundary. This command does not execute the external tools described above.

## Qualification boundary

Boolean release decision model, not deployment, migration, traffic switching or verified rollback.

## Applied engineering walkthrough

Feature flags separate deployment from exposure. Stable cohort assignment avoids a user switching behavior arbitrarily. The default on a flag-service failure should be explicitly safe, and security authorization must never depend only on a client flag. Old flags need owners and removal dates.

### Diagnose the concrete failure

Design deterministic cohort assignment for synthetic subject IDs and check repeated evaluation returns the same result. Simulate unavailable flag configuration and verify the intended default. Use releaseDecision to examine an incompatible flag contract.

### Independent exercise and evidence

Prepare a flag lifecycle with exposure limits, monitoring, kill switch and cleanup. Record assignment outcomes and server-side authorization checks; do not modify live feature settings.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.
