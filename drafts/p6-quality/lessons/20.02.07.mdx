# Branch protection

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A branch accepts merges despite a missing check.

## Step 1 — Mental model

Server-side branch protection enforces stable required check identities; local code is not server proof.

## Step 2 — Guided practice

Model a missing required result; review hypothetical branch rules without changing the repo.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** Complete commit-bound result set meets the model.

**Negative:** Missing evidence cannot authorize a merge.

## Qualification boundary

## Applied engineering walkthrough

Branch protection is an enforcement boundary, not a substitute for meaningful test definitions. Required checks should refer to the intended candidate and authorized review policy. Changing source after approval can invalidate evidence. Local decision models cannot inspect or modify actual branch rules.

### Diagnose the concrete failure

Evaluate a complete matching check set, then omit a mandatory job and verify denial. Review hypothetical rules for authorized merge and stale review without changing repository settings. Identify which real settings would require independent verification.

### Independent exercise and evidence

Write a merge policy with required jobs, evidence freshness and authorized exceptions. Record model outcomes separately from actual branch configuration and review approval.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.
