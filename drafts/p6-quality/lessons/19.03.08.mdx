# Lab full request test

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A request must authenticate, authorize, query and serialize.

## Step 1 — Mental model

Layered unit checks and real request tests verify different risks.

## Step 2 — Guided practice

Use scopedRead acceptance targets to implement a Nest route against disposable DB; exercise real owner/anonymous/foreign requests.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** Authorized HTTP request returns the expected minimal DTO.

**Negative:** Denied requests cannot reveal or modify rows.

Run the complementary local module model and inspect `scopedRead` in `examples/p6-quality/labs.mjs`. Add an assertion for the relevant boundary. This command does not execute the external tools described above.

```bash
node --test --test-name-pattern="19[.]03" examples/p6-quality/labs.test.mjs
```

## Qualification boundary

Synthetic row/actor model; no Nest DI, network server, PostgreSQL or RLS execution.

## Applied engineering walkthrough

A full request test crosses authentication, authorization, validation, persistence and serialization. Passing at one layer does not prove downstream controls. Build a small known fixture and assert both allowed and denied outcomes, including database effects.

### Diagnose the concrete failure

Exercise the intended route using the actual local Nest adapter and isolated database when available. Send an anonymous request, permitted owner request and foreign-tenant request. Verify expected status, exact public DTO and unchanged forbidden data.

### Independent exercise and evidence

Prepare a full request acceptance record with commit, environment, identities, input, HTTP result and persistence result. Keep model evidence separate from real database and adapter qualification.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.

2. Which negative case falsifies the unsafe implementation?
