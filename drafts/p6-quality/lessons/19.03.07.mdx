# Contract and snapshot tests

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A client depends on a stable task response.

## Step 1 — Mental model

Contracts assert semantics; snapshots require review and should not accept private fields.

## Step 2 — Guided practice

Assert exact scopedRead DTO; compare a real HTTP payload against a reviewed schema or snapshot.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** Required keys and types match.

**Negative:** Removed keys or added secret fields fail.

Run the complementary local module model and inspect `scopedRead` in `examples/p6-quality/labs.mjs`. Add an assertion for the relevant boundary. This command does not execute the external tools described above.

```bash
node --test --test-name-pattern="19[.]03" examples/p6-quality/labs.test.mjs
```

## Qualification boundary

Synthetic row/actor model; no Nest DI, network server, PostgreSQL or RLS execution.

## Knowledge check

1. Which public behavior or invariant is being protected?
2. Which negative case falsifies the unsafe implementation?
3. Which real runtime or manual check is still required?

**Assessment:** Submit the exact synthetic input, expected and observed outputs, a negative result, and the untested boundaries. Mark unavailable external checks not-run.
