# Contract and snapshot tests

> Unpublished instructor manuscript. A green model test is not real runtime acceptance.

## Learning outcomes

Explain the design rule, reproduce or specify an observable positive and negative experiment, and distinguish the model from external evidence.

## Context

A client depends on a stable task response.

## Step 1 — Mental model

Contracts assert semantics; snapshots require review and should not accept private fields.

## Step 2 — Guided practice

Assert exact scopedRead DTO; compare a real HTTP payload against a reviewed schema or snapshot.

Predict the outcome before running the experiment. Use only synthetic data and disposable fixtures.

## Step 3 — Acceptance

**Positive:** Required keys and types match.

**Negative:** Removed keys or added secret fields fail.

Run the complementary local module model and inspect `scopedRead` in `examples/p6-quality/labs.mjs`. Add an assertion for the relevant boundary. This command does not execute the external tools described above.

```bash
node --test --test-name-pattern="19[.]03" examples/p6-quality/labs.test.mjs
```

## Qualification boundary

Synthetic row/actor model; no Nest DI, network server, PostgreSQL or RLS execution.

## Applied engineering walkthrough

Contract tests verify the supported boundary shape and meaning. Snapshots are useful for detecting unexpected changes, but blindly updating them can approve accidental secret exposure. Assert required fields, types and excluded fields directly where the contract is critical.

### Diagnose the concrete failure

Compare the scopedRead result with the documented minimal DTO. In a disposable copy add a private field or remove a required field and confirm the assertion fails. Inspect actual HTTP serialization independently of the pure model.

### Independent exercise and evidence

Design a versioned response schema with an explicit compatibility policy for additive and breaking changes. Record expected shape, negative mutation and reviewer decision for any snapshot change.

**Evidence boundary:** These are practice instructions, not recorded test results. Preserve the existing model, specification and draft flag; external runtime qualification remains independent.
