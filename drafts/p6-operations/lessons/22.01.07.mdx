# Virtualization

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

A list renders ten thousand rows at once.

## Step 1 — Mental model

Virtualization bounds DOM work by visible range and overscan; preserve semantics, focus and scroll position.

## Step 2 — Guided practice

Render a synthetic long list with and without virtualization; measure DOM nodes and keyboard behavior.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** DOM count remains bounded; focus remains usable.

**Negative:** Missing reachable rows or lost keyboard focus fails.

## Applied engineering walkthrough

Virtualization limits mounted rows to the visible window plus overscan. It reduces DOM work but introduces focus, scrolling and accessibility challenges. Stable row identity and accurate size estimates matter, especially when rows are dynamic.

### Diagnose the concrete failure

Render a synthetic ten-thousand-row dataset in a real disposable browser with and without virtualization. Inspect DOM node count, scroll to known rows and navigate using the keyboard. Check that focus is not lost when items leave the window.

### Independent exercise and evidence

Design a list contract for stable keys, overscan, accessible row position and find/navigation behavior. Record browser measurements and manual keyboard results separately.

**Evidence boundary:** These are practice instructions, not recorded benchmark results. Preserve the existing specification, model and unpublished status. Actual browser measurement and qualification remain independent.
