# Sampling and cardinality

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

A metric uses user IDs as labels.

## Step 1 — Mental model

High cardinality increases series count; sampling controls trace volume but can bias observed data.

## Step 2 — Guided practice

Compare unique label counts for 100 users versus 3 route templates; specify a sampling policy and document errors that might be missed.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Bounded templates yield a small number of series.

**Negative:** Per-user labels explode series count; sampled data cannot prove every request traced.

## Applied engineering walkthrough

Metric cardinality grows with combinations of label values. One hundred user IDs multiplied by routes and statuses can create far more series than three route templates. Trace sampling is a separate cost and fidelity tradeoff; a sampled trace set cannot prove every request was recorded.

### Diagnose the concrete failure

Compare a synthetic label inventory using per-user labels and bounded route labels. Count distinct combinations. Define a sampling rule and identify rare failures that might not appear in a sample.

### Independent exercise and evidence

Design a telemetry budget with bounded metric dimensions, trace sampling and independent error counters. Record series counts and actual export volume when instrumentation is available.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve the existing specification, model and unpublished status. Actual instrumentation and runtime qualification remain independent.
