# Bundle analysis

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

A small page ships an oversized client bundle.

## Step 1 — Mental model

Inspect dependency composition, transfer size and parse/execute cost; split or remove work based on evidence.

## Step 2 — Guided practice

In a built disposable Next app inspect bundle output before and after removing an unused heavy dependency.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Relevant client chunk shrinks with unchanged behavior.

**Negative:** Only changing source file size without measuring output is insufficient.

## Qualification boundary

Synthetic measured-value budget only; actual Core Web Vitals, browser profiles and real-user metrics are unexecuted.

## Applied engineering walkthrough

Bundle analysis inspects delivered JavaScript and its dependency graph, not source file length. Server-only modules and client boundaries affect which code is shipped. Tree shaking and code splitting depend on actual imports and build configuration. A smaller chunk can still delay interaction if expensive to evaluate.

### Diagnose the concrete failure

Build a disposable Next application and inspect its client chunks before and after removing an unused dependency. Compare compressed transfer and parse/execution costs where measurable. Verify the affected feature still works.

### Independent exercise and evidence

Set a route-specific client budget and an explicit reviewer for exceptions. Record build configuration, chunk sizes and functional results; do not infer improvement from source edits alone.

**Evidence boundary:** These are practice instructions, not recorded benchmark results. Preserve the existing specification, model and unpublished status. Actual browser measurement and qualification remain independent.
