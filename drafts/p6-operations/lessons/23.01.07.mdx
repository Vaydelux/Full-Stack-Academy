# Architecture decision records

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

A team must choose monolith or service extraction.

## Step 1 — Mental model

An ADR records context, decision, alternatives, consequences and reconsideration triggers.

## Step 2 — Guided practice

Write a short ADR for keeping a module in-process, with measured trigger for extraction.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Applied engineering walkthrough

An architecture decision record captures context, alternatives, decision and consequences. It is a historical decision with assumptions, not an immutable command to keep the same design forever. Define measurable triggers for reconsideration rather than selecting a technology solely by preference.

### Diagnose the concrete failure

Write a synthetic ADR comparing a modular monolith, extracted worker and separate service. Identify current coupling, operational burden and the evidence that would justify revisiting the choice. Include a rejected alternative and its reason.

### Independent exercise and evidence

Create a decision register with status, owner and review triggers. Record known facts separately from hypotheses and include a practical migration or reversal strategy.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve the existing specification, model and unpublished status. Actual source dependency and runtime qualification remain independent.

## Knowledge check

1. Which invariant or operational measurement determines success?
2. What failure case disproves the unsafe design?
3. Which evidence remains missing before this can be applied to a production service?

**Assessment:** Submit input, expected/observed outcomes, a meaningful negative result and the unverified external boundaries. Mark unavailable tests not-run.
