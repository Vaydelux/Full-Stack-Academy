# OpenTelemetry instrumentation

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

An HTTP server needs repeatable tracing before application startup.

## Step 1 — Mental model

Instrument supported libraries before loading them, configure resource identity and export via a controlled collector.

## Step 2 — Guided practice

Build a disposable Node service with the OpenTelemetry SDK, start instrumentation first, send one loopback request and inspect the exported trace.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Exporter contains a service name and request span.

**Negative:** Missing instrumentation or exporter failure is not a passing trace test.

Inspect the complementary `safeLog` model in `examples/p6-operations/labs.mjs` and extend its assertions where relevant. The command below does not execute the external tools discussed in this topic.

```bash
node --test --test-name-pattern="21[.]01" examples/p6-operations/labs.test.mjs
```

## Qualification boundary

Local field-allowlist model only; Pino, exporters, collectors and Sentry require installed tools and actual trace propagation.

## Applied engineering walkthrough

OpenTelemetry instrumentation should initialize before modules that need automatic instrumentation are loaded. Exporters and processors have lifecycle and resource limits; a missing export can be instrumentation or transport failure. Tracing should not block every request on remote delivery.

### Diagnose the concrete failure

Start a disposable Node service using the installed SDK and local exporter. Send one loopback request and inspect service resource attributes and request span. Simulate exporter failure and verify application behavior and diagnostic reporting.

### Independent exercise and evidence

Design startup, sampling and bounded shutdown for telemetry. Record SDK version, exported spans and any dropped evidence; the safeLog model does not initialize OpenTelemetry.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve the existing specification, model and unpublished status. Actual instrumentation and runtime qualification remain independent.
