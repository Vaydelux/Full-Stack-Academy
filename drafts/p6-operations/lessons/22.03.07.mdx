# Baseline and regression tests

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

A performance improvement may regress next release.

## Step 1 — Mental model

Baseline captures version, workload, conditions and distributions; repeat trials and use defined thresholds.

## Step 2 — Guided practice

Store synthetic baseline and changed result, then plan matched real benchmark runs.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Regression gate catches meaningful increase under equivalent conditions.

**Negative:** Comparing different hardware/workload or ignoring variance fails.

Inspect the complementary `capacity` model in `examples/p6-operations/labs.mjs` and extend its assertions where relevant. The command below does not execute the external tools discussed in this topic.

```bash
node --test --test-name-pattern="22[.]03" examples/p6-operations/labs.test.mjs
```

## Qualification boundary

Capacity arithmetic only; no actual CDN, cache cluster, balancing, cost quotes or scaling benchmark.

## Knowledge check

1. Which invariant or operational measurement determines success?
2. What failure case disproves the unsafe design?
3. Which evidence remains missing before this can be applied to a production service?

**Assessment:** Submit input, expected/observed outcomes, a meaningful negative result and the unverified external boundaries. Mark unavailable tests not-run.
