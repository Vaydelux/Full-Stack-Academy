# Delivery guarantees

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

A broker redelivers messages after lost acknowledgement.

## Step 1 — Mental model

At-least-once can duplicate, at-most-once can lose; exactly-once claims have a specific system boundary.

## Step 2 — Guided practice

Simulate ack loss and duplicate delivery using idempotentConsumer; distinguish consumer state from external email side effect.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Duplicate does not increment local total.

**Negative:** Claiming exactly-once external delivery without evidence fails.

Inspect the complementary `idempotentConsumer` model in `examples/p6-operations/labs.mjs` and extend its assertions where relevant. The command below does not execute the external tools discussed in this topic.

```bash
node --test --test-name-pattern="23[.]03" examples/p6-operations/labs.test.mjs
```

## Qualification boundary

In-memory synthetic idempotency model; no broker, durable store, transactional outbox or exactly-once side-effect evidence.

## Applied engineering walkthrough

At-most-once, at-least-once and exactly-once guarantees apply to a defined transport or processing boundary. A broker acknowledgement can be lost after a side effect, allowing redelivery. Exactly-once broker features do not automatically guarantee exactly-once email or payment effects.

### Diagnose the concrete failure

Simulate a duplicate delivery using the existing consumer model and inspect the unchanged total. Then draw a failure after an external provider accepts a request but before the local receipt commits. Explain why the model cannot establish the external outcome.

### Independent exercise and evidence

Design a delivery contract with acknowledgement timing, durable deduplication and provider reconciliation. Record which guarantees apply to each boundary and which remain untested.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve the existing specification, model and unpublished status. Actual persistence, broker and provider qualification remain independent.
