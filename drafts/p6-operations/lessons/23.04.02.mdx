# Service discovery

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

A service instance is replaced with a new address.

## Step 1 — Mental model

Discovery maps logical service identity to healthy endpoints; stale entries and health delays require bounded retries.

## Step 2 — Guided practice

In disposable local fixture change endpoint registration and observe discovery refresh with one unhealthy instance.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Healthy endpoint selected after bounded refresh.

**Negative:** Infinite retries to stale address or unauthenticated discovery fails.

## Applied engineering walkthrough

Service discovery maps a logical service to changing endpoints. Health checks and bounded refresh influence which endpoints receive requests, but discovery does not authenticate a service by itself. Stale endpoint caches and connection reuse need explicit recovery behavior.

### Diagnose the concrete failure

In a disposable local fixture replace an endpoint registration and mark the old instance unhealthy. Observe bounded discovery refresh and request routing to the ready instance. Verify an unavailable service produces a bounded failure rather than infinite retries.

### Independent exercise and evidence

Design a discovery contract with trusted registration, health state, cache expiry and transport identity. Record actual endpoint transitions and request outcomes only when the local infrastructure runs.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve the existing specification, model and unpublished status. Actual distributed runtime qualification remains independent.
