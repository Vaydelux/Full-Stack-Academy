# Sentry error tracking

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

An exception report contains a synthetic access token.

## Step 1 — Mental model

Error tracking groups crashes and captures context; scrub secrets before sending, and restrict access/retention.

## Step 2 — Guided practice

In an isolated Sentry test transport, trigger an exception with fake sensitive context and inspect the event before transmission.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Exception is actionable without secret context.

**Negative:** Fake token appearing in a report fails the privacy gate.

Inspect the complementary `safeLog` model in `examples/p6-operations/labs.mjs` and extend its assertions where relevant. The command below does not execute the external tools discussed in this topic.

```bash
node --test --test-name-pattern="21[.]01" examples/p6-operations/labs.test.mjs
```

## Qualification boundary

Local field-allowlist model only; Pino, exporters, collectors and Sentry require installed tools and actual trace propagation.

## Applied engineering walkthrough

Error reporting needs useful stack and operation context without bearer tokens, cookies or private payloads. Scrubbing must cover nested data, breadcrumbs and URLs, not just top-level fields. SDK configuration and actual transport output need separate inspection.

### Diagnose the concrete failure

Use an isolated test transport and throw an exception containing a synthetic secret marker. Inspect the serialized event before transmission and verify the marker is absent while useful error context remains. Test nested context and breadcrumbs.

### Independent exercise and evidence

Design an error-event allowlist, retention policy and release identifier. Record actual captured event fields and denied synthetic markers; never send real credentials to a test service.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve the existing specification, model and unpublished status. Actual instrumentation and runtime qualification remain independent.
