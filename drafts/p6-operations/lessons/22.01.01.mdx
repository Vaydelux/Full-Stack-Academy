# Core Web Vitals LCP INP CLS

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

A page loads slowly, responds late and shifts layout.

## Step 1 — Mental model

LCP measures largest content render timing, INP interaction responsiveness, CLS unexpected layout movement; assess field distributions separately from lab runs.

## Step 2 — Guided practice

Use webBudget with example 2500ms LCP, 200ms INP, .1 CLS; then collect a real browser trace and record its conditions.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Independent budgets are evaluated, not averaged.

**Negative:** Missing INP or unstable layout cannot pass by fast LCP alone.

Inspect the complementary `webBudget` model in `examples/p6-operations/labs.mjs` and extend its assertions where relevant. The command below does not execute the external tools discussed in this topic.

```bash
node --test --test-name-pattern="22[.]01" examples/p6-operations/labs.test.mjs
```

## Qualification boundary

Synthetic measured-value budget only; actual Core Web Vitals, browser profiles and real-user metrics are unexecuted.

## Knowledge check

1. Which invariant or operational measurement determines success?
2. What failure case disproves the unsafe design?
3. Which evidence remains missing before this can be applied to a production service?

**Assessment:** Submit input, expected/observed outcomes, a meaningful negative result and the unverified external boundaries. Mark unavailable tests not-run.
