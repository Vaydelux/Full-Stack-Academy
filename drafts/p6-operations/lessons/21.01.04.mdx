# Traces and spans

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

A checkout calls inventory then payment.

## Step 1 — Mental model

A trace links causally related spans with parent relationships, durations and statuses; context propagation crosses process boundaries.

## Step 2 — Guided practice

Sketch a root checkout span and two child spans. In an installed tracing fixture cause payment failure and inspect parent IDs.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Both children belong to the checkout trace and payment reports failure.

**Negative:** Orphan spans or a swallowed dependency error obscure the cause.

Inspect the complementary `safeLog` model in `examples/p6-operations/labs.mjs` and extend its assertions where relevant. The command below does not execute the external tools discussed in this topic.

```bash
node --test --test-name-pattern="21[.]01" examples/p6-operations/labs.test.mjs
```

## Qualification boundary

Local field-allowlist model only; Pino, exporters, collectors and Sentry require installed tools and actual trace propagation.

## Knowledge check

1. Which invariant or operational measurement determines success?
2. What failure case disproves the unsafe design?
3. Which evidence remains missing before this can be applied to a production service?

**Assessment:** Submit input, expected/observed outcomes, a meaningful negative result and the unverified external boundaries. Mark unavailable tests not-run.
