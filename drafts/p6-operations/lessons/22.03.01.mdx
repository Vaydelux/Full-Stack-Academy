# CDN caching and purge

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

An edge cache serves an outdated product page.

## Step 1 — Mental model

CDN cache keys, TTL, invalidation and versioned assets define freshness; private content needs explicit isolation.

## Step 2 — Guided practice

Design public catalog and authenticated cart cache policies; in a local proxy test update and invalidation.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Catalog converges and cart remains private.

**Negative:** Cross-user cache leakage or stale version after purge fails.

## Applied engineering walkthrough

CDN caching reduces repeated origin traffic for eligible representations. Purging an edge cache is distinct from browser cache expiration and may propagate asynchronously. Define public versus private representations explicitly; authenticated cart data should not enter a shared public cache.

### Diagnose the concrete failure

In a disposable proxy fixture cache a public catalog response, change its authoritative version and exercise the purge contract. Check the next read and verify two distinct users cannot receive each other's private cart. Inspect actual cache headers.

### Independent exercise and evidence

Design public catalog caching with versioned assets, bounded freshness and explicit purge behavior. Record observed representation versions and isolation outcomes; a modeled purge is not provider evidence.

**Evidence boundary:** These are practice instructions, not recorded capacity or benchmark results. Preserve the existing specification, model and unpublished status. Actual deployment measurements remain independent.
