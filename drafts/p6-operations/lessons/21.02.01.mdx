# SLIs SLOs and error budgets

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

An API has a 99% successful-request objective.

## Step 1 — Mental model

SLI measures a defined population, SLO sets its target, and error budget is the permitted failure fraction over a window.

## Step 2 — Guided practice

Run errorBudget(1000,10,.99) and then 11 failures; define which requests count.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Ten failures exhaust but do not exceed the budget.

**Negative:** Eleven failures breach; zero traffic does not establish reliability.

Inspect the complementary `errorBudget` model in `examples/p6-operations/labs.mjs` and extend its assertions where relevant. The command below does not execute the external tools discussed in this topic.

```bash
node --test --test-name-pattern="21[.]02" examples/p6-operations/labs.test.mjs
```

## Qualification boundary

Synthetic error-budget arithmetic only; real probes, alerts, concurrency and fault recovery require actual isolated services.

## Knowledge check

1. Which invariant or operational measurement determines success?
2. What failure case disproves the unsafe design?
3. Which evidence remains missing before this can be applied to a production service?
