# Feature toggles

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

A module feature needs gradual enablement.

## Step 1 — Mental model

Feature toggles have default, scope, ownership and expiry; flags are not authorization.

## Step 2 — Guided practice

Design stable subject assignment with default-off; check authorized and unauthorized users.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Flag changes exposure for authorized cohort only.

**Negative:** Flag overriding permission or missing default fails.

## Applied engineering walkthrough

Feature toggles control exposure of a capability, not permission to use it. Cohort assignment should be stable for the intended subject, and unavailable configuration needs an explicit safe default. A disabled client UI does not replace server-side authorization.

### Diagnose the concrete failure

Evaluate a proposed feature flag for two synthetic authorized users and an unauthorized user. Verify stable assignment and default-off behavior, then assert the unauthorized actor remains denied even when the flag is enabled.

### Independent exercise and evidence

Design flag ownership, rollout, emergency disable and removal criteria. Record assignment and authorization outcomes independently.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve the existing specification, model and unpublished status. Actual module, persistence and runtime qualification remain independent.
