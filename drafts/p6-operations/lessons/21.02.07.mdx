# Graceful degradation

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

A recommendation service becomes unavailable.

## Step 1 — Mental model

Graceful degradation preserves the critical user journey while labeling unavailable optional data; avoid serving unauthorized cached data.

## Step 2 — Guided practice

Design checkout with optional recommendations, simulate timeout and show an explicit fallback.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Checkout remains available with a fallback.

**Negative:** A stale private response or misleading success fails.

## Qualification boundary

Synthetic error-budget arithmetic only; real probes, alerts, concurrency and fault recovery require actual isolated services.

## Applied engineering walkthrough

Graceful degradation preserves essential behavior while clearly disabling optional features. A recommendation failure must not compromise checkout correctness, and a stale private response is never a safe generic fallback. Distinguish optional data from required authorization and business invariants.

### Diagnose the concrete failure

Simulate a recommendation timeout and verify the synthetic checkout remains correct while the recommendation panel reports unavailable. Fail a required payment or authorization step separately and confirm the operation does not falsely succeed.

### Independent exercise and evidence

Design a dependency criticality matrix and explicit fallback per optional service. Record user-visible state and business outcome; qualify actual dependency failures separately.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve the existing specification, model and unpublished status. Actual resilience and runtime qualification remain independent.
