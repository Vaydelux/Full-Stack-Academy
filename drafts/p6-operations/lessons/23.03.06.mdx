# Versioned message schemas

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

A new event field reaches old consumers.

## Step 1 — Mental model

Schema evolution requires explicit versioning and compatible defaults or separate message versions.

## Step 2 — Guided practice

Create v1 and v2 synthetic messages with optional field; test old/new consumers and unknown version denial.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Compatible addition preserves old behavior.

**Negative:** Incompatible field removal or unknown version silently processed fails.

## Qualification boundary

In-memory synthetic idempotency model; no broker, durable store, transactional outbox or exactly-once side-effect evidence.

## Applied engineering walkthrough

A message schema is a compatibility boundary between independently deployed producers and consumers. Optional additions can be compatible if consumers tolerate unknown fields, but removing required fields or changing their meaning can break old versions. Unknown incompatible versions need a controlled rejection path.

### Diagnose the concrete failure

Create synthetic v1 and v2 messages with the same required fields and an optional addition. Exercise old and new consumer contracts, then remove a required field or use an unsupported version. Verify no invalid message causes a business effect.

### Independent exercise and evidence

Design a compatibility policy and producer/consumer fixture matrix with version retirement criteria. Record normalized values and denied variants separately from actual broker delivery.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve the existing specification, model and unpublished status. Actual persistence, broker and provider qualification remain independent.
