# Lab reliable event integration

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

A learner builds a reliable order-event flow.

## Step 1 — Mental model

Reliable integration combines transactional outbox, retry, durable inbox, explicit errors and idempotent effects.

## Step 2 — Guided practice

Run local consumer tests; on disposable PostgreSQL rehearse outbox and P5 inbox with independent workers and recovery.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Model handles duplicate; real DB integration must prove restart and atomicity.

**Negative:** Duplicate effects or untracked uncertain commit block qualification.

Inspect the complementary `idempotentConsumer` model in `examples/p6-operations/labs.mjs` and extend its assertions where relevant. The command below does not execute the external tools discussed in this topic.

```bash
node --test --test-name-pattern="23[.]03" examples/p6-operations/labs.test.mjs
```

## Qualification boundary

In-memory synthetic idempotency model; no broker, durable store, transactional outbox or exactly-once side-effect evidence.

## Knowledge check

1. Which invariant or operational measurement determines success?
2. What failure case disproves the unsafe design?
3. Which evidence remains missing before this can be applied to a production service?

**Assessment:** Submit input, expected/observed outcomes, a meaningful negative result and the unverified external boundaries. Mark unavailable tests not-run.
