# Lab simulated incident

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

An API outage requires coordination and recovery.

## Step 1 — Mental model

Incident drills exercise detection, assignment, mitigation, communications and validation without touching live services.

## Step 2 — Guided practice

Run incidentDecision; simulate unavailable dependency, assign roles, restore disposable fixture, record timestamps.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Recovery evidence and owner are recorded independently.

**Negative:** Declaring recovery without functional verification fails.

Inspect the complementary `incidentDecision` model in `examples/p6-operations/labs.mjs` and extend its assertions where relevant. The command below does not execute the external tools discussed in this topic.

```bash
node --test --test-name-pattern="21[.]03" examples/p6-operations/labs.test.mjs
```

## Qualification boundary

Synthetic incident decisions only; no real emergency response, restored backups, alerting or production capacity measurements.

## Knowledge check

1. Which invariant or operational measurement determines success?
2. What failure case disproves the unsafe design?
3. Which evidence remains missing before this can be applied to a production service?

**Assessment:** Submit input, expected/observed outcomes, a meaningful negative result and the unverified external boundaries. Mark unavailable tests not-run.
