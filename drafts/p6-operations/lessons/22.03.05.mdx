# Horizontal scaling

> Unpublished instructor manuscript. Local model tests are supplemental, not external runtime qualification.

## Learning outcomes

Explain the relevant engineering tradeoff, define a measurable experiment and recognize the boundary of the available evidence.

## Context

Demand doubles under an instance limit.

## Step 1 — Mental model

Horizontal scaling needs measured per-instance capacity and headroom, with downstream constraints.

## Step 2 — Guided practice

Use capacity for 160 rps, 100 per instance, 20% headroom and cap two; change demand to 161.

Use synthetic data and a disposable authorized environment. Record the expected result before the experiment.

## Step 3 — Acceptance

**Positive:** Two instances meet first scenario; next needs three.

**Negative:** Demand above cap cannot be reported feasible.

Inspect the complementary `capacity` model in `examples/p6-operations/labs.mjs` and extend its assertions where relevant. The command below does not execute the external tools discussed in this topic.

```bash
node --test --test-name-pattern="22[.]03" examples/p6-operations/labs.test.mjs
```

## Qualification boundary

Capacity arithmetic only; no actual CDN, cache cluster, balancing, cost quotes or scaling benchmark.

## Applied engineering walkthrough

Capacity arithmetic uses measured sustainable per-instance throughput, desired headroom and a resource cap. With 100 requests per second per instance and 20% reserved headroom, usable capacity is 80 per instance. Two instances fit 160 requests per second; 161 requires three under the stated model.

### Diagnose the concrete failure

Run capacity on the two adjacent demand values and inspect required instances and feasibility. Compare with a separate database connection ceiling. Verify that insufficient resource capacity cannot be reported as feasible.

### Independent exercise and evidence

Design a horizontal scaling worksheet with sustainable throughput, headroom, replica cap and dependency limits. Record the assumptions and measured basis when available; the arithmetic does not qualify actual autoscaling.

**Evidence boundary:** These are practice instructions, not recorded capacity or benchmark results. Preserve the existing specification, model and unpublished status. Actual deployment measurements remain independent.
