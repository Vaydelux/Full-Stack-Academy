## The problem we're solving

A task form accepts whitespace-only titles even though the server rejects them. Another developer types a submitted value as the pre-transform input and sends untrimmed text.

**What breaks in the learner starter:** The form has no resolver, so a whitespace title reaches the submit handler.

## Build the mental model

Zod 4 parses and transforms runtime input. React Hook Form supports the schema input type and a distinct handleSubmit output type as its third generic.

**Predict before coding:** A title containing spaces only must be blocked before POST, while a valid padded title becomes trimmed in handleSubmit.

**Scope:** This staged article uses genuine React Hook Form v7 interfaces and React 19 patterns. The staged TSX starter/instructor pairs were typechecked and exercised in a locked local Chrome qualification on November 20, 2026. This preview has not completed the separate publication and human accessibility review. The companion Node loopback Task API is educational, unauthenticated and in-memory.

<LessonStep number={2} title="Apply the instructor repair" file="drafts/forms-query/labs/zod-resolver/solution.tsx" expected="A title containing spaces only must be blocked before POST, while a valid padded title becomes trimmed in handleSubmit.">

```tsx
import * as z from 'zod';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
const Task=z.object({title:z.string().trim().min(3).max(100),priority:z.enum(['low','normal','high'])});
export default function TaskForm(){
 const {register,handleSubmit,formState:{errors}}=
  useForm<z.input<typeof Task>,unknown,z.output<typeof Task>>({
   resolver:zodResolver(Task), defaultValues:{title:'',priority:'normal'} });
 return <form onSubmit={handleSubmit(data=>console.log(data.title))}>
  <label htmlFor="task-title">Title</label><input id="task-title" {...register('title')}
   aria-invalid={Boolean(errors.title)} aria-describedby={errors.title?'title-err':undefined}/>
  {errors.title&&<p id="title-err" role="alert">{errors.title.message}</p>}
  <label htmlFor="task-priority">Priority</label><select id="task-priority" {...register('priority')}>
   <option value="normal">Normal</option><option value="low">Low</option><option value="high">High</option></select>
  <button>Submit</button>
 </form>;
}
```

**Why:** Zod 4 parses and transforms runtime input. React Hook Form supports the schema input type and a distinct handleSubmit output type as its third generic.

</LessonStep>

## Bug Hunt: reproduce, diagnose and repair

1. **Reproduce:** The form has no resolver, so a whitespace title reaches the submit handler.
2. **Diagnose:** Locate who owns the current value, where it is transformed, and which effect or async boundary can invalidate assumptions.
3. **Repair:** Use zodResolver with distinct schema input and transformed output types; validate unknown values at the HTTP boundary too.
4. **Regression:** The string `  done ` must be transformed to `done`. `   ` and a 101-character title must not invoke the submit callback. Server 422 must still be handled.
5. **Operational boundary:** zodResolver is not authorization or persistence. The loopback API rejects invalid title/priority independently and must not trust the browser schema.
