## The problem we're solving

A team binds a profile field to React state but forgets to forward onChange, leaving the form apparently read-only. Repeated rerenders add more problems when the same field is also registered in React Hook Form.

**What breaks in the learner starter:** The title is hard-coded and never updated by the registered field.

## Build the mental model

A controlled input receives its current value and change handler from React. An uncontrolled input keeps its current value in the DOM, and React Hook Form can register it via a ref. Pick one owner per field.

**Predict before coding:** Typing into a value-bound field without an onChange handler will not update it; registration with RHF avoids duplicating React state.

<LessonStep number={2} title="Apply the instructor repair" file="drafts/forms-query/labs/controlled-uncontrolled/solution.tsx" expected="Typing into a value-bound field without an onChange handler will not update it; registration with RHF avoids duplicating React state.">

```tsx
import { useState } from 'react';
import { useForm } from 'react-hook-form';
export default function TitleForm() {
  const { register, handleSubmit, formState: { errors } } =
    useForm<{ title: string }>({ defaultValues: { title: '' } });
  const [submitted, setSubmitted] = useState('');
  return <form onSubmit={handleSubmit(v => setSubmitted(v.title))}>
    <label htmlFor="title">Task title</label>
    <input id="title" {...register('title', {
      required: 'Enter a task title',
      minLength: { value: 3, message: 'Enter at least 3 characters' },
      maxLength: { value: 100, message: 'Enter 100 characters or fewer' },
    })}
      aria-invalid={Boolean(errors.title)} aria-describedby={errors.title ? 'title-error' : undefined} />
    {errors.title && <p id="title-error" role="alert">{errors.title.message ?? 'Invalid title'}</p>}
    <button type="submit">Save</button>
    <output>{submitted}</output>
  </form>;
}
```

**Why:** A controlled input receives its current value and change handler from React. An uncontrolled input keeps its current value in the DOM, and React Hook Form can register it via a ref. Pick one owner per field.

</LessonStep>

## Production decision guide: one field, one owner

A native text input already keeps transient keystrokes in the browser. When you register it with React Hook Form, RHF can validate and submit that value without maintaining a separate copy in component state. A fixed `value` prop with no change handler produces a read-only field. Give each field a deliberate owner and define `defaultValues` for a reliable reset and dirty baseline.

| Scenario | Correct owner | Regression |
| --- | --- | --- |
| Native title textbox | RHF `register` and DOM input | A constant value prevents editing |
| Custom controlled picker | `Controller` or `useController` | Displayed choice differs from submitted choice |
| Edit record loaded asynchronously | Explicit form initialization policy | Background refresh overwrites typing |
| Save confirmation | Confirmed request outcome | UI claims success for an invalid title |

**Independent exercise:** Type a valid title, submit, and inspect the last confirmed output. Then enter only two characters and verify the output does not change. Finally, explain why the API still needs its own 3–100-character validation even when the browser rejects the same input.

**Production boundary:** This instructor example confirms the submitted value locally; it does not prove the server saved a record. Keep the editable draft and the last confirmed operation conceptually distinct. If a parent fetches new data while the form is dirty, choose an explicit merge, warning or discard policy instead of silently replacing the current field.
