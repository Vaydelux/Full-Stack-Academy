## The problem we're solving

A search filter is changed while an old request is pending. The un-cancelled request finishes later and overwrites the currently selected filter, while 422 errors retry repeatedly.

**Broken behavior in the starter:** The starter discards AbortSignal, ignores response.ok, and retries errors indiscriminately.

## Build the mental model

TanStack Query supplies signal to queryFn. Pass it to fetch, throw for non-2xx HTTP statuses, and retry transient failures only with explicit limits.

**Predict before coding:** Canceling a stale query should not cache a late response; HTTP 422 must not be retried, while an intermittent 503 can be retried a bounded number of times.

**Version and deployment scope:** TanStack Query v5, React 19, TypeScript 5. The Task API is a locally bound, in-memory, unauthenticated fixture. No compatible npm dependency lock or browser qualification has been completed, so this draft cannot be marked published.

<LessonStep number={2} title="Implement the correct TanStack Query behavior" file="drafts/forms-query/labs/retries-cancellation/solution.tsx" expected="Canceling a stale query should not cache a late response; HTTP 422 must not be retried, while an intermittent 503 can be retried a bounded number of times.">

```tsx
import { useQuery } from '@tanstack/react-query';
class RequestError extends Error{
 constructor(readonly status:number){super('Task GET failed: '+status);}
}
export function TaskList(){
 const tasks=useQuery({
  queryKey:['tasks',{status:'todo'}],
  queryFn:async({signal})=>{
   const r=await fetch('/api/tasks?status=todo',{signal});
   if(!r.ok)throw new RequestError(r.status);
   return r.json() as Promise<{items:{id:string}[]}>;
  },
  retry:(count,error)=>count<2 && (!(error instanceof RequestError)||error.status>=500),
  retryDelay:attempt=>Math.min(1000*2**attempt,4000),
 });
 if(tasks.isError)return <p role="alert">Task service unavailable; retry later.</p>;
 return <output>{tasks.data?.items.length??0} tasks</output>;
}
```

**What changed:** TanStack Query supplies signal to queryFn. Pass it to fetch, throw for non-2xx HTTP statuses, and retry transient failures only with explicit limits.

</LessonStep>

## Bug Hunt: reproduce, diagnose and repair

1. **Reproduce:** The starter discards AbortSignal, ignores response.ok, and retries errors indiscriminately.
2. **Diagnose:** Trace the query key, cancellation boundary, remote response, cache update and invalidation.
3. **Repair:** Pass AbortSignal into fetch, distinguish HTTP 4xx and 5xx, and bound automatic retry behavior.
4. **Regression:** Abort an in-flight request on unmount; ensure no stale result is committed. Mock 422 (zero retries), 503 (bounded retries), and a network failure.
5. **Security and operations:** Do not retry credential failures or validation errors; aggressive retries can amplify a production incident and expose service capacity limits.
