## Performance question to investigate

**Vacuum and maintenance.** VACUUM removes dead-row storage pressure and updates visibility information; ANALYZE maintains planner statistics. Their responsibilities and execution restrictions differ.

**Broken assumption:** The starter updates statistics but does not perform vacuum maintenance. It cannot prove that dead tuples and visibility state were addressed.

The purpose of performance engineering is not to collect more indexes or force a particular query-plan node. It is to establish the correctness of the result, define a representative workload, observe the measured behavior, then decide whether one carefully scoped change produces a sustainable benefit.

This lesson uses a small synthetic multi-tenant task feed. Results can be inspected without a real account, production traffic or secrets. **It is a draft manuscript, not published course content.**

## Applied SQL walkthrough

PostgreSQL updates and deletes leave old tuple versions that become reclaimable when no relevant snapshot needs them. VACUUM makes reusable space available and helps maintain visibility information; ANALYZE updates planner statistics. Ordinary vacuum does not generally shrink the relation file. Long-running transactions may delay cleanup, and autovacuum already performs maintenance.

### Predict and diagnose the result

Use the manual evidence runbook outside a transaction block because VACUUM cannot run inside one. On a separate disposable table, insert and commit data, update and delete a sample, then inspect table statistics before and after maintenance. Statistics can lag and autovacuum may intervene, so record timestamps and configuration context.

### Independent exercise and evidence

Design a maintenance investigation for a high-churn task table. Compare dead tuple estimates, transaction age, autovacuum activity and query estimates before recommending changes. State when VACUUM FULL would require a different operational plan because of locking and rewrite cost. No production maintenance is part of this lab.

**Qualification boundary:** These are measurement instructions and hypotheses, not recorded benchmark results. Use disposable PostgreSQL data and preserve the existing starter and solution. A source check does not prove a faster query or safe production configuration.
