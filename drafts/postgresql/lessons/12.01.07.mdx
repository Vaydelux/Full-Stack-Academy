<LessonStep number={2} title="Repair the relational contract" file="drafts/postgresql/labs/ctes-subqueries/solution.sql" expected="A common table expression names intermediate relational results and makes a multi-step query easier to review. A CTE does not automatically enforce security or improve performance.">

```sql
CREATE TEMP VIEW lesson_result AS
WITH task_counts AS (
 SELECT t.project_id, COUNT(*) AS task_count
 FROM academy_tasks t
 WHERE t.tenant_id = 'alpha'
 GROUP BY t.project_id
)
SELECT p.id AS project_id, c.task_count
FROM academy_projects p
JOIN task_counts c ON c.project_id = p.id
WHERE p.tenant_id = 'alpha' AND c.task_count >= 2;
```

**Why the repair works:** A common table expression names intermediate relational results and makes a multi-step query easier to review. A CTE does not automatically enforce security or improve performance. Review the SQL predicate or constraint that excludes invalid rows and preserves required ones. If a client dynamically constructs SQL, bind parameters rather than interpolating untrusted data; these checked-in statements are intentionally static fixtures.

</LessonStep>

## Edge cases and trust boundaries

A beautifully factored CTE can still return unauthorized data if its predicates are wrong.

For production systems, distinguish this basic query exercise from actual role privileges, row-level security, constraints across tenant boundaries, input validation, indexes, transaction isolation, and migration safety. ## Applied SQL walkthrough

A common table expression names an intermediate relation within one statement. The task_counts CTE filters alpha tasks and aggregates by project before joining to the project relation. Its result is not a permanent table or an access-control boundary. PostgreSQL may inline eligible CTEs; materialization decisions affect execution plans, not the logical correctness requirement.

### Predict and diagnose the result

Compute intermediate counts: project 10 has three tasks and project 11 has two. Project 12 has no matching task group. Joining the counts and requiring at least two yields projects 10 and 11 only. Inspect intermediate results and final results independently. The final project filter remains necessary even if the CTE itself is tenant-filtered.

### Independent exercise and evidence

Design a variant reporting every alpha project including those below the threshold. Use a left join and describe the treatment of missing counts. Compare a CTE version with a derived table using EXPLAIN on a disposable database only after proving identical results. Record expected groups and the reason for the chosen structure.
