## The problem we're solving

**Tables rows columns and types.** The starter leaks the users' email field and includes a second tenant.

Consider a small project-management database. Users belong to tenants; projects have owners; tasks belong to projects. A report may look plausible while producing the wrong rows, exposing sensitive information, or dropping empty groups. You will begin with an intentionally incorrect SQL exercise, predict its observable failure, and then repair it.

## Mental model and vocabulary

Rows represent individual facts; columns have enforced PostgreSQL types and nullable constraints. A SELECT list must expose only fields the consumer is authorized to read.

Store a status as boolean instead of inventing text values; enforce tenant filtering in a data access boundary, not only in a UI. Inspect the result view's columns with information_schema to confirm the exact public projection.

## Edge cases and trust boundaries

## Applied SQL walkthrough

A relation represents facts with a defined row shape. PostgreSQL enforces declared types and nullability; a SELECT projection chooses the columns returned, while WHERE chooses rows. In the supplied fixture, alpha contains users 1, 2 and 4. User 3 belongs to beta. The repaired view intentionally includes inactive user 4 because it is a tenant directory, not an active-user report. It excludes email entirely, even for permitted rows.

### Predict and diagnose the result

Predict three rows with identifiers 1, 2 and 4, and exactly three columns: id, display_name and active. Compare the starter and solution using the acceptance script. Do not assume insertion order; select from the view with ORDER BY id when inspecting results. Inspect information_schema.columns in the current temporary schema to confirm that email is absent.

### Independent exercise and evidence

Design an active-only public directory. Predict identifiers 1 and 2, then explain why adding active=true changes the business contract rather than merely improving security. Record the returned identifiers, column names, and one forbidden tenant row. A fixed alpha predicate is not production authorization.
