# API integration tests

> Instructor draft. Local models do not qualify external identity, billing, privacy compliance or an actual capstone release.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A backend release changes routing and persistence.

## Step 1 — Mental model

Integration tests cross actual server, database and auth boundaries with isolated fixtures.

## Step 2 — Guided practice

Boot API on loopback with disposable DB; run create/read/update/deny and rollback tests.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Expected data and response changes match.

**Negative:** Mock-only tests cannot establish actual DB behavior.

Inspect the complementary `apiAcceptance` teaching model. Extend its assertions when relevant; it is not an implementation of the full external technology.

```bash
node --test --test-name-pattern="27[.]02" examples/p7-platforms/labs.test.mjs
```

## Qualification boundary

Capstone API status/DTO rubric only; no live NestJS, PostgreSQL, Prisma, Supabase or JWT validation established.

## Knowledge check

1. What is the invariant and trust boundary?
2. Which negative result falsifies an unsafe design?
3. Which real tool or reviewer must supply missing evidence?

**Assessment:** Record exact fixture input, expected and actual output, negative evidence and not-run checks. Do not substitute a design or model for a real acceptance result.
