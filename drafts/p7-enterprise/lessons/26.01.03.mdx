# Domain verification

> Instructor draft. Local models do not qualify external identity, billing, privacy compliance or an actual capstone release.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

An admin claims a company's email domain.

## Step 1 — Mental model

Domain ownership proof and organization membership are distinct; verify a scoped expiring challenge using the intended method.

## Step 2 — Guided practice

Design a synthetic DNS challenge with random token, expiration and tenant binding; test mismatched token.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Only the intended claimant completes verification.

**Negative:** Email suffix alone cannot grant admin rights.

Inspect the complementary `enterpriseAccess` teaching model. Extend its assertions when relevant; it is not an implementation of the full external technology.

## Qualification boundary

Synthetic policy check on already-validated claims only; no actual SAML assertion, SCIM, MFA, token or identity-provider verification.

## Applied engineering walkthrough

Proof of domain control establishes a scoped fact about a domain at a given time. It does not automatically grant organizational membership or authorize every address using that domain. Bind challenges to the requesting tenant, intended domain, random token and expiry; define revalidation and ownership conflict handling.

### Diagnose the concrete failure

Generate synthetic challenges for two organizations and compare the expected verification record. Try a mismatched token, expired challenge and correct token submitted by another tenant. None should assign ownership incorrectly.

### Independent exercise and evidence

Design an auditable challenge lifecycle with issuance, verification, expiry and conflict recovery. Record the actual DNS or other authorized proof method separately from the local decision model.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status and independently verify actual IdP, application authorization, database and reviewer evidence.
