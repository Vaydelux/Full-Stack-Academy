# System configuration

> Instructor draft. Local models do not qualify external identity, billing, privacy compliance or an actual capstone release.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A service changes its runtime configuration.

## Step 1 — Mental model

Configuration needs schema validation, version, secret separation, rollback and clear precedence.

## Step 2 — Guided practice

Design synthetic versioned configuration and reject invalid port or unknown setting.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Valid update preserves previous version for rollback.

**Negative:** Secret in public config or invalid update applied fails.

## Qualification boundary

Synthetic tenant-admin authorization model only; actual RBAC, audit integrity, support workflows and migration safety require runtime acceptance.

## Applied engineering walkthrough

Configuration needs a validated schema, explicit precedence, versioned updates and safe defaults. Separate secret values from ordinary settings and expose only the minimum metadata needed for administration. Reject unknown or invalid fields rather than silently accepting configuration that cannot be applied.

### Diagnose the concrete failure

Prepare two synthetic versions of application settings with conflicting precedence. Submit an invalid port, unknown key and stale revision. Verify the prior valid configuration remains active and no secret is returned in the error.

### Independent exercise and evidence

Design a staged activation and rollback process with an owner and change reason. Record the effective nonsecret configuration, version and rejected inputs, then simulate a startup failure after a proposed change.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status and independently verify actual API, database, authorization, browser and reviewer evidence.
