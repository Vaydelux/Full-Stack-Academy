## Applied engineering walkthrough

A portfolio case study should establish the problem, constraints, design decisions, implemented scope and verified results. Separate actual outcomes from planned functionality and explain remaining tradeoffs. The strongest evidence is an attributable implementation and reproducible test or demonstration, not a claim of enterprise readiness.

### Diagnose the concrete failure

Draft a one-page case study for the workspace. Attach an architecture diagram, screenshots from the actual running candidate when available and a small set of reproduced positive and negative results. Remove unsupported performance and security claims.

### Independent exercise and evidence

Prepare a short demo script covering the core task journey, a denied foreign-tenant request and recovery from a dependency failure. Record which parts can actually be demonstrated, and avoid exposing synthetic credentials or private data in shared materials.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status and independently verify actual implementation, review, recovery, cost and candidate evidence.

## Knowledge check

1. What is the invariant and trust boundary?
2. Which negative result falsifies an unsafe design?
3. Which real tool or reviewer must supply missing evidence?

**Assessment:** Record exact fixture input, expected and actual output, negative evidence and not-run checks. Do not substitute a design or model for a real acceptance result.
