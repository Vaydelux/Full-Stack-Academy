# Prisma repositories

> Instructor draft. Local models do not qualify external identity, billing, privacy compliance or an actual capstone release.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A service uses Prisma for persistence.

## Step 1 — Mental model

Repository adapters map validated domain requests to scoped database queries; generated types are not authorization.

## Step 2 — Guided practice

Implement disposable Prisma task repository and test tenant filter, pagination and transaction behavior.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Own tenant queries return expected rows.

**Negative:** Unscoped find/update or query leakage fails.

## Applied engineering walkthrough

The repository adapter translates validated use-case inputs into scoped database operations. Prisma generated types improve query correctness but do not automatically enforce tenancy. Include tenant predicates in reads and writes, stable ordering in pagination and an explicit transaction boundary for related changes.

### Diagnose the concrete failure

Seed two synthetic organizations with tasks sharing a sort value. Query one tenant with a bounded cursor, attempt a foreign record update and provoke a failure in a multi-step transaction. Check affected rows and unchanged foreign data.

### Independent exercise and evidence

Record generated client and database versions, pagination semantics and transaction evidence. Compare results under the appropriate database role; never rely on a globally privileged test client as proof of row security.
