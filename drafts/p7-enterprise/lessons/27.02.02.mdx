# Nest domain boundaries

> Instructor draft. Local models do not qualify external identity, billing, privacy compliance or an actual capstone release.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A backend mixes auth, task rules and database access.

## Step 1 — Mental model

Nest modules separate ownership, controllers, use cases and injected infrastructure.

## Step 2 — Guided practice

Create disposable task module with repository port and auth guard; test dependency injection.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Use case has explicit dependencies and route contract.

**Negative:** Controller bypassing domain/authorization policy fails.

Inspect the complementary `apiAcceptance` teaching model. Extend its assertions when relevant; it is not an implementation of the full external technology.

## Qualification boundary

Capstone API status/DTO rubric only; no live NestJS, PostgreSQL, Prisma, Supabase or JWT validation established.

## Applied engineering walkthrough

Nest modules establish a clear ownership boundary for controllers, use cases, providers and infrastructure adapters. Keep HTTP details at the transport boundary and inject a repository contract into the task use case. A guard verifies an appropriate identity or policy, while object-level authorization still belongs at the relevant decision point.

### Diagnose the concrete failure

Build a disposable task module and substitute a controlled repository in a test. Exercise correct dependency resolution, a missing provider, an anonymous request and a foreign-tenant task access.

### Independent exercise and evidence

Draw the dependency graph and identify which layer decides each invariant. Record actual module bootstrap and HTTP evidence separately from mocked provider tests; avoid circular ownership between modules.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status and independently verify actual API, database, authentication and reviewer evidence.
