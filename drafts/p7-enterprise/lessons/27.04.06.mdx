# Performance testing

> Instructor draft. Local models do not qualify external identity, billing, privacy compliance or an actual capstone release.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A service must meet a defined latency target.

## Step 1 — Mental model

Performance qualification uses matched workloads, thresholds, errors and repeatable conditions.

## Step 2 — Guided practice

Benchmark disposable API with bounded k6 or equivalent; record p95, errors and resource usage.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Measured workload meets predefined target.

**Negative:** Dropping failures or claiming synthetic samples as real benchmark fails.

## Applied engineering walkthrough

Performance qualification defines a repeatable workload, acceptable latency and error thresholds and resource limits before measuring. Compare the same request mix, dataset, duration and environment across candidates. Percentiles need adequate samples, and low latency with incorrect or rejected requests is not success.

### Diagnose the concrete failure

Run a bounded local load exercise against a disposable API with a fixed synthetic dataset. Record throughput, p95 latency, errors and resource use, then alter one variable such as query shape. Verify correct responses as part of the benchmark.

### Independent exercise and evidence

Document warm-up, concurrency, tool version, sample size and stop criteria. Repeat the workload and report variation; do not extrapolate local results to production capacity or claim a benchmark when the load tool is unavailable.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status and independently verify actual infrastructure, build, security, performance, recovery and reviewer evidence.
