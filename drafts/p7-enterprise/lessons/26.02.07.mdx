# Sandbox testing

> Instructor draft. Local models do not qualify external identity, billing, privacy compliance or an actual capstone release.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A billing feature needs a test without real charges.

## Step 1 — Mental model

Use sandbox credentials, synthetic accounts and isolated webhook routing; separate test from live data.

## Step 2 — Guided practice

Rehearse renewal, decline, duplicate delivery and cancellation in an authorized provider sandbox.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Test state changes match expectations with no live charge.

**Negative:** Live credential or missing callback evidence blocks qualification.

Inspect the complementary `entitlement` teaching model. Extend its assertions when relevant; it is not an implementation of the full external technology.

node --test --test-name-pattern="26[.]02" examples/p7-platforms/labs.test.mjs

## Qualification boundary

Synthetic entitlement policy; no payment provider authenticity, tax, invoicing, real charges or durable billing integration verified.

## Applied engineering walkthrough

Sandbox qualification must separate credentials, accounts, event endpoints and storage from production. A test event must not change live entitlements, and a successful simulator response is not evidence of real payment settlement. Refuse startup if environment identity cannot be established.

### Diagnose the concrete failure

Rehearse renewal, decline, duplicate callback and cancellation using approved sandbox fixtures. Verify live credentials are absent and every event is scoped to synthetic accounts. Inspect callback evidence rather than only dashboard status.

### Independent exercise and evidence

Prepare a sandbox-only configuration checklist and expected state timeline. Record provider mode, sanitized event identifiers and actual responses; do not create a real charge or paid resource for this exercise.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status; independently verify real sandbox signatures, database durability, billing and reviewer evidence.

## Knowledge check

1. What is the invariant and trust boundary?
2. Which negative result falsifies an unsafe design?
3. Which real tool or reviewer must supply missing evidence?

**Assessment:** Record exact fixture input, expected and actual output, negative evidence and not-run checks. Do not substitute a design or model for a real acceptance result.
