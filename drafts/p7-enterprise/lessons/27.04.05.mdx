# Security verification

> Instructor draft. Local models do not qualify external identity, billing, privacy compliance or an actual capstone release.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A release may introduce authorization and dependency regressions.

## Step 1 — Mental model

Security verification needs concrete abuse cases, dependency review and relevant trust boundaries.

## Step 2 — Guided practice

Run scoped auth tests, secret scan and current dependency audit on exact candidate; triage findings.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Blocking findings resolved or explicitly held.

**Negative:** Scanner outage or foreign tenant access fails.

## Applied engineering walkthrough

Security release review starts with trust boundaries and concrete abuse cases: unauthenticated requests, cross-tenant access, malformed inputs, secret exposure and recovery. Dependency scanning supplies useful evidence but cannot establish absence of vulnerabilities. Triage actual findings by affected version, reachability and remediation rather than silently ignoring them.

### Diagnose the concrete failure

Against the disposable candidate, run authorized negative tests for missing identity, foreign object access and invalid input. Inspect secret handling and perform the configured dependency audit on the exact lockfile when available. Verify denied mutations leave state unchanged.

### Independent exercise and evidence

Record each finding, reproducible evidence, severity rationale and remediation or time-bounded exception. Include a retest and unresolved owner; a source scan alone must not authorize a release.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status and independently verify actual infrastructure, build, security, performance, recovery and reviewer evidence.
