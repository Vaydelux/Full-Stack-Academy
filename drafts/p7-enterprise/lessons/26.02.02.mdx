# Webhook authenticity

> Instructor draft. Local models do not qualify external identity, billing, privacy compliance or an actual capstone release.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A callback claims that a payment succeeded.

## Step 1 — Mental model

Verify provider-specific signatures over required bytes and timestamp before trusting any billing event.

## Step 2 — Guided practice

Use a real sandbox provider's documented signing fixture; reject altered bytes and stale timestamps.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Valid signed event is accepted once.

**Negative:** Invalid signature or caller-supplied tenant routing fails.

Inspect the complementary `entitlement` teaching model. Extend its assertions when relevant; it is not an implementation of the full external technology.

## Qualification boundary

Synthetic entitlement policy; no payment provider authenticity, tax, invoicing, real charges or durable billing integration verified.

## Applied engineering walkthrough

Authenticate billing callbacks using the provider's documented signature algorithm, required original bytes and replay controls before interpreting the payload. A valid signature establishes message authenticity within that contract, not that a caller-provided tenant ID is trustworthy. Resolve ownership using verified provider identifiers.

### Diagnose the concrete failure

Use a permitted sandbox signing fixture, then change the body and test an expired timestamp. Verify invalid events produce no entitlement write. Try a valid event with an inconsistent internal mapping and quarantine it.

### Independent exercise and evidence

Record sanitized event ID, signature verification outcome and ownership lookup result. Include duplicate delivery and missing credentials; never publish secrets or actual payment details in test evidence.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status; independently verify real sandbox signatures, database durability, billing and reviewer evidence.
