# CRUD with pagination

> Instructor draft. Local models do not qualify external identity, billing, privacy compliance or an actual capstone release.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A workspace lists thousands of tasks.

## Step 1 — Mental model

CRUD contracts include bounded pagination, stable ordering, validation and scoped writes.

## Step 2 — Guided practice

Build local paginated list with same-sort values and invalid cursor; test owner and foreign tenant.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Pages contain each intended row without duplicates.

**Negative:** Unbounded result or cross-tenant cursor accepted fails.

## Applied engineering walkthrough

A task workspace needs bounded list queries and explicit create, update and delete contracts. Use a deterministic sort with a unique tie breaker so records sharing a timestamp cannot disappear between pages. Cursor scope, validation and tenant authorization must be enforced by the server, not inferred from the list currently displayed.

### Diagnose the concrete failure

Seed two organizations with tasks sharing a timestamp. Request consecutive pages, change the filter while retaining the old cursor and attempt to edit a foreign task. Compare returned identities and verify unauthorized writes leave data unchanged.

### Independent exercise and evidence

Document each operation's status, validation, cursor scope and concurrency policy. Add a stale-update case and an empty-list case, then record actual response and database evidence for the complete journey.
