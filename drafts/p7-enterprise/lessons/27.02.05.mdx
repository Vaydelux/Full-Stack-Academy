# Supabase Auth JWT validation

> Instructor draft. Local models do not qualify external identity, billing, privacy compliance or an actual capstone release.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

An API receives a Supabase access token.

## Step 1 — Mental model

Validate trusted issuer, signature, audience, time and key rotation using supported verification; never trust merely decoded claims.

## Step 2 — Guided practice

Use authorized local/sandbox Supabase and documented JWT validation; test expired, tampered and wrong audience tokens.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Only verified valid token establishes identity.

**Negative:** Unsigned or decoded-only token accepted fails.
