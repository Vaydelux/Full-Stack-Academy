## The problem we're solving

The practice API binds publicly on 0.0.0.0 and lacks a shutdown hook. At this level, correctness must survive a process restart, a concurrent request, an unavailable dependency, or an unauthorized caller. An advanced Nest decorator is only useful when the test proves that its registration, runtime scope and error behavior match the intended design.

<LessonStep number={2} title="Apply the versioned NestJS repair" file="drafts/nestjs/labs/production-service-skeleton/solution.ts" expected="A release candidate needs explicit adapter, loopback fixture binding, shutdown hooks and bounded error exposure.">

```ts
import { NestFactory } from '@nestjs/core';
import { Module } from '@nestjs/common';
import { FastifyAdapter, NestFastifyApplication } from '@nestjs/platform-fastify';
@Module({})
export class AppModule {}
export async function bootstrap(port = 3337): Promise<NestFastifyApplication> {
  if (!Number.isInteger(port) || port < 0 || port > 65535) throw new Error('Invalid local port');
  const app = await NestFactory.create<NestFastifyApplication>(AppModule, new FastifyAdapter());
  app.enableShutdownHooks();
  await app.listen(port, '127.0.0.1');
  return app; // caller must await app.close() after the local smoke test
}
```
