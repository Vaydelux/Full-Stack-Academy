## The problem we're solving

A malformed body reaches the controller unchanged and may produce an unexpected 500. The request pipeline is a composition of stages rather than a single controller method: middleware prepares the request, a guard decides permission, pipes parse inputs, interceptors wrap handler execution and filters normalize failures. Each stage needs its own test because correct TypeScript does not prove real HTTP behavior.

## Build the mental model

Use PipeTransform to turn unknown request payloads into parsed typed data or an explicit 400. The stage where the problem occurs matters: moving validation into an authorization check or moving a security decision into a response interceptor can accidentally expose the handler. Trace the request lifecycle from ingress to exit, and record both expected success and denial.

**Prediction:** A malformed body reaches the controller unchanged and may produce an unexpected 500. Explain whether the handler is reached, and what an HTTP client should observe.

**Release scope:** These examples target NestJS 12, Node 24, TypeScript 6. They are authored drafts, not compiler-qualified or published material. A TypeScript DTO annotation does not validate incoming JSON without a runtime pipe.

<LessonStep number={2} title="Repair the correct stage" file="drafts/nestjs/labs/pipes-zod-validation/solution.ts" expected="Use PipeTransform to turn unknown request payloads into parsed typed data or an explicit 400.">

```ts
import { BadRequestException, Injectable, PipeTransform } from '@nestjs/common';
import { z } from 'zod';
const Body = z.object({ title: z.string().trim().min(3).max(100) });
@Injectable()
export class CreateTaskPipe implements PipeTransform {
  transform(value: unknown) {
    const result = Body.safeParse(value);
    if (!result.success) throw new BadRequestException('Invalid task input');
    return result.data;
  }
}
```

## Applied engineering walkthrough

A pipe converts untrusted input into a validated value or an explicit client error. The solution uses safeParse and returns result.data, so the trimmed title reaches the controller. This is a Zod object with default unknown-key stripping, not strict unknown-field rejection. If the contract requires rejecting extra fields, use strictObject and test that choice. Pipes cannot verify who is allowed to create a task.

### Diagnose the concrete failure

Compare {title: '  task  '}, {title: 'x'} and {title: 42}. The first should return the normalized title; the others should raise BadRequestException. Also try an extra admin field: the current schema strips it. Attach the pipe to the HTTP argument and verify actual 400 responses before claiming end-to-end validation.
