## The problem we're solving

The HTTP handler never runs because middleware forgets to call next. The request pipeline is a composition of stages rather than a single controller method: middleware prepares the request, a guard decides permission, pipes parse inputs, interceptors wrap handler execution and filters normalize failures. Each stage needs its own test because correct TypeScript does not prove real HTTP behavior.

## Build the mental model

Middleware has to call next exactly once after attaching safe request data. The stage where the problem occurs matters: moving validation into an authorization check or moving a security decision into a response interceptor can accidentally expose the handler. Trace the request lifecycle from ingress to exit, and record both expected success and denial.

**Prediction:** The HTTP handler never runs because middleware forgets to call next. Explain whether the handler is reached, and what an HTTP client should observe.

**Release scope:** These examples target NestJS 12, Node 24, TypeScript 6. They are authored drafts, not compiler-qualified or published material. Do not create a trust boundary from an unverified client-supplied header.

```ts
import { randomUUID } from 'node:crypto';
import { Injectable, NestMiddleware } from '@nestjs/common';
@Injectable()
export class CorrelationMiddleware implements NestMiddleware {
  use(req: { correlationId?: string }, _res: unknown, next: () => void) {
    req.correlationId = randomUUID();
    next();
  }
}
```

**Why this design:** Middleware has to call next exactly once after attaching safe request data. Do not create a trust boundary from an unverified client-supplied header.

</LessonStep>

## Applied engineering walkthrough

Middleware runs early, before guards and pipes. It is appropriate for correlation metadata and cross-cutting request preparation, not for deciding object-level access. Call next exactly once unless ending the response deliberately. The fixture generates its own random UUID; a caller-supplied correlation header may be useful for tracing but is not authentication, and should be bounded and sanitized before logging.

### Diagnose the concrete failure

Send two requests and trace generated IDs separately. In the broken starter, next is not called, so the downstream handler never executes. A real HTTP test needs a short client deadline rather than waiting forever. The existing request-pipeline suite invokes the middleware class directly; passing that check alone does not prove the HTTP adapter wiring.

### Independent exercise and evidence

Add a safe request-start marker to the middleware in a disposable copy, omitting headers and payloads. Compare successful forwarding, deliberate response termination and an accidental missing next call. Record the marker count, unique IDs and whether the handler ran.
