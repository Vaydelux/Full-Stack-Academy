```ts
import { Test } from '@nestjs/testing';
import { Injectable } from '@nestjs/common';
@Injectable()
export class Mailer { async send(_to: string) {} }
@Injectable()
export class Notifications {
  constructor(private readonly mailer: Mailer) {}
  async notify(to: string) { await this.mailer.send(to); }
}
export async function buildTestModule(fake: { send(to: string): Promise<void> }) {
  return Test.createTestingModule({ providers: [Notifications, Mailer] })
    .overrideProvider(Mailer).useValue(fake).compile();
}
```

**Why it works:** Provider overrides let integration-style tests exercise real Nest DI without contacting external systems. Keep test credentials isolated and block accidental production endpoints.

</LessonStep>

## Applied engineering walkthrough

TestingModule exercises real Nest dependency injection without needing a live external service. Override the mailer before compile, then resolve Notifications through the container. A fake records calls or throws to model failure. This confirms wiring and delegation, not delivery by a real email provider. For end-to-end delivery use a safe sandbox and separate explicit qualification.

### Diagnose the concrete failure

Provide a fake mailer that captures its recipient, invoke notify and assert one matching call. Then configure the fake to reject and verify notify propagates the error rather than claiming success. Close the testing module. The default mailer in the teaching fixture is inert; do not treat this as proof of real delivery.

### Independent exercise and evidence

Design a fake payment or notification adapter with success, timeout and permanent failure outcomes. Choose observable assertions for each. Record call counts and captured synthetic data, and ensure no network requests or actual credentials are used.
