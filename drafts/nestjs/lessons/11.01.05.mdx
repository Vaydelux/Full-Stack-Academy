## The problem we're solving

A malformed PORT is converted into NaN and the application fails during startup. A team reviewing a NestJS service must understand *why* this is a failure, not merely memorize decorator names. This lesson isolates the failure in one short source file so the learner can compare the runtime contract before and after the change.

## Build the mental model

Parse environment settings once at the composition root before opening any network port. In NestJS 12, decorators register metadata used by the Nest runtime; the TypeScript class is not automatically a route or managed provider. A running application must still compose its modules, resolve dependencies, and handle failures at the actual HTTP or service boundary.

**Predict:** Before reading the instructor solution, describe the client-visible response or container behavior when the broken starter is used. A malformed PORT is converted into NaN and the application fails during startup.

**Trust and version boundary:** Target Node.js 24, TypeScript 6 and NestJS 12 with real installed packages. The repository has not yet completed an npm-locked Nest runtime test for this draft. Source existence is not evidence of a functioning server. Do not log secrets or return raw environment values to clients.

```ts
import { z } from 'zod';
const PortSchema = z.coerce.number().int().min(1024).max(65535);
export function parsePort(raw: string | undefined): number {
  return PortSchema.parse(raw ?? '3337');
}
export const apiPort = parsePort(process.env.PORT);
```

**Reasoning:** Parse environment settings once at the composition root before opening any network port. Do not log secrets or return raw environment values to clients. This repair does not imply that external users are authorized; it solves only the bounded lesson contract.

</LessonStep>

## Design alternatives and debugging strategy

A quick workaround would hide the immediate symptom, but it would leave the original ownership or lifecycle error intact. Start by tracing the source that creates the Nest application and the providers registered in its module graph; then inspect the exact request path, active context, or emitted response affected by this lesson. Prefer an isolated test that can be run repeatedly without a live external database or credential.

- **When it is appropriate:** Parse environment settings once at the composition root before opening any network port.
- **When it is not enough:** If multiple requests, tenants, or worker processes are involved, test the same boundary under concurrency and treat incoming data as untrusted.
- **How to confirm the repair:** Exercise valid PORT=3337, absent PORT, and invalid PORT=abc independently.
- **What to document:** The expected failure code, verification command, dependency version, and whether a browser, HTTP, or service-layer test actually executed.
