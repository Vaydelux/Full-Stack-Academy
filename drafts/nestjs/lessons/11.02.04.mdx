## The problem we're solving

The interceptor discards the route return value, so clients receive unrelated content. The request pipeline is a composition of stages rather than a single controller method: middleware prepares the request, a guard decides permission, pipes parse inputs, interceptors wrap handler execution and filters normalize failures. Each stage needs its own test because correct TypeScript does not prove real HTTP behavior.

## Build the mental model

An interceptor should preserve the route result while adding a bounded response envelope or trace metadata. The stage where the problem occurs matters: moving validation into an authorization check or moving a security decision into a response interceptor can accidentally expose the handler. Trace the request lifecycle from ingress to exit, and record both expected success and denial.

**Prediction:** The interceptor discards the route return value, so clients receive unrelated content. Explain whether the handler is reached, and what an HTTP client should observe.

**Release scope:** These examples target NestJS 12, Node 24, TypeScript 6. They are authored drafts, not compiler-qualified or published material. Do not echo access tokens, cookies, or private headers as tracing metadata.

```ts
import { randomUUID } from 'node:crypto';
import { CallHandler, ExecutionContext, Injectable, NestInterceptor } from '@nestjs/common';
import { map } from 'rxjs/operators';
@Injectable()
export class TraceInterceptor implements NestInterceptor {
  intercept(_ctx: ExecutionContext, next: CallHandler) {
    const traceId = randomUUID();
    return next.handle().pipe(map(data => ({ data, traceId })));
  }
}
```

**Why this design:** An interceptor should preserve the route result while adding a bounded response envelope or trace metadata. Do not echo access tokens, cookies, or private headers as tracing metadata.

</LessonStep>

## Applied engineering walkthrough

An interceptor wraps downstream execution through next.handle, which returns an observable. RxJS map transforms successful emitted data; finalize is useful for cleanup or duration observation on success, error or cancellation. The example wraps a route result and generates a trace ID. It does not propagate an existing distributed trace or automatically catch all errors. Avoid manually subscribing, which may duplicate work or break the request lifecycle.

### Diagnose the concrete failure

Compare the starter's response to the route's original value. The solution must preserve the original data inside the envelope and return a bounded UUID trace ID. Count handler invocations; there should be one for the fixture. Test a downstream error separately: map should not turn an exception into a successful response.

### Independent exercise and evidence

Propose a duration interceptor that records safe metadata through finalize without changing the response schema. Define tests for success and thrown errors. Record handler call count, original data, returned envelope and how errors reach the filter.
