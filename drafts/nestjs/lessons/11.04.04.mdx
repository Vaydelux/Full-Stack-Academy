<LessonStep number={2} title="Apply the versioned NestJS repair" file="drafts/nestjs/labs/graceful-shutdown/solution.ts" expected="A long-running provider must stop timers and close connections as Nest shuts down.">

```ts
import { Injectable, OnApplicationShutdown } from '@nestjs/common';
export class Connection { close() {} }
@Injectable()
export class Worker implements OnApplicationShutdown {
  private stopped = false;
  constructor(private readonly connection: Connection) {}
  onApplicationShutdown() {
    if (this.stopped) return;
    this.stopped = true;
    this.connection.close();
  }
}
```

**Why it works:** A long-running provider must stop timers and close connections as Nest shuts down. Handle SIGTERM with bounded work; never continue accepting traffic after critical dependency loss.

</LessonStep>

## Applied engineering walkthrough

Graceful shutdown is a resource-ownership protocol: stop accepting new work, drain bounded in-flight work, then close clients. The fixture demonstrates one idempotent close guard; it does not implement a drain or asynchronous connection shutdown. Setting stopped before close avoids duplicate calls, but a throwing close requires an explicit recovery policy. Signal-triggered lifecycle hooks must be enabled and exercised separately from app.close.

### Diagnose the concrete failure

Invoke the worker shutdown hook twice with a recording connection and check the close count remains one. In the full app, initiate shutdown while a request is active; observe whether new work is refused and ongoing work drains within a deadline. A fake close count alone cannot prove sockets or pools are released.

### Independent exercise and evidence

Design a worker shutdown sequence with a deadline, no new jobs and a final connection close. Record the expected behavior when an active job finishes, times out or the close operation fails. Decide whether an orchestrator should retry the job after termination.
