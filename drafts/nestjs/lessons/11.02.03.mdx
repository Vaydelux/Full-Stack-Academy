## The problem we're solving

A guard always returns true and the route accepts unauthenticated requests. The request pipeline is a composition of stages rather than a single controller method: middleware prepares the request, a guard decides permission, pipes parse inputs, interceptors wrap handler execution and filters normalize failures. Each stage needs its own test because correct TypeScript does not prove real HTTP behavior.

## Build the mental model

Nest guards make an access decision before protected route handling. The stage where the problem occurs matters: moving validation into an authorization check or moving a security decision into a response interceptor can accidentally expose the handler. Trace the request lifecycle from ingress to exit, and record both expected success and denial.

**Prediction:** A guard always returns true and the route accepts unauthenticated requests. Explain whether the handler is reached, and what an HTTP client should observe.

**Release scope:** These examples target NestJS 12, Node 24, TypeScript 6. They are authored drafts, not compiler-qualified or published material. A toy Bearer string is only an educational fixture; production must verify signed credentials and scope.

```ts
import { CanActivate, ExecutionContext, Injectable } from '@nestjs/common';
@Injectable()
export class AccessGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const req = context.switchToHttp().getRequest<{ headers: { authorization?: string } }>();
    return req.headers.authorization === 'Bearer teaching-only';
  }
}
```

**Why this design:** Nest guards make an access decision before protected route handling. A toy Bearer string is only an educational fixture; production must verify signed credentials and scope.

## Applied engineering walkthrough

Authentication establishes who the principal is; authorization decides which action and resource that principal can access. A guard can deny a request before controller execution. The teaching-only bearer string is deliberately not a production credential or JWT verifier. A real service must verify the credential, then check resource membership and tenant ownership; returning false normally yields 403, while an authentication guard may throw 401 explicitly.

### Diagnose the concrete failure

Use the existing guard fixture with absent authorization, an invalid bearer value and its exact teaching value. Expect false, false and true. Then design a real HTTP test that proves a denied request never reaches a protected handler. For a tenant-aware service, also test a valid identity requesting another tenant's object.

### Independent exercise and evidence

Sketch a verified-principal guard followed by a membership policy. State what should happen for no credential, an authenticated non-member and an authorized member. Record the decision and whether the controller/repository executes; never use actual credentials in recorded evidence.
