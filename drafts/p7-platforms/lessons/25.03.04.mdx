# Map clients

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A map client loads visible results.

## Step 1 — Mental model

Client should query bounded viewport, cluster or paginate results, and preserve accessible non-map alternatives.

## Step 2 — Guided practice

Use a synthetic point list and viewport filter in a local map client; test narrow screen and keyboard alternative.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Visible bounded points and accessible list agree.

**Negative:** Fetching all private coordinates or inaccessible map-only UI fails.

## Qualification boundary

## Applied engineering walkthrough

A map viewport can change quickly during pan and zoom, so request bounded data and cancel or ignore stale responses. Cluster or paginate dense point sets without implying that the visible markers represent every record. Provide a usable list or table alternative to map-only controls.

### Diagnose the concrete failure

Use a synthetic point list, change the viewport twice and delay the first response. Verify that the older response cannot overwrite the current view and that a dense viewport cannot request unlimited records.

### Independent exercise and evidence

Design a keyboard-operable list with synchronized selection, clear empty and loading states and accessible names. Record narrow-screen and keyboard results independently of map rendering correctness.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status and independently verify actual PostGIS, browser, device and reviewer evidence.
