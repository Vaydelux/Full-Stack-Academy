# Battery memory and app size

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A mobile app drains battery after idle.

## Step 1 — Mental model

Measure wakeups, network activity, heap and binary size under controlled conditions rather than guessing.

## Step 2 — Guided practice

Record baseline on a test device, disable redundant polling, compare battery/network/size measurements.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Work decreases without missed required updates.

**Negative:** One unrepresentative measurement or broken sync fails.

## Qualification boundary

Synthetic queue acknowledgement model only; physical touch, OS background behavior, push delivery and store acceptance require device tests.

## Applied engineering walkthrough

A meaningful performance comparison requires matched workloads. Mobile energy consumption depends on radio activity, CPU, wakeups and device state; smaller JavaScript assets alone do not demonstrate battery improvement. Choose a scenario and measure separate resource indicators.

### Diagnose the concrete failure

Record a baseline for a task screen with repeated polling. Remove redundant requests without changing refresh correctness and compare request count, wakeups, memory and response latency.

### Independent exercise and evidence

Document model, OS, network conditions, duration and build variant. Repeat measurements to show variability and distinguish binary-size change from actual battery or runtime improvements.
