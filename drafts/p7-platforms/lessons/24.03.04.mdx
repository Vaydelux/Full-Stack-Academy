# Window and file APIs

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A desktop app imports a user-selected document.

## Step 1 — Mental model

Prefer a native file picker and bounded paths; validate type, size and symlinks at native boundary.

## Step 2 — Guided practice

Select a synthetic file and try an out-of-scope path in an isolated app.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Only intended file is readable.

**Negative:** Path traversal or arbitrary file overwrite fails.

Inspect the complementary `desktopAllowed` teaching model. Extend its assertions when relevant; it is not an implementation of the full external technology.

## Qualification boundary

Synthetic command permission model; actual Rust commands, capability enforcement, installers and signatures require platform builds.

## Applied engineering walkthrough

A file picker supplies user intent for a specific resource, not blanket permission to traverse a directory. Validate the opened file at the native boundary, limit reads and do not trust extensions as content validation. Account for symlinks and changes between validation and opening.

### Diagnose the concrete failure

Use a temporary directory, a valid document and a separate out-of-scope fixture. Try an allowed selection, a forbidden path and a link to it. Confirm no unauthorized bytes are returned.

### Independent exercise and evidence

Define accepted size and format, test empty and oversized files, and document safe handle-based access. A string prefix comparison alone does not demonstrate containment.
