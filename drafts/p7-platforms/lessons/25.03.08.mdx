# Lab map-backed search

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A learner implements nearby search.

## Step 1 — Mental model

A geospatial search combines validated points, scoped query, correct distance and bounded result count.

## Step 2 — Guided practice

Run validPoint; build disposable PostGIS search with known distance fixtures and map/list UI.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Returned authorized points meet radius and ordering contract.

**Negative:** Foreign locations, invalid points or unbounded results fail.

Inspect the complementary `validPoint` teaching model. Extend its assertions when relevant; it is not an implementation of the full external technology.

## Qualification boundary

Coordinate validation model only; real PostGIS geometry, index, map rendering and location privacy require separate acceptance.

## Applied engineering walkthrough

A spatial search is a complete boundary: validate coordinates, enforce tenant scope, choose correct distance semantics, bound result count and present results accessibly. Ranking by distance does not substitute for row authorization. Establish known fixtures before optimizing the query.

### Diagnose the concrete failure

Create a disposable PostGIS dataset with near, far, boundary and foreign-tenant points. Verify membership and deterministic distance ordering, including a tied distance and rejected invalid radius.

### Independent exercise and evidence

Build a map/list UI with bounded pagination and stale-request handling. Submit SQL plan, expected and observed result IDs, denied access cases and accessibility observations. Keep actual database and browser qualification distinct from the local validPoint model.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status and independently verify actual PostGIS, browser, device and reviewer evidence.
