# Rust boundary mental model

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A Rust command receives malformed JSON.

## Step 1 — Mental model

Rust types and Result errors are useful but do not replace input and authorization checks.

## Step 2 — Guided practice

Implement a small typed command in a disposable Tauri app; send valid and invalid payloads.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Valid payload returns a typed response; invalid input has a safe error.

**Negative:** Panic, secret leakage or unchecked path fails.

Inspect the complementary `desktopAllowed` teaching model. Extend its assertions when relevant; it is not an implementation of the full external technology.

node --test --test-name-pattern="24[.]03" examples/p7-platforms/labs.test.mjs

## Qualification boundary

Synthetic command permission model; actual Rust commands, capability enforcement, installers and signatures require platform builds.

## Knowledge check

1. What is the invariant and trust boundary?
2. Which negative result falsifies an unsafe design?
3. Which real tool or reviewer must supply missing evidence?

**Assessment:** Record exact fixture input, expected and actual output, negative evidence and not-run checks. Do not substitute a design or model for a real acceptance result.
