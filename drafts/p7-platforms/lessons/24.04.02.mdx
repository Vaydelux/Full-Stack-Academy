# Push notifications

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A mobile app sends task reminders.

## Step 1 — Mental model

Push tokens identify installations, not user authorization; consent, token refresh and notification privacy matter.

## Step 2 — Guided practice

Design synthetic push registration and revocation; use a permitted test provider to send one notification.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Intended authorized device receives a minimal message.

**Negative:** Cross-user delivery or confidential lockscreen content fails.

Inspect the complementary `resumeQueue` teaching model. Extend its assertions when relevant; it is not an implementation of the full external technology.

node --test --test-name-pattern="24[.]04" examples/p7-platforms/labs.test.mjs

## Qualification boundary

Synthetic queue acknowledgement model only; physical touch, OS background behavior, push delivery and store acceptance require device tests.

## Knowledge check

1. What is the invariant and trust boundary?
2. Which negative result falsifies an unsafe design?
3. Which real tool or reviewer must supply missing evidence?

**Assessment:** Record exact fixture input, expected and actual output, negative evidence and not-run checks. Do not substitute a design or model for a real acceptance result.
