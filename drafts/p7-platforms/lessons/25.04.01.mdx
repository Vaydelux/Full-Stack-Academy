# Object storage and CDN delivery

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A private video needs efficient object delivery.

## Step 1 — Mental model

Object storage owns bytes; CDN caches representations under defined authorization and freshness policies.

## Step 2 — Guided practice

Design private object and public thumbnail paths with scoped cache policy; test synthetic unauthorized access.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Private object is denied without authorized capability.

**Negative:** Shared cache exposing protected media fails.

## Applied engineering walkthrough

Object storage is the source of bytes; a CDN serves cached representations under a defined freshness and access policy. Public thumbnails and private originals need different cache keys, origin permissions and delivery controls. Never assume an obscure object path is an authorization mechanism.

### Diagnose the concrete failure

Design a public thumbnail and private original for a synthetic upload. Request each as an authorized and unauthorized caller; test that a cached private response is not reused for an unrelated identity.

### Independent exercise and evidence

Document object ownership, cache key, expiry and invalidation rules. Record origin and edge responses and explain how revocation behaves while a previously issued capability remains valid.
