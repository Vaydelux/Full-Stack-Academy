# Auto updates and signing

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

An update downloads a replacement executable.

## Step 1 — Mental model

Update trust requires signed artifacts and verified metadata; TLS alone does not establish artifact authenticity.

## Step 2 — Guided practice

Design test signing keys and rehearse valid versus tampered update on disposable platform build.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Tampered artifact is refused before install.

**Negative:** Disabling signature verification fails.

Inspect the complementary `desktopAllowed` teaching model. Extend its assertions when relevant; it is not an implementation of the full external technology.

## Qualification boundary

Synthetic command permission model; actual Rust commands, capability enforcement, installers and signatures require platform builds.

## Applied engineering walkthrough

Updater authenticity requires signature verification using a trusted public key and appropriate artifact metadata. Transport encryption is not an artifact signature. Plan key rotation, release channels and recovery from installation failure before enabling automatic updates.

### Diagnose the concrete failure

With disposable signing material, compare a valid update against a modified artifact. Verify the tampered artifact is rejected and the installed version remains usable.

### Independent exercise and evidence

Prepare a release record with target architecture, version, digest, signature and recovery steps. Keep private keys out of source and evidence; a mock cannot establish actual updater behavior.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status and independently verify actual Tauri builds, OS behavior and reviewer evidence.
