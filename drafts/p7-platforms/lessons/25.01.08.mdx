# Lab event dashboard

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A learner creates an event dashboard.

## Step 1 — Mental model

Metric grain, deduplication, freshness and privacy must be visible alongside charts.

## Step 2 — Guided practice

Use aggregateEvents on fixed synthetic events; build real query/dashboard only in disposable DB and reconcile totals.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Dashboard count matches known event population.

**Negative:** Inflated duplicates or hidden freshness delay fails.

Inspect the complementary `aggregateEvents` teaching model. Extend its assertions when relevant; it is not an implementation of the full external technology.

## Qualification boundary

In-memory count/deduplication model; no warehouse, materialized-view freshness, ClickHouse or dbt runtime qualification.

## Applied engineering walkthrough

A trustworthy dashboard defines metric grain, filters, time zone, deduplication, freshness and privacy alongside its chart. Visual agreement with an expected shape does not establish correct aggregation. Use a small deterministic fixture whose totals can be calculated independently.

### Diagnose the concrete failure

Run aggregateEvents on synthetic duplicate and distinct events, then compare results with an actual disposable database query. Test empty data, late arrival and an unauthorized scope rather than only the happy path.

### Independent exercise and evidence

Create a metric card with freshness and definition, reconcile displayed totals to the source and record any mismatches. Keep real SQL execution and chart accessibility review separate from local model evidence.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status and independently verify actual database, analytics tools and reviewer evidence.
