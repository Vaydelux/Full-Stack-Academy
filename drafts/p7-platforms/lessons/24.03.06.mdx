# Local SQLite storage

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A desktop workspace must survive restart.

## Step 1 — Mental model

SQLite supports local transactions; schema migration and storage location must be explicit per user.

## Step 2 — Guided practice

Create a temporary DB, write a task, restart and verify migration/reopen.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Record survives restart and schema remains compatible.

**Negative:** Writing into installer directory or losing data fails.

## Applied engineering walkthrough

Use a per-user application data location rather than the install directory or current working directory. Transactions protect related writes; versioned migrations establish schema evolution. A failed migration needs a defined recovery strategy, including backup and incompatible downgrade handling.

### Diagnose the concrete failure

Create a database at schema version one, insert a task and restart. Upgrade to version two, inspect the existing row, then induce a failed migration and verify data and version.

### Independent exercise and evidence

Test a second user directory and unavailable disk. Record supported backup and restore behavior and distinguish a reopened database from merely creating a new database.
