# Native packaging

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A Windows app needs an installer or portable build.

## Step 1 — Mental model

Packaging depends on target architecture, webview/runtime prerequisites and signing; build on supported toolchains.

## Step 2 — Guided practice

Produce a real development artifact and inspect version, target and dependency requirements.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Artifact launches on a clean authorized test machine.

**Negative:** Merely zipping source or inventing signing evidence fails.

Inspect the complementary `desktopAllowed` teaching model. Extend its assertions when relevant; it is not an implementation of the full external technology.

## Qualification boundary

Synthetic command permission model; actual Rust commands, capability enforcement, installers and signatures require platform builds.

## Applied engineering walkthrough

An artifact is specific to its OS and architecture and may depend on a supported WebView runtime. Development compilation is not evidence of clean-machine installation. Keep debug packaging separate from release signing, installer dependencies and distribution requirements.

### Diagnose the concrete failure

Build a development artifact for an available target. Inspect architecture, identity, dependencies and embedded UI version. Install under a clean test account and start without a development server.

### Independent exercise and evidence

Create a target matrix with hashes, install, launch and uninstall behavior. Mark unavailable operating systems not-run instead of treating a single host build as cross-platform acceptance.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status and independently verify actual Tauri builds, OS behavior and reviewer evidence.
