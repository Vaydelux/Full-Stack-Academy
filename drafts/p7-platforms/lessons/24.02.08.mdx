# Lab offline task edits

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A learner edits and deletes tasks on two disconnected clients.

## Step 1 — Mental model

An offline sync lab needs durable local writes, conflict handling, tombstones and authenticated server reconciliation.

## Step 2 — Guided practice

Rehearse edit, replay, delete and stale resurrection using the model; then implement same cases with SQLite and a disposable API.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Model invariants hold; actual restart test is recorded separately.

**Negative:** Lost queue data or stale resurrection blocks real acceptance.
