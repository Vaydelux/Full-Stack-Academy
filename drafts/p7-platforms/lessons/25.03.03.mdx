# Distance and bounding boxes

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A user searches within a radius.

## Step 1 — Mental model

Bounding boxes approximate candidate regions; exact distance predicate determines radius membership.

## Step 2 — Guided practice

Construct inside/outside/edge cases and compare ST_DWithin with a bounding-box filter.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Inside points included, outside excluded using correct units.

**Negative:** Treating box corners as exact circle matches fails.

## Applied engineering walkthrough

A bounding box can efficiently identify possible matches but is not equivalent to a distance-radius predicate. Corners can lie outside the intended circle. Use a distance function with correct units and an explicit inclusion rule, including antimeridian considerations for global coverage.

### Diagnose the concrete failure

Construct synthetic inside, outside, boundary and corner points. Compare a bounding-box filter to ST_DWithin with the chosen coordinate type; identify the false positives in the broad filter.

### Independent exercise and evidence

Define a radius limit, result cap and deterministic sort. Include a fixture near the longitude wrap boundary if the service supports global search. Record exact membership and query units.
