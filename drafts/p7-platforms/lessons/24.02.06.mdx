# Secure offline data

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A device cache contains confidential workspace data.

## Step 1 — Mental model

Encrypt sensitive offline data where appropriate, scope it to the signed-in actor and define logout/remote-revocation limits.

## Step 2 — Guided practice

Create synthetic per-account cache partitions; switch users and inspect old account access.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** New user cannot read the prior user's data.

**Negative:** Shared cache or plaintext secrets fail review.

## Qualification boundary

In-memory sync model; actual SQLite persistence, durable queue, crash recovery and conflict reconciliation are not established.

## Applied engineering walkthrough

Partition offline data, files, queues and keys by the authenticated account. Encryption at rest does not authorize access by the wrong account in an unlocked application. Remote revocation cannot immediately wipe an unreachable device, so document the residual risk.

### Diagnose the concrete failure

Sign in as two synthetic accounts in sequence. Inspect query results and pending operations after switching, logging out offline and restarting. Never replay the first account's edits under the second identity.

### Independent exercise and evidence

Define cleanup failure, retention and key lifecycle behavior. Record local deletion independently from actual server revocation and test using synthetic credentials only.
