# Data validation

> Instructor draft. Local models do not qualify native platforms, real providers or production deployments.

## Learning outcomes

Explain the engineering decision, reproduce or design the positive and negative experiment, and identify the remaining evidence.

## Context

A client submits latitude 91.

## Step 1 — Mental model

Coordinates must be finite and within expected range; validate order, SRID and size server-side.

## Step 2 — Guided practice

Run validPoint with valid, swapped invalid, NaN and out-of-range values.

Use synthetic data, a disposable environment and authorized accounts only. Record expected behavior before execution.

## Step 3 — Acceptance

**Positive:** Valid coordinate accepted.

**Negative:** Out-of-range or nonfinite value rejected.

Inspect the complementary `validPoint` teaching model. Extend its assertions when relevant; it is not an implementation of the full external technology.

## Qualification boundary

Coordinate validation model only; real PostGIS geometry, index, map rendering and location privacy require separate acceptance.

## Applied engineering walkthrough

Reject nonfinite coordinates and values outside documented longitude and latitude ranges before passing them into spatial SQL. A swapped coordinate pair can still be numerically valid, so range checks cannot prove correct ordering. Validate radius, result count and spatial input size separately.

### Diagnose the concrete failure

Exercise validPoint with finite valid coordinates, out-of-range latitude, NaN and a swapped pair that remains within both ranges. Explain why the last case requires a clear client contract rather than range validation alone.

### Independent exercise and evidence

Define structured coordinate fields, SRID and error responses. Test malformed JSON, missing fields and oversized spatial requests against a disposable API; record accepted inputs and rejected cases.

**Evidence boundary:** These are practice instructions, not recorded results. Preserve draft status and independently verify actual PostGIS, browser, device and reviewer evidence.
