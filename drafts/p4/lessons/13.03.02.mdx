## Architectural challenge

**Connection pooling.** Prisma ORM v7 relies on the underlying database driver adapter for connection pooling. A pool should be constructed at a well-defined process lifecycle with limits derived from total replicas.

**Reproducible failure:** A route handler creates a new PrismaPg pool and PrismaClient per request. With multiple server instances, those connections can exhaust the PostgreSQL limit.

When a service evolves from a single-developer prototype into an API used by several organizations, an apparently valid query may introduce security gaps, schema drift, or operational load. </LessonStep>

<LessonStep number={2} title="Apply the narrow corrected boundary" file="drafts/p4/labs/bounded-adapter-pool/solution.ts" expected="The data and deployment invariant is explicitly enforced or observable.">

```ts
// Composition root: initialize once per process, not per HTTP request.
const connectionString = process.env.DATABASE_URL;
if (!connectionString) throw new Error("Missing database URL");
const adapter = new PrismaPg({
  connectionString,
  max: 5,
  connectionTimeoutMillis: 3000,
});
export const prisma = new PrismaClient({ adapter });
// Deployment config must budget max * server processes + reserves.
```

**Why it is safer:** Move construction into a server-only composition root, set a bounded adapter pool and budget combined server-instance usage and reserved administration connections.

Do not assume a successful CLI or TypeScript compile proves that the caller was authorized. Generated types protect shapes, not per-request permissions. Similarly, a DB transaction cannot roll back independent external side effects.

</LessonStep>

## Design trade-offs and real-world constraints

Prisma ORM v7 relies on the underlying database driver adapter for connection pooling. A pool should be constructed at a well-defined process lifecycle with limits derived from total replicas.

Move construction into a server-only composition root, set a bounded adapter pool and budget combined server-instance usage and reserved administration connections.

This pool max is illustrative, not a universally safe production value. PgBouncer transaction pooling can change session assumptions; verify prepared statements and TLS with the selected pooler.

In a multi-tenant API, input validation, role-aware database credentials, optimistic concurrency, migration review and response-shape controls must be considered together. Favor bounded queries and explicit domain operations over returning raw privileged ORM interfaces to HTTP handlers. Record the query plan or migration state instead of guessing.
