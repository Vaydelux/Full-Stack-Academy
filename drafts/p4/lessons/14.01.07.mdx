## Architecture problem

**Free tier vs production operations.** Free-tier resources are excellent learning environments but do not automatically supply production recovery, capacity, compliance or availability guarantees. Evaluate operations against actual business needs and current provider limits.

**Unsafe starting point:** The starter equates having a working free project with production release readiness, without backups, monitoring or security review.

Supabase is not a single unrestricted database client. Different credentials and services have different trust boundaries. This source lesson makes the boundary explicit so a working demonstration does not accidentally teach learners to expose server credentials, ignore RLS, or apply migrations against the wrong project.

type Evidence = { backupRestoreTested: boolean; monitored: boolean;
  budgetAlerts: boolean; securityReview: boolean; capacityTested: boolean };
function productionReady(evidence: Evidence) {
  return Object.values(evidence).every(Boolean);
}
const readyForProduction = productionReady({
  backupRestoreTested: false, monitored: false, budgetAlerts: false,
  securityReview: false, capacityTested: false,
});

## Applied persistence walkthrough

A pricing plan is a resource and service entitlement, not proof of production readiness. Backup availability, restore procedures, capacity, observability and security require evidence specific to the workload and current project. The boolean checklist is deliberately false by default, but booleans alone do not authenticate evidence. Do not hardcode changing quotas or prices into a lesson.

### Diagnose the concrete failure

Create a small workload model estimating requests, storage, database connections and expected peak use. Compare that model with current official plan limits and actual project settings when qualifying. Test an incomplete evidence checklist and confirm it does not report readiness; associate every true flag with a real record.

### Independent exercise and evidence

Write an operating decision record for a solo developer's test project and a paying customer deployment. Include budget alerts, measured capacity, backup/restore evidence and an upgrade trigger. Record date and official plan source; no purchase or hosted resource change is needed.

**Qualification boundary:** These are acceptance instructions, not recorded results. Use an isolated local Supabase environment or an explicitly approved disposable project. Preserve the starter and solution; do not treat source review as live platform or security qualification.
