## Why this lesson matters

**Prisma 7 driver adapters.** PrismaPg bridges the generated client to node-postgres. The adapter owns connection configuration, TLS requirements and pooling options; it must receive a PostgreSQL-compatible URL, not an Accelerate URL.

**Broken real-world assumption:** Constructing PrismaClient without the required driver adapter is not a valid Prisma ORM v7 PostgreSQL integration.

An ORM is not an access-control mechanism or a database deployment tool by itself. Treat the generated TypeScript types, database constraints, migration history and the authenticated request context as separate boundaries. The learner should be able to explain what each boundary guarantees and what it does not.

<LessonStep number={2} title="Implement the safe version" file="drafts/p4/labs/postgres-driver-adapter/solution.ts" expected="A version-7-compatible repair with explicit trust boundaries.">

```ts
import { PrismaClient } from "../generated/prisma/client";
import { PrismaPg } from "@prisma/adapter-pg";

function requiredUrl() {
  const value = process.env.DATABASE_URL;
  if (!value) throw new Error("DATABASE_URL is required");
  return value;
}
const adapter = new PrismaPg({ connectionString: requiredUrl() });
export const prisma = new PrismaClient({ adapter });
```

**How the repair works:** Build the adapter once in server-only code with an explicitly required URL. Import the generated client from the schema's chosen output directory and pass { adapter } to PrismaClient.

</LessonStep>

## Architecture, correctness and performance

PrismaPg bridges the generated client to node-postgres. The adapter owns connection configuration, TLS requirements and pooling options; it must receive a PostgreSQL-compatible URL, not an Accelerate URL.

Build the adapter once in server-only code with an explicitly required URL. Import the generated client from the schema's chosen output directory and pass { adapter } to PrismaClient.

A Prisma adapter connection may use a privileged database role and bypass Supabase RLS. A server-side connection is not automatically authorized for every tenant.

A production-ready persistence boundary has to address error mapping, least-privileged database credentials, transaction/connection lifecycle, tenant authorization and request cancellation. Whenever schema changes are involved, review migration SQL and compatibility with the previous app version. Never expose database credentials in a `NEXT_PUBLIC_` variable or include them in a public web bundle.
