## Why this lesson matters

**Environment configuration.** A config file tells Prisma's CLI where to find the schema, migration history and connection URL. Secrets belong in runtime/CI secret storage, never in files or variables bundled for the browser.

**Broken real-world assumption:** The starter puts secrets into a NEXT_PUBLIC variable and suggests a pre-v7 datasource URL placement.

An ORM is not an access-control mechanism or a database deployment tool by itself. Treat the generated TypeScript types, database constraints, migration history and the authenticated request context as separate boundaries. The learner should be able to explain what each boundary guarantees and what it does not.

  schema: "prisma/schema.prisma",
  migrations: { path: "prisma/migrations" },

## Architecture, correctness and performance

A config file tells Prisma's CLI where to find the schema, migration history and connection URL. Secrets belong in runtime/CI secret storage, never in files or variables bundled for the browser.

Use Prisma config with a server-only DATABASE_URL. Some Prisma 7.10+ initialization templates name this prisma7.config.ts; use the version-matched CLI file convention rather than assuming cross-major compatibility.

CLI config is not automatic authorization. A correct URL can still connect as a superuser; explicitly scope roles, environment and migration rights.

A production-ready persistence boundary has to address error mapping, least-privileged database credentials, transaction/connection lifecycle, tenant authorization and request cancellation. Whenever schema changes are involved, review migration SQL and compatibility with the previous app version. Never expose database credentials in a `NEXT_PUBLIC_` variable or include them in a public web bundle.
