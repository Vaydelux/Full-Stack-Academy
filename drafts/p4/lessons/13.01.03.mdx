## Why this lesson matters

**Prisma Client generation.** Prisma ORM v7's prisma-client generator writes TypeScript output to a custom directory. The import path is determined by generator.output; runtime construction for PostgreSQL also needs an adapter.

**Broken real-world assumption:** The starter assumes the old package import and instantiates Prisma without the ORM v7 PostgreSQL driver adapter.

An ORM is not an access-control mechanism or a database deployment tool by itself. Treat the generated TypeScript types, database constraints, migration history and the authenticated request context as separate boundaries. The learner should be able to explain what each boundary guarantees and what it does not.

## Architecture, correctness and performance

Prisma ORM v7's prisma-client generator writes TypeScript output to a custom directory. The import path is determined by generator.output; runtime construction for PostgreSQL also needs an adapter.

Generate explicitly with npx prisma generate and import PrismaClient from the configured generated location. Instantiate it with PrismaPg in the composition root, not in each service.

Do not commit generated clients from a developer's machine as a substitute for reproducible builds; pin versions and commit an authentic lockfile.

A production-ready persistence boundary has to address error mapping, least-privileged database credentials, transaction/connection lifecycle, tenant authorization and request cancellation. Whenever schema changes are involved, review migration SQL and compatibility with the previous app version. Never expose database credentials in a `NEXT_PUBLIC_` variable or include them in a public web bundle.
