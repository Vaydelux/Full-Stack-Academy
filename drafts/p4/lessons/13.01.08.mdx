## Why this lesson matters

**Lab connect to Postgres.** A successful connection is only the beginning. A safe repository method couples a server-verified tenant identity with an explicit projection, bounded result size, and defined ordering.

**Broken real-world assumption:** The starter fetches every tenant's tasks and all selected model fields from a potentially privileged server connection.

An ORM is not an access-control mechanism or a database deployment tool by itself. Treat the generated TypeScript types, database constraints, migration history and the authenticated request context as separate boundaries. The learner should be able to explain what each boundary guarantees and what it does not.

## Architecture, correctness and performance

A successful connection is only the beginning. A safe repository method couples a server-verified tenant identity with an explicit projection, bounded result size, and defined ordering.

Use where tenantId from trusted server context, select only safe public columns, bound take and order deterministically. Validate the generated query against two test tenants.

Prisma's server-side database user may bypass Supabase RLS. Enforce tenant/object authorization at the API boundary and prefer least-privileged database roles.

A production-ready persistence boundary has to address error mapping, least-privileged database credentials, transaction/connection lifecycle, tenant authorization and request cancellation. Whenever schema changes are involved, review migration SQL and compatibility with the previous app version. Never expose database credentials in a `NEXT_PUBLIC_` variable or include them in a public web bundle.

## Applied persistence walkthrough

The read path begins with a server-verified tenant, then uses a bounded query and explicit projection. A tenant predicate is required even when the primary key is globally unique. Selecting only public fields reduces accidental disclosure but is not a membership check. The shown verifiedTenantIdFromRequest is a placeholder for a real authorization boundary, not a value to accept from the browser.

### Diagnose the concrete failure

Generate the client and seed two tenant datasets in a disposable database. Confirm the query returns at most twenty rows in ID order, with only id and title. Test missing tenant context and a second tenant's known record. Inspect the built client bundle to ensure the database URL is absent.

### Independent exercise and evidence

Design a server endpoint that derives tenant context from verified membership, calls the repository and returns only public fields. Record positive and negative row IDs, response fields, query limit and the real database role.
