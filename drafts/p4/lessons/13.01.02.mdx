## Why this lesson matters

**Models relations and enums.** Relations describe how keys connect rows; enum values constrain the application's representable states. In multi-tenant tables, a composite tenant/owner foreign key is a useful integrity defense in depth.

**Broken real-world assumption:** The starter's owner foreign key checks only a numeric ID, allowing an alpha task to reference a beta user when the relationship is extended to multi-tenant data.

An ORM is not an access-control mechanism or a database deployment tool by itself. Treat the generated TypeScript types, database constraints, migration history and the authenticated request context as separate boundaries. The learner should be able to explain what each boundary guarantees and what it does not.

<LessonStep number={2} title="Implement the safe version" file="drafts/p4/labs/relations-and-enums/solution.prisma" expected="A version-7-compatible repair with explicit trust boundaries.">

```prisma
enum TaskState { TODO DONE }
model User {
  id Int @id
  tenantId String
  tasks Task[]
  @@unique([tenantId, id])
}
model Task {
  id Int @id
  tenantId String
  ownerId Int
  owner User @relation(fields: [tenantId, ownerId], references: [tenantId, id])
  state TaskState @default(TODO)
  @@index([tenantId, ownerId])
}
```

**How the repair works:** Add tenantId to both models, declare a composite unique referenced key and reference it from Task; index the child-side lookup.

</LessonStep>

## Architecture, correctness and performance

Relations describe how keys connect rows; enum values constrain the application's representable states. In multi-tenant tables, a composite tenant/owner foreign key is a useful integrity defense in depth.

Add tenantId to both models, declare a composite unique referenced key and reference it from Task; index the child-side lookup.

Prisma's @relation is a data relationship, not an actor authorization decision. A valid same-tenant owner can still be unauthorized for a particular user.

A production-ready persistence boundary has to address error mapping, least-privileged database credentials, transaction/connection lifecycle, tenant authorization and request cancellation. Whenever schema changes are involved, review migration SQL and compatibility with the previous app version. Never expose database credentials in a `NEXT_PUBLIC_` variable or include them in a public web bundle.
