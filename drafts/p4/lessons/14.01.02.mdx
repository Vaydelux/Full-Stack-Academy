## Architecture problem

**Project environments.** Local, staging and production Supabase resources must use separate credentials and destructive-operation safeguards. An environment label alone does not stop a mistaken remote command.

**Unsafe starting point:** The starter silently connects to production if the test URL is absent, allowing test scripts to modify real user data.

Supabase is not a single unrestricted database client. Different credentials and services have different trust boundaries. This source lesson makes the boundary explicit so a working demonstration does not accidentally teach learners to expose server credentials, ignore RLS, or apply migrations against the wrong project.

<LessonStep number={2} title="Use scoped configuration or explicit RLS" file="drafts/p4/labs/isolate-supabase-environments/solution.ts" expected="A clear, reviewable boundary appropriate to the operation.">

```ts
export function requireTestProjectUrl() {
  const value = process.env.SUPABASE_TEST_URL;
  if (!value) throw new Error("SUPABASE_TEST_URL is required");
  const url = new URL(value);
  if (url.protocol !== "http:" && url.protocol !== "https:")
    throw new Error("Invalid project URL");
  // Require an explicit test-only project reference approved by the operator.
  if (process.env.ACADEMY_TEST_PROJECT_APPROVED !== "YES")
    throw new Error("Test project approval required");
  return url.toString();
}
```

**Repair:** Fail closed when test credentials are absent and require an explicit operator-approved test project before proceeding with integration experiments.

</LessonStep>

**Positive proof:** Inspect the active project reference, database host and test credentials before local migrations. Verify no published environment variables point at the live project.

**Required negative proof:** Run the local test harness without SUPABASE_TEST_URL and with a missing approval flag; both should stop before any network request.

**Remaining boundary:** An approval flag is a guardrail, not a cryptographic guarantee of environment identity. Compare project IDs and role privileges before destructive operations.

The acceptance file is a manual/real-stack qualification plan. It is not an automatically successful integration test and does not qualify a production project.
