## Integration defect

**Migration ownership rules.** Prisma migrations and Supabase migrations both operate on the same PostgreSQL schema. Uncoordinated dual ownership can create drift, destructive changes and unreplayable environments.

**What fails in an actual application:** The starter lets two independent unreviewed schema operations modify the same table without an authoritative history.

A full-stack application can use both a Supabase client and a direct Prisma ORM 7 PostgreSQL adapter. These access paths do not automatically share the same user authorization context. The browser may have a valid JWT while a server's database role can read far more than that JWT would authorize.

## API, RLS and migration trade-offs

Prisma migrations and Supabase migrations both operate on the same PostgreSQL schema. Uncoordinated dual ownership can create drift, destructive changes and unreplayable environments.

Document table-by-table ownership: Prisma Migrate for selected application models, Supabase migrations for policy/platform SQL, with one reviewed pipeline applying each change in a controlled order.

Neither migrate deploy nor supabase db push is safe to call blindly against production. Current CLI versions, migration locks and rollback/forward-fix plans need independent review.

Explicitly choose how identity is propagated between Next.js, NestJS, Prisma, and Supabase. When a privileged server role bypasses RLS, the NestJS service must check permissions and the database role should still be restricted. Prefer verified membership from trusted server data over user-editable metadata or query parameters.

## Extend the ERP laboratory

Create synthetic organizations alpha and beta with overlapping IDs, a membership table and private documents. Run requests through both Supabase's Data API and a Prisma-backed NestJS endpoint. Verify permitted rows, denied rows, mutation effects and clean database recreation from migrations. Record whether your test uses a JWT-backed user or a privileged SQL role; those results are not interchangeable.
