## Architectural challenge

**Raw SQL escape hatches.** Use Prisma's tagged $queryRaw/Prisma.sql binding for values when the ORM API cannot express a query. Keep identifiers static and include server-verified tenant predicates and a bounded projection.

**Reproducible failure:** An admin report passes a search string directly into a raw SELECT. A malicious title becomes SQL syntax instead of a parameter, while an otherwise correct row filter fails to scope the tenant.

When a service evolves from a single-developer prototype into an API used by several organizations, an apparently valid query may introduce security gaps, schema drift, or operational load. Before looking at the corrected code, describe the invariant and the actor or environment whose behavior violates it.

<LessonStep number={2} title="Apply the narrow corrected boundary" file="drafts/p4/labs/parameterized-raw-sql/solution.ts" expected="The data and deployment invariant is explicitly enforced or observable.">

```ts
// Prisma 7: tagged query values are bound, not pasted into SQL.
const pattern = "%" + search + "%";
const tasks = await prisma.$queryRaw<
  Array<{ id: number; title: string }>
>(
  Prisma.sql`SELECT id, title FROM tasks
    WHERE tenant_id = ${trustedTenantId}
      AND title ILIKE ${pattern}
    ORDER BY id DESC LIMIT 50`
);
```

**Why it is safer:** Bind every user value through Prisma.sql, include the verified tenant, order by a stable key and cap the result. Avoid $queryRawUnsafe for dynamically assembled user strings.

Do not assume a successful CLI or TypeScript compile proves that the caller was authorized. Generated types protect shapes, not per-request permissions. Similarly, a DB transaction cannot roll back independent external side effects.

</LessonStep>

In a multi-tenant API, input validation, role-aware database credentials, optimistic concurrency, migration review and response-shape controls must be considered together. Favor bounded queries and explicit domain operations over returning raw privileged ORM interfaces to HTTP handlers. Record the query plan or migration state instead of guessing.

## Applied persistence walkthrough

Tagged raw queries bind data values instead of concatenating them into SQL syntax. The example binds tenant and search pattern; percent and underscore remain pattern operators in ILIKE, not SQL injection. Identifiers and sort directions cannot be bound like values and require an allowlisted choice. The generic result type is a compile-time assertion, not runtime validation.

### Diagnose the concrete failure

Compare the emitted query and bound arguments for a search containing an apostrophe, percent and underscore. Verify the tenant predicate and fifty-row cap. If literal substring search is required, define escaping semantics for wildcard characters. Verify physical table and column names match the deployed mapping.

### Independent exercise and evidence

Design an allowlisted sorting API with a fixed SQL fragment for each accepted sort and bound filter values. Record permitted results and invalid-sort rejection, without including confidential parameters in logs.

**Qualification boundary:** These are acceptance instructions, not recorded results. Use the pinned Prisma 7 toolchain and disposable PostgreSQL database. Preserve the starter and solution; source review does not qualify generated code or authorization.
