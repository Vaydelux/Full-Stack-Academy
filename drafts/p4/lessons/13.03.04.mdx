## Architectural challenge

**Expand-contract changes.** Expand–backfill–contract separates adding a compatible field, migrating historical rows, updating application writers and finally enforcing the new constraint.

**Reproducible failure:** A migration adds a required column to a populated table in one step, potentially failing or blocking a mixed-version deployment.

When a service evolves from a single-developer prototype into an API used by several organizations, an apparently valid query may introduce security gaps, schema drift, or operational load. Before looking at the corrected code, describe the invariant and the actor or environment whose behavior violates it.

<LessonStep number={2} title="Apply the narrow corrected boundary" file="drafts/p4/labs/expand-backfill-contract-prisma/solution.sql" expected="The data and deployment invariant is explicitly enforced or observable.">

```sql
-- Stage 1: compatible expansion (on a disposable database).
ALTER TABLE training_tasks ADD COLUMN priority integer;
-- Stage 2: verified idempotent backfill.
UPDATE training_tasks SET priority = 1 WHERE priority IS NULL;
-- Stage 3: enforce only after old writers are upgraded.
ALTER TABLE training_tasks ALTER COLUMN priority SET NOT NULL;
```

**Why it is safer:** Stage schema changes, backfill in safe bounded batches in larger workloads, then enforce the required contract after every running application version writes valid data.

Do not assume a successful CLI or TypeScript compile proves that the caller was authorized. Generated types protect shapes, not per-request permissions. Similarly, a DB transaction cannot roll back independent external side effects.

</LessonStep>

## Design trade-offs and real-world constraints

Expand–backfill–contract separates adding a compatible field, migrating historical rows, updating application writers and finally enforcing the new constraint.

Stage schema changes, backfill in safe bounded batches in larger workloads, then enforce the required contract after every running application version writes valid data.

The example's one-shot UPDATE is for tiny synthetic data only. Large production backfills need batching, observability, timeouts, lock review and potentially online validation.

In a multi-tenant API, input validation, role-aware database credentials, optimistic concurrency, migration review and response-shape controls must be considered together. Favor bounded queries and explicit domain operations over returning raw privileged ORM interfaces to HTTP handlers. Record the query plan or migration state instead of guessing.
