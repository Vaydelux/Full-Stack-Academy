## The problem we're solving

A Next.js 16 dynamic page treats params as a synchronous object, producing an undefined slug in a request. This local fixture isolates a concrete failure before we introduce any external state or deployment.

## Build the mental model

Dynamic route params are promised in current Next.js App Router conventions, so await them in Server Components. Validate path values before using them in a database query or rendering; route params are untrusted strings, not authorization.

**Predict before running:** The repaired implementation respects its documented contract.
