## The problem we're solving

The guide route `/guides/[slug]` must reject malformed slugs and await the `params` Promise rather than reading a synchronous property.

**Failure:** The starter never awaits params and returns a placeholder slug.

## Build the mental model

In Next.js 16, dynamic page params are asynchronous and should be awaited before validating, decoding or using a slug.

**Prediction:** Valid IDs return a normalized slug, malformed IDs throw, and the input Promise is handled asynchronously.

**Proof boundary:** The local Node/TSX fixture verifies this lesson's deterministic model and initial React markup. It does **not** start Next.js, compile route conventions, simulate streaming, or prove HTTP status codes. A separately built Next application and browser/HTTP test are needed before release qualification.

**Real App Router shape:**

```tsx
// app/guides/[slug]/page.tsx
import { notFound } from 'next/navigation';
type Props = { params: Promise<{ slug: string }> };
export default async function GuidePage({ params }: Props) {
  const { slug } = await params;
  if (!/^[a-z0-9-]+$/.test(slug)) notFound();
  return <article><h1>Guide: {slug}</h1></article>;
}
```

**Nuance:** `params` is a Promise in current Next App Router conventions. Validate what it refers to before a database, file or HTTP call; pattern validation alone does not authorize a private resource.
