## The problem we're solving

A form accepts whitespace-only names and reloads the page before showing a useful validation result. Browser Interaction topics require both executable JavaScript logic and a real local HTML document. The fixture uses synthetic content with no external scripts, endpoints or data uploads.

## Build the mental model

Native form controls provide name, label and constraint APIs; submit events can be enhanced with preventDefault. Trim user input, validate the intended shape, and send feedback to a real status region. Client validation improves UX but never replaces server validation.

**Predict before running:** Whitespace and one-character values are rejected, while a valid name yields safe text feedback.

<LessonStep number={2} title="Implement the browser-safe interaction" file="labs/js-forms/starter/index.html" expected={"Whitespace and one-character values are rejected, while a valid name yields safe text feedback."}>

Replace the defective handler without discarding native elements or semantics. For untrusted content use `textContent`, not an unsafe HTML sink.

```js
document.querySelector('#form').addEventListener('submit',event=>{event.preventDefault();const value=document.querySelector('#name').value;document.querySelector('#status').textContent=value.trim().length>=2?'Accepted: '+value.trim():'Please enter at least two nonspace characters.';});
```

**Predict before running:** Whitespace and one-character values are rejected, while a valid name yields safe text feedback.

**Why the repair works:** Native form controls provide name, label and constraint APIs; submit events can be enhanced with preventDefault. Trim user input, validate the intended shape, and send feedback to a real status region. Client validation improves UX but never replaces server validation.

**Proof:** Compare the resulting DOM and accessibility state to the instructor `solution/index.html` using the same input.

</LessonStep>
