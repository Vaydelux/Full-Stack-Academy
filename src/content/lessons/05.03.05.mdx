## The problem we're solving

A cache key ignores shared configuration changes, yielding a false cache hit for outdated compiled output. This offline workshop is part of the Git/monorepo track; no workspace installation, external package query or Vercel build runs when reading the lesson.

## Build the mental model

Build cache correctness depends on identifying every input that can affect task output, including package source, lockfile, toolchain config and dependency artifacts. A content hash cannot magically detect omitted inputs. This offline SHA-256 exercise validates deterministic keys and invalidation, not actual Turborepo remote cache behavior.

**Predict before running:** Same content yields the same cache key, but changes in shared config or dependencies invalidate it.

Preserve the exported `solve` entry and implement the smallest correct policy, noting whether this example is a simplified model rather than an actual pnpm/turbo invocation.

```js
import {createHash} from 'node:crypto';export function solve(inputs){if(!inputs||typeof inputs!=='object')throw new TypeError('Inputs required');const keys=['source','lockfile','tsconfig','dependencies'];for(const key of keys)if(typeof inputs[key]!=='string')throw new TypeError('Missing cache input: '+key);return createHash('sha256').update(JSON.stringify(keys.map(key=>[key,inputs[key]]))).digest('hex');}
```

**Predict before running:** Same content yields the same cache key, but changes in shared config or dependencies invalidate it.

**Why the repair works:** Build cache correctness depends on identifying every input that can affect task output, including package source, lockfile, toolchain config and dependency artifacts. A content hash cannot magically detect omitted inputs. This offline SHA-256 exercise validates deterministic keys and invalidation, not actual Turborepo remote cache behavior.
