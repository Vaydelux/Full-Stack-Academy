## The problem we're solving

Checking a selection box styles only the checkbox, while the surrounding panel should visibly indicate selected state. We will repair a specific CSS behavior in an offline component so that a future design system has predictable boundaries. There is no external font, image or API dependency.

## Build the mental model

The relational :has() pseudo-class matches an element based on conditions among related elements. A component can style itself when a descendant input is checked. Use :has() where it communicates state cleanly; keep proper label associations and do not treat CSS appearance as a substitute for form semantics.

**Predict before running:** Checking the box changes the card's border while preserving the checkbox's native state.

## Explore and verify

A syntactically valid color, selector or animation is not necessarily accessible or performant. Test color contrast for actual foreground/background pairs; preserve focus, reduced-motion behavior and narrow layouts. The Node fixture assertions check reviewed CSS patterns, and Chromium independently checks representative rendered behavior. Neither constitutes a full multi-device accessibility certification.
