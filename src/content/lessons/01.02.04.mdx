## The problem we're solving

A form requires JavaScript to render its submit button. When scripts fail to load, the user has no working path forward. The HTML should establish a baseline action before optional enhancements.

## Build the mental model

Progressive enhancement starts with semantic HTML and working browser defaults. The form's action and method express baseline behavior; JavaScript may intercept the submit for a local preview and render accessible feedback. If scripting is blocked, the browser can still navigate to a usable local confirmation page. This exercise is a demonstration only: the bundled static receipt cannot store messages or verify delivery. A real service should implement server-side validation, CSRF controls where applicable, rate limits and a real response. Only prevent default after establishing a working enhancement; avoid telling the learner that a preview equals a saved operation.

**Predict before running:** With JavaScript disabled, a form with an action, method, named controls and submit button should still perform its baseline navigation.

<LessonStep number={1} title={"Implement the baseline first"} file="labs/forms-enhancement/starter/index.html" expected={"With scripts disabled, valid submission reaches a local confirmation page."}>

The HTML form has an explicit local action and named required field.

```html
<form id="question-form" action="receipt.html" method="get">
  <label for="question">Question</label>
  <textarea id="question" name="question" required></textarea>
  <button type="submit">Preview question</button>
</form>
```

</LessonStep>

<LessonStep number={2} title={"Include a meaningful fallback receipt"} file="labs/forms-enhancement/starter/index.html" expected={"A learner receives a usable destination even if JavaScript is disabled."}>

The receipt tells the truth: a local demonstration, not a delivered message.

```html
<main>
  <h1>Local question preview</h1>
  <p>This static page cannot receive or store your submission.</p>
  <a href="index.html">Return to the question</a>
</main>
```

</LessonStep>

<LessonStep number={3} title={"Optionally enhance after the form has been built"} file="labs/forms-enhancement/starter/index.html" expected={"With scripts enabled, the page stays in place and displays an accurate, accessible local status."}>

Attach submit handling after the HTML exists, then set a visible live-region status.

```js
const form=document.querySelector('#question-form');
form.addEventListener('submit',event=>{
  event.preventDefault();
  const question=new FormData(form).get('question');
  document.querySelector('#status').textContent='Local preview ready ('+String(question).length+' characters). Nothing sent.';
});
```

</LessonStep>

## Bug Hunt: identify the root cause

An engineer sets `action=''` and removes the submit button because JavaScript always handles it in local testing. With scripts blocked, the user cannot complete the action. Restore a meaningful fallback and test JavaScript-disabled Chromium navigation.
