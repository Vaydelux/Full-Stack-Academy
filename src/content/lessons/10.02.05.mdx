## The problem we're solving

A task API slices its data into pages before filtering and sorting, producing missing matches and inconsistent page boundaries.

**Fault to find:** The starter pages first, then filters, so matches from later rows are invisible on the first page. This track uses Node 24 built-ins and fetch-compatible `Response` where appropriate; no paid platform or remote arbitrary-code execution is needed.

## Build the mental model

Validate filter and sort query parameters against allowlists, sort/filter the authoritative result set before pagination and cap page size.

**Expected repair:** Filtered rows are sorted globally before slicing and invalid pagination values are rejected.

HTTP semantics follow RFC 9110. Public errors can use RFC 9457 Problem Details; do not invent return codes or copy internal stack traces into public responses. Pure helper tests are useful but the final capstone runs a real loopback server and tests wire responses.

<LessonStep number={2} title="Implement standards-based HTTP behavior" file="labs/http-filter-page/starter/solution.mjs" expected="Filtered rows are sorted globally before slicing and invalid pagination values are rejected.">

```js
export function listTasks(rows,{status='all',page=1,limit=2,order='asc'}={}){
 if(!['all','open','done'].includes(status)||!['asc','desc'].includes(order))throw new RangeError('Invalid filter');
 if(!Number.isSafeInteger(page)||page<1||!Number.isSafeInteger(limit)||limit<1||limit>50)throw new RangeError('Invalid page');
 const filtered=rows.filter(x=>status==='all'||x.status===status);
 const sorted=[...filtered].sort((a,b)=>a.title.localeCompare(b.title)*(order==='asc'?1:-1)||String(a.id).localeCompare(String(b.id)));
 return sorted.slice((page-1)*limit,page*limit);
}
```

**Why this is correct:** Validate filter and sort query parameters against allowlists, sort/filter the authoritative result set before pagination and cap page size.

</LessonStep>
