## The problem we're solving

Environment separation can create user-visible reliability or security failures. The starter considers every NEXT_PUBLIC_ setting safe even if its name signals a secret.

## Build the mental model

Restrict browser-exposed values to explicitly public names and never put secrets in NEXT_PUBLIC_ variables or next.config env. **Expected result:** A public site label passes; an API key, token or password is refused.

Offline tests verify small, deterministic policy models. They cannot establish real HTTP security, deployment compatibility, image loading, environment secrecy or network diagnostics.

<LessonStep number={2} title="Repair the policy and runtime boundary" file="labs/next-environment-separation/starter/solution.tsx" expected="A public site label passes; an API key, token or password is refused.">

```tsx
export function publicEnvCandidate(name:string){return /^NEXT_PUBLIC_[A-Z0-9_]+$/.test(name) && !/(SECRET|TOKEN|PASSWORD|PRIVATE|API_KEY|CREDENTIAL)/.test(name);}
```

**Why it works:** Restrict browser-exposed values to explicitly public names and never put secrets in NEXT_PUBLIC_ variables or next.config env.

</LessonStep>
