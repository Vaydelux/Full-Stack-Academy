## The problem we're solving

A sticky reference sidebar never sticks during page scroll even though position: sticky is present. The goal is a predictable local repair, not a decorative mockup. The HTML fixture is fully offline and has an intentionally failing starter plus an instructor solution.

## Build the mental model

Sticky positioning depends on a scroll container and inset; overflow on an ancestor can change the nearest scrollport and prevent the expected viewport sticking. A parent that is too short also limits sticky travel. Inspect the ancestor overflow chain, element height and inset before adding z-index.

**Predict before running:** The sidebar stays near the viewport top while scrolling the long article on a wide viewport.

<LessonStep number={2} title="Repair the rule, not the screenshot" file="labs/css-sticky-debug/starter/index.html" expected={"The sidebar stays near the viewport top while scrolling the long article on a wide viewport."}>

Replace the defective declaration with this rule from the instructor implementation. Do not change the semantic markup or hide overflow simply to mask a layout defect.

```css
.layout { display: grid; grid-template-columns: minmax(0, 1fr) 11rem; align-items: start; gap: 1rem; overflow: visible; } .sidebar { position: sticky; top: 1rem; align-self: start; } @media (max-width: 40rem) { .layout { grid-template-columns: minmax(0, 1fr); } }
```

**Predict before running:** The sidebar stays near the viewport top while scrolling the long article on a wide viewport.

**Why it works:** Sticky positioning depends on a scroll container and inset; overflow on an ancestor can change the nearest scrollport and prevent the expected viewport sticking. A parent that is too short also limits sticky travel. Inspect the ancestor overflow chain, element height and inset before adding z-index.

**Proof:** Compare the properties and geometry with `labs/css-sticky-debug/solution/index.html`, using DevTools, not merely text-searching the CSS source.

</LessonStep>
