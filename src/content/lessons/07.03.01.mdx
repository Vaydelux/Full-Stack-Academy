## The problem we're solving

A personalized inbox must be requested at runtime; an author mistakenly assumes every server fetch is automatically cached and shared.

**Failure mode:** The starter marks a personal inbox as safe to share across users.

## Build the mental model

Treat request-specific data as runtime data and never cache user-specific output globally. Cache Components enables explicit opt-in caching of eligible work. This module specifically uses **Next.js 16 with `cacheComponents: true`**; avoid mixing with the legacy `dynamic`, route-segment `revalidate` or `fetchCache` configuration model. The offline assertions are data/decision models; they do not access Next's actual cache internals, HTTP, or database.

**Expected behavior:** Public catalogue data can be considered cacheable; private messages and authorization-sensitive records cannot be shared.
