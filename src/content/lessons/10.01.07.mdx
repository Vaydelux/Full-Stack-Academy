## The problem we're solving

Two termination signals arrive during shutdown. The server closes twice, causing duplicate resource cleanup and lost error handling.

**Deliberate defect:** The starter starts another cleanup for each signal and retains the listeners indefinitely. This exercise runs under Node.js 24 using built-in modules—no paid service, hosted data source or arbitrary learner-code runner.

## Build the mental model

Register SIGTERM/SIGINT handlers with an idempotent shutdown gate and detach listeners after cleanup.

**Predict before writing code:** Termination cleanup runs exactly once even when two signals arrive.

The exact Node.js API documentation is linked below. These exercises model concrete runtime behavior, not a screenshot of a server. They must not be interpreted as proof of container permission boundaries, a production reverse proxy or multi-process request isolation.

```js
export function installShutdown(signals,close){
 let closing=false;
 const callback=()=>{
  if(closing)return;
  closing=true;
  signals.off('SIGTERM',callback);signals.off('SIGINT',callback);
  void Promise.resolve().then(close);
 };
 signals.on('SIGTERM',callback);signals.on('SIGINT',callback);
 return ()=>{
  signals.off('SIGTERM',callback);signals.off('SIGINT',callback);
 };
}
```

**Causal reasoning:** Register SIGTERM/SIGINT handlers with an idempotent shutdown gate and detach listeners after cleanup.

</LessonStep>
