## The problem we're solving

A component showcase includes duplicate IDs and unlabeled icon-only controls, so keyboard and assistive-technology users cannot identify actions reliably.

## Build the mental model

A reusable gallery should validate stable IDs and accessible labels, provide consistent design tokens, and separate presentational variants from behavior. Test every control across disabled, loading, error, dark/light and compact states.

**Predict first:** Valid gallery elements keep unique IDs and nonempty accessible names, while duplicate or empty entries are rejected before rendering.

<LessonStep number={2} title="Fix the policy and verify edge cases" file="labs/ui-component-gallery/starter/solution.ts" expected="Valid gallery elements keep unique IDs and nonempty accessible names, while duplicate or empty entries are rejected before rendering.">

```ts

export type Spec={id:string;label:string;kind:"button"|"link"};export function solve(specs:readonly Spec[]){const seen=new Set<string>();return specs.map(s=>{if(!/^[a-z0-9-]+$/.test(s.id)||seen.has(s.id)||!s.label.trim())throw new TypeError("Unique IDs and accessible names required");seen.add(s.id);return {id:s.id,label:s.label.trim(),kind:s.kind};});}

```

**Why it works:** A reusable gallery should validate stable IDs and accessible labels, provide consistent design tokens, and separate presentational variants from behavior. Test every control across disabled, loading, error, dark/light and compact states.

**Proof:** Run `npm run lab:ui-component-gallery` and inspect the instructor test output.

</LessonStep>
