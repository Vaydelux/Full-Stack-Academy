## The problem we're solving

The starter permits duplicate component identities and disabled preview entries. A robust component system has to work across dark and light themes, keyboard input, small screens and real data, not merely appear correct in a screenshot.

## Build the mental model

Build a semantic component gallery with stable IDs, typed states, theme tokens and deliberately selected examples. **Predict before executing:** Gallery excludes disabled examples and fails on duplicate IDs.

**Runtime boundary:** This lesson's fixture is local TypeScript only. It does not compile Tailwind CSS, install shadcn or Radix/Base UI, mount a browser interaction, or verify visual contrast on real content. Those require a dedicated UI build and accessibility checks.

```tsx
export type Item={id:string;enabled:boolean};export function gallery(items:readonly Item[]){const seen=new Set<string>();return items.filter(x=>{if(seen.has(x.id))throw new Error('Duplicate ID');seen.add(x.id);return x.enabled;});}
```

**Why it works:** Build a semantic component gallery with stable IDs, typed states, theme tokens and deliberately selected examples.

</LessonStep>
