## The problem we're solving

An event handler runs a CPU-heavy callback on the main thread and freezes other requests; a learner also assumes timers, microtasks and immediate callbacks are interchangeable.

**Deliberate defect:** The starter mistakenly emits the immediate phase synchronously before the scheduled microtask. This exercise runs under Node.js 24 using built-in modules—no paid service, hosted data source or arbitrary learner-code runner.

## Build the mental model

Observe actual synchronous, microtask and setImmediate execution, and offload long-running CPU jobs to worker_threads instead of blocking the event loop.

**Predict before writing code:** The actual Node ordering remains sync → microtask → setImmediate, without relying on nondeterministic timer races.

The exact Node.js API documentation is linked below. These exercises model concrete runtime behavior, not a screenshot of a server. They must not be interpreted as proof of container permission boundaries, a production reverse proxy or multi-process request isolation.
