## The problem we're solving

The starter generates a script-readable session cookie with no secure attributes. Real services must establish who can request a resource, constrain how the request is interpreted, and prevent unexpected data disclosure.

## Build the mental model

Set Secure, HttpOnly, SameSite and host-only cookie scope on opaque session identifiers; understand how bearer headers differ from automatically sent cookies.

**Expected outcome:** A host-only opaque session cookie has HttpOnly, Secure, SameSite=Lax and Path=/ and rejects newline injection.

**Production boundary:** The __Host- prefix requires Secure, Path=/ and no Domain attribute. Session IDs must be cryptographically random and server-verified; this serializer is not an auth system.
