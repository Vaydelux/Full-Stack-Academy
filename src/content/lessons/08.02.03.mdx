## The problem we're solving

The starter returns all items despite a search term. Advanced UI interactions need a robust identity and focus model so the component works with touch, keyboard and screen readers rather than only a mouse.

## Build the mental model

Filter combobox options predictably while keeping option IDs stable and keyboard navigation distinct from selection. **Expected behavior:** Search is case-insensitive and excludes nonmatching options without mutating the source.

**Evidence boundary:** The local test checks a pure data or interaction-policy function. It does not prove DOM focus, ARIA announcements, actual event sequences, animation timing or a third-party library's mounted behavior. Use a real local browser and accessible component primitives for those claims.

```tsx
export type Option={id:string;label:string};export function filterOptions(items:readonly Option[],term:string){const q=term.trim().toLocaleLowerCase();return items.filter(x=>x.label.toLocaleLowerCase().includes(q));}
```
