## The problem we're solving

A custom dropdown never updates aria-expanded, allows focus onto hidden options and closes when Tab is pressed.

## Build the mental model

Choose a disclosure or menu pattern based on actual semantics. Keep expanded state synchronized with visible content and use a tested primitive for complex listbox/menu behaviors. Never conflate a simple disclosure navigation panel with a full ARIA menu.

**Predict first:** Expanded state and visible panel visibility agree for both open and closed transitions.

## Production library pattern

```tsx
"use client";
import * as DropdownMenu from "@radix-ui/react-dropdown-menu";
function AccountMenu(){return <DropdownMenu.Root><DropdownMenu.Trigger>Account options</DropdownMenu.Trigger><DropdownMenu.Portal><DropdownMenu.Content><DropdownMenu.Item>Profile</DropdownMenu.Item><DropdownMenu.Item>Settings</DropdownMenu.Item></DropdownMenu.Content></DropdownMenu.Portal></DropdownMenu.Root>;}
```

A Radix DropdownMenu follows menu semantics, which differ from ordinary site navigation disclosure links. The offline test covers only an expanded/visible invariant.
