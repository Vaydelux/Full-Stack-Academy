## The problem we're solving

The starter focuses a disabled action at index zero. Advanced UI interactions need a robust identity and focus model so the component works with touch, keyboard and screen readers rather than only a mouse.

## Build the mental model

Distinguish an action menu from a listbox, and never focus disabled actions when a dropdown opens. **Expected behavior:** Initial focus lands on the first enabled action or -1 for an empty/disabled menu.

**Evidence boundary:** The local test checks a pure data or interaction-policy function. It does not prove DOM focus, ARIA announcements, actual event sequences, animation timing or a third-party library's mounted behavior. Use a real local browser and accessible component primitives for those claims.
