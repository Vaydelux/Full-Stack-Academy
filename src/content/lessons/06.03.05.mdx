## The problem we're solving

An implementation assumes changing a ref value triggers a render, so the displayed count never updates. This local fixture isolates a concrete failure before we introduce any external state or deployment.

## Build the mental model

useRef persists a mutable container between renders but changes to current do not schedule rendering. Store timer IDs, external handles or previous values in refs; use state for values that must update the screen.

**Predict before running:** The repaired implementation respects its documented contract.
