## The problem we're solving

A row of topic chips overflows a narrow phone because its author treated Flexbox as an inflexible single line. The goal is a predictable local repair, not a decorative mockup. The HTML fixture is fully offline and has an intentionally failing starter plus an instructor solution.

## Build the mental model

Flexbox allocates one-dimensional space along the main axis, then aligns items on the cross axis. flex-wrap permits additional lines; gap creates layout spacing without edge-margin surprises. A flexible child may need min-inline-size: 0 to shrink when content is long.

**Predict before running:** At a 320px viewport, the chips wrap into additional lines instead of creating a horizontal scrollbar.

**Why it fails:** Flexbox allocates one-dimensional space along the main axis, then aligns items on the cross axis. flex-wrap permits additional lines; gap creates layout spacing without edge-margin surprises. A flexible child may need min-inline-size: 0 to shrink when content is long.

**Proof:** Check display, flexWrap, gap, child flexBasis and documentElement.scrollWidth. Record the value in the starter before moving on.

</LessonStep>

<LessonStep number={2} title="Repair the rule, not the screenshot" file="labs/css-flexbox/starter/index.html" expected={"At a 320px viewport, the chips wrap into additional lines instead of creating a horizontal scrollbar."}>

Replace the defective declaration with this rule from the instructor implementation. Do not change the semantic markup or hide overflow simply to mask a layout defect.

```css
.demo { display: flex; flex-wrap: wrap; gap: 1rem; align-items: center; } .chip { flex: 1 1 9rem; min-inline-size: 0; }
```

**Predict before running:** At a 320px viewport, the chips wrap into additional lines instead of creating a horizontal scrollbar.

**Why it works:** Flexbox allocates one-dimensional space along the main axis, then aligns items on the cross axis. flex-wrap permits additional lines; gap creates layout spacing without edge-margin surprises. A flexible child may need min-inline-size: 0 to shrink when content is long.

**Proof:** Compare the properties and geometry with `labs/css-flexbox/solution/index.html`, using DevTools, not merely text-searching the CSS source.

</LessonStep>

<LessonStep number={3} title="Measure and regression-check the behavior" file="labs/css-flexbox/starter/index.html" expected="Narrow and wide states remain usable, with no unexpected horizontal overflow.">

```js
const root = document.documentElement;
const surface = document.querySelector('#demo');
console.log({
  fitsViewport: root.scrollWidth <= innerWidth,
  display: getComputedStyle(surface).display,
  inlineSize: surface.getBoundingClientRect().width
});
```

**Predict before running:** A specific layout value changes as expected, and the repaired surface stays within its available width.

**Why it works:** Browser computed styles and bounding boxes reflect selector matching, layout algorithm and containing-block constraints.

**Proof:** Check display, flexWrap, gap, child flexBasis and documentElement.scrollWidth.
