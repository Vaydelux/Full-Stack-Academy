## The problem we're solving

A row appears deleted immediately on click and stays deleted even when a simulated server rejection occurs.

## Build the mental model

Optimistic updates are provisional projections, not persisted truth. Keep a confirmed data source, stable row identity and a clear rollback/reconciliation strategy; server authorization and idempotency remain mandatory.

**Predict first:** A rejected server mutation preserves the confirmed rows and never silently commits the optimistic projection.

<LessonStep number={2} title="Fix the policy and verify edge cases" file="labs/ui-optimistic-tables/starter/solution.ts" expected="A rejected server mutation preserves the confirmed rows and never silently commits the optimistic projection.">

```ts

export function solve<T extends {id:string}>(rows:readonly T[],id:string,approved:boolean):T[]{return approved?rows.filter(x=>x.id!==id):[...rows];}

```

**Why it works:** Optimistic updates are provisional projections, not persisted truth. Keep a confirmed data source, stable row identity and a clear rollback/reconciliation strategy; server authorization and idempotency remain mandatory.

**Proof:** Run `npm run lab:ui-optimistic-tables` and inspect the instructor test output.
