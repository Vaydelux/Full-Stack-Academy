## The problem we're solving

A task list needs predictable add, toggle and remove operations as UI complexity grows. Distributing ad-hoc mutation logic across buttons makes transitions hard to reason about and test. The following exercise is React 19 and TypeScript 5 source checked into this repository, not a remote code runner.

## Build the mental model

Model each state transition as an explicit typed action and return new state without mutating it. It can return the existing state; actions that change data should produce the new immutable state. **Important boundary:** A pure-function test validates state transitions and static React rendering checks initial markup; neither alone simulates an interactive browser or verifies hydration and effect behavior.

**Predict before you run:** Add, toggle and remove are deterministic and duplicate IDs do not create duplicate tasks.

<LessonStep number={2} title="Repair the state ownership or transition" file="labs/react-reducer/starter/solution.tsx" expected="Add, toggle and remove are deterministic and duplicate IDs do not create duplicate tasks.">

Apply a correction that respects the relevant React snapshot, identity, immutability, or single-source-of-truth rule.

```tsx
export type Todo={id:string;text:string;done:boolean};
export type Action={type:'add';item:Todo}|{type:'toggle';id:string}|{type:'remove';id:string};
export function todoReducer(state:readonly Todo[],action:Action):readonly Todo[] {
 switch(action.type){
  case 'add': return state.some(x=>x.id===action.item.id)?state:[...state,action.item];
  case 'toggle': return state.map(x=>x.id===action.id?{...x,done:!x.done}:x);
  case 'remove': return state.filter(x=>x.id!==action.id);
 }
}
```

**Why the repair works:** Model each state transition as an explicit typed action and return new state without mutating it.

</LessonStep>
