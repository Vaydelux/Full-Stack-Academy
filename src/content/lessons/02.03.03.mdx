## The problem we're solving

The lesson card stays bright white when the browser requests a dark color scheme, producing an inconsistent reading experience. We will repair a specific CSS behavior in an offline component so that a future design system has predictable boundaries. There is no external font, image or API dependency.

## Build the mental model

color-scheme informs the browser about supported schemes for native controls and browser-provided UI. light-dark() selects an appropriate color when the element supports both schemes, based on the user preference. A dark background must be paired with dark-mode foreground colors to preserve contrast.

**Predict before running:** A browser preferring dark mode renders a dark surface and light text; light mode does the reverse.

## Explore and verify

A syntactically valid color, selector or animation is not necessarily accessible or performant. Test color contrast for actual foreground/background pairs; preserve focus, reduced-motion behavior and narrow layouts. The Node fixture assertions check reviewed CSS patterns, and Chromium independently checks representative rendered behavior. Neither constitutes a full multi-device accessibility certification.
