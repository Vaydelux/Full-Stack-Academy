## The problem we're solving

A prototype writes a session token to localStorage and treats this as secure authentication. It also fails when storage is disabled. We will narrow storage to a harmless visual preference and provide a memory fallback, while explaining why server-managed session cookies have distinct security controls.

## Build the mental model

Web Storage is origin-scoped client-readable data. localStorage generally persists across sessions, while sessionStorage is bound to a tab's page session; both may be blocked or cleared. Neither has HttpOnly protection from page JavaScript. Cookies are sent according to domain/path and policy; Secure limits eligible transport, HttpOnly prevents JavaScript reads, and SameSite helps control cross-site sending. None of these properties makes XSS irrelevant. A server, not this offline fixture, must set real session-cookie policies.

**Predict before running:** A blocked localStorage setter should not crash the page; the page may retain a preference in memory for the current visit.

<LessonStep number={2} title={"Handle storage being unavailable"} file="labs/web-storage/starter/index.html" expected={"A storage-denied environment can still update the current UI."}>

Wrap storage access because privacy settings and file:// origins may throw.

```js
try {
  localStorage.setItem(key, theme);
} catch {
  memory.set(key, theme);
}
```

**Predict before running:** A storage-denied environment can still update the current UI.

**Why it works:** Storage APIs are not guaranteed writable in all execution contexts.

**Proof it works:** Use the two theme buttons and check the visible status.

</LessonStep>


<LessonStep number={3} title={"Separate client storage from server session policy"} file="labs/web-storage/starter/index.html" expected={"The example never creates a session or stores actual credentials."}>

Treat a cookie example as educational text, not a functional login.

```js
// Example HTTP response header set by a server (not JS):
// Set-Cookie: sid=<opaque>; Secure; HttpOnly; SameSite=Lax; Path=/
```

**Predict before running:** The example never creates a session or stores actual credentials.

**Why it works:** HttpOnly cookies cannot be created with the HttpOnly flag through document.cookie.

**Proof it works:** Explain why document.cookie cannot verify whether a cookie is HttpOnly.

</LessonStep>
