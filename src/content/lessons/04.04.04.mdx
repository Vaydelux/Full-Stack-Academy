## The problem we're solving

A library publishes its internal configuration files as if they were stable public imports. This is a local repository/package-development lesson. A passing fixture alone is not a published npm release and does not create a Vercel deployment.

## Build the mental model

An explicit package exports map establishes supported entry points, constrains consumer deep imports, and may supply separate import/require and type paths. Treat private files as internal even when they exist on disk; build artifacts must match each declared export before release.

**Predict before running:** Only an intentional package export subpath resolves; internal files remain unavailable to consumers.

## Explore and verify

Modules and public declaration files are build artifacts; configured npm publication, signed provenance and integration tests are separate engineering gates. Do not treat a local manifest as deployable until the paths have real output.
