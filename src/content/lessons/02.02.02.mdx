## The problem we're solving

A desktop two-column sidebar layout spills outside a phone because its track widths are fixed in pixels. The goal is a predictable local repair, not a decorative mockup. The HTML fixture is fully offline and has an intentionally failing starter plus an instructor solution.

## Build the mental model

Grid defines two-dimensional row and column tracks, while grid-template-areas connects semantic regions to explicit placements. minmax(0, 1fr) allows long content to shrink within the track. Name areas and switch to a single track when content no longer fits.

**Predict before running:** The phone uses one track; desktop uses two fluid tracks without horizontal overflow.

## Guided implementation

<LessonStep number={1} title="Reproduce the actual defect" file="labs/css-grid-areas/starter/index.html" expected={"A 900px minimum grid layout stays too wide for a phone."}>

Use the original CSS from the starter. Resist the temptation to add `!important` until you know which computed property is causing the failure.

```css
.demo { display: grid; grid-template-columns: 600px 300px; grid-template-areas: "content sidebar"; gap: 1rem; } .content { grid-area: content; } .sidebar { grid-area: sidebar; }
```

**Predict before running:** A 900px minimum grid layout stays too wide for a phone.

**Why it fails:** Grid defines two-dimensional row and column tracks, while grid-template-areas connects semantic regions to explicit placements. minmax(0, 1fr) allows long content to shrink within the track. Name areas and switch to a single track when content no longer fits.

**Proof:** Inspect the computed gridTemplateColumns at 320px and 1100px and confirm each grid area placement. Record the value in the starter before moving on.

</LessonStep>

<LessonStep number={2} title="Repair the rule, not the screenshot" file="labs/css-grid-areas/starter/index.html" expected={"The phone uses one track; desktop uses two fluid tracks without horizontal overflow."}>

Replace the defective declaration with this rule from the instructor implementation. Do not change the semantic markup or hide overflow simply to mask a layout defect.

```css
.demo { display: grid; grid-template-columns: minmax(0, 2fr) minmax(0, 1fr); grid-template-areas: "content sidebar"; gap: 1rem; } .content { grid-area: content; min-inline-size: 0; } .sidebar { grid-area: sidebar; min-inline-size: 0; } @media (max-width: 38rem) { .demo { grid-template-columns: minmax(0, 1fr); grid-template-areas: "content" "sidebar"; } }
```

**Predict before running:** The phone uses one track; desktop uses two fluid tracks without horizontal overflow.

**Why it works:** Grid defines two-dimensional row and column tracks, while grid-template-areas connects semantic regions to explicit placements. minmax(0, 1fr) allows long content to shrink within the track. Name areas and switch to a single track when content no longer fits.

**Proof:** Compare the properties and geometry with `labs/css-grid-areas/solution/index.html`, using DevTools, not merely text-searching the CSS source.

</LessonStep>

<LessonStep number={3} title="Measure and regression-check the behavior" file="labs/css-grid-areas/starter/index.html" expected="Narrow and wide states remain usable, with no unexpected horizontal overflow.">

Open Responsive Design Mode at 320px and 1100px. For applicable lessons, scroll, inspect an accessible scrolling region or constrain the query container while keeping the viewport fixed.

```js
const root = document.documentElement;
const surface = document.querySelector('#demo');
console.log({
  fitsViewport: root.scrollWidth <= innerWidth,
  display: getComputedStyle(surface).display,
  inlineSize: surface.getBoundingClientRect().width
});
```

**Predict before running:** A specific layout value changes as expected, and the repaired surface stays within its available width.

**Why it works:** Browser computed styles and bounding boxes reflect selector matching, layout algorithm and containing-block constraints.

**Proof:** Inspect the computed gridTemplateColumns at 320px and 1100px and confirm each grid area placement.

</LessonStep>
