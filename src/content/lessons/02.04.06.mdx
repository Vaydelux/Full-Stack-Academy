## The problem we're solving

A desktop-sized card clips on mobile and a button has no visible keyboard focus, but the developer only reviewed screenshots. A code review should require a reproducible symptom and realistic verification, not only a polished image. The local fixture is synthetic, deterministic and offline.

## Build the mental model

DevTools Styles and Computed panels explain which declarations win; the Layout panel reveals sizing and scroll containment; the Performance panel can identify layout and paint work. Debug the measurable symptom first, then rerun narrow width, zoom and keyboard focus states. Source linting alone cannot prove rendered behavior.

**Predict before running:** The panel fits a 320px viewport, the synthetic long token wraps and keyboard focus has an outline.

## Prerequisites and preflight

Continue from [the previous canonical CSS lesson](/learn/02.04.05). Open `labs/css-devtools-audit/starter/index.html` in Chromium; use DevTools Styles, Computed and Performance where needed. Node.js 24 runs the local fixture tests. No cloud build, server credentials or external data is needed.

<LessonStep number={3} title="Regress across device and preference states" file="labs/css-devtools-audit/starter/index.html" expected="The corrected component is readable at phone size, keyboard accessible and respects relevant motion/theme preferences.">

Check 320px and wide viewport geometry; keyboard Tab and focus; RTL if a logical property is used; reduced motion and dark preference when relevant. For browser performance, collect a trace with sufficient repeatability rather than inventing a timing.

```js
const root = document.documentElement;
const demo = document.querySelector('#demo');
console.log({ withinViewport: root.scrollWidth <= innerWidth, currentColor: getComputedStyle(demo).color, inlineSize: demo.getBoundingClientRect().width });
```

**Predict before running:** The repaired state is observable without forcing horizontal scroll, and the required preference-dependent declarations take effect.

**Why it matters:** A renderer's behavior depends on actual geometry, animations and preferences, not an offline syntax scan.

**Proof:** Inspect scrollWidth versus innerWidth, computed overflowWrap, and outlineStyle in keyboard focus mode.

</LessonStep>

## Explore and verify

Use DevTools to inspect computed styles and the Performance recording when making speed claims. Not every transform is composited; not every font loading strategy removes CLS; not every visually distinct control is accessible. The Node tests check instructor patterns; the isolated browser suite observes representative states. Manual assistive-technology and cross-browser checks remain outside the automated guarantee.
