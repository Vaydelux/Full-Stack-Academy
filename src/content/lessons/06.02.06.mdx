## The problem we're solving

A composer input and live preview must always display the same text as the user edits. Separate local copies of a text field and preview can drift when only one child receives updates. The following exercise is React 19 and TypeScript 5 source checked into this repository, not a remote code runner.

## Build the mental model

Keep one authoritative state value in the closest common parent and pass it to controlled siblings. In the nearest common ancestor that coordinates both consumers. **Important boundary:** A pure-function test validates state transitions and static React rendering checks initial markup; neither alone simulates an interactive browser or verifies hydration and effect behavior.

**Predict before you run:** Initial input and preview agree, and the parent owns the update callback.

```tsx
import {useState} from 'react';
export function TextComposer({initial=''}:{initial?:string}) {
 const [text,setText]=useState(initial);
 return <section><label htmlFor="composer">Message</label>
  <input id="composer" value={text} onChange={e=>setText(e.target.value)}/>
  <output aria-label="Preview">{text||'Empty message'}</output></section>;
}
```

**Why the repair works:** Keep one authoritative state value in the closest common parent and pass it to controlled siblings.
