## The problem we're solving

A card with left padding and a left border looks wrong when displayed right-to-left. Our task is to repair the actual style behavior, not just make a static screenshot look convincing. This workshop uses synthetic content in a standalone offline HTML file; it needs no account, cloud API or deployed preview.

## Build the mental model

Logical properties describe block and inline flow relative to writing direction. padding-inline-start and border-inline-start follow the start edge for the current writing mode. dir controls bidirectional text layout but does not itself flip every CSS physical property.

**Predict before running:** The visual accent starts on the right in rtl and moves left in ltr.

## Guided implementation

<LessonStep number={1} title="Reproduce and inspect the failing state" file="labs/css-logical/starter/index.html" expected="A physical border-left stays on the left in RTL.">

Start from the intentionally incorrect declaration and inspect the matched and computed styles. Before making changes, determine which element owns the value and whether a CSS rule is matched but overridden.

```css
.card { padding-left: 1.5rem; border-left: 5px solid #075e7b; }
```

**Predict before running:** A physical border-left stays on the left in RTL.

**Why it fails:** Logical properties describe block and inline flow relative to writing direction. padding-inline-start and border-inline-start follow the start edge for the current writing mode. dir controls bidirectional text layout but does not itself flip every CSS physical property.

**Proof:** Open DevTools, select the target element, and confirm the failing computed property. Write the observed value before replacing the rule.

</LessonStep>

<LessonStep number={2} title="Apply the targeted CSS repair" file="labs/css-logical/starter/index.html" expected="The visual accent starts on the right in rtl and moves left in ltr.">

Replace the incorrect rule with the following CSS. Keep the native HTML controls and all semantic content unchanged.

```css
.card { padding-inline-start: 1.5rem; border-inline-start: 5px solid #075e7b; }
```

**Predict before running:** The visual accent starts on the right in rtl and moves left in ltr.

**Why it works:** Logical properties describe block and inline flow relative to writing direction. padding-inline-start and border-inline-start follow the start edge for the current writing mode. dir controls bidirectional text layout but does not itself flip every CSS physical property.

**Proof:** Check getComputedStyle borderRightWidth and borderLeftWidth before and after toggling direction.

</LessonStep>

<LessonStep number={3} title="Verify responsiveness and interaction" file="labs/css-logical/starter/index.html" expected="The repaired solution works at narrow and wide viewports without hiding keyboard focus or producing horizontal overflow.">

Use DevTools Responsive Design Mode: select a 320px width, then a wide desktop width. Inspect the relevant computed style again. Where the lab includes a button or writing-direction toggle, test it using Tab and Enter.

```js
const target = document.querySelector('.card');
console.log(getComputedStyle(target).boxSizing);
console.log(document.documentElement.scrollWidth <= innerWidth);
```

**Predict before running:** A visible computed property changes as described, but the document remains scrollable normally with no unwanted horizontal overflow.

**Why it works:** Browser-computed styles and measured dimensions describe actual rendered rules, rather than assuming the presence of source text is enough.

**Proof:** Compare the computed result with the instructor solution and record one failing case from the original starter.

</LessonStep>
