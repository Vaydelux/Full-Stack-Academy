## The problem we're solving

An inventory command treats a remove operation as an addition because its implementation ignores the discriminant. This advanced-types lab requires both compile-time evidence and meaningful runtime behavior; TypeScript's erased types alone cannot fix logic bugs.

## Build the mental model

A discriminated union uses a shared literal field to select a known variant. A switch narrows fields per case, and a never fallback makes missing variants apparent at compile time. External inputs still need validation before casting them as a domain command.

**Predict before running:** Remove commands decrease stock while invalid underflows raise explicit errors.

<LessonStep number={2} title="Implement the correct type/runtime relationship" file="labs/ts-discriminated/starter/solution.ts" expected={"Remove commands decrease stock while invalid underflows raise explicit errors."}>

Preserve exported `solve` and tighten the behavior without adding an unsound `as any` cast.

```ts
export type Command={kind:'add';amount:number}|{kind:'remove';amount:number};export function solve(stock:number,command:Command):number{if(!Number.isFinite(stock)||!Number.isFinite(command.amount)||command.amount<0)throw new TypeError('Invalid stock command');switch(command.kind){case 'add':return stock+command.amount;case 'remove':if(stock<command.amount)throw new RangeError('Insufficient stock');return stock-command.amount;default:{const exhaustive:never=command;return exhaustive;}}}
```

**Predict before running:** Remove commands decrease stock while invalid underflows raise explicit errors.

**Why the fix works:** A discriminated union uses a shared literal field to select a known variant. A switch narrows fields per case, and a never fallback makes missing variants apparent at compile time. External inputs still need validation before casting them as a domain command.

**Proof:** The same Node test now passes; the separate compiler-negative test rejects invalid static usage.

</LessonStep>
