## The problem we're solving

A single-page tool has 50 generic divs and updates a progress label silently. Someone using landmarks cannot reach the main task quickly, and completion feedback is not announced.

## Build the mental model

The browser accessibility tree exposes roles, names and states inferred from native HTML and ARIA. Prefer elements such as header, nav, main, aside and footer for landmarks. Use one central main region and meaningful heading order. A polite live region announces a non-urgent update; role=alert is intended for important errors that require immediate attention, not routine news. Accessible output varies by browser and screen reader, and an automated role locator cannot certify all announcements. Inspect the accessibility tree and perform actual assistive-technology testing when possible.

**Predict before running:** Adding role=alert to every message makes the page noisy, not necessarily more accessible. Routine updates should often use role=status.

## Prerequisites

Complete [the previous lesson](/learn/01.03.02). Work in a trusted local checkout with Node.js 24 and Chromium. Browser role and focus tests are valuable but are not substitutes for actual screen-reader use or formal accessibility conformance testing.

<LessonStep number={1} title={"Give the page native navigable regions"} file="labs/a11y-semantics/starter/index.html" expected={"Landmark navigation can discover navigation, main and footer without custom roles."}>

Use semantic landmarks and a named nav instead of generic divs.

```html
<header><p>Workshop resources</p></header>
<nav aria-label="Resource navigation"><a href="#main-content">Read the guide</a></nav>
<main id="main-content"><h1>Workshop resources</h1></main>
<footer><p>Learning resources only.</p></footer>
```

</LessonStep>

<LessonStep number={2} title={"Expose a stable heading hierarchy"} file="labs/a11y-semantics/starter/index.html" expected={"The page has a coherent heading hierarchy for navigation."}>

Use h2 inside a section and h3 for nested material; avoid choosing levels solely for visual size.

```html
<section aria-labelledby="guide-title">
  <h2 id="guide-title">Getting started</h2>
  <p>Read the overview before beginning.</p>
</section>
```

</LessonStep>

<LessonStep number={3} title={"Announce local state politely"} file="labs/a11y-semantics/starter/index.html" expected={"Status content changes without moving focus or claiming persistent storage."}>

Put routine feedback in a status region, and update its text after a native button is activated.

```js
<p id="progress" role="status" aria-live="polite">No section marked reviewed.</p>
<button type="button" id="review">Mark guide reviewed</button>
<script>document.querySelector('#review').addEventListener('click',()=>{
  document.querySelector('#progress').textContent='Guide reviewed locally. Nothing saved.';
});</script>
```

</LessonStep>

## Bug Hunt: reproduce and fix a real accessibility defect

A routine 'progress complete' banner is assigned role=alert and steals attention repeatedly. Use role=status and keep the focused control stable.
