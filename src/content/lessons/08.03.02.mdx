## The problem we're solving

The starter paginates first, then filters, so matching rows can disappear from the wrong page. Enterprise interfaces need correct data scope, stable identities, accessible states and predictable behavior under pagination, refresh and mobile layouts.

## Build the mental model

Apply filtering and sorting to a consistent dataset before pagination, or delegate all three operations coherently to a server.

**Prediction:** Filtering occurs before stable sorting and pagination; page zero contains matching results.

**Scope of evidence:** The instructor's local Node tests exercise a pure data transformation. TanStack Table v8 and TanStack Virtual require separate dependency installation and mounted browser tests. Never treat sorting the current server page as global sorting, or browser-side role checks as server authorization.

```tsx
export function selectPage(rows:readonly string[],term:string,page:number,size:number){if(!Number.isInteger(page)||page<0||!Number.isInteger(size)||size<1)throw new RangeError('Invalid page');const q=term.toLowerCase();return rows.filter(x=>x.toLowerCase().includes(q)).sort((a,b)=>a.localeCompare(b)).slice(page*size,(page+1)*size);}
```

**Why this works:** Apply filtering and sorting to a consistent dataset before pagination, or delegate all three operations coherently to a server.

</LessonStep>
