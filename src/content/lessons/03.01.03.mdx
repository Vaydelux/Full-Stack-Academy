## The problem we're solving

A permission check treats the string 'false' as enabled because any nonempty string is truthy. This workshop uses independent local modules and synthetic data; the code can be run with Node.js 24 without an account, network request, credential, or Vercel build.

## Build the mental model

Truthy conversion and equality are different operations. === compares without coercion; Boolean('false') is true because the string has content. At a permission boundary accept only the literal boolean true, never loosely treat user input as authorization.

**Predict before running:** Only the boolean literal true grants access; strings, numbers and false do not.
