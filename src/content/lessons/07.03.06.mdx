## The problem we're solving

A documentation homepage changes weekly, while an account profile is different for every signed-in user. They need different rendering and freshness strategies.

**Failure mode:** The starter chooses static rendering for every page, including authenticated profiles.

## Build the mental model

Choose static/precomputed pages for stable public content, revalidated cached public content for changing shared data, and dynamic request-specific rendering for private data. This module specifically uses **Next.js 16 with `cacheComponents: true`**; avoid mixing with the legacy `dynamic`, route-segment `revalidate` or `fetchCache` configuration model. The offline assertions are data/decision models; they do not access Next's actual cache internals, HTTP, or database.

**Expected behavior:** Stable marketing = static; edited public articles = revalidated cache; personal profile = dynamic.

```tsx
export type PageKind='marketing'|'news'|'profile';
export function renderingStrategy(kind:PageKind){
 if(kind==='marketing')return 'static';
 if(kind==='news')return 'revalidated-public';
 return 'request-dynamic';
}
```
