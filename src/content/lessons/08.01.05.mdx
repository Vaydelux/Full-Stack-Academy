## The problem we're solving

Applying both px-2 and px-4 to a button creates a conflicting spacing contract that can change when classes are composed in different orders.

## Build the mental model

Use explicit component variants and a conflict-aware merge utility such as tailwind-merge when integrating dynamic Tailwind classes. A naive string concatenation cannot resolve conflicting utility families; the local exercise narrowly models horizontal padding precedence.

**Predict first:** For the demonstrated px-* family, the later override replaces the earlier spacing class without discarding unrelated styles.

```ts
export function solve(base:string,override:string):string{const classes=base.split(/\s+/).filter(Boolean);const newer=override.split(/\s+/).filter(Boolean);return [...classes.filter(c=>!newer.some(n=>n.startsWith("px-")&&c.startsWith("px-"))),...newer].join(" ");}

```

**Proof:** Run `npm run lab:ui-variant-merging` and inspect the instructor test output.

</LessonStep>

## Production library pattern

```tsx
import {clsx,type ClassValue} from "clsx";
import {twMerge} from "tailwind-merge";
export function cn(...inputs:ClassValue[]){return twMerge(clsx(inputs));}
const button=cn("rounded px-2","px-4","focus-visible:ring-2");
```

Actual tailwind-merge and clsx behavior requires installing those packages. The narrow local pure function is deliberately not advertised as a full implementation.
