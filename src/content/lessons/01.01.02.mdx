## The problem we're solving

Search results show a meaningless page title, social shares display a generic label, and the mobile page shrinks unexpectedly. These can be independent document metadata problems rather than layout bugs.

## Build the mental model

The `head` includes character encoding, viewport settings, page title and metadata for user agents. The title is visible in the browser tab and often used by search results; a description is a hint, not a guarantee of a search snippet. The canonical link communicates a preferred URL when equivalent pages exist; only use an accurate URL for the actual deployed page. Open Graph properties are for social previews but services may ignore or cache them. `utf-8` should appear early. The metadata in this exercise uses `example.com` as a **placeholder** and must be replaced with a real canonical URL before publishing a production site.

**Predict before running:** Does setting `meta name=description` guarantee that a search engine uses your exact text in every result? No. Search engines may choose contextual snippets.

## Prerequisites

Complete [the previous lesson](/learn/01.01.01) or review its objectives. A browser, text editor, Node.js 24 and this repository are enough. These examples are intentionally standalone and avoid remote services, account credentials or arbitrary browser scripts.

<LessonStep number={1} title={"Declare encoding and mobile viewport"} file="labs/html-metadata/starter/index.html" expected={"The document has explicit UTF-8 decoding and a responsive layout viewport."}>

Start from a complete document and put both declarations in head before page content.

```html
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
```

</LessonStep>

<LessonStep number={2} title={"Add a meaningful title and summary"} file="labs/html-metadata/starter/index.html" expected={"The browser title identifies this page rather than the whole site generically."}>

Write a unique title and describe the page accurately; avoid repeating keywords without useful context.

```html
<title>Visitor guide | Community workshop</title>
<meta name="description" content="Find workshop hours, resources, and the steps for attending your first session.">
```

</LessonStep>

<LessonStep number={3} title={"Provide a canonical URL and social preview fields"} file="labs/html-metadata/starter/index.html" expected={"The canonical uses an absolute HTTPS URL and the social title matches the document title."}>

Use an illustrative HTTPS URL and matching social title; in a real app compute the exact public URL at build time.

```html
<link rel="canonical" href="https://example.com/workshop/visitor-guide">
<meta property="og:type" content="article">
<meta property="og:title" content="Visitor guide | Community workshop">
<meta property="og:description" content="Hours, resources, and first-session guidance.">
```

</LessonStep>

## Bug Hunt: diagnose before changing markup

A canonical link points at `http://localhost:3000` in a public build. This can confuse indexing and sharing. Replace the placeholder with the exact public HTTPS URL and test the emitted metadata on production.
