## The problem we're solving

An academy shell must keep navigation stable while page content changes, and a separately keyed template can reset a transition animation.

**Failure:** The starter drops page children and renders the shell alone.

## Build the mental model

Layouts preserve shared UI and local state between sibling navigations; templates create a fresh instance when a matching segment changes.

**Prediction:** A semantic layout encloses both shared navigation and the requested page body.

**Proof boundary:** The local Node/TSX fixture verifies this lesson's deterministic model and initial React markup. It does **not** start Next.js, compile route conventions, simulate streaming, or prove HTTP status codes. A separately built Next application and browser/HTTP test are needed before release qualification.

**Real App Router shape:**

```tsx
// app/layout.tsx: shared root shell
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="en"><body><header>Academy</header>{children}</body></html>;
}
// app/(learning)/template.tsx: optional, remounts on segment navigation
export default function Template({ children }: { children: React.ReactNode }) {
  return <section>{children}</section>;
}
```

**Nuance:** Only the root layout should own html/body in this simplified application. A template does not automatically make all data refresh; it changes component remount behavior, not the persistence model.

</LessonStep>
