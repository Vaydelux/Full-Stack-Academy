## The problem we're solving

An editorial page needs a cache tag so a published update can invalidate the correct course without evicting unrelated content.

**Failure mode:** The starter produces the same global tag for every course, causing unrelated pages to invalidate together.

## Build the mental model

Use deterministic, bounded, public-data cache tags and a cacheLife policy inside a `use cache` scope. This module specifically uses **Next.js 16 with `cacheComponents: true`**; avoid mixing with the legacy `dynamic`, route-segment `revalidate` or `fetchCache` configuration model. The offline assertions are data/decision models; they do not access Next's actual cache internals, HTTP, or database.

**Expected behavior:** Different course IDs produce distinct namespaced cache tags; malformed identifiers are rejected.
