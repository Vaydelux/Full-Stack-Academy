## The problem we're solving

A publication editor updates an article. The model must ensure that only the author can publish a new revision and that the correct invalidation mode is selected.

**Failure mode:** The starter allows nonowners to publish and does not increment the version.

## Build the mental model

Authorize the exact record, validate the new title, persist the revision, then invalidate the relevant public cache tag using the appropriate semantics. This module specifically uses **Next.js 16 with `cacheComponents: true`**; avoid mixing with the legacy `dynamic`, route-segment `revalidate` or `fetchCache` configuration model. The offline assertions are data/decision models; they do not access Next's actual cache internals, HTTP, or database.

**Expected behavior:** Only the owner can publish valid content; versions increment without mutating past snapshots.

export type Post={id:string;ownerId:string;title:string;revision:number};
export function publishPost(post:Post,actor:string,title:string):Post|null{
 if(post.ownerId!==actor||!title.trim()||title.trim().length>120)return null;
 return {...post,title:title.trim(),revision:post.revision+1};
}
