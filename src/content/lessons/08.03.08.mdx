## The problem we're solving

The starter allows any viewer to approve any record, ignoring the role and current status. Enterprise interfaces need correct data scope, stable identities, accessible states and predictable behavior under pagination, refresh and mobile layouts.

## Build the mental model

Coordinate a role-aware operational table with stable row IDs, action authorization and clear status feedback.

**Prediction:** Only a reviewer can approve a pending record; prior state is preserved for unauthorized actions.

**Scope of evidence:** The instructor's local Node tests exercise a pure data transformation. TanStack Table v8 and TanStack Virtual require separate dependency installation and mounted browser tests. Never treat sorting the current server page as global sorting, or browser-side role checks as server authorization.

<LessonStep number={2} title="Repair the typed data contract" file="labs/ui-operational-console/starter/solution.tsx" expected="Only a reviewer can approve a pending record; prior state is preserved for unauthorized actions.">

```tsx
export type Role='viewer'|'reviewer';export type Item={id:string;status:'pending'|'approved'};export function approve(role:Role,item:Item){if(role!=='reviewer'||item.status!=='pending')return null;return {...item,status:'approved'};}
```

**Why this works:** Coordinate a role-aware operational table with stable row IDs, action authorization and clear status feedback.

</LessonStep>
