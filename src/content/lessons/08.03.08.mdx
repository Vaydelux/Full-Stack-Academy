## The problem we're solving

An operations dashboard shows cross-tenant records, duplicate row IDs and an empty state that silently hides active filters.

## Build the mental model

A professional operations console needs tenant-scoped server authorization, stable row IDs, explicit query/filter/sort/page state, accessible status announcements and a resilient responsive layout. Client filtering alone does not enforce tenant boundaries.

**Predict first:** Only records for the authorized tenant remain in the projected view and duplicate public IDs are rejected.

<LessonStep number={2} title="Fix the policy and verify edge cases" file="labs/ui-ops-console/starter/solution.ts" expected="Only records for the authorized tenant remain in the projected view and duplicate public IDs are rejected.">

```ts

export type RecordRow={id:string;tenant:string;title:string};export function solve(rows:readonly RecordRow[],tenant:string):RecordRow[]{if(!tenant.trim())throw new TypeError("Tenant required");const allowed=rows.filter(r=>r.tenant===tenant);if(new Set(allowed.map(x=>x.id)).size!==allowed.length)throw new TypeError("Duplicate row IDs");return allowed.map(x=>({id:x.id,tenant:x.tenant,title:x.title}));}

```

**Why it works:** A professional operations console needs tenant-scoped server authorization, stable row IDs, explicit query/filter/sort/page state, accessible status announcements and a resilient responsive layout. Client filtering alone does not enforce tenant boundaries.

**Proof:** Run `npm run lab:ui-ops-console` and inspect the instructor test output.

</LessonStep>
