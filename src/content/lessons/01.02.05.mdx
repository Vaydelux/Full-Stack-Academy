## The problem we're solving

A form appears to accept only images using the accept attribute. Someone assumes this restriction is secure and sends unverified file bytes to a backend. The accept attribute is a selection hint, not a trust boundary.

## Build the mental model

The file input exposes a FileList after the user selects files. The `accept` attribute helps filter the chooser but does not enforce a security rule; MIME metadata and filenames can be spoofed. Client checks for size and type improve user experience but do not replace independent server-side content validation, malware screening, storage authorization and quotas. A real upload requires a POST endpoint and typically multipart/form-data. This offline lesson intentionally performs **no upload** and does not read file contents; it reports local selection metadata only.

**Predict before running:** If a file picker says accept=image/png, can a malicious client still submit a file with another type? Yes. Validate again on the trusted server.

<LessonStep number={1} title={"Declare explicit file selection guidance"} file="labs/forms-files/starter/index.html" expected={"The native file chooser gives format hints and an explicit accessible description."}>

Attach a visible label, a hint ID and an accept list to the file input.

```html
<label for="attachment">Choose an example attachment</label>
<p id="file-hint">PNG, JPEG or PDF; up to 1 MB. Nothing will be uploaded.</p>
<input id="attachment" name="attachment" type="file" accept=".png,.jpg,.jpeg,.pdf,image/png,image/jpeg,application/pdf" aria-describedby="file-hint" required>
```

</LessonStep>

<LessonStep number={2} title={"Validate selection metadata locally"} file="labs/forms-files/starter/index.html" expected={"An unsupported or too-large file is rejected by the local preview without reading its contents."}>

Use the browser File object; do not trust its reported type as proof of safe server content.

```js
const file=document.querySelector('#attachment').files[0];
const allowed=new Set(['image/png','image/jpeg','application/pdf']);
if(file && allowed.has(file.type) && file.size <= 1_000_000){
  console.log('File passes local hints, but has not been uploaded.');
}
```

</LessonStep>

<LessonStep number={3} title={"Keep the demonstration intentionally offline"} file="labs/forms-files/starter/index.html" expected={"The browser does not navigate or attempt an upload, even for a valid local selection."}>

Intercept submission to avoid an unintended network request; display an accurate local status.

```js
form.addEventListener('submit',event=>{
  event.preventDefault();
  // Recheck the currently selected File and display only its filename and size.
});
// A real service must validate file content and authorization server-side.
```

</LessonStep>

## Bug Hunt: diagnose and repair the behavior

A developer checks only the extension and uploads the file to public storage. Add server-side type and content validation, size limits, access checks and safe storage names before any real upload.
