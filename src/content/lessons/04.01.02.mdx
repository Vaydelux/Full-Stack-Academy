## The problem we're solving

A numeric quantity parses only its integer prefix and silently truncates decimal inputs. The checked-in examples are TypeScript 5 modules targeting the repository's strict compiler settings. Node 24 plus the installed tsx runner execute the instructor tests without a remote environment.

## Build the mental model

Type inference derives a static type from expressions; annotations describe intended contracts but do not fix incorrect arithmetic. Use Number and Number.isFinite for numeric input and avoid parseInt when fractional quantities are permitted.

**Predict before running:** Decimal input remains decimal and invalid strings produce explicit errors.

<LessonStep number={2} title="Implement the typed repair" file="labs/ts-inference/starter/solution.ts" expected={"Decimal input remains decimal and invalid strings produce explicit errors."}>

Preserve exported `solve`; narrow unknown inputs and maintain the intended inferred/annotated return contract.

```ts
export function solve(raw:string):number{if(typeof raw!=='string'||raw.trim()==='')throw new TypeError('A numeric string is required');const value=Number(raw.trim());if(!Number.isFinite(value))throw new TypeError('Finite number required');return value;}
```

**Predict before running:** Decimal input remains decimal and invalid strings produce explicit errors.

**Why it works:** Type inference derives a static type from expressions; annotations describe intended contracts but do not fix incorrect arithmetic. Use Number and Number.isFinite for numeric input and avoid parseInt when fractional quantities are permitted.

**Proof:** Compare the repaired student's output with the instructor solution under the same typed test cases.

</LessonStep>

<LessonStep number={3} title="Exercise runtime and compiler contracts" file="labs/ts-inference/solution.test.mjs" expected="The reviewed solution has a passing strict TypeScript compile and actual regression assertions.">

```ts
assert.equal(solve('2.5'),2.5);assert.equal(solve('0'),0);assert.throws(()=>solve('oops'),TypeError);assert.throws(()=>solve(''),TypeError);
```

**Predict before running:** Correct runtime behavior and a valid static type signature are separate, both required.

**Why it matters:** TypeScript cannot block malformed JSON after the source has been compiled; user input still needs runtime guards.

**Proof:** Run `npm run lab:ts-inference` then `npm run typecheck`.
