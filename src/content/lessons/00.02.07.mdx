## The problem we're solving

Git commits show the wrong author, but changing user.email does not fix push authentication. Commit metadata and access to a remote are distinct. A repository can contain valid commits even when it has no remote at all.

## Build the mental model

Git stores your commit author name and email as metadata; these do not grant access to GitHub. SSH authentication uses a private key kept on your machine and a public key registered with a service. Protect the private key with a passphrase and never paste it into a chat or repository. Verify the service's published host-key fingerprint before accepting a first-time host prompt. HTTPS with a credential manager is also valid; SSH is optional. Git config can be system, global, or repository-local. This exercise uses local settings in a temporary repo and does not modify global configuration or send data to a remote.

<LessonStep number={3} title={"Understand SSH without modifying credentials"} file="labs/git-ssh-setup/starter/.gitignore" expected={"You can identify the public key file and describe host-key verification."}>

If you choose to configure your own GitHub access, follow the official GitHub guide. Check for existing keys before creating one. Choose a new unused path if you need another key, use a passphrase, and upload only the .pub file. The following commands show the workflow; do not overwrite an existing key. Compare GitHub's published host fingerprint before accepting a prompt. This is optional manual practice, not required for automated tests.

```bash
# Example only: use a new path, not an existing key:
ssh-keygen -t ed25519 -C "your-email@example.com" -f "$HOME/.ssh/academy_ed25519"
# Register only academy_ed25519.pub with your account.
# After configuring your SSH agent, test:
ssh -T git@github.com
```

</LessonStep>

## Explore it yourself

Use git config --show-origin --get user.email to see where the effective value comes from. Use git remote -v to inspect URLs; the lab needs no remote. On Windows, Git for Windows and WSL can have different SSH clients and config files. Follow the GitHub guide for your chosen environment. Never disable StrictHostKeyChecking to make a connection work.

<Misconception claim={"Setting Git user.name or email signs me into GitHub."} correction={"Commit identity is metadata. Remote authentication requires a valid credential such as SSH or a credential manager."} />

## Bug Hunt: diagnose before you change code

A developer mistakenly stages .env.local. If it has not been committed, unstage it and add ignore rules. If a real secret has been committed, rotate it first; removing the file alone does not remove the secret from history.
