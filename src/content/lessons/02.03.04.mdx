## The problem we're solving

A button's hover animation lasts several seconds and ignores a user's reduced-motion preference. We will repair a specific CSS behavior in an offline component so that a future design system has predictable boundaries. There is no external font, image or API dependency.

## Build the mental model

A CSS transition interpolates a property between states; a keyframe animation defines a time sequence. Prefer specific properties over transition: all, and limit effects to those that support comprehension. prefers-reduced-motion lets you remove or simplify nonessential animation for motion-sensitive readers.

**Predict before running:** Normal-motion pointer hover uses a short transform transition; reduced motion removes the transition entirely.

Replace only the defective style block with this instructor implementation. Preserve native labels, buttons and focus order. Do not use blanket `!important` overrides to hide a state problem.

```css
.demo-button { transition: transform 160ms ease-out; } .demo-button:hover { transform: translateY(-2px); } @media (prefers-reduced-motion: reduce) { .demo-button { transition: none; animation: none; } }
```

</LessonStep>

## Explore and verify

A syntactically valid color, selector or animation is not necessarily accessible or performant. Test color contrast for actual foreground/background pairs; preserve focus, reduced-motion behavior and narrow layouts. The Node fixture assertions check reviewed CSS patterns, and Chromium independently checks representative rendered behavior. Neither constitutes a full multi-device accessibility certification.
