## The problem we're solving

A public blog should refresh stale-while-revalidate after a content edit, but a writer who just saved a change needs read-your-writes behavior.

**Failure mode:** The starter routes all mutations through the same background stale-while-revalidate policy, even when immediate visibility is required.

## Build the mental model

Use revalidateTag(tag, 'max') for stale-while-revalidate and updateTag(tag) inside Server Actions for immediate read-your-writes semantics. This module specifically uses **Next.js 16 with `cacheComponents: true`**; avoid mixing with the legacy `dynamic`, route-segment `revalidate` or `fetchCache` configuration model. The offline assertions are data/decision models; they do not access Next's actual cache internals, HTTP, or database.

**Expected behavior:** Public scheduled freshness chooses revalidateTag; a confirmed author edit chooses updateTag.

**Framework example (illustrative; not executed here):**

```tsx
import {revalidateTag,updateTag} from 'next/cache';
// Content management or webhook context:

// Inside a Server Action after an authorized mutation:
updateTag('courses:react-19');
// updateTag is limited to Server Actions. Neither call replaces auth validation.
```

**Operational nuance:** The older single-argument revalidateTag invalidation form is deprecated for this mode. `updateTag` is not a general Route Handler API; use documented context-specific functions.
