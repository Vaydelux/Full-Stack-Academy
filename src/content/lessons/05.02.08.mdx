## The problem we're solving

A synthetic .env.local file was already committed; writing a new .gitignore rule falsely reassures the team that the past exposure has been removed. The lesson uses synthetic local data; passing its test does not configure actual branch protection or trigger a release.

## Build the mental model

Ignore patterns do not untrack already committed files or erase historical blobs. A local safe response stages removal from the index, preserves the ignored local file and documents remediation. If a real secret was exposed, revoke/rotate it immediately and coordinate history rewriting carefully because forks and clones may retain copies.

**Predict before running:** The synthetic local file remains on disk but is absent from the current index; old history still contains it.

```js
export function solve({git,write}){write('.gitignore','.env.local\n');git(['rm','--cached','.env.local']);git(['add','.gitignore']);git(['commit','--quiet','-m','security: stop tracking local environment file']);}
```
