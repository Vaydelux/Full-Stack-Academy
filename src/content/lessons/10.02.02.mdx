## The problem we're solving

A JSON-only endpoint returns a JSON response even when the client explicitly refuses it with Accept: application/json;q=0.

**Fault to find:** The starter assumes every Accept header permits JSON and ignores quality zero. This track uses Node 24 built-ins and fetch-compatible `Response` where appropriate; no paid platform or remote arbitrary-code execution is needed.

## Build the mental model

Parse Accept media ranges and q-values deliberately, honoring application/json, application/* and */* only when quality is nonzero.

**Expected repair:** Valid JSON/wildcard media ranges are allowed, while text/html-only or q=0 are rejected.

HTTP semantics follow RFC 9110. Public errors can use RFC 9457 Problem Details; do not invent return codes or copy internal stack traces into public responses. Pure helper tests are useful but the final capstone runs a real loopback server and tests wire responses.

<LessonStep number={2} title="Implement standards-based HTTP behavior" file="labs/http-accept-json/starter/solution.mjs" expected="Valid JSON/wildcard media ranges are allowed, while text/html-only or q=0 are rejected.">

```js
export function acceptsJson(accept='*/*'){
 const ranges=String(accept).split(',');
 return ranges.some(part=>{
  const [raw,...params]=part.trim().split(';');
  const media=raw.trim().toLowerCase();
  if(!['application/json','application/*','*/*'].includes(media))return false;
  const qPart=params.find(x=>x.trim().toLowerCase().startsWith('q='));
  if(!qPart)return true;
  const value=Number(qPart.split('=')[1]);
  return Number.isFinite(value)&&value>0&&value<=1;
 });
}
```

**Why this is correct:** Parse Accept media ranges and q-values deliberately, honoring application/json, application/* and */* only when quality is nonzero.

</LessonStep>
