## The problem we're solving

A feature is committed on a side branch but the main branch remains unchanged. This lesson is an offline, repeatable source-control exercise; it never touches the learner's actual project repository or opens a hosted pull request.

## Build the mental model

Branches are movable refs to commits. A merge incorporates reachable feature commits into the target branch; rebase replays commits onto a different base and rewrites commit identity. For shared branches prefer a reviewed merge over rewriting others' published history.

**Predict before running:** The target main branch contains feature.txt and records a merge commit.

<LessonStep number={2} title="Repair the Git workflow" file="labs/git-branch-merge/starter/solution.mjs" expected={"The target main branch contains feature.txt and records a merge commit."}>

Preserve the exported `solve` contract; call the local `git` helper with explicit argument arrays rather than issuing shell strings. The instructor workflow is:

```js
export function solve({git,write}){git(['switch','-c','feature/ui']);write('feature.txt','Ready\n');git(['add','feature.txt']);git(['commit','--quiet','-m','feat: add UI']);git(['switch','main']);git(['merge','--no-ff','--quiet','-m','merge: feature ui','feature/ui']);}
```

**Predict before running:** The target main branch contains feature.txt and records a merge commit.

**Why it works:** Branches are movable refs to commits. A merge incorporates reachable feature commits into the target branch; rebase replays commits onto a different base and rewrites commit identity. For shared branches prefer a reviewed merge over rewriting others' published history.

**Proof:** The same deterministic fixture should now satisfy the intended history, index and working-tree state.

</LessonStep>
