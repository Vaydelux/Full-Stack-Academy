## The problem we're solving

A dashboard chart shrinks unreadable axis labels to fit mobile, while the underlying values are inaccessible without pointer hover.

## Build the mental model

A chart should provide a semantic textual summary or data table, and resize without horizontal overflow. Normalize numeric inputs, avoid inventing missing values, and ensure focusable legends/tooltips are accessible to keyboard and screen-reader users.

**Predict first:** Valid nonnegative series normalize to values between zero and one; accessible summaries remain available independently of chart drawing.

```ts
export function solve(values:readonly number[]):number[]{if(values.some(v=>!Number.isFinite(v)||v<0))throw new TypeError("Invalid chart input");const max=Math.max(0,...values);return values.map(v=>max===0?0:v/max);}

```

**Why it works:** A chart should provide a semantic textual summary or data table, and resize without horizontal overflow. Normalize numeric inputs, avoid inventing missing values, and ensure focusable legends/tooltips are accessible to keyboard and screen-reader users.

**Proof:** Run `npm run lab:ui-responsive-charts` and inspect the instructor test output.

## Production library pattern

```tsx
import React from "react";
function AccessibleSeries(){return <section aria-labelledby="chart-title"><h2 id="chart-title">Revenue trend</h2><p>Revenue doubled from Jan to Feb.</p><table><caption>Values</caption><tbody><tr><th scope="row">Jan</th><td>10</td></tr><tr><th scope="row">Feb</th><td>20</td></tr></tbody></table></section>;}
```

An actual chart renderer and zoom/keyboard tests are additional gates. The local solver only validates normalization and server-rendered table semantics.
