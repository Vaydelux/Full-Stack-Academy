## The problem we're solving

Long-lived feature branches accumulate changes and merge conflicts while the team assumes the trunk is always releasable. The lesson uses synthetic local data; passing its test does not configure actual branch protection or trigger a release.

## Build the mental model

Trunk-based development integrates small, reviewable changes frequently into a protected mainline. Branch age and commit size are signals rather than universal hard limits. Our local policy flags stale branches but cannot replace branch protection, feature flags or peer review.

**Predict before running:** Only stale, conflicted or unreviewed branches are flagged for attention—not healthy short-lived changes.

<LessonStep number={2} title="Implement the explicit review or release contract" file="labs/team-trunk-policy/starter/solution.mjs" expected={"Only stale, conflicted or unreviewed branches are flagged for attention—not healthy short-lived changes."}>

Prefer an explicit result and a narrow, auditable policy; do not invent remote approvals or call an external API.

```js
export function solve(branches,{maxAgeDays=2}={}){if(!Array.isArray(branches)||!Number.isFinite(maxAgeDays)||maxAgeDays<0)throw new TypeError('Valid branch policy required');return branches.filter(b=>b.name!=='main'&&(!b.reviewed||b.ageDays>maxAgeDays||b.hasConflicts)).map(b=>({branch:b.name,reason:b.hasConflicts?'conflicts':!b.reviewed?'unreviewed':'stale'}));}
```

**Predict before running:** Only stale, conflicted or unreviewed branches are flagged for attention—not healthy short-lived changes.

**Why the repair works:** Trunk-based development integrates small, reviewable changes frequently into a protected mainline. Branch age and commit size are signals rather than universal hard limits. Our local policy flags stale branches but cannot replace branch protection, feature flags or peer review.

**Proof:** Run the same independent test after editing; a green result demonstrates this local policy only.

</LessonStep>

<LessonStep number={3} title="Test both positive and negative outcomes" file="labs/team-trunk-policy/solution.test.mjs" expected="Passes a precise expected-output contract and rejects a misleading or invalid case.">

```js
const branches=[{name:'main',ageDays:5,reviewed:true,hasConflicts:false},{name:'feature/old',ageDays:5,reviewed:true,hasConflicts:false},{name:'feature/new',ageDays:1,reviewed:true,hasConflicts:false},{name:'feature/conflict',ageDays:1,reviewed:true,hasConflicts:true},{name:'feature/unreviewed',ageDays:1,reviewed:false,hasConflicts:false}];assert.deepEqual(solve(branches),[{branch:'feature/old',reason:'stale'},{branch:'feature/conflict',reason:'conflicts'},{branch:'feature/unreviewed',reason:'unreviewed'}]);assert.deepEqual(solve([]),[]);
```

**Predict before running:** The corrected policy distinguishes reviewable, unreviewed and invalid inputs.

**Why it matters:** Branch protection, reviewer permissions, remote signatures and provenance are external guarantees; local policy simulation cannot establish them.

**Proof:** Run `npm run lab:team-trunk-policy` and inspect the failure messages when targeting the starter.

</LessonStep>
