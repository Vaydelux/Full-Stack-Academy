## The problem we're solving

A migrated stylesheet still relies on legacy v3 @tailwind directives, so the v4 build no longer follows the recommended CSS-first entrypoint.

## Build the mental model

Tailwind v4 uses a CSS-first setup with @import "tailwindcss". Keep custom tokens in CSS using @theme and use the framework's current PostCSS/Vite integration rather than assuming an old JavaScript config drives everything.

**Predict first:** The corrected stylesheet uses @import, and an explicit @theme token avoids legacy v3 directives.

## Production library pattern

```tsx
/* src/app/globals.css */
@import "tailwindcss";
@theme { --color-brand-500: oklch(0.61 0.15 225); }
/* Validate with Tailwind v4’s real build tool */
```

The code shown above is CSS, not TSX; the snippet is illustrative and not compiled by React SSR. Actual Tailwind CSS processing is a separate local build gate.
