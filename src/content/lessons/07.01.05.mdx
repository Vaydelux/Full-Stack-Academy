## The problem we're solving

A legacy guide path redirects to the new category, an unknown slug returns 404, and a valid guide renders a canonical page.

**Failure:** The starter redirects every unknown slug to the homepage, hiding actual missing content.

## Build the mental model

Separate missing resources from legitimate redirects: call notFound for absence, redirect for navigation policy, and render real records normally.

**Prediction:** Known guide loads, legacy guide redirects, and truly missing guide gets a not-found decision.

**Proof boundary:** The local Node/TSX fixture verifies this lesson's deterministic model and initial React markup. It does **not** start Next.js, compile route conventions, simulate streaming, or prove HTTP status codes. A separately built Next application and browser/HTTP test are needed before release qualification.

```tsx
export type RouteDecision={kind:'render';slug:string}|{kind:'redirect';to:string}|{kind:'notFound'};
export function decideGuide(slug:string):RouteDecision{
 if(slug==='react')return {kind:'render',slug};
 if(slug==='old-react')return {kind:'redirect',to:'/guides/react'};
 return {kind:'notFound'};
}
```

**Why it works:** Separate missing resources from legitimate redirects: call notFound for absence, redirect for navigation policy, and render real records normally.

**Real App Router shape:**

```tsx
// app/guides/[slug]/page.tsx
import { redirect, notFound } from 'next/navigation';
export default async function Page({ params }: { params: Promise<{slug:string}> }) {
  const { slug } = await params;
  if (slug === 'old-react') redirect('/guides/react');
  if (slug !== 'react') notFound();
  return <h1>React guide</h1>;
}
```

**Nuance:** Both helpers throw control-flow errors. Don't swallow them inside a catch-all try/catch. Never create redirects from unchecked user URLs (open redirects).

</LessonStep>
