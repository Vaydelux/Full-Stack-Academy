## The problem we're solving

A request body is trusted as a TypeScript interface, so a negative quantity is silently accepted. In a full-stack application, this boundary can lead to incorrect data or information disclosure even if the TypeScript project compiles successfully.

## Build the mental model

unknown is the correct starting type for untrusted input. Zod 4 schemas perform actual runtime checks and safeParse returns success/data or failure/error without throwing for expected invalid data. Strict schemas may also reject unrecognized keys when that is part of the contract.

**Predict before running:** Valid data becomes a typed record, while negative counts and extra fields fail the runtime schema.

<LessonStep number={2} title="Validate and map a trusted domain value" file="labs/ts-parse-unknown/starter/solution.ts" expected={"Valid data becomes a typed record, while negative counts and extra fields fail the runtime schema."}>

Use unknown at the boundary, a runtime predicate or strict schema and a public result type. Handle expected invalid data explicitly.

```ts
import {z} from 'zod';const ItemSchema=z.strictObject({id:z.string().min(1),qty:z.number().int().nonnegative()});export type Item=z.infer<typeof ItemSchema>;export function solve(raw:unknown):Item|null{const parsed=ItemSchema.safeParse(raw);return parsed.success?parsed.data:null;}
```

**Predict before running:** Valid data becomes a typed record, while negative counts and extra fields fail the runtime schema.

**Why the repair works:** unknown is the correct starting type for untrusted input. Zod 4 schemas perform actual runtime checks and safeParse returns success/data or failure/error without throwing for expected invalid data. Strict schemas may also reject unrecognized keys when that is part of the contract.

**Proof:** Compare clean and malformed cases against the verified instructor module.

</LessonStep>

## Explore and verify

Use boundary-oriented reasoning: the outer layer receives unknown, the parser enforces shape and units, and only then may a domain function use a trusted type. Separate validation from authorization; a successful schema parse never proves the actor has permission.
