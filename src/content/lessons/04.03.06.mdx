## The problem we're solving

A public API DTO with price in cents is used as a domain money value without checking integer units or currency. In a full-stack application, this boundary can lead to incorrect data or information disclosure even if the TypeScript project compiles successfully.

## Build the mental model

DTOs represent transport contracts, while domain types encode normalized business meaning. Validate the DTO and map only allowed fields into a stable domain model. Never trust a TypeScript interface to enforce positive amounts, permitted currency, or tenant authorization.

**Predict before running:** Cents are normalized into domain units only after integer and currency validation.

<LessonStep number={2} title="Validate and map a trusted domain value" file="labs/ts-dtos/starter/solution.ts" expected={"Cents are normalized into domain units only after integer and currency validation."}>

Use unknown at the boundary, a runtime predicate or strict schema and a public result type. Handle expected invalid data explicitly.

```ts
type DTO={id:string;priceCents:number;currency:'PHP'|'USD'};export type Domain=Readonly<{id:string;price:number;currency:DTO['currency']}>;export function solve(raw:unknown):Domain|null{if(!raw||typeof raw!=='object'||!('id' in raw)||typeof raw.id!=='string'||!raw.id||!('priceCents' in raw)||typeof raw.priceCents!=='number'||!Number.isSafeInteger(raw.priceCents)||raw.priceCents<0||!('currency' in raw)||(raw.currency!=='PHP'&&raw.currency!=='USD'))return null;return Object.freeze({id:raw.id,price:raw.priceCents/100,currency:raw.currency});}
```

**Predict before running:** Cents are normalized into domain units only after integer and currency validation.

**Why the repair works:** DTOs represent transport contracts, while domain types encode normalized business meaning. Validate the DTO and map only allowed fields into a stable domain model. Never trust a TypeScript interface to enforce positive amounts, permitted currency, or tenant authorization.

**Proof:** Compare clean and malformed cases against the verified instructor module.

</LessonStep>

## Explore and verify

Use boundary-oriented reasoning: the outer layer receives unknown, the parser enforces shape and units, and only then may a domain function use a trusted type. Separate validation from authorization; a successful schema parse never proves the actor has permission.
