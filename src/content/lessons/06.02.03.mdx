## The problem we're solving

A shopping cart updates its total as quantities change without risking a stale cached field. Storing the derived total separately creates two sources of truth that can disagree. The following exercise is React 19 and TypeScript 5 source checked into this repository, not a remote code runner.

## Build the mental model

Compute totals from the authoritative item list during render instead of synchronizing a second total state. A value that can be recomputed from current inputs should not drift out of sync with its source. **Important boundary:** A pure-function test validates state transitions and static React rendering checks initial markup; neither alone simulates an interactive browser or verifies hydration and effect behavior.

**Predict before you run:** The total follows item prices and quantities and rejects negative quantities.

```tsx
export type LineItem={id:string;price:number;quantity:number};
export function cartTotal(items:readonly LineItem[]) {
 if(items.some(x=>!Number.isFinite(x.price)||x.price<0||!Number.isSafeInteger(x.quantity)||x.quantity<0)) throw new RangeError('Invalid cart item');
 return items.reduce((sum,x)=>sum+x.price*x.quantity,0);
}
export function CartSummary({items}:{items:readonly LineItem[]}) {
 return <output aria-label="Cart total">{cartTotal(items).toFixed(2)}</output>;
}
```

**Why the repair works:** Compute totals from the authoritative item list during render instead of synchronizing a second total state.

</LessonStep>
