## The problem we're solving

A response helper exposes secret internal fields by spreading a full user object into a public API result. This advanced-types lab requires both compile-time evidence and meaningful runtime behavior; TypeScript's erased types alone cannot fix logic bugs.

## Build the mental model

Pick, Omit, Partial, Required and Readonly transform compile-time shapes; they do not strip runtime properties automatically. Construct an explicit public projection instead of returning raw objects with a type assertion.

**Predict before running:** The returned object contains only explicitly public fields, even at runtime.

Preserve exported `solve` and tighten the behavior without adding an unsound `as any` cast.

```ts
type User={id:string;name:string;secret:string};export type Public=Pick<User,'id'|'name'>;export function solve(user:Readonly<User>):Public{return {id:user.id,name:user.name};}
```

**Predict before running:** The returned object contains only explicitly public fields, even at runtime.

**Proof:** The same Node test now passes; the separate compiler-negative test rejects invalid static usage.
