## The problem we're solving

A report totals item prices but accidentally mutates the caller's array when sorting. This workshop uses independent local modules and synthetic data; the code can be run with Node.js 24 without an account, network request, credential, or Vercel build.

## Build the mental model

Arrays preserve ordered records; objects organize named fields. reduce computes an aggregate without mutation, while [...records] makes a shallow copy before sort. Validate numeric fields and avoid treating an array of objects as deep-immutable without reviewing nested references.

**Predict before running:** The report is sorted by price but the input array order and numeric total remain correct.

<LessonStep number={2} title="Repair the underlying language rule" file="labs/js-collections/starter/solution.mjs" expected={"The report is sorted by price but the input array order and numeric total remain correct."}>

Replace the defective implementation with an explicit, minimal solution. Preserve the exported function name so the same tests exercise both versions.

```js
export function solve(items){if(!Array.isArray(items)||items.some(x=>!x||typeof x.name!=='string'||!Number.isFinite(x.price)))throw new TypeError('Invalid item');const sorted=[...items].sort((a,b)=>b.price-a.price);return {names:sorted.map(x=>x.name),total:items.reduce((sum,x)=>sum+x.price,0)};}
```

**Why it works:** Arrays preserve ordered records; objects organize named fields. reduce computes an aggregate without mutation, while [...records] makes a shallow copy before sort. Validate numeric fields and avoid treating an array of objects as deep-immutable without reviewing nested references.

**Proof:** Run the starter verifier again and compare the results with the instructor implementation.

</LessonStep>
