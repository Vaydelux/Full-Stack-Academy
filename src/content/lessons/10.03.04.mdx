## The problem we're solving

The starter allows unlimited requests regardless of the key or time window. Real services must establish who can request a resource, constrain how the request is interpreted, and prevent unexpected data disclosure.

## Build the mental model

Bound requests per actor in a sliding time window and reject excess attempts before expensive processing; distributed gateways need shared enforcement.

**Expected outcome:** The third request in a two-request window is blocked; calls after the window recover.

**Production boundary:** This in-memory example has no eviction or distributed durability; for production bound key cardinality, apply quotas at gateway and storage, and support trusted actor identity.

```js
export function makeLimiter(limit,windowMs){
 if(!Number.isInteger(limit)||limit<1||!Number.isInteger(windowMs)||windowMs<1)throw new RangeError('Invalid limits');
 const records=new Map();
 return {check(actor,now){
  if(typeof actor!=='string'||actor.length<1||actor.length>128||!Number.isFinite(now)||now<0)throw new TypeError('Invalid request');
  const current=(records.get(actor)??[]).filter(time=>time>now-windowMs);
  const allowed=current.length<limit;
  if(allowed)current.push(now);
  records.set(actor,current);
  return {allowed,remaining:Math.max(0,limit-current.length)};
 }};
}
```

**Why this works:** Bound requests per actor in a sliding time window and reject excess attempts before expensive processing; distributed gateways need shared enforcement.

</LessonStep>
