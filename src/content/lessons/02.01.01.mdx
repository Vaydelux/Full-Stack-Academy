## The problem we're solving

A card highlights every nested item when only direct children should be styled. Our task is to repair the actual style behavior, not just make a static screenshot look convincing. This workshop uses synthetic content in a standalone offline HTML file; it needs no account, cloud API or deployed preview.

## Build the mental model

A selector is a matching query over elements. The space combinator matches descendants; > matches immediate children; + matches the next adjacent sibling; ~ matches subsequent siblings. Classes express component intent more safely than deep structural chains.

**Predict before running:** Only the direct tag should receive the colored background.

## Guided implementation

<LessonStep number={1} title="Reproduce and inspect the failing state" file="labs/css-selectors/starter/index.html" expected="The descendant selector colors both direct and nested tags.">

Start from the intentionally incorrect declaration and inspect the matched and computed styles. Before making changes, determine which element owns the value and whether a CSS rule is matched but overridden.

```css
.card .tag { background: #0c567a; color: white; }
```

**Predict before running:** The descendant selector colors both direct and nested tags.

**Why it fails:** A selector is a matching query over elements. The space combinator matches descendants; > matches immediate children; + matches the next adjacent sibling; ~ matches subsequent siblings. Classes express component intent more safely than deep structural chains.

**Proof:** Open DevTools, select the target element, and confirm the failing computed property. Write the observed value before replacing the rule.

</LessonStep>

<LessonStep number={2} title="Apply the targeted CSS repair" file="labs/css-selectors/starter/index.html" expected="Only the direct tag should receive the colored background.">

Replace the incorrect rule with the following CSS. Keep the native HTML controls and all semantic content unchanged.

```css
.card > .tag { background: #0c567a; color: white; }
```

**Predict before running:** Only the direct tag should receive the colored background.

**Why it works:** A selector is a matching query over elements. The space combinator matches descendants; > matches immediate children; + matches the next adjacent sibling; ~ matches subsequent siblings. Classes express component intent more safely than deep structural chains.

**Proof:** getComputedStyle on direct and nested tags returns different background colors.

</LessonStep>

<LessonStep number={3} title="Verify responsiveness and interaction" file="labs/css-selectors/starter/index.html" expected="The repaired solution works at narrow and wide viewports without hiding keyboard focus or producing horizontal overflow.">

Use DevTools Responsive Design Mode: select a 320px width, then a wide desktop width. Inspect the relevant computed style again. Where the lab includes a button or writing-direction toggle, test it using Tab and Enter.

```js
const target = document.querySelector('.card');
console.log(getComputedStyle(target).boxSizing);
console.log(document.documentElement.scrollWidth <= innerWidth);
```

**Predict before running:** A visible computed property changes as described, but the document remains scrollable normally with no unwanted horizontal overflow.

**Why it works:** Browser-computed styles and measured dimensions describe actual rendered rules, rather than assuming the presence of source text is enough.

**Proof:** Compare the computed result with the instructor solution and record one failing case from the original starter.

</LessonStep>
