## The problem we're solving

Every semantic tone returns one hardcoded color. A robust component system has to work across dark and light themes, keyboard input, small screens and real data, not merely appear correct in a screenshot.

## Build the mental model

Use semantic CSS variables for theme state and Tailwind @theme tokens for utility generation. **Predict before executing:** Success, warning and danger resolve to distinct theme variable names.

**Runtime boundary:** This lesson's fixture is local TypeScript only. It does not compile Tailwind CSS, install shadcn or Radix/Base UI, mount a browser interaction, or verify visual contrast on real content. Those require a dedicated UI build and accessibility checks.

```tsx
export type Tone='success'|'warning'|'danger';export function tokenFor(tone:Tone){const tokens:Record<Tone,string>={success:'var(--color-success)',warning:'var(--color-warning)',danger:'var(--color-danger)'};return tokens[tone];}
```

**Why it works:** Use semantic CSS variables for theme state and Tailwind @theme tokens for utility generation.

</LessonStep>
