## The problem we're solving

A button hardcodes a blue hex color in multiple variants, making dark mode and shared branding inconsistent.

## Build the mental model

Use semantic CSS custom properties and Tailwind v4 @theme mappings rather than repeating absolute color literals. Define foreground/background pairs, keep dark-mode mappings explicit, and measure contrast instead of guessing.

**Predict first:** Default and dark modes resolve through distinct semantic tokens while components stop duplicating hardcoded hex colors.

## Production library pattern

```tsx
/* CSS-first Tailwind v4 mapping */
:root { --surface-action: oklch(0.52 0.15 240); --on-action: white; }
.dark { --surface-action: oklch(0.68 0.13 240); --on-action: #080f1b; }
@theme inline { --color-action: var(--surface-action); }
```

The CSS token mapping requires Tailwind v4 processing and computed-style verification. Server-rendering a className does not establish color contrast.
