## The problem we're solving

A form uses Number('') and silently saves a blank amount as zero. This workshop uses independent local modules and synthetic data; the code can be run with Node.js 24 without an account, network request, credential, or Vercel build.

## Build the mental model

JavaScript coercion can produce surprising yet valid values: Number('') is 0, Boolean('false') is true and NaN is still of type number. Validate input intent before conversion and require a finite number afterwards.

**Predict before running:** Blank and nonnumeric input produce explicit failures, while a literal zero remains a valid amount.

<LessonStep number={2} title="Repair the underlying language rule" file="labs/js-coercion/starter/solution.mjs" expected={"Blank and nonnumeric input produce explicit failures, while a literal zero remains a valid amount."}>

Replace the defective implementation with an explicit, minimal solution. Preserve the exported function name so the same tests exercise both versions.

```js
export function solve(text) { if (typeof text!=='string'||text.trim()==='') return {ok:false,reason:'empty-or-not-text'};const number=Number(text.trim());return Number.isFinite(number)?{ok:true,value:number}:{ok:false,reason:'not-finite'}; }
```

**Why it works:** JavaScript coercion can produce surprising yet valid values: Number('') is 0, Boolean('false') is true and NaN is still of type number. Validate input intent before conversion and require a finite number afterwards.

**Proof:** Run the starter verifier again and compare the results with the instructor implementation.

</LessonStep>
