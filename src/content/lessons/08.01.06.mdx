## The problem we're solving

Dark-mode text is selected by visual intuition and the team never checks its foreground-to-background contrast ratio.

## Build the mental model

WCAG relative luminance uses linearized sRGB channels. For normal-sized text, target at least 4.5:1 contrast under WCAG AA, and evaluate every theme, disabled state and focus indicator separately. A React provider can switch tokens but cannot make poor color pairs compliant.

**Predict first:** Pure black on white yields a 21:1 ratio and identical colors yield 1:1; theme compliance must still be checked in the browser.

<LessonStep number={2} title="Fix the policy and verify edge cases" file="labs/ui-theme-contrast/starter/solution.ts" expected="Pure black on white yields a 21:1 ratio and identical colors yield 1:1; theme compliance must still be checked in the browser.">

```ts

export function solve(foreground:string,background:string):number{const lum=(hex:string)=>{if(!/^#[0-9a-f]{6}$/i.test(hex))throw new TypeError("Expected #RRGGBB");const c=[1,3,5].map(i=>parseInt(hex.slice(i,i+2),16)/255).map(v=>v<=0.04045?v/12.92:Math.pow((v+0.055)/1.055,2.4));return c[0]*0.2126+c[1]*0.7152+c[2]*0.0722;};const a=lum(foreground),b=lum(background);return (Math.max(a,b)+0.05)/(Math.min(a,b)+0.05);}

```

**Proof:** Run `npm run lab:ui-theme-contrast` and inspect the instructor test output.

</LessonStep>

## Production library pattern

```tsx
/* Pair foreground and surface tokens, not only background variants. */
:root{--surface: #ffffff;--on-surface: #0f172a;}
.dark{--surface: #0f172a;--on-surface: #ffffff;}
@theme inline{--color-surface: var(--surface);--color-on-surface: var(--on-surface);}
```

CSS tokens are not executed by this React SSR test. Verify computed colors, contrast, focus and reduced motion in each real theme.
