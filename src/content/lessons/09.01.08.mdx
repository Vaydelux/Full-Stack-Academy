## The problem we're solving

A public profile form collects a display name, email, age, communication preference and required consent. Unknown fields and invalid values must be rejected, not sent to a remote API.

**Broken behavior:** The starter returns success for untrusted input and does not normalize or reject any fields.

## Build the mental model

Share one strict Zod 4 schema between browser practice and local acceptance tests; validate unknown input and expose only normalized, approved fields.

**Predict before coding:** Normalize valid input, reject underage, bad email, missing consent and unexpected keys.

**Important boundary:** TypeScript types are erased at runtime. These exercises import Zod 4 from the repository's locked dependencies and run actual `safeParse` or `parse` assertions, not simulated validation. Runtime validation does not authenticate a caller, authorize object access, or persist data.
