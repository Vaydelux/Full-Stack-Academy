## The problem we're solving

The starter emits an empty source file and cannot expose any documented operation. API schemas, operation IDs, examples, authorization descriptions and client integrations must remain consistent across changes.

## Build the mental model

Generate a real bounded ECMAScript SDK from a trusted OpenAPI 3.1 file, with distinct operations and runtime bearer injection, never embedding credentials into source.

**Expected outcome:** The generated client exposes getHealth, listNotes and createNote and performs the expected fetch calls.

**Version and scope:** This module uses OpenAPI Specification **3.1.1** and one checked-in JSON contract at `examples/task-contract/task-api.openapi.json`. The smallest client generator is deliberately restricted to static, trusted GET/POST operations. This pinned local generator deliberately supports only static paths and GET/POST. It is not a substitute for production-grade SDK tooling, schema compilation or OAuth flows.
