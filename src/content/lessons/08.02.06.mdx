## The problem we're solving

The starter mutates the original item array and does not move items correctly. Advanced UI interactions need a robust identity and focus model so the component works with touch, keyboard and screen readers rather than only a mouse.

## Build the mental model

Provide an equivalent keyboard reorder action and announce the new position; never require a pointer to complete a sort. **Expected behavior:** Reorder returns a new list; moving the first item to the last preserves its stable ID.

**Evidence boundary:** The local test checks a pure data or interaction-policy function. It does not prove DOM focus, ARIA announcements, actual event sequences, animation timing or a third-party library's mounted behavior. Use a real local browser and accessible component primitives for those claims.

```tsx
export function move<T>(items:readonly T[],from:number,to:number):T[]{if(!Number.isInteger(from)||!Number.isInteger(to)||from<0||to<0||from>=items.length||to>=items.length)return [...items];const next=[...items];const [row]=next.splice(from,1);next.splice(to,0,row);return next;}
```

**Principle:** Provide an equivalent keyboard reorder action and announce the new position; never require a pointer to complete a sort.

</LessonStep>
