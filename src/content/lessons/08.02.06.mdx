## The problem we're solving

A sortable list can only be rearranged by pointer dragging, so keyboard-only users have no way to change item order.

## Build the mental model

Every drag-and-drop interaction needs a keyboard-operable alternative with clear focus, announcements and a reversible result. For an immutable reorder, return a new list without changing the caller's original array.

**Predict first:** Moving an item produces the correct immutable order and a keyboard-operable Move up action remains available.

<LessonStep number={2} title="Fix the policy and verify edge cases" file="labs/ui-drag-drop/starter/solution.ts" expected="Moving an item produces the correct immutable order and a keyboard-operable Move up action remains available.">

```ts

export function solve<T>(items:readonly T[],from:number,to:number):T[]{if(!Number.isInteger(from)||!Number.isInteger(to)||from<0||to<0||from>=items.length||to>=items.length)throw new TypeError("Invalid reorder");const output=[...items];const moved=output.splice(from,1)[0];output.splice(to,0,moved);return output;}

```

**Why it works:** Every drag-and-drop interaction needs a keyboard-operable alternative with clear focus, announcements and a reversible result. For an immutable reorder, return a new list without changing the caller's original array.

**Proof:** Run `npm run lab:ui-drag-drop` and inspect the instructor test output.

</LessonStep>

## Production library pattern

```tsx
"use client";
import React from "react";
// Integrate a supported drag library only after implementing keyboard sensors and announcements.
function MoveUp({title,onMove}:{title:string;onMove:()=>void}){return <button type="button" onClick={onMove} aria-label={"Move "+title+" up"}>Up</button>;}
```

The lesson provides a real keyboard alternative but does not integrate pointer dragging or a DnD library. Test focus preservation and announcements in a browser.
