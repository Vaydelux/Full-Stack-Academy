## The problem we're solving

A helper uses unchecked any for a request object, bypassing type safety and accepting malformed IDs. This is a local repository/package-development lesson. A passing fixture alone is not a published npm release and does not create a Vercel deployment.

## Build the mental model

TypeScript-aware ESLint rules can reject explicit any and unsafe operations, complementing strict compiler checks. Linting is static guidance, not input validation; start with unknown and narrow at runtime. In a larger monorepo, scope rules by file and avoid globally weakening them to silence a lesson.

**Predict before running:** The implementation uses unknown rather than any and handles invalid objects without property access crashes.
