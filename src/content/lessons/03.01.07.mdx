## The problem we're solving

Updating nested profile preferences modifies the original user object and drops unrelated profile fields. This workshop uses independent local modules and synthetic data; the code can be run with Node.js 24 without an account, network request, credential, or Vercel build.

## Build the mental model

Object spread creates a new shallow object, not a recursive clone. To update nested structures immutably, copy every modified path. Destructuring names important fields, but never assume spread validates input schemas.

**Predict before running:** The output has the new theme while both the original object and unrelated profile fields survive.

Replace the defective implementation with an explicit, minimal solution. Preserve the exported function name so the same tests exercise both versions.

```js
export function solve(user,theme){if(!user||typeof user.profile!=='object'||typeof theme!=='string')throw new TypeError('Invalid profile');return {...user,profile:{...user.profile,theme}};}
```

**Why it works:** Object spread creates a new shallow object, not a recursive clone. To update nested structures immutably, copy every modified path. Destructuring names important fields, but never assume spread validates input schemas.

**Proof:** Run the starter verifier again and compare the results with the instructor implementation.

const user={id:'1',profile:{name:'Ada',theme:'light'}};const next=solve(user,'dark');assert.notEqual(next,user);assert.notEqual(next.profile,user.profile);assert.deepEqual(next.profile,{name:'Ada',theme:'dark'});assert.equal(user.profile.theme,'light');
