## The problem we're solving

A guide page needs a readable document title, concise description and safe route-specific metadata.

**Failure:** The starter returns the same homepage metadata regardless of topic and ignores unknown slugs.

## Build the mental model

Use Next.js Metadata API and static icon files rather than adding arbitrary head elements at runtime.

**Prediction:** Metadata is generated from a validated topic name and never renders untrusted HTML.

**Proof boundary:** The local Node/TSX fixture verifies this lesson's deterministic model and initial React markup. It does **not** start Next.js, compile route conventions, simulate streaming, or prove HTTP status codes. A separately built Next application and browser/HTTP test are needed before release qualification.

```tsx
export type GuideMeta={title:string;description:string};
export function metadataForGuide(slug:string):GuideMeta{
 const titles:Record<string,string>={react:'React guide',nextjs:'Next.js guide'};
 const title=titles[slug];
 if(!title)throw new Error('Unknown guide');
 return {title:`${title} | Academy`,description:`Learn ${title} with practical examples.`};
}
```

**Why it works:** Use Next.js Metadata API and static icon files rather than adding arbitrary head elements at runtime.

</LessonStep>

**Real App Router shape:**

```tsx
// app/guides/[slug]/page.tsx
import type { Metadata } from 'next';
type Props = { params: Promise<{ slug: string }> };
export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { slug } = await params;
  return {title: slug === 'react' ? 'React | Academy' : 'Guide | Academy', robots: {index: slug === 'react'}};
}
// Place icons as app/icon.png, app/apple-icon.png or configured metadata icons.
```

**Nuance:** App Router metadata belongs to Server Components and can be asynchronous. A favicon file is a static asset with browser caching; metadata generation does not authorize a route and should reflect canonical content, not expose private titles.

</LessonStep>
