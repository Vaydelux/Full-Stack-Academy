## The problem we're solving

A notification button must reveal a readable status after activation, and the test should locate it by accessible role. **Failure case:** The starter omits both the accessible button state and the notification announcement.

## Build the mental model

Test behavior observable to a person rather than implementation details. React Testing Library requires an installed DOM runtime and is not provided by this repository's locked dependencies.

**Expected result:** A notice button provides a named control, correctly marked pressed state, and a status region.

**Evidence boundary:** Node tests run reviewed fixtures, not arbitrary learner code. React server markup proves initial output only. A browser or configured DOM environment is required for real user events, hydration, the React DevTools Profiler, and state preservation after reordering. This repo does not currently declare or lock React Testing Library; do not claim these Node checks exercise that dependency.

```tsx
import {useState} from 'react';
export function AnnouncementButton(){
 const [active,setActive]=useState(false);
 return <section><button type="button" aria-pressed={active} onClick={()=>setActive(current=>!current)}>Toggle notice</button>
 <p role="status">{active?'Notice enabled':'Notice disabled'}</p></section>;
}
```
