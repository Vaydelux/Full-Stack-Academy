## The problem we're solving

Image and asset optimization can create user-visible reliability or security failures. The starter preloads every thumbnail and accepts invalid image dimensions.

## Build the mental model

Reserve image dimensions and preload only a measured LCP candidate, using next/image and optimized font delivery. **Expected result:** Valid hero is preloaded; thumbnails lazy-load and invalid dimensions throw.

Offline tests verify small, deterministic policy models. They cannot establish real HTTP security, deployment compatibility, image loading, environment secrecy or network diagnostics.

<LessonStep number={2} title="Repair the policy and runtime boundary" file="labs/next-image-assets/starter/solution.tsx" expected="Valid hero is preloaded; thumbnails lazy-load and invalid dimensions throw.">

```tsx
export function assetPlan(kind:'hero'|'thumbnail',width:number,height:number){if(!Number.isSafeInteger(width)||!Number.isSafeInteger(height)||width<=0||height<=0)throw new RangeError('Invalid dimensions');return {width,height,preload:kind==='hero',loading:kind==='hero'?'eager':'lazy'};}
```

**Why it works:** Reserve image dimensions and preload only a measured LCP candidate, using next/image and optimized font delivery.

</LessonStep>
