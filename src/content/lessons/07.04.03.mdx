## The problem we're solving

A course index includes both published tutorials and planned placeholders. Search engines should see only finished, publicly accessible pages in the sitemap.

**Defect:** The starter publishes drafts and private pages as sitemap entries.

## Build the mental model

Produce sitemap URLs only for public published pages; use robots metadata for indexability, not robots.txt as an access-control mechanism.

**Predict before running:** Only public published slugs enter the sitemap, without duplicate IDs.

The academy exercises reviewed TypeScript/React logic locally. It does not automatically exercise the Next.js Metadata API, search crawler, browser page loading, network waterfall, Lighthouse or real-user field metrics. Those are separate qualification gates.

```tsx
export type Page={slug:string;published:boolean;public:boolean};
export function sitemapSlugs(pages:readonly Page[]){
 return [...new Set(pages.filter(x=>x.published&&x.public&&/^[a-z0-9-]+$/.test(x.slug)).map(x=>x.slug))];
}
```

**Root principle:** Produce sitemap URLs only for public published pages; use robots metadata for indexability, not robots.txt as an access-control mechanism.

</LessonStep>

**Next.js 16 usage pattern (illustrative):**

```tsx
// app/sitemap.ts
import type {MetadataRoute} from 'next';
export default async function sitemap():Promise<MetadataRoute.Sitemap>{
 const slugs=await getPublicPublishedSlugs();
 return slugs.map(slug=>({url:'https://academy.example/learn/'+slug}));
}
// app/robots.ts
export default function robots(){return {rules:{userAgent:'*',allow:'/'},sitemap:'https://academy.example/sitemap.xml'};}
```

**Production nuance:** Robots exclusions are advisory to crawlers, not a privacy layer. Restricted content must be inaccessible without authorization. Actual sitemap/robots URLs must be inspected after building.

</LessonStep>
