## The problem we're solving

A wide global selector styles unrelated cards, creating unnecessary matching scope and accidental regressions. A code review should require a reproducible symptom and realistic verification, not only a polished image. The local fixture is synthetic, deterministic and offline.

## Build the mental model

Selector cost depends on DOM shape, mutation patterns, and browser optimizations. Avoid blanket claims that one pseudo-class is always slow. Prefer stable component boundaries and measure actual style-recalculation work in DevTools; scoping makes both performance reasoning and maintainability easier.

**Predict before running:** The learning-list item uses its own color while the editorial item has a separate style.

## Explore and verify

Use DevTools to inspect computed styles and the Performance recording when making speed claims. Not every transform is composited; not every font loading strategy removes CLS; not every visually distinct control is accessible. The Node tests check instructor patterns; the isolated browser suite observes representative states. Manual assistive-technology and cross-browser checks remain outside the automated guarantee.
