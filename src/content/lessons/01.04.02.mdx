## The problem we're solving

A small client calls fetch, immediately parses JSON and shows success on every resolved promise. A 503 response still resolves, broken JSON can throw, and users cannot cancel. We will build a deterministic offline simulator that follows the same response and failure contracts without calling a live API.

## Build the mental model

fetch resolves to a Response even for HTTP errors such as 404 or 503; check response.ok and response.status explicitly. A network failure rejects the promise, and response.json() can independently reject when the body is not valid JSON. AbortController lets a caller signal that pending work is no longer needed. Here the transport returns locally constructed Response objects, so no real request, external server or API key is involved.

**Predict before running:** A Response with status 503 has ok=false even though the promise resolves. JSON parsing of a malformed response fails separately.

<LessonStep number={1} title={"Handle HTTP status before JSON"} file="labs/web-fetch-json/starter/index.html" expected={"The HTTP-error demonstration should report HTTP 503, not claim a network outage."}>

Read the Response contract before touching the body. This sample uses a local transport, not a real server.

```js
const response = await readDemo('http-error', signal);
if (!response.ok) throw new Error('HTTP ' + response.status);
const data = await response.json();
```

**Predict before running:** The HTTP-error demonstration should report HTTP 503, not claim a network outage.

**Why it works:** A non-2xx HTTP response is different from a rejected transport promise.

**Proof it works:** Click Simulate HTTP 503 and confirm the status explicitly mentions 503.

</LessonStep>


<LessonStep number={2} title={"Handle parse and network failures"} file="labs/web-fetch-json/starter/index.html" expected={"Malformed JSON should report a parse failure; a simulated transport error should report a transport failure."}>

Catch the thrown parsing or transport error and display an accurate branch.

```js
try {
  const response = await readDemo(mode, signal);
  if (!response.ok) throw new Error('HTTP ' + response.status);
  const data = await response.json();
  status.textContent = data.items.length + ' sample items loaded locally.';
} catch (error) {
  status.textContent = error.name === 'AbortError' ? 'Request cancelled.' : 'Request failed: ' + error.message;
}
```

**Predict before running:** Malformed JSON should report a parse failure; a simulated transport error should report a transport failure.

**Why it works:** Not every failure means a server returned an error status.

**Proof it works:** Trigger each local scenario and compare the visible status.

</LessonStep>


<LessonStep number={3} title={"Cancel and avoid stale UI work"} file="labs/web-fetch-json/starter/index.html" expected={"Cancellation should be reported without a fabricated successful fetch."}>

Keep an AbortController for the current request, and abort it when cancellation is requested.

```js
let controller;
function cancel(){
  controller?.abort();
}
document.querySelector('#cancel').addEventListener('click', cancel);
```

**Predict before running:** Cancellation should be reported without a fabricated successful fetch.

**Why it works:** A signal represents cancellation intent; the transport or consumer must honor it.

**Proof it works:** Start Load sample JSON, quickly click Cancel request and verify the cancellation state.

</LessonStep>
