## The problem we're solving

An older slow search response overwrites a newer fast one, showing stale UI data. This lab uses local Node.js timers, Promises and injected mock transport rather than relying on external APIs or a deployed site.

## Build the mental model

Async operations may resolve in a different order than they started. A monotonically increasing request token lets the consumer accept only its latest result. This guards UI state but does not cancel network work unless paired with a signal.

**Predict before running:** The new result is accepted and the late old result is discarded without corrupting visible state.

Make the smallest meaningful correction and preserve the `solve` module contract. For transport cases, keep request functions injectable so the same test can simulate success, failure, timeout and cancellation.

```js
export function solve(){let current=0;return async task=>{const id=++current;const value=await task();return id===current?{accepted:true,value}:{accepted:false,value:null};};}
```

**Proof:** Verify that all promises settle and timer/listener cleanup occurs even after failure.
