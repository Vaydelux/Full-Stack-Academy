## The problem we're solving

A support search must expose a query field with an accessible name and announce its result count. **Failure case:** The starter uses unlabeled input markup, so `getByRole('searchbox', { name: 'Search support' })` cannot find it.

## Build the mental model

Prefer roles and associated labels over brittle CSS classes, positions or test IDs when querying UI.

**Expected result:** The searchbox has a proper accessible name and results use a status region.

**Evidence boundary:** Node tests run reviewed fixtures, not arbitrary learner code. React server markup proves initial output only. A browser or configured DOM environment is required for real user events, hydration, the React DevTools Profiler, and state preservation after reordering. This repo does not currently declare or lock React Testing Library; do not claim these Node checks exercise that dependency.

<LessonStep number={2} title="Repair the implementation contract" file="labs/react-accessible-queries/starter/solution.tsx" expected="The searchbox has a proper accessible name and results use a status region.">

```tsx
export function SupportSearch({results}:{results:number}){
 return <form role="search"><label htmlFor="support-query">Search support</label>
 <input id="support-query" type="search" name="q"/>
 <p role="status">{results===1?'1 result':`${results} results`}</p>
 <button type="submit">Search</button></form>;
}
```

**Why this works:** Prefer roles and associated labels over brittle CSS classes, positions or test IDs when querying UI.

</LessonStep>
