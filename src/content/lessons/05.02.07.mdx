## The problem we're solving

Release notes omit bug fixes and include internal build-maintenance commits as user-visible features. The lesson uses synthetic local data; passing its test does not configure actual branch protection or trigger a release.

## Build the mental model

A changelog summarizes user-visible changes grouped by version and category rather than reproducing the entire commit log. Conventional messages help classification, but release notes still require human editorial review for impact, migration steps and known issues. This example intentionally produces local Markdown only.

**Predict before running:** The release notes include features and fixes grouped in readable sections, excluding purely internal chores.

<LessonStep number={2} title="Implement the explicit review or release contract" file="labs/team-changelog/starter/solution.mjs" expected={"The release notes include features and fixes grouped in readable sections, excluding purely internal chores."}>

Prefer an explicit result and a narrow, auditable policy; do not invent remote approvals or call an external API.

```js
export function solve(version,commits){if(typeof version!=='string'||!Array.isArray(commits))throw new TypeError('Version/commits required');const items=commits.map(c=>/^(feat|fix): (.+)$/.exec(c)).filter(Boolean);const groups=[['feat','Added'],['fix','Fixed']];return ['## '+version,...groups.flatMap(([type,heading])=>{const lines=items.filter(m=>m[1]===type).map(m=>'- '+m[2]);return lines.length?['### '+heading,...lines]:[];})].join('\n')+'\n';}
```

**Predict before running:** The release notes include features and fixes grouped in readable sections, excluding purely internal chores.

**Why the repair works:** A changelog summarizes user-visible changes grouped by version and category rather than reproducing the entire commit log. Conventional messages help classification, but release notes still require human editorial review for impact, migration steps and known issues. This example intentionally produces local Markdown only.

**Proof:** Run the same independent test after editing; a green result demonstrates this local policy only.

</LessonStep>

<LessonStep number={3} title="Test both positive and negative outcomes" file="labs/team-changelog/solution.test.mjs" expected="Passes a precise expected-output contract and rejects a misleading or invalid case.">

assert.equal(solve('1.2.0',['feat: add search','fix: repair login','chore: ci tuning']),'## 1.2.0\n### Added\n- add search\n### Fixed\n- repair login\n');assert.equal(solve('1.0.0',[]),'## 1.0.0\n');
