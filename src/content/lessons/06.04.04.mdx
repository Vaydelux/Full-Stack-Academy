## The problem we're solving

A search page has an expensive result list whose rendering can slow down direct text input. The starter filter discards the query and leaves every item visible.

## Build the mental model

Allow a slow result view to lag behind urgent input state without delaying keystrokes. The value supplied to a lower-priority render of a consumer, not the user's immediate controlled input value. The React 19 APIs used here have distinct contracts: context passes values, transitions schedule nonurgent updates, deferred values let rendering lag, and optimistic state is a temporary view during an Action. These lessons use local data, not backend persistence.

**Predict before you run:** Only names matching the provided query appear; the client component delegates an expensive view to a deferred query value.

The instructor repair preserves the public exports while fixing the value propagation, scheduling, or state reconciliation defect:

```tsx
import {useDeferredValue,useState} from 'react';
export function searchNames(names:readonly string[],query:string){
 const q=query.trim().toLocaleLowerCase();return names.filter(n=>n.toLocaleLowerCase().includes(q));
}
export function DeferredSearch({names}:{names:readonly string[]}){
 const [query,setQuery]=useState('');const deferred=useDeferredValue(query);
 const matches=searchNames(names,deferred);
 return <section><label htmlFor="deferred-query">Name</label><input id="deferred-query" value={query} onChange={e=>setQuery(e.target.value)}/>
 <ul>{matches.map(n=><li key={n}>{n}</li>)}</ul></section>;
}
```
