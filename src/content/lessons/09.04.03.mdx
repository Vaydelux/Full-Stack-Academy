## The problem we're solving

A theme preference may be safe to remember, but a session token or secret must never be saved in localStorage merely because it lives in the same store.

**Broken behavior:** The starter persists a token along with theme, exposing sensitive values in a browser-readable storage record.

## Build the mental model

Use Zustand persist with a strict partialize allowlist and controlled hydration; localStorage is user-readable and must never become a secret store.

**Predict:** Theme is persisted but token is omitted from serialized state, even after token updates.

**Evidence boundary:** The local test imports the real Zustand 5 `createStore` API and, where appropriate, the official middleware. The store is created afresh per test; it does not use a global request-scoped server singleton. Passing Node assertions does not prove browser hydration, cross-tab synchronization or HTTP authorization.

```ts
import {createStore} from 'zustand/vanilla';
import {persist,createJSONStorage} from 'zustand/middleware';
import type {StateStorage} from 'zustand/middleware';
type Theme='light'|'dark';
export type PrefState={theme:Theme;token:string;setTheme:(theme:Theme)=>void;setToken:(token:string)=>void};
type StoredPrefs={theme:Theme};
export function makePrefsStore(storage:StateStorage){
 return createStore<PrefState>()(persist<PrefState,StoredPrefs>((set)=>({
  theme:'light',token:'',setTheme:theme=>set({theme}),setToken:token=>set({token}),
 }),{name:'academy-ui-preferences',storage:createJSONStorage<StoredPrefs>(()=>storage),skipHydration:true,
 partialize:state=>({theme:state.theme})}));
}
```

**Reasoning:** Use Zustand persist with a strict partialize allowlist and controlled hydration; localStorage is user-readable and must never become a secret store.

</LessonStep>
