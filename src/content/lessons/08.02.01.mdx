## The problem we're solving

The starter forces an animation even when reduced motion is requested. Advanced UI interactions need a robust identity and focus model so the component works with touch, keyboard and screen readers rather than only a mouse.

## Build the mental model

Respect prefers-reduced-motion: keep state changes perceivable without forced displacement or animation. **Expected behavior:** Reduced motion uses zero duration; ordinary motion can use a short transition.

**Evidence boundary:** The local test checks a pure data or interaction-policy function. It does not prove DOM focus, ARIA announcements, actual event sequences, animation timing or a third-party library's mounted behavior. Use a real local browser and accessible component primitives for those claims.
