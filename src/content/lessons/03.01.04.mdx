## The problem we're solving

A score classifier checks its lower threshold first and marks excellent results as merely passing. This workshop uses independent local modules and synthetic data; the code can be run with Node.js 24 without an account, network request, credential, or Vercel build.

## Build the mental model

Condition order is observable behavior. Test high-priority branches before broad lower thresholds, handle non-finite values, and make each return path explicit so no valid input falls through unexpectedly.

**Predict before running:** A 90-point score is excellent, while invalid and out-of-range numbers are rejected.

**Why it fails:** A score classifier checks its lower threshold first and marks excellent results as merely passing.

<LessonStep number={2} title="Repair the underlying language rule" file="labs/js-control-flow/starter/solution.mjs" expected={"A 90-point score is excellent, while invalid and out-of-range numbers are rejected."}>

Replace the defective implementation with an explicit, minimal solution. Preserve the exported function name so the same tests exercise both versions.

```js
export function solve(score) { if(typeof score!=='number'||!Number.isFinite(score)||score<0||score>100)return 'invalid';if(score>=80)return 'excellent';if(score>=50)return 'pass';return 'retry'; }
```

**Why it works:** Condition order is observable behavior. Test high-priority branches before broad lower thresholds, handle non-finite values, and make each return path explicit so no valid input falls through unexpectedly.

**Proof:** Run the starter verifier again and compare the results with the instructor implementation.

</LessonStep>

<LessonStep number={3} title="Verify edge cases and write down the contract" file="labs/js-control-flow/solution.test.mjs" expected="All reviewed input/output assertions pass; the original failing case is explained rather than hidden.">

```js
assert.equal(solve(90),'excellent');assert.equal(solve(50),'pass');assert.equal(solve(49),'retry');assert.equal(solve(NaN),'invalid');assert.equal(solve(101),'invalid');
```

**Predict before running:** A 90-point score is excellent, while invalid and out-of-range numbers are rejected.

**Why it matters:** Observable input/output contracts make language assumptions testable, repeatable and independent of a browser deployment.
