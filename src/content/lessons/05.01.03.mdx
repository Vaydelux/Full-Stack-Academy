## The problem we're solving

A shared branch already contains a faulty settings commit and someone proposes discarding history with reset --hard. This lesson is an offline, repeatable source-control exercise; it never touches the learner's actual project repository or opens a hosted pull request.

## Build the mental model

Restore changes the working tree/index, reset moves the current branch ref and can discard local changes, and revert creates a new commit that inverses an earlier commit. For shared history, revert preserves the audit trail without rewriting everyone's refs.

**Predict before running:** A new revert commit restores safe settings while preserving the earlier bad commit in history.
