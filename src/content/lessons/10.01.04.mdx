## The problem we're solving

A server fetches a slow upstream dependency and ignores cancellation, leaving hung requests and leaking internal error details.

**Deliberate defect:** The starter ignores non-success status and treats HTML error pages as valid JSON. This exercise runs under Node.js 24 using built-in modules—no paid service, hosted data source or arbitrary learner-code runner.

## Build the mental model

Use Node's standard fetch and AbortSignal.timeout with an explicit HTTP status check; reject unexpected JSON content types before parsing.

**Predict before writing code:** A JSON 200 response is parsed; an HTTP 503 response and an HTML content type are rejected.

The exact Node.js API documentation is linked below. These exercises model concrete runtime behavior, not a screenshot of a server. They must not be interpreted as proof of container permission boundaries, a production reverse proxy or multi-process request isolation.

<LessonStep number={2} title="Repair the standard Node API usage" file="labs/node-fetch-abort/starter/solution.mjs" expected="A JSON 200 response is parsed; an HTTP 503 response and an HTML content type are rejected.">

```js
export async function fetchJson(url,{fetchImpl=fetch,timeoutMs=3000}={}){
 if(!Number.isSafeInteger(timeoutMs)||timeoutMs<1||timeoutMs>30000)throw new RangeError('Invalid timeout');
 const response=await fetchImpl(url,{signal:AbortSignal.timeout(timeoutMs),headers:{accept:'application/json'}});
 if(!response.ok)throw new Error('Upstream HTTP '+response.status);
 if(!/\bapplication\/(?:[\w.+-]*\+)?json\b/i.test(response.headers.get('content-type')??''))throw new Error('Unexpected content type');
 return response.json();
}
```

**Causal reasoning:** Use Node's standard fetch and AbortSignal.timeout with an explicit HTTP status check; reject unexpected JSON content types before parsing.

</LessonStep>
