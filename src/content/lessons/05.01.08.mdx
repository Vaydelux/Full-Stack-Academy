## The problem we're solving

A feature is developed without a branch, testable commit message, or clear merge back into main. This lesson is an offline, repeatable source-control exercise; it never touches the learner's actual project repository or opens a hosted pull request.

## Build the mental model

A full Git feature workflow begins with a clean baseline, creates an isolated branch, edits and stages a deliberate file, commits with purpose, checks the diff and merges after review. Local tests demonstrate source-state transitions but never replace a hosted PR, approvals or branch-protection checks.

**Predict before running:** The feature exists on a reviewed local branch, then lands on main with a clean working tree.

## Explore and verify

Run `git status`, `git log --oneline --graph`, `git diff`, or `git show` as appropriate in a disposable clone. The exercises deliberately avoid real credentials, network remotes and destructive commands against your own worktree. Code review and branch protection require a separate hosting workflow.
