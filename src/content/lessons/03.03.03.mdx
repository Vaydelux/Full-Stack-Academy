## The problem we're solving

An async workflow returns an unresolved promise as its result and never converts task rejection into a useful error outcome. This lab uses local Node.js timers, Promises and injected mock transport rather than relying on external APIs or a deployed site.

## Build the mental model

An async function always returns a Promise. await unwraps fulfillment and throws on rejection; catching at the correct boundary lets the caller distinguish success from a controlled error without swallowing unrelated failures.

**Predict before running:** The successful task yields its actual value, and rejected tasks become explicit error results.

<LessonStep number={2} title="Apply the async boundary and handle errors" file="labs/js-async-await/starter/solution.mjs" expected={"The successful task yields its actual value, and rejected tasks become explicit error results."}>

Make the smallest meaningful correction and preserve the `solve` module contract. For transport cases, keep request functions injectable so the same test can simulate success, failure, timeout and cancellation.

```js
export async function solve(task){if(typeof task!=='function')throw new TypeError('Task required');try{return {ok:true,value:await task()};}catch(error){return {ok:false,error:error instanceof Error?error.message:'unknown-error'};}}
```

**Predict before running:** The successful task yields its actual value, and rejected tasks become explicit error results.

**Why it works:** An async function always returns a Promise. await unwraps fulfillment and throws on rejection; catching at the correct boundary lets the caller distinguish success from a controlled error without swallowing unrelated failures.

**Proof:** Verify that all promises settle and timer/listener cleanup occurs even after failure.

</LessonStep>
