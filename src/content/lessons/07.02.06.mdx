## The problem we're solving

A slow recommendations section should not block the entire article from being readable. The loading state must be announced clearly.

**Symptom:** The starter renders Loading in the success state and Ready while pending, reversing the accessible status contract.

## Build the mental model

Suspense enables parts of the tree to reveal when ready; provide meaningful fallback UI without confusing loaded data and in-flight work.

**Predict first:** Pending displays a status, ready displays the content, and errors remain distinct from loading.

The local fixture tests only an isolated TypeScript/React contract; actual Server Component compilation, network transport, streaming, Server Actions, security isolation and browser hydration require a separate compiled Next.js 16 application and integration tests.

```tsx
export type ResourceState='pending'|'ready'|'error';
export function ResourceNotice({state}:{state:ResourceState}){
 if(state==='pending')return <p role="status">Loading recommendations…</p>;
 if(state==='error')return <p role="alert">Recommendations unavailable.</p>;
 return <p>Recommendations ready.</p>;
}
```

**Why it works:** Suspense enables parts of the tree to reveal when ready; provide meaningful fallback UI without confusing loaded data and in-flight work.

</LessonStep>
