## The problem we're solving

A resource dashboard needs to show loading while data is suspended and a clear recovery message when a descendant throws during rendering. The starter error boundary returns its children even after failure state is set.

## Build the mental model

Provide a localized error fallback and a separate loading fallback without treating both conditions as the same failure. Suspense handles a suspended render with a loading fallback; an error boundary handles rendering errors with a failure fallback. The React 19 APIs used here have distinct contracts: context passes values, transitions schedule nonurgent updates, deferred values let rendering lag, and optimistic state is a temporary view during an Action. These lessons use local data, not backend persistence.

**Predict before you run:** The initial boundary renders children; a derived failure state renders a semantic alert fallback.

<LessonStep number={2} title="Repair the React 19 component contract" file="labs/react-error-suspense/starter/solution.tsx" expected="The initial boundary renders children; a derived failure state renders a semantic alert fallback.">

The instructor repair preserves the public exports while fixing the value propagation, scheduling, or state reconciliation defect:

```tsx
import {Component,Suspense,type ReactNode} from 'react';
export class RescueBoundary extends Component<{children:ReactNode},{failed:boolean}>{
 state={failed:false};
 static getDerivedStateFromError(){return {failed:true};}
 render(){return this.state.failed?<p role="alert">Cannot show this panel.</p>:this.props.children;}
}
export function LoadingSection({children}:{children:ReactNode}){
 return <Suspense fallback={<p role="status">Loading resource…</p>}>{children}</Suspense>;
}
```

**Why it works:** Provide a localized error fallback and a separate loading fallback without treating both conditions as the same failure.

</LessonStep>
