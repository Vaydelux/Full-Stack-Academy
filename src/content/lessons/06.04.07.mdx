## The problem we're solving

A failed component throws and collapses the entire page without a localized fallback or recovery plan. This local fixture isolates a concrete failure before we introduce any external state or deployment.

## Build the mental model

Error boundaries catch render-time errors in their descendant tree, while Suspense shows a loading fallback when a child suspends. These solve different problems; boundaries do not automatically catch every event handler or async callback error.

**Predict before running:** The repaired implementation respects its documented contract.

This is an actual React 19 component, which the lab renders to initial HTML. Interactions after hydration are not certified by an SSR check.

```tsx

import React,{Suspense} from 'react';
import {solve} from './solution';
class Boundary extends React.Component<{children:React.ReactNode},{failed:boolean}>{state={failed:false};static getDerivedStateFromError(){return {failed:true};}render(){return this.state.failed?<p role="alert">{solve(new Error('hidden'))}</p>:this.props.children;}}
export function Workshop(){return <section aria-label="Error boundary"><Boundary><Suspense fallback={<p>Loading section</p>}><h2>Recoverable workspace</h2></Suspense></Boundary></section>;}

```
