## The problem we're solving

A package advertises a public API but ships stale export paths and no deterministic typed release verification. This is a local repository/package-development lesson. A passing fixture alone is not a published npm release and does not create a Vercel deployment.

## Build the mental model

A typed package release must align source exports, generated JavaScript, declaration files, package exports map and versioned runtime requirements. A local package blueprint is not the same as publishing to npm; build and test artifacts offline first, then validate consumers and release only when configured.

**Predict before running:** Only a versioned package manifest with the expected public JS entry is accepted by the local release gate.

## Explore and verify

Compare what the TypeScript compiler can statically prove with what Node.js resolves at runtime. Modules and public declaration files are build artifacts; configured npm publication, signed provenance and integration tests are separate engineering gates. Do not treat a local manifest as deployable until the paths have real output.
