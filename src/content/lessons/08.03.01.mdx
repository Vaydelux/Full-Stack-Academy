## The problem we're solving

A data grid renders internal identifiers and fails to label its main status column for screen readers.

## Build the mental model

Column definitions describe stable IDs, headers and cell rendering. Use header cells and row scopes in native tables; TanStack Table supplies headless table state and rendering but not accessibility automatically. Keep private fields out of public display columns.

**Predict first:** Only unique, public columns with meaningful headers are accepted before rendering.

```ts

export type Column={id:string;header:string};export function solve(cols:readonly Column[]):Column[]{const used=new Set<string>();return cols.map(x=>{if(!x.id.trim()||!x.header.trim()||used.has(x.id)||x.id.startsWith("_"))throw new TypeError("Unique public, named column required");used.add(x.id);return {id:x.id,header:x.header.trim()};});}

```

**Why it works:** Column definitions describe stable IDs, headers and cell rendering. Use header cells and row scopes in native tables; TanStack Table supplies headless table state and rendering but not accessibility automatically. Keep private fields out of public display columns.

**Proof:** Run `npm run lab:ui-table-columns` and inspect the instructor test output.

</LessonStep>

## Production library pattern

```tsx
import {createColumnHelper} from "@tanstack/react-table";
type Task={id:string;status:string};
const column=createColumnHelper<Task>();
export const columns=[column.accessor("status",{header:"Status",cell:info=>info.getValue()})];
```

TanStack Table is a headless library and is not installed in the isolated teaching fixture. Check real sorting, keyboard and row semantics in an integrated app.
