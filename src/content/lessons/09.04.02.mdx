## The problem we're solving

A filter panel should update sorting without overwriting a typed search query. A subscriber to sorting should not rerun when only the query changes.

**Broken behavior:** The starter's setSort overwrites the query string and leaves the sort state unchanged.

## Build the mental model

Use bounded state slices, stable primitive selectors, and subscribeWithSelector for targeted subscriptions to a vanilla Zustand store.

**Predict:** Changing query leaves sort subscribers quiet; changing sort notifies them exactly once.

**Evidence boundary:** The local test imports the real Zustand 5 `createStore` API and, where appropriate, the official middleware. The store is created afresh per test; it does not use a global request-scoped server singleton. Passing Node assertions does not prove browser hydration, cross-tab synchronization or HTTP authorization.

```ts
import {createStore} from 'zustand/vanilla';
import {subscribeWithSelector} from 'zustand/middleware';
export type SortState={query:string;sort:'title'|'recent';setQuery:(q:string)=>void;setSort:(s:'title'|'recent')=>void};
export function makeSortStore(){
 return createStore<SortState>()(subscribeWithSelector(set=>({
  query:'',sort:'title',
  setQuery:query=>set({query}),
  setSort:sort=>set({sort}),
 })));
}
```

**React/browser usage pattern (illustrative until mounted and tested):**

```tsx
import {createStore} from 'zustand/vanilla';
import {subscribeWithSelector} from 'zustand/middleware';
const store=createStore(subscribeWithSelector(set=>({filter:'all',setFilter:(filter:string)=>set({filter})})));
const unsubscribe=store.subscribe(s=>s.filter,(filter,previous)=>console.log(filter,previous));
store.getState().setFilter('active');unsubscribe();
// In React prefer selectors returning stable primitive values; avoid creating fresh objects every render in Zustand 5.
```

**Trust boundary:** Never treat a UI role, selected row or persisted browser token as server authorization. Query data and private records still require server-side validation and access controls.

</LessonStep>
