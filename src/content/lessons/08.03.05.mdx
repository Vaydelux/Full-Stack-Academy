## The problem we're solving

An empty result set is displayed as a loading spinner forever, leaving users unsure whether the query completed.

## Build the mental model

Loading, genuinely empty, ready and error are different states with different next actions. Show a calm empty-state explanation and a retry affordance for recoverable failures, and keep status messages accessible.

**Predict first:** Empty and error states have distinct messages instead of being disguised as loading.

<LessonStep number={2} title="Fix the policy and verify edge cases" file="labs/ui-table-states/starter/solution.ts" expected="Empty and error states have distinct messages instead of being disguised as loading.">

```ts

export type State="loading"|"empty"|"ready"|"error";export function solve(state:State):string{switch(state){case "loading":return "Loading…";case "empty":return "No matching records";case "ready":return "Results";case "error":return "Could not load records";}}

```

**Why it works:** Loading, genuinely empty, ready and error are different states with different next actions. Show a calm empty-state explanation and a retry affordance for recoverable failures, and keep status messages accessible.

**Proof:** Run `npm run lab:ui-table-states` and inspect the instructor test output.

</LessonStep>
