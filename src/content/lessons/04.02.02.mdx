## The problem we're solving

A helper claims to retrieve a requested property but always returns the object's first value, relying on a cast to hide the mismatch. This advanced-types lab requires both compile-time evidence and meaningful runtime behavior; TypeScript's erased types alone cannot fix logic bugs.

## Build the mental model

keyof T produces the property-key union of T; indexed access T[K] links a requested key to its value type. typeof can capture a runtime declaration's static type, but it does not make an incorrect runtime key lookup correct.

**Predict before running:** The key/value type relationship is preserved and the requested property is actually returned.

Preserve exported `solve` and tighten the behavior without adding an unsound `as any` cast.

```ts
export function solve<T extends object,K extends keyof T>(object:T,key:K):T[K]{return object[key];}
```

**Predict before running:** The key/value type relationship is preserved and the requested property is actually returned.

**Why the fix works:** keyof T produces the property-key union of T; indexed access T[K] links a requested key to its value type. typeof can capture a runtime declaration's static type, but it does not make an incorrect runtime key lookup correct.

**Proof:** The same Node test now passes; the separate compiler-negative test rejects invalid static usage.

</LessonStep>
