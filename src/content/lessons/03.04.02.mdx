## The problem we're solving

Newly added list items do not respond to click because listeners were attached only to existing children. Browser Interaction topics require both executable JavaScript logic and a real local HTML document. The fixture uses synthetic content with no external scripts, endpoints or data uploads.

## Build the mental model

Bubbling allows an ancestor listener to handle interactions from current and future descendants. Find the closest relevant target and check it belongs to the expected list before processing untrusted DOM content. Native buttons remain accessible to keyboard users.

**Predict before running:** A newly inserted B button works through the original ancestor listener.

<LessonStep number={2} title="Implement the browser-safe interaction" file="labs/js-delegation/starter/index.html" expected={"A newly inserted B button works through the original ancestor listener."}>

Replace the defective handler without discarding native elements or semantics. For untrusted content use `textContent`, not an unsafe HTML sink.

```js
const list=document.querySelector('#items');list.addEventListener('click',event=>{const button=event.target.closest('button[data-name]');if(!button||!list.contains(button))return;document.querySelector('#status').textContent=button.dataset.name;});document.querySelector('#append').addEventListener('click',()=>{const li=document.createElement('li');const b=document.createElement('button');b.type='button';b.dataset.name='B';b.textContent='Select B';li.append(b);list.append(li);});
```

**Predict before running:** A newly inserted B button works through the original ancestor listener.

**Why the repair works:** Bubbling allows an ancestor listener to handle interactions from current and future descendants. Find the closest relevant target and check it belongs to the expected list before processing untrusted DOM content. Native buttons remain accessible to keyboard users.

**Proof:** Compare the resulting DOM and accessibility state to the instructor `solution/index.html` using the same input.

</LessonStep>
