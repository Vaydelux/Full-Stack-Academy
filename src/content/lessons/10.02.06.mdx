## The problem we're solving

An API returns a stack trace and environment credentials inside a 500 response, exposing internal implementation details to clients.

**Fault to find:** The starter includes an untrusted diagnostics field in public JSON errors. This track uses Node 24 built-ins and fetch-compatible `Response` where appropriate; no paid platform or remote arbitrary-code execution is needed.

## Build the mental model

Return a standards-based application/problem+json response with type, title, and status; never serialize raw stack traces or environment values.

**Expected repair:** The error response uses application/problem+json and excludes sensitive debug details.

HTTP semantics follow RFC 9110. Public errors can use RFC 9457 Problem Details; do not invent return codes or copy internal stack traces into public responses. Pure helper tests are useful but the final capstone runs a real loopback server and tests wire responses.
