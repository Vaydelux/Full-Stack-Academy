## The problem we're solving

A registration form receives invalid email and nested profile data. Throwing or trusting the input loses actionable field errors.

**Broken behavior:** The starter always reports ok and echoes unvalidated input as trustworthy data.

## Build the mental model

Use safeParse as a discriminated result, inspect ZodError.issues with explicit paths and format field errors without leaking raw payloads.

**Predict before coding:** Return ok=false and issue paths for invalid email or age; never throw for normal validation failures.

**Important boundary:** TypeScript types are erased at runtime. These exercises import Zod 4 from the repository's locked dependencies and run actual `safeParse` or `parse` assertions, not simulated validation. Runtime validation does not authenticate a caller, authorize object access, or persist data.

<LessonStep number={2} title="Implement the Zod 4 schema and typed output" file="labs/zod-safeparse-issues/starter/solution.ts" expected="Return ok=false and issue paths for invalid email or age; never throw for normal validation failures.">

```ts
import * as z from 'zod';
const Signup=z.strictObject({email:z.email(),age:z.number().int().min(18)});
export function validateSignup(input:unknown){
 const parsed=Signup.safeParse(input);
 if(parsed.success)return {ok:true as const,data:parsed.data,issues:[]};
 return {ok:false as const,issues:parsed.error.issues.map(issue=>({
  path:issue.path.map(String).join('.'),message:issue.message,
 }))};
}
```

**Why this works:** Use safeParse as a discriminated result, inspect ZodError.issues with explicit paths and format field errors without leaking raw payloads.

</LessonStep>

**Representative application usage:**

```ts
import * as z from 'zod';
const Profile=z.strictObject({contact:z.email(),age:z.number().min(18)});
const checked=Profile.safeParse({contact:'bad',age:12});
if(!checked.success){
  const errors=z.flattenError(checked.error);
  console.log(errors.fieldErrors); // field-specific messages, not secrets
}
// Zod 4 uses z.treeifyError/z.flattenError, not deprecated error.flatten().
```

**Security and operations:** Never log raw rejected payloads, secrets or personal data. Validate again at server boundaries; a browser schema is for usability, not authorization.
