## The problem we're solving

The starter renders all rows no matter how many items are present. Enterprise interfaces need correct data scope, stable identities, accessible states and predictable behavior under pagination, refresh and mobile layouts.

## Build the mental model

Render a bounded visible window with overscan and preserve item IDs, keyboard navigation and screen reader access.

**Prediction:** The computed range is clamped inside the collection while accounting for overscan.

**Scope of evidence:** The instructor's local Node tests exercise a pure data transformation. TanStack Table v8 and TanStack Virtual require separate dependency installation and mounted browser tests. Never treat sorting the current server page as global sorting, or browser-side role checks as server authorization.

```tsx
export function visibleRange(total:number,start:number,count:number,overscan:number){if([total,start,count,overscan].some(x=>!Number.isSafeInteger(x)||x<0))throw new RangeError('Invalid window');return {from:Math.min(total,Math.max(0,start-overscan)),to:Math.min(total,start+count+overscan)};}
```

**Why this works:** Render a bounded visible window with overscan and preserve item IDs, keyboard navigation and screen reader access.

</LessonStep>
