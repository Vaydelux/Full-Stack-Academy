## The problem we're solving

A parser swallows an invalid JSON exception and reports success with an empty object. The practice fixture uses Node 24 ESM and synthetic data, not an external service or browser deployment.

## Build the mental model

Catch only errors you can meaningfully handle. SyntaxError from JSON.parse can become an explicit result, but valid JSON can still be the wrong shape. Unexpected errors should propagate or be handled at an appropriate boundary instead of silently changing failures into success.

**Predict before running:** Malformed syntax and invalid object shape produce distinguishable errors without inventing successful data.

<LessonStep number={2} title="Repair the semantic boundary" file="labs/js-errors/starter/solution.mjs" expected={"Malformed syntax and invalid object shape produce distinguishable errors without inventing successful data."}>

Implement the corrected behavior using the relevant lexical, prototype, module or copying rule. Preserve the named `solve` export.

```js
export function solve(raw){if(typeof raw!=='string')return {ok:false,error:'not-text'};let parsed;try{parsed=JSON.parse(raw);}catch(error){if(error instanceof SyntaxError)return {ok:false,error:'invalid-json'};throw error;}if(!parsed||typeof parsed!=='object'||Array.isArray(parsed)||typeof parsed.name!=='string')return {ok:false,error:'invalid-shape'};return {ok:true,value:{name:parsed.name}};}
```

**Why the repair works:** Catch only errors you can meaningfully handle. SyntaxError from JSON.parse can become an explicit result, but valid JSON can still be the wrong shape. Unexpected errors should propagate or be handled at an appropriate boundary instead of silently changing failures into success.

**Proof:** Compare independent instances, object identity or errors under the same test file.

</LessonStep>
