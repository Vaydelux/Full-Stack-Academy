## The problem we're solving

An authenticated user submits a title update for a project; a valid session is insufficient unless that user is authorized for the exact project.

**Symptom:** The starter grants any signed-in user write access to any project ID.

## Build the mental model

Treat every Server Action as a public mutation entry point; validate input and authorize the specific object on every request.

**Predict first:** Only a matching member with a nonblank bounded title may update a project; unauthorized access is rejected.

The local fixture tests only an isolated TypeScript/React contract; actual Server Component compilation, network transport, streaming, Server Actions, security isolation and browser hydration require a separate compiled Next.js 16 application and integration tests.

```tsx
export type Principal={id:string}|null;
export type Project={id:string;memberIds:readonly string[]};
export function canChangeTitle(principal:Principal,project:Project,title:string){
 return Boolean(principal&&project.memberIds.includes(principal.id)&&title.trim().length>=1&&title.trim().length<=120);
}
```
