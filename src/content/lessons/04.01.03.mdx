## The problem we're solving

A membership gate defaults to basic behavior for every user, even after a correctly typed pro user is supplied. The checked-in examples are TypeScript 5 modules targeting the repository's strict compiler settings. Node 24 plus the installed tsx runner execute the instructor tests without a remote environment.

## Build the mental model

Union types encode alternatives, intersection types combine required properties, and literal types constrain exact values. Static unions help exhaustive code paths but do not replace runtime validation of data arriving from external systems.

**Predict before running:** Both allowed literal tiers produce distinct outcomes while malformed external values fail.

<LessonStep number={2} title="Implement the typed repair" file="labs/ts-unions/starter/solution.ts" expected={"Both allowed literal tiers produce distinct outcomes while malformed external values fail."}>

Preserve exported `solve`; narrow unknown inputs and maintain the intended inferred/annotated return contract.

```ts
type Tier='basic'|'pro';type User={id:string}&{tier:Tier};export function solve(user:User):string{if(!user||typeof user.id!=='string'||(user.tier!=='basic'&&user.tier!=='pro'))throw new TypeError('Invalid user');return user.tier+':'+user.id;}
```

**Predict before running:** Both allowed literal tiers produce distinct outcomes while malformed external values fail.

**Why it works:** Union types encode alternatives, intersection types combine required properties, and literal types constrain exact values. Static unions help exhaustive code paths but do not replace runtime validation of data arriving from external systems.

**Proof:** Compare the repaired student's output with the instructor solution under the same typed test cases.

</LessonStep>

<LessonStep number={3} title="Exercise runtime and compiler contracts" file="labs/ts-unions/solution.test.mjs" expected="The reviewed solution has a passing strict TypeScript compile and actual regression assertions.">

```ts
assert.equal(solve({id:'u1',tier:'pro'}),'pro:u1');assert.equal(solve({id:'u2',tier:'basic'}),'basic:u2');assert.throws(()=>solve({id:'u3',tier:'other'}),TypeError);
```

**Predict before running:** Correct runtime behavior and a valid static type signature are separate, both required.

**Why it matters:** TypeScript cannot block malformed JSON after the source has been compiled; user input still needs runtime guards.

**Proof:** Run `npm run lab:ts-unions` then `npm run typecheck`.

</LessonStep>
