## The problem we're solving

The starter accepts missing label and initial focus. Advanced UI interactions need a robust identity and focus model so the component works with touch, keyboard and screen readers rather than only a mouse.

## Build the mental model

Use a named modal with correct initial focus, keyboard containment, Escape closing and focus restoration to the trigger. **Expected behavior:** A dialog plan must provide a named title, cancel action and focus target.

**Evidence boundary:** The local test checks a pure data or interaction-policy function. It does not prove DOM focus, ARIA announcements, actual event sequences, animation timing or a third-party library's mounted behavior. Use a real local browser and accessible component primitives for those claims.
