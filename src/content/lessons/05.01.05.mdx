## The problem we're solving

A feature branch has no review evidence and no diff check, so reviewers cannot distinguish the intended change from whitespace defects. This lesson is an offline, repeatable source-control exercise; it never touches the learner's actual project repository or opens a hosted pull request.

## Build the mental model

A pull request is a provider-level review workflow built around a proposed diff, status checks and human decisions. Git itself can inspect the branch range with git diff main...feature and check whitespace with --check. This offline fixture creates review evidence but deliberately does not claim to open a real GitHub PR.

**Predict before running:** The feature diff is checkable and contains specific review evidence, without creating a remote PR.

<LessonStep number={2} title="Repair the Git workflow" file="labs/git-review/starter/solution.mjs" expected={"The feature diff is checkable and contains specific review evidence, without creating a remote PR."}>

Preserve the exported `solve` contract; call the local `git` helper with explicit argument arrays rather than issuing shell strings. The instructor workflow is:

```js
export function solve({git,write}){git(['switch','-c','feature/docs']);write('note.md','New docs\n');git(['add','note.md']);git(['commit','--quiet','-m','docs: add guide']);const checked=git(['diff','--check','main...feature/docs']);if(checked.status!==0)throw new Error('Whitespace diff');write('REVIEW.md','Scope: documentation\nVerification: git diff --check main...feature/docs\nReviewer question: Are new terms accurate?\n');git(['add','REVIEW.md']);git(['commit','--quiet','-m','docs: describe review evidence']);}
```

**Predict before running:** The feature diff is checkable and contains specific review evidence, without creating a remote PR.

**Why it works:** A pull request is a provider-level review workflow built around a proposed diff, status checks and human decisions. Git itself can inspect the branch range with git diff main...feature and check whitespace with --check. This offline fixture creates review evidence but deliberately does not claim to open a real GitHub PR.

**Proof:** The same deterministic fixture should now satisfy the intended history, index and working-tree state.

</LessonStep>

assert.match(git(['diff','--name-only','main...feature/docs']).stdout,/note\.md/);assert.match(git(['show','HEAD:REVIEW.md']).stdout,/Reviewer question/);assert.equal(git(['diff','--check','main...feature/docs']).status,0);
