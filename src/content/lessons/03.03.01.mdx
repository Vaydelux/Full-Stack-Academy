## The problem we're solving

A developer expects a timer callback to execute before synchronous statements and an already-resolved promise reaction. This lab uses local Node.js timers, Promises and injected mock transport rather than relying on external APIs or a deployed site.

## Build the mental model

Synchronous code completes on the call stack; promise reactions run as microtasks at a microtask checkpoint; timer callbacks run in a later task. A scheduled timer never interrupts the current synchronous stack.

**Predict before running:** The synchronous final step appears before the promise reaction, which appears before the timer.

<LessonStep number={2} title="Apply the async boundary and handle errors" file="labs/js-event-loop/starter/solution.mjs" expected={"The synchronous final step appears before the promise reaction, which appears before the timer."}>

Make the smallest meaningful correction and preserve the `solve` module contract. For transport cases, keep request functions injectable so the same test can simulate success, failure, timeout and cancellation.

```js
export async function solve(){const events=['sync'];setTimeout(()=>events.push('timer'),0);Promise.resolve().then(()=>events.push('promise'));events.push('end-sync');await new Promise(resolve=>setTimeout(resolve,10));return events;}
```

**Predict before running:** The synchronous final step appears before the promise reaction, which appears before the timer.

**Why it works:** Synchronous code completes on the call stack; promise reactions run as microtasks at a microtask checkpoint; timer callbacks run in a later task. A scheduled timer never interrupts the current synchronous stack.

**Proof:** Verify that all promises settle and timer/listener cleanup occurs even after failure.

</LessonStep>
