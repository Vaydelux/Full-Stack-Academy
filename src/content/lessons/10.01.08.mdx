## The problem we're solving

A service accepts an upload as a single unbounded buffer, letting large requests exhaust memory and suppressing useful integrity information.

**Deliberate defect:** The starter hashes arbitrarily large content because it never checks the advertised byte budget. This exercise runs under Node.js 24 using built-in modules—no paid service, hosted data source or arbitrary learner-code runner.

## Build the mental model

Hash the incoming stream incrementally using node:crypto and enforce a strict byte ceiling before retaining or persisting any bytes.

**Predict before writing code:** A small upload returns the correct SHA-256 digest; an oversized one fails before completion.

The exact Node.js API documentation is linked below. These exercises model concrete runtime behavior, not a screenshot of a server. They must not be interpreted as proof of container permission boundaries, a production reverse proxy or multi-process request isolation.

```js
import {Readable} from 'node:stream';
import {createHash} from 'node:crypto';
export async function digestUpload(chunks,maxBytes){
 if(!Number.isSafeInteger(maxBytes)||maxBytes<0)throw new RangeError('Invalid byte limit');
 const hash=createHash('sha256');let bytes=0;
 for await(const item of Readable.from(chunks)){
  const chunk=Buffer.isBuffer(item)?item:Buffer.from(item);
  bytes+=chunk.byteLength;
  if(bytes>maxBytes)throw new RangeError('Upload too large');
  hash.update(chunk);
 }
 return {bytes,sha256:hash.digest('hex')};
}
```

**Causal reasoning:** Hash the incoming stream incrementally using node:crypto and enforce a strict byte ceiling before retaining or persisting any bytes.

</LessonStep>
