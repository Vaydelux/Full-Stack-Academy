## The problem we're solving

A course search sorts by title, but mutating the input list breaks other consumers and makes caching unreliable. **Failure case:** The starter sorts the original array in place, changing a parent-owned collection.

## Build the mental model

Use memoization only for measured costly derived work or stable callback identity needed by memoized children.

**Expected result:** Sorting returns a new filtered list and preserves the original input order.

**Evidence boundary:** Node tests run reviewed fixtures, not arbitrary learner code. React server markup proves initial output only. A browser or configured DOM environment is required for real user events, hydration, the React DevTools Profiler, and state preservation after reordering. This repo does not currently declare or lock React Testing Library; do not claim these Node checks exercise that dependency.

```tsx
import {useMemo,useState} from 'react';
export function selectCourses(courses:readonly string[],query:string){
 const normalized=query.trim().toLocaleLowerCase();
 return courses.filter(x=>x.toLocaleLowerCase().includes(normalized)).sort((a,b)=>a.localeCompare(b));
}
export function CoursePicker({courses}:{courses:readonly string[]}){
 const [query,setQuery]=useState('');
 const visible=useMemo(()=>selectCourses(courses,query),[courses,query]);
 return <section><label htmlFor="course-query">Course</label>
 <input id="course-query" value={query} onChange={e=>setQuery(e.target.value)}/>
 <ul>{visible.map(course=><li key={course}>{course}</li>)}</ul></section>;
}
```
