## The problem we're solving

Two independent click counters unexpectedly share one mutable module-level count. This workshop uses independent local modules and synthetic data; the code can be run with Node.js 24 without an account, network request, credential, or Vercel build.

## Build the mental model

A closure retains access to its lexical environment after its outer function returns. Factory-local state gives each instance independent behavior; exposed methods can return values without leaking the private mutable binding.

**Predict before running:** Two created counters retain different private values regardless of call order.

<LessonStep number={2} title="Repair the underlying language rule" file="labs/js-closures/starter/solution.mjs" expected={"Two created counters retain different private values regardless of call order."}>

Replace the defective implementation with an explicit, minimal solution. Preserve the exported function name so the same tests exercise both versions.

```js
export function solve(start=0){if(!Number.isInteger(start))throw new TypeError('Integer start required');let count=start;return Object.freeze({increment(){return ++count;},value(){return count;}});}
```

**Why it works:** A closure retains access to its lexical environment after its outer function returns. Factory-local state gives each instance independent behavior; exposed methods can return values without leaking the private mutable binding.

**Proof:** Run the starter verifier again and compare the results with the instructor implementation.

</LessonStep>
