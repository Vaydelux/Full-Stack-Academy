## The problem we're solving

An activity counter must derive its label from the latest input without changing an external singleton while rendering. **Failure case:** The starter transforms every count into a fixed label, concealing a stale snapshot.

## Build the mental model

Keep render logic pure because React may start, replay, interrupt or discard render work before a commit.

**Expected result:** Each input produces a deterministic derived description, including zero and plural cases.

**Evidence boundary:** Node tests run reviewed fixtures, not arbitrary learner code. React server markup proves initial output only. A browser or configured DOM environment is required for real user events, hydration, the React DevTools Profiler, and state preservation after reordering. This repo does not currently declare or lock React Testing Library; do not claim these Node checks exercise that dependency.

```tsx
import {useState,useTransition} from 'react';
export function activityLabel(count:number){
 if(!Number.isSafeInteger(count)||count<0)throw new RangeError('Count must be nonnegative');
 return count===1?'1 activity':`${count} activities`;
}
export function ActivityPanel(){
 const [count,setCount]=useState(0);const [pending,startTransition]=useTransition();
 return <section><button type="button" onClick={()=>startTransition(()=>setCount(n=>n+1))}>Add activity</button>
 <p role="status">{pending?'Updating':activityLabel(count)}</p></section>;
}
```

**Why this works:** Keep render logic pure because React may start, replay, interrupt or discard render work before a commit.

</LessonStep>

assert.equal(mod.activityLabel(1),'1 activity');assert.equal(mod.activityLabel(4),'4 activities');assert.throws(()=>mod.activityLabel(-1),RangeError);
assert.match(renderToStaticMarkup(createElement(mod.ActivityPanel)),/0 activities/);

**Beyond the static model:** Concurrency is not parallel JavaScript execution. Urgent UI (input text, focus) remains responsive while React schedules lower-priority rendering; side effects belong after commit, not in render. An SSR assertion cannot prove interruptions.
