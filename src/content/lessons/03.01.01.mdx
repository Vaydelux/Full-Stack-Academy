## The problem we're solving

An invoice accumulator leaks state between runs and mishandles shadowed block variables. This workshop uses independent local modules and synthetic data; the code can be run with Node.js 24 without an account, network request, credential, or Vercel build.

## Build the mental model

A let binding has block scope; const prevents rebinding, not mutation of referenced objects. A fresh function-local accumulator makes repeated calls independent; var is function-scoped and can blur intended boundaries.

**Predict before running:** A separate call starts its accumulator at zero and refuses non-finite inputs.

<LessonStep number={2} title="Repair the underlying language rule" file="labs/js-scope/starter/solution.mjs" expected={"A separate call starts its accumulator at zero and refuses non-finite inputs."}>

Replace the defective implementation with an explicit, minimal solution. Preserve the exported function name so the same tests exercise both versions.

```js
export function solve(values) { let total=0; for (const value of values) { if (!Number.isFinite(value)) throw new TypeError('Finite numbers required'); total+=value; } return total; }
```

**Why it works:** A let binding has block scope; const prevents rebinding, not mutation of referenced objects. A fresh function-local accumulator makes repeated calls independent; var is function-scoped and can blur intended boundaries.

**Proof:** Run the starter verifier again and compare the results with the instructor implementation.

</LessonStep>
