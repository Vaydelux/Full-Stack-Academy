## The problem we're solving

A dashboard says its data load failed, but no one recorded whether the request reached the server, returned a non-2xx response or contained malformed JSON. Debugging from a red error banner alone leads to untestable guesses. We will build a repeatable local probe and record the exact evidence that distinguishes response, transport and parsing.

## Build the mental model

A request investigation follows trigger, request URL/method, response status, content type, body parse and UI outcome. DevTools Network and Console record different parts of this story. A Blob URL can be fetched locally without contacting a remote service; a new Response with 503 is a simulator, not an observed HTTP 503 over the network. Keep those distinctions honest. Real user tokens, cookies and query secrets should be removed from shared screenshots or logs.

**Predict before running:** The Blob URL request resolves and parses valid JSON. Simulating a 503 Response should report 503; malformed JSON should report a parsing failure. Only the Blob fetch produces an actual fetch entry.

<LessonStep number={1} title={"Make a reproducible local fetch"} file="labs/web-devtools/starter/index.html" expected={"A local blob: fetch can appear in Network but does not contact an Internet API."}>

Create a JSON Blob and object URL, fetch it, then revoke the URL.

```js
const blob = new Blob([JSON.stringify({items:['DOM','Fetch']})],
  {type:'application/json'});
const url = URL.createObjectURL(blob);
try { const response = await fetch(url); /* inspect */ }
finally { URL.revokeObjectURL(url); }
```

**Predict before running:** A local blob: fetch can appear in Network but does not contact an Internet API.

**Why it works:** Isolating the transport makes test results deterministic and keeps real data out.

**Proof it works:** Open Network, click Inspect local request, and filter for blob.

</LessonStep>


<LessonStep number={2} title={"Classify the response"} file="labs/web-devtools/starter/index.html" expected={"The valid Blob returns two entries; a constructed 503 Response does not."}>

Check status before parsing; keep a simulated HTTP failure clearly labeled.

```js
if (!response.ok) throw new Error('HTTP ' + response.status);
const payload = await response.json();
status.textContent = payload.items.length + ' local entries';
```

**Predict before running:** The valid Blob returns two entries; a constructed 503 Response does not.

**Why it works:** A non-2xx response and a JSON parsing exception are distinct debugging branches.

**Proof it works:** Compare visible messages for the three local actions.

</LessonStep>
