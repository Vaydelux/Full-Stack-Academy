## The problem we're solving

A dashboard needs to show a count without writing directly into DOM nodes while rendering. Mixing DOM writes into render can produce effects for renders that React later discards. This lesson uses local React 19 / TypeScript 5 fixtures; the website does not execute learner-provided code.

## Build the mental model

Separate pure render calculations from the browser's eventual DOM commit. No. React can evaluate renders before choosing what DOM changes, if any, to commit. A React element is a description of UI; server rendering verifies initial markup but cannot, by itself, prove a browser interaction, reconciliation, or a DOM commit.

**Predict before you run:** A deterministic formatter creates identical labels for identical inputs and a semantic view renders them.

Replace the starter's implementation with the reviewed approach below. Keep its public exports stable.

```tsx
export function formatCount(count:number) {
  if(!Number.isSafeInteger(count)||count<0) throw new RangeError('Invalid count');
  return count===1 ? '1 notification' : `${count} notifications`;
}
export function NotificationSummary({count}:{count:number}) {
  return <p aria-live="polite">{formatCount(count)}</p>;
}
```

**Predict before you run:** A deterministic formatter creates identical labels for identical inputs and a semantic view renders them.

**Why the repair works:** Separate pure render calculations from the browser's eventual DOM commit.
