## The problem we're solving

After a content update, a reader still sees a stale article. A debugger needs to distinguish untagged content, wrongly scoped cache keys and missing invalidation.

**Failure mode:** The starter always reports 'cache healthy', even for private data or missing tags.

## Build the mental model

Diagnose the cache scope, tag identity and invalidation event before changing TTL values or adding extra caches. This module specifically uses **Next.js 16 with `cacheComponents: true`**; avoid mixing with the legacy `dynamic`, route-segment `revalidate` or `fetchCache` configuration model. The offline assertions are data/decision models; they do not access Next's actual cache internals, HTTP, or database.

**Expected behavior:** Missing tags and unsafe shared-private cache are flagged; a public tagged cache is accepted.

```tsx
export function cacheDiagnosis(scope:'public'|'private',tag:string){
 if(scope==='private')return 'unsafe-shared-scope';
 if(!/^courses:[a-z0-9-]+$/.test(tag))return 'missing-or-invalid-tag';
 return 'healthy';
}
```
