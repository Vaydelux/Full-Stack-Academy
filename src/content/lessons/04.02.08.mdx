## The problem we're solving

A function asserts that arbitrary JSON contains a valid email and crashes when the payload is missing or malformed. This advanced-types lab requires both compile-time evidence and meaningful runtime behavior; TypeScript's erased types alone cannot fix logic bugs.

## Build the mental model

An as assertion changes what the compiler assumes, not what runtime data actually contains. Narrow unknown using guards and return a discriminated Result for expected validation failures. Avoid double casts as a substitute for schema parsing.

**Predict before running:** Malformed payloads produce explicit validation failures without property-access crashes.

<LessonStep number={2} title="Implement the correct type/runtime relationship" file="labs/ts-unsafe-casts/starter/solution.ts" expected={"Malformed payloads produce explicit validation failures without property-access crashes."}>

Preserve exported `solve` and tighten the behavior without adding an unsound `as any` cast.

```ts
export type Result={ok:true;email:string}|{ok:false;error:string};export function solve(raw:unknown):Result{if(!raw||typeof raw!=='object'||!('email' in raw)||typeof raw.email!=='string')return {ok:false,error:'missing-email'};const email=raw.email.trim().toLowerCase();if(!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email))return {ok:false,error:'invalid-email'};return {ok:true,email};}
```

**Predict before running:** Malformed payloads produce explicit validation failures without property-access crashes.

**Why the fix works:** An as assertion changes what the compiler assumes, not what runtime data actually contains. Narrow unknown using guards and return a discriminated Result for expected validation failures. Avoid double casts as a substitute for schema parsing.

**Proof:** The same Node test now passes; the separate compiler-negative test rejects invalid static usage.

</LessonStep>
