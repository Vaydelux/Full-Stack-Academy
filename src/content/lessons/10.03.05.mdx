## The problem we're solving

The starter trusts the declared Content-Length and never counts actual streamed bytes. Real services must establish who can request a resource, constrain how the request is interpreted, and prevent unexpected data disclosure.

## Build the mental model

Enforce a preflight Content-Length ceiling and independently count streamed bytes, rejecting mismatched and oversized bodies.

**Expected outcome:** Actual multibyte payloads count true bytes and oversized or mismatched bodies fail.

**Production boundary:** Production uploads also need timeout limits, content scanning, quotas, storage isolation, stream cancellation and safe file names.

```js
export async function readBounded(chunks,limit,declared){
 if(!Number.isSafeInteger(limit)||limit<0)throw new RangeError('Invalid limit');
 if(declared!==undefined&&(!Number.isSafeInteger(declared)||declared<0||declared>limit))throw new RangeError('Declared body too large');
 const data=[];let count=0;
 for await(const value of chunks){
  const chunk=Buffer.isBuffer(value)?value:Buffer.from(value);
  count+=chunk.byteLength;
  if(count>limit)throw new RangeError('Body too large');
  data.push(chunk);
 }
 if(declared!==undefined&&count!==declared)throw new RangeError('Mismatched length');
 return Buffer.concat(data);
}
```

**Why this works:** Enforce a preflight Content-Length ceiling and independently count streamed bytes, rejecting mismatched and oversized bodies.

</LessonStep>
