## The problem we're solving

A large catalogue search blocks typing when the filtering work is coupled to every high-priority input update. The starter ignores the query and displays stale results even when a new search term is supplied.

## Build the mental model

Schedule nonurgent result updates in a Transition while keeping controlled typing responsive. Updates driving the controlled input must remain synchronous; a Transition can schedule less urgent result work. The React 19 APIs used here have distinct contracts: context passes values, transitions schedule nonurgent updates, deferred values let rendering lag, and optimistic state is a temporary view during an Action. These lessons use local data, not backend persistence.

**Predict before you run:** The pure filter finds only matching entries and preserves source order; initial React markup lists all entries.

The instructor repair preserves the public exports while fixing the value propagation, scheduling, or state reconciliation defect:

```tsx
import {useState,useTransition} from 'react';
export function matchOptions(options:readonly string[],query:string){
 const needle=query.trim().toLocaleLowerCase();
 return options.filter(option=>option.toLocaleLowerCase().includes(needle));
}
export function TransitionSearch({options}:{options:readonly string[]}){
 const [query,setQuery]=useState('');const [resultQuery,setResultQuery]=useState('');
 const [pending,startTransition]=useTransition();
 return <section><label htmlFor="transition-query">Search</label>
 <input id="transition-query" value={query} onChange={e=>{const next=e.target.value;setQuery(next);startTransition(()=>setResultQuery(next));}}/>
 {pending&&<p role="status">Updating results</p>}
 <ul>{matchOptions(options,resultQuery).map(option=><li key={option}>{option}</li>)}</ul></section>;
}
```
