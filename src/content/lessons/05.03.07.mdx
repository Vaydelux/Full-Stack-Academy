## The problem we're solving

An automated dependency update is treated as risk-free even when a new major version can break public APIs. This offline workshop is part of the Git/monorepo track; no workspace installation, external package query or Vercel build runs when reading the lesson.

## Build the mental model

SemVer categorizes compatibility expectations, not security guarantees. Review changelogs, advisories, peer-dependency constraints and integration tests before updating; pin tested versions in the lockfile. This exercise analyzes synthetic pinned versions only and does not pretend to query today's registry.

**Predict before running:** Major/minor/patch changes are classified accurately, while downgrades and unchanged pins are explicit.

```js
export function solve(current,next){if(!/^\d+\.\d+\.\d+$/.test(current)||!/^\d+\.\d+\.\d+$/.test(next))throw new TypeError('Stable versions required');const a=current.split('.').map(Number),b=next.split('.').map(Number);if(b[0]<a[0]||(b[0]===a[0]&&b[1]<a[1])||(b[0]===a[0]&&b[1]===a[1]&&b[2]<a[2]))return 'downgrade';if(b[0]!==a[0])return 'major';if(b[1]!==a[1])return 'minor';if(b[2]!==a[2])return 'patch';return 'unchanged';}
```
