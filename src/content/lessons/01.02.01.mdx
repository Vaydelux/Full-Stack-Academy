## The problem we're solving

A registration form relies on placeholders instead of labels. When the visitor starts typing, the instructions disappear; a screen-reader user cannot identify the fields or the choice group.

## Build the mental model

A form control needs a programmatically associated label: use `label for` matching the control ID, or nest an input inside a label. Placeholder text does not replace a label. The `name` identifies a field for submission; the `id` connects references inside this document. `fieldset` and `legend` group related radio controls into a named choice. `aria-describedby` adds instructions without replacing the accessible name. Avoid unnecessary ARIA when native elements already encode semantics.

**Predict before running:** Will an input become correctly labeled merely because it contains a placeholder with a description? No: the placeholder is not a label.

<LessonStep number={1} title={"Build an explicitly labeled text input"} file="labs/forms-labels/starter/index.html" expected={"Clicking the label focuses its corresponding input."}>

The name field has a persistent label that works even after typing.

```html
<label for="full-name">Full name</label>
<input id="full-name" name="fullName" autocomplete="name" required>
```

</LessonStep>

<LessonStep number={2} title={"Connect help text to a separate control"} file="labs/forms-labels/starter/index.html" expected={"Accessibility inspection reads the field name and helpful description."}>

Use aria-describedby for format guidance; the label stays the accessible name.

```html
<label for="contact-email">Contact email</label>
<p id="email-hint">Use an address you can access.</p>
<input id="contact-email" name="email" type="email" aria-describedby="email-hint" required>
```

</LessonStep>

<LessonStep number={3} title={"Group exclusive choices with native elements"} file="labs/forms-labels/starter/index.html" expected={"Only one session can be selected at a time, and the group has a visible legend."}>

Radio inputs with the same name form a set and their fieldset provides the group label.

```html
<fieldset>
  <legend>Preferred session</legend>
  <label><input type="radio" name="session" value="morning" required> Morning</label>
  <label><input type="radio" name="session" value="afternoon"> Afternoon</label>
</fieldset>
```

</LessonStep>

## Bug Hunt: identify the root cause

The contact field's visible label points at `id=contact`, but the input is `id=contact-email`. Fix the association, then verify the browser exposes both name and description.
