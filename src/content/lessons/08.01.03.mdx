## The problem we're solving

An overlay merely toggles display:none and never gives its content a name or a predictable modal state.

## Build the mental model

Radix primitives provide behavioral foundations for dialogs, menus and other interactive patterns, but Radix must be selected and installed deliberately. Newer shadcn/ui configurations may use Base UI instead; the chosen primitive system determines the actual composition API.

**Predict first:** An open dialog advertises its dialog role and accessible name; focus management still needs a real primitive and browser test.

## Production library pattern

```tsx
"use client";
import * as Dialog from "@radix-ui/react-dialog";
export function ConfirmDialog(){return <Dialog.Root><Dialog.Trigger>Open</Dialog.Trigger><Dialog.Portal><Dialog.Overlay/><Dialog.Content><Dialog.Title>Confirm action</Dialog.Title><Dialog.Description>Review this choice.</Dialog.Description><Dialog.Close>Cancel</Dialog.Close></Dialog.Content></Dialog.Portal></Dialog.Root>;}
```

Radix package installation and interactive focus tests are required. This academy fixture only checks static semantics, and the illustrative Radix snippet is not compiled by the lab.
