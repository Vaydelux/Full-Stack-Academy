## The problem we're solving

A destructive record-delete action commits immediately with no confirmation or undo path, causing irreversible mistakes.

## Build the mental model

Good interface behavior makes system status visible, prevents predictable errors, supports recovery and uses consistent controls. Actions with destructive consequences need an appropriate confirmation or undo mechanism without unnecessary dialogs for harmless operations.

**Predict first:** A destructive delete cannot proceed with the same no-confirmation policy as harmless viewing.
