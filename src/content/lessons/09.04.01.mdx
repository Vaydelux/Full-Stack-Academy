## The problem we're solving

A global dialog should be controlled by transient UI state, but a developer accidentally ignores the requested open/close action and confuses it with server records.

**Broken behavior:** The starter's setOpen action always closes the dialog, so shared UI state cannot respond to an open request.

## Build the mental model

Use Zustand for genuinely shared client UI state, the URL for linkable filters and a dedicated data cache for remote server records.

**Predict:** A new vanilla Zustand store begins closed and responds to both open and close actions.

**Evidence boundary:** The local test imports the real Zustand 5 `createStore` API and, where appropriate, the official middleware. The store is created afresh per test; it does not use a global request-scoped server singleton. Passing Node assertions does not prove browser hydration, cross-tab synchronization or HTTP authorization.
