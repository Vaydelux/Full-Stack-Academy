## The problem we're solving

A reset selector repeatedly overrides component styles, so developers keep adding specificity. Our task is to repair the actual style behavior, not just make a static screenshot look convincing. This workshop uses synthetic content in a standalone offline HTML file; it needs no account, cloud API or deployed preview.

## Build the mental model

Cascade layers establish an explicit priority before specificity is compared. Among normal author declarations, later declared layers take precedence over earlier ones. For important declarations, layer precedence reverses; unlayered normal author styles outrank layered normal author styles.

**Predict before running:** The action button uses the components layer's dark teal background.

## Guided implementation

<LessonStep number={1} title="Reproduce and inspect the failing state" file="labs/css-layers/starter/index.html" expected="The component layer omits background, so the button inherits the reset background.">

Start from the intentionally incorrect declaration and inspect the matched and computed styles. Before making changes, determine which element owns the value and whether a CSS rule is matched but overridden.

```css
@layer reset, components; @layer reset { button { background: #ddd; color: #222; } } @layer components { .action { color: #fff; } }
```

**Predict before running:** The component layer omits background, so the button inherits the reset background.

**Why it fails:** Cascade layers establish an explicit priority before specificity is compared. Among normal author declarations, later declared layers take precedence over earlier ones. For important declarations, layer precedence reverses; unlayered normal author styles outrank layered normal author styles.

**Proof:** Open DevTools, select the target element, and confirm the failing computed property. Write the observed value before replacing the rule.

</LessonStep>

<LessonStep number={2} title="Apply the targeted CSS repair" file="labs/css-layers/starter/index.html" expected="The action button uses the components layer's dark teal background.">

Replace the incorrect rule with the following CSS. Keep the native HTML controls and all semantic content unchanged.

```css
@layer reset, components; @layer reset { button { background: #ddd; color: #222; } } @layer components { .action { background: #075e7b; color: #fff; } }
```

**Predict before running:** The action button uses the components layer's dark teal background.

**Why it works:** Cascade layers establish an explicit priority before specificity is compared. Among normal author declarations, later declared layers take precedence over earlier ones. For important declarations, layer precedence reverses; unlayered normal author styles outrank layered normal author styles.

**Proof:** getComputedStyle(action).backgroundColor matches the component layer's value.

</LessonStep>

<LessonStep number={3} title="Verify responsiveness and interaction" file="labs/css-layers/starter/index.html" expected="The repaired solution works at narrow and wide viewports without hiding keyboard focus or producing horizontal overflow.">

Use DevTools Responsive Design Mode: select a 320px width, then a wide desktop width. Inspect the relevant computed style again. Where the lab includes a button or writing-direction toggle, test it using Tab and Enter.

```js
const target = document.querySelector('.card');
console.log(getComputedStyle(target).boxSizing);
console.log(document.documentElement.scrollWidth <= innerWidth);
```

**Predict before running:** A visible computed property changes as described, but the document remains scrollable normally with no unwanted horizontal overflow.

**Why it works:** Browser-computed styles and measured dimensions describe actual rendered rules, rather than assuming the presence of source text is enough.

**Proof:** Compare the computed result with the instructor solution and record one failing case from the original starter.

</LessonStep>
