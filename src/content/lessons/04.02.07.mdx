## The problem we're solving

A key validator accepts any string containing a colon, including unrecognized prefixes and empty identifiers. This advanced-types lab requires both compile-time evidence and meaningful runtime behavior; TypeScript's erased types alone cannot fix logic bugs.

## Build the mental model

Template literal types encode string shape patterns in the type system, such as course:${string} and topic:${string}. The type does not validate runtime strings; a user-defined guard must still check the permitted prefix and nonempty payload.

**Predict before running:** Recognized namespaces with nonempty identifiers pass; unrelated prefixes and empty values fail.

<LessonStep number={2} title="Implement the correct type/runtime relationship" file="labs/ts-template-literals/starter/solution.ts" expected={"Recognized namespaces with nonempty identifiers pass; unrelated prefixes and empty values fail."}>

Preserve exported `solve` and tighten the behavior without adding an unsound `as any` cast.

```ts
export type Key=`course:${string}`|`topic:${string}`;export function solve(raw:string):raw is Key{return typeof raw==='string'&&(/^(course|topic):[^\s:][^\s]*$/.test(raw));}
```

**Predict before running:** Recognized namespaces with nonempty identifiers pass; unrelated prefixes and empty values fail.

**Why the fix works:** Template literal types encode string shape patterns in the type system, such as course:${string} and topic:${string}. The type does not validate runtime strings; a user-defined guard must still check the permitted prefix and nonempty payload.

**Proof:** The same Node test now passes; the separate compiler-negative test rejects invalid static usage.
