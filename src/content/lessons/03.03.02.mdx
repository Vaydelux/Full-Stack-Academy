## The problem we're solving

A trace puts a setTimeout callback before queueMicrotask and Promise.then reactions that were scheduled in the same turn. This lab uses local Node.js timers, Promises and injected mock transport rather than relying on external APIs or a deployed site.

## Build the mental model

Microtasks drain after the current task's synchronous work, before the next timer task. Overusing queueMicrotask can starve rendering because each queued microtask may schedule more microtasks. Use short isolated examples to reason about ordering, not timing claims.

**Predict before running:** Both microtasks finish in registration order before a zero-delay timer callback.

<LessonStep number={2} title="Apply the async boundary and handle errors" file="labs/js-microtasks/starter/solution.mjs" expected={"Both microtasks finish in registration order before a zero-delay timer callback."}>

Make the smallest meaningful correction and preserve the `solve` module contract. For transport cases, keep request functions injectable so the same test can simulate success, failure, timeout and cancellation.

```js
export async function solve(){const out=['sync'];queueMicrotask(()=>out.push('queueMicrotask'));Promise.resolve().then(()=>out.push('promise'));setTimeout(()=>out.push('timer'),0);await new Promise(resolve=>setTimeout(resolve,10));return out;}
```

**Predict before running:** Both microtasks finish in registration order before a zero-delay timer callback.

**Why it works:** Microtasks drain after the current task's synchronous work, before the next timer task. Overusing queueMicrotask can starve rendering because each queued microtask may schedule more microtasks. Use short isolated examples to reason about ordering, not timing claims.

**Proof:** Verify that all promises settle and timer/listener cleanup occurs even after failure.

</LessonStep>
