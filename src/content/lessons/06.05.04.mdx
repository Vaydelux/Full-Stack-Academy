## The problem we're solving

A list looks sluggish and an engineer must summarize Profiler durations without calling every render a regression. **Failure case:** The starter calculates zero for every profiler sample, hiding evidence that a render consumed time.

## Build the mental model

Measure before optimizing. Distinguish actual duration, base duration and a rendering event rather than assuming every render is waste.

**Expected result:** The profiler summary returns a finite total duration and correct sample count.

**Evidence boundary:** Node tests run reviewed fixtures, not arbitrary learner code. React server markup proves initial output only. A browser or configured DOM environment is required for real user events, hydration, the React DevTools Profiler, and state preservation after reordering. This repo does not currently declare or lock React Testing Library; do not claim these Node checks exercise that dependency.

```tsx
import {Profiler,type ReactNode} from 'react';
export function summarizeRenders(samples:readonly number[]){
 if(samples.some(x=>!Number.isFinite(x)||x<0))throw new RangeError('Invalid render sample');
 return {count:samples.length,totalMs:samples.reduce((sum,x)=>sum+x,0)};
}
export function ProfiledSection({children,onRender}:{children:ReactNode;onRender:(id:string,phase:'mount'|'update'|'nested-update',actualDuration:number)=>void}){
 return <Profiler id="section" onRender={(id,phase,duration)=>onRender(id,phase,duration)}>{children}</Profiler>;
}
```

**Why this works:** Measure before optimizing. Distinguish actual duration, base duration and a rendering event rather than assuming every render is waste.

</LessonStep>
