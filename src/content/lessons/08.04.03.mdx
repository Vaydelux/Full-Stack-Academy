## The problem we're solving

The starter never marks an invalid field or links it to an error description. Mature design QA tests user comprehension, accessibility, visual hierarchy and realistic layout under stress, not merely whether an interface renders.

## Build the mental model

Associate persistent visible labels and error descriptions with each input, and announce actionable validation feedback.

**Expected outcome:** Invalid fields reference an error ID and aria-invalid; valid fields omit stale errors.

**Evidence boundary:** This local test verifies a deterministic model or audit decision. It cannot claim a WCAG audit, human usability result, assistive technology behavior, actual CLS/LCP measurement, or cross-browser compatibility. Collect those in a real locally served application with documented scenarios.

**Representative UI example and QA checklist:**

```tsx
<form><label htmlFor="email">Email address</label><input id="email" type="email" aria-invalid="true" aria-describedby="email-error"/><p id="email-error">Enter a valid email address.</p><button>Continue</button></form>
// A server must validate too; ARIA and native validity are not permission checks.
```

A high-quality release gate combines keyboard and touch interaction, actual screen-reader observations, image/embedding stability, and valid WCAG/heuristic assessment.

</LessonStep>
