## The problem we're solving

A component's colors are hardcoded in multiple declarations, so switching theme variables has no effect. We will repair a specific CSS behavior in an offline component so that a future design system has predictable boundaries. There is no external font, image or API dependency.

## Build the mental model

Custom properties participate in the cascade and are resolved when var() is used. A token such as --surface is a value contract, not a global constant; descendants can override it for nested themes. Provide sensible fallbacks and avoid assuming every color combination meets contrast requirements.

**Predict before running:** Clicking Switch component tokens updates the actual surface and text color without rewriting hardcoded declarations.

## Explore and verify

A syntactically valid color, selector or animation is not necessarily accessible or performant. Test color contrast for actual foreground/background pairs; preserve focus, reduced-motion behavior and narrow layouts. The Node fixture assertions check reviewed CSS patterns, and Chromium independently checks representative rendered behavior. Neither constitutes a full multi-device accessibility certification.
