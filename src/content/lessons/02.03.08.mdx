## The problem we're solving

A reusable component kit has no coherent theme contract, breaks on narrow containers and hides keyboard focus. We will repair a specific CSS behavior in an offline component so that a future design system has predictable boundaries. There is no external font, image or API dependency.

## Build the mental model

A reusable kit combines cascade-aware tokens, explicit state, accessible focus treatment, logical padding and container-driven layout. A theme toggle should update the component's tokens rather than rewriting every child style; reduced-motion preferences should simplify effects. A verified demo is not a full production design system.

**Predict before running:** The kit responds to theme changes, switches its logical accent edge in RTL, remains one column when narrow and retains visible keyboard focus.

## Prerequisites and preflight

Continue from [the previous canonical lesson](/learn/02.03.07). Open `labs/css-theme-kit/starter/index.html` locally in Chromium or another modern CSS browser, and inspect Styles/Computed in DevTools. Node.js 24 runs the static fixture tests; a private account or cloud deployment is not required.

Replace only the defective style block with this instructor implementation. Preserve native labels, buttons and focus order. Do not use blanket `!important` overrides to hide a state problem.

```css
.kit { container-type: inline-size; --surface: #ffffff; --ink: #17364a; --accent: #075e7b; padding-inline: 1rem; border-inline-start: 4px solid var(--accent); } .kit[data-theme="dark"] { --surface: #172f44; --ink: #f7fbfd; --accent: #85dff2; } .kit-card { background: var(--surface); color: var(--ink); padding: 1rem; border-radius: .5rem; } .kit-content { display: grid; grid-template-columns: minmax(0, 1fr); gap: 1rem; } @container (min-width: 32rem) { .kit-content { grid-template-columns: repeat(2, minmax(0, 1fr)); } } .kit-button:focus-visible { outline: 3px solid #c45105; outline-offset: 3px; } @media (prefers-reduced-motion: reduce) { .kit-button { transition: none; animation: none; } }
```

A theme toggle should update the component's tokens rather than rewriting every child style; reduced-motion preferences should simplify effects. A verified demo is not a full production design system.

**Proof:** Compare the computed style against the unchanged starter using the exact same browser setting.

</LessonStep>

**Predict before running:** The corrected component's computed state is consistent with the browser preference or native input state, and there is no unexpected horizontal page overflow.

## Explore and verify

A syntactically valid color, selector or animation is not necessarily accessible or performant. Test color contrast for actual foreground/background pairs; preserve focus, reduced-motion behavior and narrow layouts. The Node fixture assertions check reviewed CSS patterns, and Chromium independently checks representative rendered behavior. Neither constitutes a full multi-device accessibility certification.
