## The problem we're solving

A project is not reproducible just because the original developer can start it. Someone on a clean Windows machine or Linux environment must be able to clone, install, validate and test using documented prerequisites. This capstone makes that evidence concrete.

## Build the mental model

Configuration must be explicit: runtime version, package manager, lockfile, scripts, local settings, safe examples, and a clear README. The app must validate its config and return a failing exit code when checks fail. The commit should include the lockfile and exclude real secrets, generated outputs and node_modules. This starter is a tiny dependency-free Node project so the verification can run in a temporary copy without network access. A real production workstation may also use a version manager, Docker and service credentials; those are not necessary for this checkpoint.

<LessonStep number={2} title={"Implement safe config and the project entry point"} file="labs/workstation-capstone/starter/package.json" expected={"npm start prints a ready message using a non-secret mode and validated port."}>

Replace the starter app.mjs with the following. This is a CLI demonstration, not an HTTP service. Keep .env.example synthetic and ignore .env and other local variants.

```js
import {pathToFileURL} from 'node:url';
export function config(env) {
  const port=env.PORT??'3100';
  if(!/^\d+$/.test(port)||Number(port)<1||Number(port)>65535)throw new Error('Invalid PORT');
  const mode=env.APP_MODE??'development';
  if(!['development','test','production'].includes(mode))throw new Error('Invalid APP_MODE');
  return {port:Number(port),mode};
}
if(process.argv[1]&&import.meta.url===pathToFileURL(process.argv[1]).href){
  const value=config(process.env);
  console.log('Ready on '+value.port+' ('+value.mode+')');
}
```

</LessonStep>

<LessonStep number={3} title={"Recreate the project from a clean copy"} file="labs/workstation-capstone/starter/package.json" expected={"The solution installs, checks, tests and starts from an isolated directory."}>

Run these commands from the starter project folder. Create the lockfile intentionally before ci if you changed the manifest. The course acceptance test copies the fixture into an OS temporary directory and runs the same steps; it never modifies your global setup.

```powershell
npm install --package-lock-only --ignore-scripts --no-audit --no-fund
npm ci --ignore-scripts --no-audit --no-fund
npm run verify
npm start
```

</LessonStep>

## Bug Hunt: diagnose before you change code

A project starts only if a developer's personal environment variables already exist. Provide a safe example, validate startup configuration and document the commands. The clean-copy test must not depend on their machine.
