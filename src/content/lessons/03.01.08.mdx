## The problem we're solving

A CSV-like import pipeline retains malformed entries, changes the original source and produces nondeterministic output order. This workshop uses independent local modules and synthetic data; the code can be run with Node.js 24 without an account, network request, credential, or Vercel build.

## Build the mental model

A deterministic transformation pipeline separates validation, mapping and sorting. Keep the input immutable, reject bad numeric values, produce stable predictable output, and ensure every stage has a test including an empty input and repeated calls.

**Predict before running:** Only valid normalized records appear, alphabetized, with accurate totals and no input mutation.

<LessonStep number={2} title="Repair the underlying language rule" file="labs/js-transformer/starter/solution.mjs" expected={"Only valid normalized records appear, alphabetized, with accurate totals and no input mutation."}>

Replace the defective implementation with an explicit, minimal solution. Preserve the exported function name so the same tests exercise both versions.

```js
export function solve(rows){if(!Array.isArray(rows))throw new TypeError('Expected rows');return rows.filter(r=>r&&typeof r.name==='string'&&r.name.trim()&&Number.isInteger(r.qty)&&r.qty>=0&&Number.isFinite(r.price)&&r.price>=0).map(r=>({name:r.name.trim(),total:Math.round(r.qty*r.price*100)/100})).sort((a,b)=>a.name.localeCompare(b.name));}
```

**Why it works:** A deterministic transformation pipeline separates validation, mapping and sorting. Keep the input immutable, reject bad numeric values, produce stable predictable output, and ensure every stage has a test including an empty input and repeated calls.

**Proof:** Run the starter verifier again and compare the results with the instructor implementation.

</LessonStep>
