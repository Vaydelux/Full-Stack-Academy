## The problem we're solving

A form's click handler prevents every default action and stops keyboard submission. Another listener records raw email and password values to a debug log. Event handling should observe the correct event and prevent only the action you intend to replace.

## Build the mental model

The input event fires as a value is edited, while change generally represents a committed selection or edit and has different timing across controls. Submit belongs to a form rather than the clicked button, and normal validation prevents invalid submission. Event listeners can observe capture or bubble phases; stopPropagation affects other listeners and is not a substitute for preventDefault. Use preventDefault only when intentionally taking over a default action such as a local demo submission. A simple diagnostic should log event names and control identifiers, never private field contents.

**Predict before running:** If a submit button is activated while a required field is empty, will the form's submit event necessarily fire? No: native validation ordinarily blocks submission first.

<LessonStep number={1} title={"Attach listeners to the form and controls"} file="labs/forms-events/starter/index.html" expected={"The display reports which event occurred and its control name, not the entered data."}>

Observe event names, not user-entered values.

```js
form.addEventListener('input',event=>{
  status.textContent='Last event: input ('+event.target.name+')';
});
form.addEventListener('change',event=>{
  status.textContent='Last event: change ('+event.target.name+')';
});
```

</LessonStep>

<LessonStep number={2} title={"Intercept only the local demo submission"} file="labs/forms-events/starter/index.html" expected={"Valid Enter and button submission show the same status, with no navigation."}>

Use the form submit event rather than a button click to preserve Enter-key submission.

```js
form.addEventListener('submit',event=>{
  event.preventDefault();
  status.textContent='Local submission prevented; no data sent.';
});
```

</LessonStep>

<LessonStep number={3} title={"Keep helper buttons independent"} file="labs/forms-events/starter/index.html" expected={"The clear action leaves the form fields and URL intact."}>

A helper button uses type=button so it cannot accidentally submit.

```html
<button type="submit">Review changes</button>
<button type="button" id="clear-log">Clear event summary</button>
```

</LessonStep>

## Bug Hunt: diagnose and repair the behavior

The developer listens only for button clicks. A user submits by pressing Enter and bypasses the debug status. Listen for the form's submit event and preserve native validation.
