## The problem we're solving

A reader using landmark navigation hears only generic groups because everything is a `div`. A keyboard user must tab through every navigation link before reaching the article.

## Build the mental model

HTML landmark elements communicate document roles: `header` may represent a banner in the page context; `nav` provides navigation; `main` identifies primary content; `aside` offers complementary content; `footer` provides closing information. Their implicit accessibility roles are better than redundant `role` attributes. Most pages have only one primary `main`. If multiple navigation regions exist, give each a descriptive accessible label. A skip link provides a keyboard shortcut to primary content. Check that the target exists and focus behavior works in a real browser, not just a text regex.

**Predict before running:** If a skip link targets an ID that is absent, it is visible markup but cannot help reach main content. Test the fragment target.

## Prerequisites

Complete [the previous lesson](/learn/01.01.02) or review its objectives. A browser, text editor, Node.js 24 and this repository are enough. These examples are intentionally standalone and avoid remote services, account credentials or arbitrary browser scripts.

<LessonStep number={1} title={"Identify document regions"} file="labs/html-landmarks/starter/index.html" expected={"The accessibility tree contains meaningful navigation and main landmarks."}>

Start with `header`, `nav`, `main`, `aside` and `footer` instead of anonymous containers.

```html
<header><p>Community workshop</p></header>
<nav aria-label="Primary navigation">
  <a href="#overview">Overview</a>
  <a href="#resources">Resources</a>
</nav>
<main id="main-content"><h1 id="overview">Learn the basics</h1></main>
```

</LessonStep>

<LessonStep number={2} title={"Add a skip link before repeated navigation"} file="labs/html-landmarks/starter/index.html" expected={"Keyboard users can follow the fragment directly to the main content region."}>

Put the first focusable link at the top of body and point it at the existing main ID.

```html
<a href="#main-content">Skip to main content</a>
<!-- main later must include id="main-content" -->
```

</LessonStep>

<LessonStep number={3} title={"Name complementary content and close the page"} file="labs/html-landmarks/starter/index.html" expected={"Main, navigation and complementary content have distinct accessible contexts."}>

Use an aside with its own heading, along with a footer outside the main article.

```html
<aside aria-labelledby="resources-heading">
  <h2 id="resources-heading">Further resources</h2>
  <p>Read the workshop handbook.</p>
</aside>
<footer><p>Community learning resources.</p></footer>
```

</LessonStep>

## Explore it yourself

Open `labs/html-landmarks/starter/index.html` directly in a browser. Use DevTools Elements to compare the DOM tree with the source and inspect the accessibility tree. Change one element, reload and note the effect; do not treat a page that merely renders as evidence of complete semantics.

## Bug Hunt: diagnose before changing markup

A skip link says `href=#content`, but the main region has `id=main-content`. Fix the ID mismatch, then use the keyboard to confirm the skip link reaches the intended region.
