## The problem we're solving

A card set to 100% width overflows its small viewport after adding padding and borders. Our task is to repair the actual style behavior, not just make a static screenshot look convincing. This workshop uses synthetic content in a standalone offline HTML file; it needs no account, cloud API or deployed preview.

## Build the mental model

By default content-box adds padding and borders outside the declared width. border-box includes both in the declared width, but margins remain external. max-inline-size limits the card without relying on viewport-specific pixel calculations.

**Predict before running:** The card's border box fits within the available inline size.

## Guided implementation

<LessonStep number={1} title="Reproduce and inspect the failing state" file="labs/css-box-model/starter/index.html" expected="Content-box adds 4rem padding and border width beyond 100%.">

Start from the intentionally incorrect declaration and inspect the matched and computed styles. Before making changes, determine which element owns the value and whether a CSS rule is matched but overridden.

```css
.card { box-sizing: content-box; inline-size: 100%; max-inline-size: 34rem; padding: 2rem; border: 3px solid #195472; }
```

**Predict before running:** Content-box adds 4rem padding and border width beyond 100%.

**Why it fails:** By default content-box adds padding and borders outside the declared width. border-box includes both in the declared width, but margins remain external. max-inline-size limits the card without relying on viewport-specific pixel calculations.

**Proof:** Open DevTools, select the target element, and confirm the failing computed property. Write the observed value before replacing the rule.

</LessonStep>

<LessonStep number={2} title="Apply the targeted CSS repair" file="labs/css-box-model/starter/index.html" expected="The card's border box fits within the available inline size.">

Replace the incorrect rule with the following CSS. Keep the native HTML controls and all semantic content unchanged.

```css
.card { box-sizing: border-box; inline-size: 100%; max-inline-size: 34rem; padding: 2rem; border: 3px solid #195472; }
```

**Predict before running:** The card's border box fits within the available inline size.

**Why it works:** By default content-box adds padding and borders outside the declared width. border-box includes both in the declared width, but margins remain external. max-inline-size limits the card without relying on viewport-specific pixel calculations.

**Proof:** At 390px, documentElement.scrollWidth must be at most innerWidth.

</LessonStep>

<LessonStep number={3} title="Verify responsiveness and interaction" file="labs/css-box-model/starter/index.html" expected="The repaired solution works at narrow and wide viewports without hiding keyboard focus or producing horizontal overflow.">

Use DevTools Responsive Design Mode: select a 320px width, then a wide desktop width. Inspect the relevant computed style again. Where the lab includes a button or writing-direction toggle, test it using Tab and Enter.

```js
const target = document.querySelector('.card');
console.log(getComputedStyle(target).boxSizing);
console.log(document.documentElement.scrollWidth <= innerWidth);
```

**Predict before running:** A visible computed property changes as described, but the document remains scrollable normally with no unwanted horizontal overflow.

**Why it works:** Browser-computed styles and measured dimensions describe actual rendered rules, rather than assuming the presence of source text is enough.

**Proof:** Compare the computed result with the instructor solution and record one failing case from the original starter.

</LessonStep>
