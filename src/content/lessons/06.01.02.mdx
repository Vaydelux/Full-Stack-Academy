## The problem we're solving

A profile badge must display different people without duplicating markup or rewriting DOM nodes. A component that changes its props couples rendering to hidden mutations and becomes unpredictable. This lesson uses local React 19 / TypeScript 5 fixtures; the website does not execute learner-provided code.

## Build the mental model

Treat props as read-only inputs to a component, not mutable application state. Props are inputs owned by the parent; rendering should derive output without changing them. A React element is a description of UI; server rendering verifies initial markup but cannot, by itself, prove a browser interaction, reconciliation, or a DOM commit.

**Predict before you run:** The same component renders two distinct badges and safely escapes displayed names.

export interface BadgeProps { name: string; role: string }
export function Badge({ name, role }: BadgeProps) {
  return <article aria-label="Team member"><h2>{name}</h2><p>{role}</p></article>;

## Bug Hunt: reproduce, diagnose and repair

**Symptom:** A component that changes its props couples rendering to hidden mutations and becomes unpredictable.

**Diagnosis:** Trace the starter implementation to the first incorrect branch or missing prop; inspect the failing expected output rather than guessing about visual appearance.

**Repair:** Treat props as read-only inputs to a component, not mutable application state.

**Regression:** Re-run the local checks with altered input and verify the intended behavior without relying on Vercel, GitHub Actions, or public APIs.
