## The problem we're solving

A course detail page can read database records on the server, while a small Save button needs browser state. Marking the whole page as a Client Component would ship unnecessary code and can expose unsafe imports.

**Symptom:** The starter treats every source module as a Client Component, even when it has no client directive.

## Build the mental model

The `use client` directive defines a client module boundary, not a global rendering switch. Keep server-side data access out of the client graph.

**Predict first:** A true leading client directive is detected; an ordinary Server Component defaults to server.

The local fixture tests only an isolated TypeScript/React contract; actual Server Component compilation, network transport, streaming, Server Actions, security isolation and browser hydration require a separate compiled Next.js 16 application and integration tests.

```tsx
export type Boundary='server'|'client';
export function detectBoundary(source:string):Boundary{
 const first=source.trimStart().split(/\r?\n/,1)[0].trim();
 return /^(['"])use client\1;?$/.test(first)?'client':'server';
}
export function BoundaryLabel({source}:{source:string}){return <p>{detectBoundary(source)}</p>;}
```

**Why it works:** The `use client` directive defines a client module boundary, not a global rendering switch. Keep server-side data access out of the client graph.

</LessonStep>
