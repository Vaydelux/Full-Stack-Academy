## The problem we're solving

A modal opens but keyboard focus remains behind it, then disappears after closing. People using keyboards or assistive technology lose the current reading position.

## Build the mental model

Focus is the browser's active interaction target. Native dialog.showModal() makes the rest of the document inert while modal, applies modal semantics and handles Escape dismissal. Provide a meaningful accessible name and a predictable initial focus target; after closure focus should return to the element that opened the dialog. Avoid arbitrary positive tabindex and custom keydown Tab traps. Use the dialog close event for reliable restoration. When dynamically updating content, move focus only when needed, not after every click.

**Predict before running:** After a modal closes, users should be able to continue where they started, rather than having focus jump to the top of the document.

<LessonStep number={1} title={"Use a native modal and a descriptive title"} file="labs/a11y-focus/starter/index.html" expected={"The dialog is named and provides an explicit way to close."}>

Make the heading the dialog's accessible name.

```html
<button type="button" id="open-dialog">Review workshop settings</button>
<dialog id="settings" aria-labelledby="settings-title">
  <h2 id="settings-title">Workshop settings</h2>
  <button type="button" id="close-dialog">Close settings</button>
</dialog>
```

</LessonStep>

<LessonStep number={2} title={"Move initial focus and open with showModal"} file="labs/a11y-focus/starter/index.html" expected={"Keyboard focus is inside the modal while it is open."}>

Let the browser enforce modal inertness; focus a descriptive heading using tabindex=-1.

```js
const opener=document.querySelector('#open-dialog');
const dialog=document.querySelector('#settings');
opener.addEventListener('click',()=>{
  dialog.showModal();
  document.querySelector('#settings-title').focus();
});
```

</LessonStep>

<LessonStep number={3} title={"Restore the trigger after any close path"} file="labs/a11y-focus/starter/index.html" expected={"After closing via Escape or the button, focus returns to Review workshop settings."}>

Use the close event so both Escape and close-button behavior restore focus.

```js
dialog.addEventListener('close',()=>opener.focus());
document.querySelector('#close-dialog').addEventListener('click',()=>dialog.close());
```

</LessonStep>
