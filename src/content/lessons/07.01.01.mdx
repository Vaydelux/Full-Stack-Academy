## The problem we're solving

A documentation site must map checked-in route files to actual URLs without exposing private organizational group names.

**Failure:** The starter turns `(marketing)` into a visible URL segment, producing incorrect routes.

## Build the mental model

File-system segments determine App Router URLs. Route groups in parentheses organize files without appearing in the public pathname.

**Prediction:** Group markers disappear while real segment names remain in order.

**Proof boundary:** The local Node/TSX fixture verifies this lesson's deterministic model and initial React markup. It does **not** start Next.js, compile route conventions, simulate streaming, or prove HTTP status codes. A separately built Next application and browser/HTTP test are needed before release qualification.

```tsx
export function routeFromSegments(parts:readonly string[]){
 const segments=parts.filter(s=>s&&!/^\([^/]+\)$/.test(s)&&s!=='page.tsx');
 return '/'+segments.join('/');
}
export function RouteNotice({parts}:{parts:readonly string[]}){
 return <code>{routeFromSegments(parts)}</code>;
}
```

**Why it works:** File-system segments determine App Router URLs. Route groups in parentheses organize files without appearing in the public pathname.

</LessonStep>

<LessonStep number={3} title="Verify data/route invariants and inspect real file conventions" file="labs/next-route-segments/solution.test.mjs" expected="The instructor solution passes offline assertions; production routing remains a separate local Next build/browser gate.">

```js
assert.equal(mod.routeFromSegments(['(marketing)','products','page.tsx']),'/products');
assert.equal(mod.routeFromSegments(['guides','nextjs','page.tsx']),'/guides/nextjs');
assert.match(renderToStaticMarkup(createElement(mod.RouteNotice,{parts:['(docs)','guide','page.tsx']})),/\/guide/);
```

**Real App Router shape:**

```tsx
app/
  layout.tsx          # required root layout with <html> and <body>
  page.tsx            # /
  (marketing)/        # group not present in URL
    about/page.tsx    # /about
  guides/[slug]/page.tsx   # /guides/:slug
```

**Nuance:** Route groups do not alter URLs; they can affect layout organization and colliding paths still cause conflicts. Nested pages require an appropriate parent layout. File-system mapping is framework behavior; our offline helper only models the path convention.

</LessonStep>
