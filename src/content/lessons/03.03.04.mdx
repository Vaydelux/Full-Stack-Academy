## The problem we're solving

A dashboard loses the successful tasks whenever one independent request rejects. This lab uses local Node.js timers, Promises and injected mock transport rather than relying on external APIs or a deployed site.

## Build the mental model

Promise.all rejects when any input rejects, making it useful for all-or-nothing dependencies; Promise.allSettled returns individual fulfillment/rejection results, which is better for independent work. Choose intentionally instead of pretending partial failures are successes.

**Predict before running:** Independent successful results are preserved even when a sibling task fails.

<LessonStep number={2} title="Apply the async boundary and handle errors" file="labs/js-all-settled/starter/solution.mjs" expected={"Independent successful results are preserved even when a sibling task fails."}>

Make the smallest meaningful correction and preserve the `solve` module contract. For transport cases, keep request functions injectable so the same test can simulate success, failure, timeout and cancellation.

```js
export async function solve(tasks){if(!Array.isArray(tasks)||tasks.some(t=>typeof t!=='function'))throw new TypeError('Function tasks required');const outcomes=await Promise.allSettled(tasks.map(task=>Promise.resolve().then(task)));return {values:outcomes.filter(o=>o.status==='fulfilled').map(o=>o.value),errors:outcomes.filter(o=>o.status==='rejected').map(o=>String(o.reason instanceof Error?o.reason.message:o.reason))};}
```

**Predict before running:** Independent successful results are preserved even when a sibling task fails.

**Why it works:** Promise.all rejects when any input rejects, making it useful for all-or-nothing dependencies; Promise.allSettled returns individual fulfillment/rejection results, which is better for independent work. Choose intentionally instead of pretending partial failures are successes.

**Proof:** Verify that all promises settle and timer/listener cleanup occurs even after failure.

</LessonStep>
