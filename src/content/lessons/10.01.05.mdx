## The problem we're solving

An endpoint concatenates a user-provided file name onto a storage root, allowing ../ traversal or symbolic-link escape from the intended directory.

**Deliberate defect:** The starter joins paths without verifying the resulting file remains inside the allowed root. This exercise runs under Node.js 24 using built-in modules—no paid service, hosted data source or arbitrary learner-code runner.

## Build the mental model

Resolve the trusted root and target with fs.realpath, then check path.relative containment. Do not treat a string prefix check as filesystem security.

**Predict before writing code:** Authorized files are readable; ../ and symbolic links escaping the root are rejected.

The exact Node.js API documentation is linked below. These exercises model concrete runtime behavior, not a screenshot of a server. They must not be interpreted as proof of container permission boundaries, a production reverse proxy or multi-process request isolation.

```js
import {readFile,realpath} from 'node:fs/promises';
import {resolve,relative,isAbsolute,sep} from 'node:path';
export async function readContained(root,name){
 if(typeof name!=='string'||!name||name.includes('\0'))throw new Error('Invalid file name');
 const [base,target]=await Promise.all([realpath(root),realpath(resolve(root,name))]);
 const rel=relative(base,target);
 if(rel==='..'||rel.startsWith('..'+sep)||isAbsolute(rel))throw new Error('Path outside root');
 return readFile(target,'utf8');
}
```

**Causal reasoning:** Resolve the trusted root and target with fs.realpath, then check path.relative containment. Do not treat a string prefix check as filesystem security.

</LessonStep>
