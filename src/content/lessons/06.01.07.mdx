## The problem we're solving

A selected filter button must communicate its state and respond only when activated. Calling a handler in JSX while rendering triggers side effects before a user clicks. This lesson uses local React 19 / TypeScript 5 fixtures; the website does not execute learner-provided code.

## Build the mental model

Pass a callback to onClick; do not invoke it during rendering. onClick receives a function reference or a function that calls the desired operation on activation. A React element is a description of UI; server rendering verifies initial markup but cannot, by itself, prove a browser interaction, reconciliation, or a DOM commit.

**Predict before you run:** A button starts unpressed, exposes aria-pressed and calls the parent callback exactly once when invoked.

Replace the starter's implementation with the reviewed approach below. Keep its public exports stable.

```tsx
export function SelectionButton({selected,onToggle}:{selected:boolean;onToggle:()=>void}) {
  return <button type="button" aria-pressed={selected} onClick={onToggle}>
    {selected ? 'Selected' : 'Select'}
  </button>;
}
```

**Predict before you run:** A button starts unpressed, exposes aria-pressed and calls the parent callback exactly once when invoked.

**Why the repair works:** Pass a callback to onClick; do not invoke it during rendering.
