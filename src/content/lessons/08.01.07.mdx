## The problem we're solving

An eight-item desktop navigation is forced onto a 320px screen, producing offscreen links and keyboard focus that disappears outside the viewport.

## Build the mental model

Use a stable responsive navigation model: provide semantic nav and labeled controls, show a compact disclosure on small screens, preserve focus when collapsing and test 200% zoom. A 768px breakpoint is an example policy, not a universal guarantee.

**Predict first:** A narrow viewport chooses compact navigation, while desktop width chooses full navigation. The actual collapse animation and focus behavior still need browser QA.

## Production library pattern

```tsx
"use client";
import React,{useState} from "react";
export function MobileNav(){const [open,setOpen]=useState(false);return <><button type="button" aria-controls="links" aria-expanded={open} onClick={()=>setOpen(v=>!v)}>Menu</button><nav id="links" aria-label="Main" hidden={!open}><a href="/learn">Learn</a></nav></>;}
```

The pure contract only checks a breakpoint decision; an actual responsive layout and keyboard navigation must be measured in Chromium/Firefox/Safari.
