## The problem we're solving

The starter includes disabled and unpublished destinations in the menu. A robust component system has to work across dark and light themes, keyboard input, small screens and real data, not merely appear correct in a screenshot.

## Build the mental model

Use disclosure semantics, keyboard-operable controls and stable public navigation links independent of breakpoint. **Predict before executing:** Only visible, enabled and internal destinations remain.

**Runtime boundary:** This lesson's fixture is local TypeScript only. It does not compile Tailwind CSS, install shadcn or Radix/Base UI, mount a browser interaction, or verify visual contrast on real content. Those require a dedicated UI build and accessibility checks.

<LessonStep number={2} title="Repair the typed source contract" file="labs/ui-responsive-nav/starter/solution.tsx" expected="Only visible, enabled and internal destinations remain.">

```tsx
export type Nav={href:string;visible:boolean;enabled:boolean};export const menuLinks=(items:readonly Nav[])=>items.filter(x=>x.visible&&x.enabled&&x.href.startsWith('/')&&!x.href.startsWith('//'));
```

**Why it works:** Use disclosure semantics, keyboard-operable controls and stable public navigation links independent of breakpoint.

</LessonStep>
