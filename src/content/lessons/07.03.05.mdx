## The problem we're solving

A SaaS dashboard caches a response without separating organizations. Another organization's account may then receive private records.

**Failure mode:** The starter declares every cached document public regardless of access scope.

## Build the mental model

Separate public cache entries from tenant- or principal-scoped responses; never share personalized data under a global key. This module specifically uses **Next.js 16 with `cacheComponents: true`**; avoid mixing with the legacy `dynamic`, route-segment `revalidate` or `fetchCache` configuration model. The offline assertions are data/decision models; they do not access Next's actual cache internals, HTTP, or database.

**Expected behavior:** Only records explicitly marked public qualify for shared caching; organization-owned and private records do not.
