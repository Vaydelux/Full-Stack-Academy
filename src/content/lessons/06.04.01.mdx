## The problem we're solving

A deeply nested button receives the wrong theme because each intermediary overrides a duplicated theme prop. This local fixture isolates a concrete failure before we introduce any external state or deployment.

## Build the mental model

Context lets descendants read a provider's value without prop drilling. Providers should be placed as narrowly as possible to avoid updating unrelated consumers, and consumers should have a meaningful default or enforce provider presence.

**Predict before running:** The repaired implementation respects its documented contract.

```tsx

'use client';
import React,{createContext,useContext,useState} from 'react';
import {solve} from './solution';
const Theme=createContext<'light'|'dark'>('light');
function ReadTheme(){return <output>Theme: {solve(useContext(Theme))}</output>;}
export function Workshop(){const [theme,setTheme]=useState<'light'|'dark'>('dark');return <Theme.Provider value={theme}><section aria-label="Theme provider"><button type="button" onClick={()=>setTheme(t=>t==='light'?'dark':'light')}>Toggle theme</button><ReadTheme /></section></Theme.Provider>;}

```
