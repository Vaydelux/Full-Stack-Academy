## The problem we're solving

Nested components need a theme label, but passing the same theme prop through every intermediate component increases accidental coupling. The starter renders a hardcoded theme label and never reads the current context.

## Build the mental model

Share a stable theme value through a provider while rejecting missing provider setup in a custom consumer. It supplies a value to descendants without passing an identical prop through each intermediate layer. The React 19 APIs used here have distinct contracts: context passes values, transitions schedule nonurgent updates, deferred values let rendering lag, and optimistic state is a temporary view during an Action. These lessons use local data, not backend persistence.

**Predict before you run:** Providing dark mode renders Theme: dark and a consumer outside the provider throws a clear setup error.

The instructor repair preserves the public exports while fixing the value propagation, scheduling, or state reconciliation defect:

```tsx
import {createContext,useContext,type ReactNode} from 'react';
const ThemeContext=createContext<'light'|'dark'|null>(null);
export function ThemeFrame({mode,children}:{mode:'light'|'dark';children:ReactNode}) {
 return <ThemeContext.Provider value={mode}>{children}</ThemeContext.Provider>;
}
export function ThemeLabel(){
 const mode=useContext(ThemeContext);if(mode===null)throw new Error('Missing ThemeFrame provider');
 return <p>Theme: {mode}</p>;
}
```

**Why it works:** Share a stable theme value through a provider while rejecting missing provider setup in a custom consumer.

</LessonStep>
