## The problem we're solving

An optional biography can be null in API data and a missing notification preference should default to false; confusing null with undefined causes validation failures.

**Broken behavior:** The starter treats a nullable biography as nonnullable and fails to produce default values.

## Build the mental model

Distinguish optional (undefined), nullable (null), and default (missing input); deliberately choose output types and default semantics in Zod 4.

**Predict before coding:** Null biography parses, missing opt-in defaults to false, and locale defaults to en.

**Important boundary:** TypeScript types are erased at runtime. These exercises import Zod 4 from the repository's locked dependencies and run actual `safeParse` or `parse` assertions, not simulated validation. Runtime validation does not authenticate a caller, authorize object access, or persist data.

<LessonStep number={2} title="Implement the Zod 4 schema and typed output" file="labs/zod-optional-defaults/starter/solution.ts" expected="Null biography parses, missing opt-in defaults to false, and locale defaults to en.">

```ts
import * as z from 'zod';
export const Prefs=z.strictObject({
 bio:z.string().nullable().optional(),
 optIn:z.boolean().default(false),
 locale:z.enum(['en','fil']).default('en'),
});
```

**Why this works:** Distinguish optional (undefined), nullable (null), and default (missing input); deliberately choose output types and default semantics in Zod 4.

</LessonStep>
