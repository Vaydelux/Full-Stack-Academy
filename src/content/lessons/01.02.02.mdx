## The problem we're solving

A form accepts an invalid email and impossible seat count because every field is an unconstrained text box. The team then assumes a JavaScript alert is a reliable security validation layer.

## Build the mental model

Native constraints include `required`, `type=email`, `min`, `max`, `minlength`, and `pattern` where supported. The browser checks applicable constraints before a normal submit event. `checkValidity()` returns a result and can dispatch invalid events; `reportValidity()` also displays built-in validation UI. A submission bypassed with `form.submit()` can skip validation. These APIs improve user experience but cannot validate trust: a server must revalidate and authorize every submitted value. Constraints need clear labels and visible instructions.

**Predict before running:** If a required email field is empty, the form's submit handler should not run during normal interactive validation, even if JavaScript is installed.

## Bug Hunt: identify the root cause

The UI calls `form.submit()` directly in a click listener. This skips normal interactive constraint checks. Use a native submit button, or `requestSubmit()` when programmatic submission is necessary.
