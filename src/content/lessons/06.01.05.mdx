## The problem we're solving

A task list can sort and insert tasks without attaching item identity to its position. Using array indices for keys misidentifies records after insertion or reorder. This lesson uses local React 19 / TypeScript 5 fixtures; the website does not execute learner-provided code.

## Build the mental model

Use stable record IDs as keys so React can associate items across reorderings. Indices represent positions rather than records, so reordering can transfer state to the wrong item. A React element is a description of UI; server rendering verifies initial markup but cannot, by itself, prove a browser interaction, reconciliation, or a DOM commit.

**Predict before you run:** List order follows input, empty state is explicit, and list elements use task IDs as keys.

Replace the starter's implementation with the reviewed approach below. Keep its public exports stable.

```tsx
export type Task = {id:string; title:string};
export function TaskList({tasks}:{tasks:readonly Task[]}) {
  if(tasks.length===0) return <p role="status">No tasks yet.</p>;
  return <ul>{tasks.map(task=><li key={task.id} data-id={task.id}>{task.title}</li>)}</ul>;
}
```

**Predict before you run:** List order follows input, empty state is explicit, and list elements use task IDs as keys.

**Why the repair works:** Use stable record IDs as keys so React can associate items across reorderings.
