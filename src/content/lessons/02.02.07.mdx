## The problem we're solving

A three-column course catalog tries to fit all cards on a phone, producing unreadably narrow columns. The goal is a predictable local repair, not a decorative mockup. The HTML fixture is fully offline and has an intentionally failing starter plus an instructor solution.

## Build the mental model

Responsive design starts from the smallest practical layout and adds columns only when content has space. Use content-driven rem breakpoints, fluid tracks with minmax(0, 1fr), and test keyboard focus at every state. Breakpoints describe layout constraints, not particular device brands.

**Predict before running:** A phone displays one readable column; wide screens show three equally flexible columns.

<LessonStep number={2} title="Repair the rule, not the screenshot" file="labs/css-breakpoints/starter/index.html" expected={"A phone displays one readable column; wide screens show three equally flexible columns."}>

Replace the defective declaration with this rule from the instructor implementation. Do not change the semantic markup or hide overflow simply to mask a layout defect.

```css
.cards { display: grid; grid-template-columns: minmax(0, 1fr); gap: 1rem; } @media (min-width: 45rem) { .cards { grid-template-columns: repeat(3, minmax(0, 1fr)); } }
```

**Predict before running:** A phone displays one readable column; wide screens show three equally flexible columns.

**Why it works:** Responsive design starts from the smallest practical layout and adds columns only when content has space. Use content-driven rem breakpoints, fluid tracks with minmax(0, 1fr), and test keyboard focus at every state. Breakpoints describe layout constraints, not particular device brands.

**Proof:** Compare the properties and geometry with `labs/css-breakpoints/solution/index.html`, using DevTools, not merely text-searching the CSS source.

</LessonStep>

<LessonStep number={3} title="Measure and regression-check the behavior" file="labs/css-breakpoints/starter/index.html" expected="Narrow and wide states remain usable, with no unexpected horizontal overflow.">

```js
const root = document.documentElement;

console.log({
  fitsViewport: root.scrollWidth <= innerWidth,
  display: getComputedStyle(surface).display,

});
```

**Predict before running:** A specific layout value changes as expected, and the repaired surface stays within its available width.

**Why it works:** Browser computed styles and bounding boxes reflect selector matching, layout algorithm and containing-block constraints.
