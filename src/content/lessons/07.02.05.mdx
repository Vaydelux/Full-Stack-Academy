## The problem we're solving

A browser asks for paginated public resources through a Next.js Route Handler. The handler must reject extreme page sizes before querying a backend.

**Symptom:** The starter trusts any limit, including zero, negative and unbounded values.

## Build the mental model

Validate URL parameters at the route boundary, bound resource consumption and return a stable response/error contract.

**Predict first:** Limits 1–50 are allowed, invalid values rejected, and absent limit defaults to 20.

The local fixture tests only an isolated TypeScript/React contract; actual Server Component compilation, network transport, streaming, Server Actions, security isolation and browser hydration require a separate compiled Next.js 16 application and integration tests.

```tsx
export function parsePageSize(raw:string|null):number|null{
 if(raw===null)return 20;
 if(!/^\d{1,2}$/.test(raw))return null;
 const value=Number(raw);
 return Number.isSafeInteger(value)&&value>=1&&value<=50?value:null;
}
```

**Why it works:** Validate URL parameters at the route boundary, bound resource consumption and return a stable response/error contract.
