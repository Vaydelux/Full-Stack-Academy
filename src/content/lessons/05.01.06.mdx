## The problem we're solving

Two branches edit the same line and Git cannot infer the intended combined message. This lesson is an offline, repeatable source-control exercise; it never touches the learner's actual project repository or opens a hosted pull request.

## Build the mental model

Merge conflicts represent competing edits to the same content. Inspect both sides, author an intentional resolved file preserving compatible work, stage it, and commit the merge. Do not blindly choose ours or theirs when both changes matter; check conflict markers are gone before finalizing.

**Predict before running:** The merge has two parents and the resolved file retains both changes without conflict markers.

```js

```

**Predict before running:** The merge has two parents and the resolved file retains both changes without conflict markers.

**Why it works:** Merge conflicts represent competing edits to the same content. Inspect both sides, author an intentional resolved file preserving compatible work, stage it, and commit the merge.
