## The problem we're solving

Every success toast is announced as an assertive alert, interrupting screen-reader navigation for routine confirmations.

## Build the mental model

Use noninterrupting status announcements for routine success, and reserve assertive alerts for urgent problems that require immediate attention. Keep toast copy concise, make actions keyboard reachable, and avoid vanishing content before it can be understood.

**Predict first:** Success and informational messages use polite status semantics, while urgent errors use alert semantics.

## Production library pattern

```tsx
"use client";
import React from "react";
export function SaveStatus({saved}:{saved:boolean}){return <output role="status" aria-live="polite">{saved?"Changes saved":"Unsaved changes"}</output>;}
```

Real live-region timing and screen-reader speech must be tested in the browser. An SSR role attribute alone is only initial semantics.
