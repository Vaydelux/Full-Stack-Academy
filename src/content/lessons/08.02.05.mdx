## The problem we're solving

The starter duplicates every queued notification, drowning out the message. Advanced UI interactions need a robust identity and focus model so the component works with touch, keyboard and screen readers rather than only a mouse.

## Build the mental model

Use polite status regions for routine confirmations and assertive alerts only for urgent errors; deduplicate stale notifications. **Expected behavior:** New notification IDs append once and repeated IDs update rather than duplicate.

**Evidence boundary:** The local test checks a pure data or interaction-policy function. It does not prove DOM focus, ARIA announcements, actual event sequences, animation timing or a third-party library's mounted behavior. Use a real local browser and accessible component primitives for those claims.
