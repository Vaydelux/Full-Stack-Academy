## The problem we're solving

A trusted profile DTO extends a base identity with a role. Combining object fields must preserve strictness and inferred TS types.

**Broken behavior:** The starter allows all roles and unknown props and never bounds names or IDs.

## Build the mental model

Compose strict schemas with safeExtend and derive TS types via z.infer; reject unknown keys and out-of-range domain fields.

**Predict before coding:** Only named reader/editor roles parse; unknown keys fail and TS types follow the schema.

**Important boundary:** TypeScript types are erased at runtime. These exercises import Zod 4 from the repository's locked dependencies and run actual `safeParse` or `parse` assertions, not simulated validation. Runtime validation does not authenticate a caller, authorize object access, or persist data.

<LessonStep number={2} title="Implement the Zod 4 schema and typed output" file="labs/zod-composition-types/starter/solution.ts" expected="Only named reader/editor roles parse; unknown keys fail and TS types follow the schema.">

```ts
import * as z from 'zod';
const Identity=z.strictObject({id:z.string().min(1),name:z.string().trim().min(2)});
export const User=Identity.safeExtend({role:z.enum(['reader','editor'])});
export type UserData=z.infer<typeof User>;
```

**Why this works:** Compose strict schemas with safeExtend and derive TS types via z.infer; reject unknown keys and out-of-range domain fields.

</LessonStep>

**Representative application usage:**

```ts
import * as z from 'zod';
const Base=z.strictObject({id:z.string().min(1)});
const WithRole=Base.safeExtend({role:z.enum(['reader','editor'])});
type User=z.infer<typeof WithRole>;
// TS inference reflects the validated output, not an external database model.
// Use safeExtend when preserving refinements matters.
```

**Security and operations:** Never log raw rejected payloads, secrets or personal data. Validate again at server boundaries; a browser schema is for usability, not authorization.
