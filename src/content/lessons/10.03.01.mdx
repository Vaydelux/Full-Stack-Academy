## The problem we're solving

The starter trusts an X-Forwarded-Proto header from every remote address. Real services must establish who can request a resource, constrain how the request is interpreted, and prevent unexpected data disclosure.

## Build the mental model

Honor forwarded HTTPS headers only from an explicitly trusted proxy and never let a direct attacker spoof transport security.

**Expected outcome:** Spoofed HTTPS from an untrusted client stays insecure; trusted proxy HTTPS is recognized.

**Production boundary:** Trusted proxies must strip client-supplied forwarding headers. This minimal model does not verify proxy TLS, connection authenticity or a multi-hop chain.

<LessonStep number={2} title="Implement the bounded guard or server behavior" file="labs/security-proxy-tls/starter/solution.mjs" expected="Spoofed HTTPS from an untrusted client stays insecure; trusted proxy HTTPS is recognized.">

```js
export function isSecureRequest(request,trustedProxyIps=[]){
 if(request.encrypted===true)return true;
 const trusted=trustedProxyIps.includes(request.remoteAddress);
 if(!trusted)return false;
 const value=request.headers['x-forwarded-proto'];
 return typeof value==='string'&&value.trim().toLowerCase()==='https';
}
```

**Why this works:** Honor forwarded HTTPS headers only from an explicitly trusted proxy and never let a direct attacker spoof transport security.

</LessonStep>
