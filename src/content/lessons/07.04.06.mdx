## The problem we're solving

A performance audit reports Largest Contentful Paint, Interaction to Next Paint and Cumulative Layout Shift; the team must classify them consistently.

**Defect:** The starter treats every positive metric as good, masking poor loading, interaction or layout stability.

## Build the mental model

Classify LCP, INP and CLS using documented good/needs-improvement/poor thresholds, then measure the 75th percentile across real users.

**Predict before running:** LCP 2500 ms, INP 200 ms and CLS 0.1 are good; extreme values are poor.

The academy exercises reviewed TypeScript/React logic locally. It does not automatically exercise the Next.js Metadata API, search crawler, browser page loading, network waterfall, Lighthouse or real-user field metrics. Those are separate qualification gates.

<LessonStep number={2} title="Repair the measurable contract" file="labs/next-core-web-vitals/starter/solution.tsx" expected="LCP 2500 ms, INP 200 ms and CLS 0.1 are good; extreme values are poor.">

```tsx
export type Metric='LCP'|'INP'|'CLS';
export function vitalsGrade(metric:Metric,value:number){
 if(!Number.isFinite(value)||value<0)throw new RangeError('Invalid vital');
 const good={LCP:2500,INP:200,CLS:0.1};const poor={LCP:4000,INP:500,CLS:0.25};
 return value<=good[metric]?'good':value>poor[metric]?'poor':'needs-improvement';
}
```

**Root principle:** Classify LCP, INP and CLS using documented good/needs-improvement/poor thresholds, then measure the 75th percentile across real users.

</LessonStep>
