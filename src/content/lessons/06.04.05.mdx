## The problem we're solving

A comment list shows an optimistic item permanently even after the mutation fails. This local fixture isolates a concrete failure before we introduce any external state or deployment.

## Build the mental model

useOptimistic projects temporary state while an Action is pending. Add the optimistic change inside an Action/Transition and reconcile to confirmed server state on success or failure. Never treat optimistic UI as server-side persistence or authorization.

**Predict before running:** The repaired implementation respects its documented contract.
