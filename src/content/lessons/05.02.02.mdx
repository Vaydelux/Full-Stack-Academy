## The problem we're solving

Release automation cannot classify a commit titled update because it lacks a structured intent. The lesson uses synthetic local data; passing its test does not configure actual branch protection or trigger a release.

## Build the mental model

Conventional Commits defines a parseable type, optional scope, breaking-change marker and description. This enables changelog tooling and review clarity but is not a security boundary. Validate first-line syntax and reject empty descriptions without pretending that a valid title proves quality.

**Predict before running:** Conventional titles yield structured intent; ambiguous or empty messages fail.

<LessonStep number={2} title="Implement the explicit review or release contract" file="labs/team-commit-messages/starter/solution.mjs" expected={"Conventional titles yield structured intent; ambiguous or empty messages fail."}>

Prefer an explicit result and a narrow, auditable policy; do not invent remote approvals or call an external API.

```js
export function solve(message){if(typeof message!=='string')return null;const match=/^(feat|fix|docs|refactor|perf|test|chore)(?:\(([a-z0-9-]+)\))?(!)?: (\S.*)$/.exec(message.trim());return match?{type:match[1],scope:match[2]??null,breaking:Boolean(match[3]),description:match[4]}:null;}
```

**Predict before running:** Conventional titles yield structured intent; ambiguous or empty messages fail.

**Why the repair works:** Conventional Commits defines a parseable type, optional scope, breaking-change marker and description. This enables changelog tooling and review clarity but is not a security boundary. Validate first-line syntax and reject empty descriptions without pretending that a valid title proves quality.

**Proof:** Run the same independent test after editing; a green result demonstrates this local policy only.

</LessonStep>

<LessonStep number={3} title="Test both positive and negative outcomes" file="labs/team-commit-messages/solution.test.mjs" expected="Passes a precise expected-output contract and rejects a misleading or invalid case.">

```js
assert.deepEqual(solve('feat(api): add endpoint'),{type:'feat',scope:'api',breaking:false,description:'add endpoint'});assert.deepEqual(solve('fix!: remove legacy client'),{type:'fix',scope:null,breaking:true,description:'remove legacy client'});assert.equal(solve('update'),null);assert.equal(solve('feat: '),null);
```

**Predict before running:** The corrected policy distinguishes reviewable, unreviewed and invalid inputs.

**Why it matters:** Branch protection, reviewer permissions, remote signatures and provenance are external guarantees; local policy simulation cannot establish them.

**Proof:** Run `npm run lab:team-commit-messages` and inspect the failure messages when targeting the starter.

</LessonStep>
