## The problem we're solving

A fixed-width reading panel extends beyond small screens and looks awkwardly stretched on a large monitor. The goal is a predictable local repair, not a decorative mockup. The HTML fixture is fully offline and has an intentionally failing starter plus an instructor solution.

## Build the mental model

min(), max() and clamp() are CSS value functions, not JavaScript functions. min(100%, 42rem) lets a panel fit its container and caps its width. clamp() supplies lower/preferred/upper bounds, but not every combination is automatically accessible: zoom and font scaling still need tests.

**Predict before running:** The reading panel never exceeds its parent and stays capped near 42rem on a large screen.

<LessonStep number={2} title="Repair the rule, not the screenshot" file="labs/css-intrinsic/starter/index.html" expected={"The reading panel never exceeds its parent and stays capped near 42rem on a large screen."}>

Replace the defective declaration with this rule from the instructor implementation. Do not change the semantic markup or hide overflow simply to mask a layout defect.

```css
.demo { inline-size: min(100%, 42rem); padding: clamp(0.75rem, 2vw, 1.75rem); margin-inline: auto; }
```

**Predict before running:** The reading panel never exceeds its parent and stays capped near 42rem on a large screen.

**Why it works:** min(), max() and clamp() are CSS value functions, not JavaScript functions. min(100%, 42rem) lets a panel fit its container and caps its width. clamp() supplies lower/preferred/upper bounds, but not every combination is automatically accessible: zoom and font scaling still need tests.

**Proof:** Compare the properties and geometry with `labs/css-intrinsic/solution/index.html`, using DevTools, not merely text-searching the CSS source.

</LessonStep>
