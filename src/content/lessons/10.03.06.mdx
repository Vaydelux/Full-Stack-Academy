## The problem we're solving

The starter permits any HTTP URL containing the string of an allowed domain, including lookalikes. Real services must establish who can request a resource, constrain how the request is interpreted, and prevent unexpected data disclosure.

## Build the mental model

Validate exact upstream HTTPS hostnames, reject credentials, alternate ports, IP literals and redirects—but recognize DNS rebinding and egress remain separate network controls.

**Expected outcome:** Only exact, explicitly allowlisted HTTPS destinations pass the URL policy.

**Production boundary:** Never claim this pure URL policy is complete SSRF prevention: verify resolved IPv4/IPv6 addresses at connect time, prevent DNS rebinding and disable redirects; enforce network egress ACLs.

```js
import {isIP} from 'node:net';
export function allowedUpstream(raw,allowedHosts){
 try{
  const url=new URL(raw);
  if(url.protocol!=='https:'||url.username||url.password||url.port&&url.port!=='443')return false;
  const host=url.hostname.toLowerCase();
  if(isIP(host)||host==='localhost'||host.endsWith('.localhost'))return false;
  return allowedHosts.some(allowed=>host===allowed.toLowerCase());
 }catch{return false;}
}
```

**Why this works:** Validate exact upstream HTTPS hostnames, reject credentials, alternate ports, IP literals and redirects—but recognize DNS rebinding and egress remain separate network controls.
