## The problem we're solving

A request body parser decodes any arbitrary JSON and later spreads untrusted __proto__ keys into a plain object; it also ignores payload byte limits.

**Fault to find:** The starter accepts prototype-polluting keys and unbounded JSON bodies. This track uses Node 24 built-ins and fetch-compatible `Response` where appropriate; no paid platform or remote arbitrary-code execution is needed.

## Build the mental model

Bound raw UTF-8 body size before JSON.parse, require an object payload and recursively reject prototype-sensitive object keys.

**Expected repair:** Normal object JSON parses; oversized, malformed, array and __proto__ payloads are rejected.

HTTP semantics follow RFC 9110. Public errors can use RFC 9457 Problem Details; do not invent return codes or copy internal stack traces into public responses. Pure helper tests are useful but the final capstone runs a real loopback server and tests wire responses.

<LessonStep number={2} title="Implement standards-based HTTP behavior" file="labs/http-safe-json/starter/solution.mjs" expected="Normal object JSON parses; oversized, malformed, array and __proto__ payloads are rejected.">

```js
export function parseJsonObject(raw,maxBytes=1024){
 if(typeof raw!=='string'||!Number.isSafeInteger(maxBytes)||maxBytes<1)throw new TypeError('Invalid input');
 if(Buffer.byteLength(raw)>maxBytes)throw new RangeError('Body too large');
 const parsed=JSON.parse(raw);
 if(!parsed||typeof parsed!=='object'||Array.isArray(parsed))throw new TypeError('Expected object');
 const check=value=>{
  if(!value||typeof value!=='object')return;
  for(const key of Object.keys(value)){
   if(['__proto__','constructor','prototype'].includes(key))throw new TypeError('Unsafe key');
   check(value[key]);
  }
 };
 check(parsed);return parsed;
}
```

**Why this is correct:** Bound raw UTF-8 body size before JSON.parse, require an object payload and recursively reject prototype-sensitive object keys.

</LessonStep>

**Production adaptation and limits:**

```js
// On HTTP request: buffer size should be limited while streaming,
// not only after the entire request has already been read.
for await(const chunk of req){
 received+=chunk.length;
 if(received>MAX_REQUEST_BYTES)throw new Error('Body too large');
}
// After decoding: parse, validate schema, reject unsafe object keys,
// and never Object.assign raw untrusted JSON into configuration prototypes.
```

**Operational distinction:** The reference implementation intentionally excludes production identities, durable database transactions, distributed replay records, rate limiting, SSRF protection, and deployment. Those require separate lessons and genuine integration checks.

</LessonStep>
