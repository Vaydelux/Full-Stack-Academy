## The problem we're solving

Two IDs with the same string representation are accidentally interchangeable in business logic. In a full-stack application, this boundary can lead to incorrect data or information disclosure even if the TypeScript project compiles successfully.

## Build the mental model

A branded intersection type can distinguish IDs statically without changing their runtime string representation. Branded values should only be created through a validating constructor; a cast alone cannot prove the format. Brands do not encrypt or authorize access to resources.

**Predict before running:** Only IDs matching the reviewed format are branded; arbitrary strings and other resource prefixes are rejected.

## Explore and verify

Use boundary-oriented reasoning: the outer layer receives unknown, the parser enforces shape and units, and only then may a domain function use a trusted type. Separate validation from authorization; a successful schema parse never proves the actor has permission.
