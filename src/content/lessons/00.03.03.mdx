## The problem we're solving

An invoice of two units priced at 250 centavos each shows a subtotal of 252 instead of 500. Logging more values is possible, but a debugger lets you pause exactly where a wrong expression is evaluated.

## Build the mental model

A breakpoint pauses execution before or at an operation. Stepping over executes the next statement without entering calls; stepping into follows a call; stepping out resumes to the caller. Watch expressions calculate values while paused. Conditional breakpoints limit noise to matching cases. The built-in Node inspector can expose debugging control; keep it bound to loopback and never deploy an accessible inspector to production. For money, use integer minor units; tax is represented here in basis points (100 basis points = 1%).

**Predict before running:** Why is priceCents + quantity wrong for two items? It adds quantities to prices instead of multiplying units by the unit price.

<LessonStep number={3} title={"Correct the calculation and validate inputs"} file="labs/debugger-watches/starter/exercise.mjs" expected={"Two units at 250 cents have subtotal 500; at 10% tax, total is 550."}>

Replace addition with multiplication. Reject invalid quantities, cents and tax rates to avoid silently rendering NaN or negative totals.

```js
export function invoiceTotal(items, taxBasisPoints = 0) {
  if (!Number.isSafeInteger(taxBasisPoints) || taxBasisPoints < 0 || taxBasisPoints > 10000) throw new Error('Invalid tax rate');
  let subtotalCents = 0;
  for (const item of items) {
    if (!Number.isSafeInteger(item.quantity) || item.quantity < 1 || !Number.isSafeInteger(item.priceCents) || item.priceCents < 0) throw new Error('Invalid line item');
    subtotalCents += item.quantity * item.priceCents;
    if (!Number.isSafeInteger(subtotalCents)) throw new Error('Unsafe total');
  }
  const taxCents = Math.round(subtotalCents * taxBasisPoints / 10000);
  return { subtotalCents, taxCents, totalCents: subtotalCents + taxCents };
}
```

</LessonStep>
