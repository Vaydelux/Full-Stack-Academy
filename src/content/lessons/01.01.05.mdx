## The problem we're solving

A checklist is written as one long paragraph separated by newlines. It looks like a list after styling, but browsers and screen readers don't know which lines are individual items.

## Build the mental model

HTML conveys relationships through elements. `p` represents a paragraph; `ul` groups items where order is not significant; `ol` represents a meaningful sequence; `dl`, `dt`, and `dd` describe terms and their descriptions. A `blockquote` marks an extended quotation and `cite` identifies a creative work's title; it should not be used solely for indentation. A `figure` with `figcaption` describes a self-contained illustration, example or excerpt—not only photographs. Choose based on information meaning, then style with CSS.

**Predict before running:** If a sequence must be followed in order, should you use `ul` because its bullets look smaller? No; use `ol` and style it separately.

<LessonStep number={1} title={"Write readable paragraphs and unordered resources"} file="labs/html-text-lists/starter/index.html" expected={"Three distinct list items can be navigated as a list."}>

Use paragraphs for prose, then a list of resources that have no intrinsic sequence.

```html
<p>Start with a clear session goal, then gather the tools you need.</p>
<ul>
  <li>Notebook for questions</li>
  <li>Accessible workshop guide</li>
  <li>Quiet space for reflection</li>
</ul>
```

</LessonStep>

<LessonStep number={2} title={"Add an ordered procedure and a glossary"} file="labs/html-text-lists/starter/index.html" expected={"A reader can identify a sequence and a definition list."}>

Use `ol` for sequential steps; provide `dt` and `dd` relationships when defining terms.

```html
<ol>
  <li>Read the introduction.</li>
  <li>Try a local example.</li>
  <li>Explain the outcome to a peer.</li>
</ol>
<dl>
  <dt>Markup</dt><dd>Document structure represented using elements.</dd>
</dl>
```

</LessonStep>

<LessonStep number={3} title={"Quote and caption material appropriately"} file="labs/html-text-lists/starter/index.html" expected={"The quotation, attribution and code figure have separate semantic roles."}>

Do not fake a public figure quote. This example attributes original workshop handbook text.

```html
<blockquote>
  <p>A useful workshop makes space for questions and different approaches.</p>
</blockquote>
<p>From <cite>Workshop Handbook</cite>.</p>
<figure>
  <pre><code>&lt;main&gt;Your article&lt;/main&gt;</code></pre>
  <figcaption>Example: one main region for the article.</figcaption>
</figure>
```

</LessonStep>

## Bug Hunt: identify the actual source of the problem

A list of numbered steps is typed with literal `1.` and `<br>` in a paragraph. Replace it with a semantic `ol` and check that the screen reader can report the list length.
