## The problem we're solving

A demo iframe runs code beside the academy interface and posts status events to its parent. If it gets a same-origin sandbox escape or the parent trusts any incoming message, the parent can be tricked. We'll constrain the iframe and accept only a tiny, expected status payload. We also discuss the server-set CSP headers needed in a hosted production environment.

## Build the mental model

CSP constrains permitted resources and behaviors, most effectively through an HTTP response header. It does not sanitize DOM text or replace output encoding. iframe sandbox isolates an embedded document; sandbox='allow-scripts' without allow-same-origin gives its contents an opaque origin. An opaque-origin child must generally target '*' when posting to its parent, so the parent must validate event.source, event.origin and the message schema and never include secrets in the exchange. This local page deliberately posts only a static status.

**Predict before running:** A message from a different window, or an unexpected payload, should be ignored even if it uses the same 'kind' field.

Treat this as an illustrative HTTP response header; a meta tag cannot enforce every directive.

```js
// Content-Security-Policy: default-src 'self';
//   object-src 'none'; base-uri 'none'; frame-ancestors 'none'
```

**Predict before running:** This header blocks plug-in objects and base URL rewrites; frame-ancestors must be sent as a response header.

**Why it works:** CSP is enforced by the browser after the server supplies the policy.

**Proof it works:** Explain why 'unsafe-inline' undermines script restrictions; do not apply this header blindly to Next.js.

</LessonStep>

<LessonStep number={3} title={"Validate postMessage before updating status"} file="labs/web-csp/starter/index.html" expected={"Only the expected child event may update the parent status."}>

Compare source, opaque origin and a narrow static payload.

```js
window.addEventListener('message', (event) => {
  if (event.source !== frame.contentWindow) return;
  if (event.origin !== 'null') return;
  if (event.data?.kind !== 'academy-demo-ready') return;
  if (event.data.value !== 'isolated') return;
  status.textContent = 'Sandbox signaled ready.';
});
```

**Predict before running:** Only the expected child event may update the parent status.

**Why it works:** Message data is untrusted input even when sent by an iframe.

**Proof it works:** Reload and wait for the local ready status; send a fake window message and verify it is ignored.

</LessonStep>
