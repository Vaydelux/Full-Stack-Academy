## The problem we're solving

A GET API sends a full JSON body even when the client has a matching ETag, wasting bandwidth and making conditional cache behavior impossible.

**Fault to find:** The starter ignores conditional request headers and always responds 200 with a body. This track uses Node 24 built-ins and fetch-compatible `Response` where appropriate; no paid platform or remote arbitrary-code execution is needed.

## Build the mental model

Generate a deterministic ETag for the representation and honor If-None-Match with 304 and no body for unchanged GET responses.

**Expected repair:** A fresh request receives 200 and ETag; a matching strong or weak condition receives 304 with an empty body.

HTTP semantics follow RFC 9110. Public errors can use RFC 9457 Problem Details; do not invent return codes or copy internal stack traces into public responses. Pure helper tests are useful but the final capstone runs a real loopback server and tests wire responses.

<LessonStep number={2} title="Implement standards-based HTTP behavior" file="labs/http-etag-conditional/starter/solution.mjs" expected="A fresh request receives 200 and ETag; a matching strong or weak condition receives 304 with an empty body.">

```js
import {createHash} from 'node:crypto';
export function conditionalJson(data,ifNoneMatch=''){
 const body=JSON.stringify(data);
 const etag='"'+createHash('sha256').update(body).digest('hex')+'"';
 const options={'etag':etag,'cache-control':'private, no-cache'};
 const matches=String(ifNoneMatch).split(',').map(x=>x.trim().replace(/^W\//,'')).some(x=>x===etag||x==='*');
 if(matches)return new Response(null,{status:304,headers:options});
 return new Response(body,{status:200,headers:{...options,'content-type':'application/json'}});
}
```

**Why this is correct:** Generate a deterministic ETag for the representation and honor If-None-Match with 304 and no body for unchanged GET responses.

</LessonStep>
