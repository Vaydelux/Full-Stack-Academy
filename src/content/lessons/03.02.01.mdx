## The problem we're solving

A numeric generator includes the end boundary and never rejects a zero step, which can trap callers in an infinite loop. The practice fixture uses Node 24 ESM and synthetic data, not an external service or browser deployment.

## Build the mental model

An iterable exposes Symbol.iterator; a generator pauses at yield and resumes on demand. A half-open range excludes stop, and forward/backward steps require boundary conditions that make progress.

**Predict before running:** A forward range is half-open, and a reverse range terminates safely.

<LessonStep number={2} title="Repair the semantic boundary" file="labs/js-iterators/starter/solution.mjs" expected={"A forward range is half-open, and a reverse range terminates safely."}>

Implement the corrected behavior using the relevant lexical, prototype, module or copying rule. Preserve the named `solve` export.

```js
export function* solve(start,stop,step=1){if(![start,stop,step].every(Number.isFinite)||step===0)throw new RangeError('Finite nonzero step required');for(let x=start;step>0?x<stop:x>stop;x+=step)yield x;}
```

**Predict before running:** A forward range is half-open, and a reverse range terminates safely.

**Why the repair works:** An iterable exposes Symbol.iterator; a generator pauses at yield and resumes on demand. A half-open range excludes stop, and forward/backward steps require boundary conditions that make progress.

**Proof:** Compare independent instances, object identity or errors under the same test file.

</LessonStep>
