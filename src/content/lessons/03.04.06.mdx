## The problem we're solving

A UI claims every operation is fast without measuring work or identifying the action being timed. Browser Interaction topics require both executable JavaScript logic and a real local HTML document. The fixture uses synthetic content with no external scripts, endpoints or data uploads.

## Build the mental model

performance.mark and performance.measure capture named durations for a specific execution; they do not establish statistically significant performance across hardware. Measure representative work, clean up marks, and inspect DevTools Performance before making a real-world claim. Never fabricate a fixed milliseconds result.

**Predict before running:** The UI reports an actual local measurement and checksum instead of an invented performance result.

<LessonStep number={2} title="Implement the browser-safe interaction" file="labs/js-profiling/starter/index.html" expected={"The UI reports an actual local measurement and checksum instead of an invented performance result."}>

Replace the defective handler without discarding native elements or semantics. For untrusted content use `textContent`, not an unsafe HTML sink.

```js
document.querySelector('#measure').addEventListener('click',()=>{performance.mark('course-start');let total=0;for(let i=0;i<10000;i++)total+=i;performance.mark('course-end');performance.measure('course-calculation','course-start','course-end');const entry=performance.getEntriesByName('course-calculation','measure').at(-1);document.querySelector('#status').textContent='Measured local calculation; checksum '+total+', duration '+entry.duration.toFixed(3)+' ms in this browser.';performance.clearMarks('course-start');performance.clearMarks('course-end');performance.clearMeasures('course-calculation');});
```

**Predict before running:** The UI reports an actual local measurement and checksum instead of an invented performance result.

**Why the repair works:** performance.mark and performance.measure capture named durations for a specific execution; they do not establish statistically significant performance across hardware. Measure representative work, clean up marks, and inspect DevTools Performance before making a real-world claim. Never fabricate a fixed milliseconds result.

**Proof:** Compare the resulting DOM and accessibility state to the instructor `solution/index.html` using the same input.

</LessonStep>

```js
export function solve(values){if(!Array.isArray(values)||values.some(x=>!Number.isFinite(x)))throw new TypeError('Numbers required');return {sum:values.reduce((a,b)=>a+b,0),count:values.length};}
assert.deepEqual(solve([1,2,3]),{sum:6,count:3});assert.deepEqual(solve([]),{sum:0,count:0});assert.throws(()=>solve([NaN]),TypeError);
```
