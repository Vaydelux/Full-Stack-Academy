## The problem we're solving

The starter logs nested passwords, Authorization values and cookies unchanged. Real services must establish who can request a resource, constrain how the request is interpreted, and prevent unexpected data disclosure.

## Build the mental model

Redact known secret-bearing keys recursively before logging and avoid mutating original request objects or emitting raw tokens.

**Expected outcome:** Nested and array-based secret values are removed, while original input and public IDs remain unchanged.

**Production boundary:** Blocklisting keys is not sufficient for production DLP: prefer explicit allowlisted structured log fields and short-lived correlation IDs; scrub free-text payloads separately.

```js
const PRIVATE=new Set(['authorization','cookie','set-cookie','password','passwd','token','access_token','refresh_token','apikey','api_key','secret']);
export function redactLog(value){
 const visit=(data,seen)=>{
  if(!data||typeof data!=='object')return data;
  if(seen.has(data))return '[Circular]';
  seen.add(data);
  const output=Array.isArray(data)?data.map(item=>visit(item,seen)):Object.fromEntries(Object.entries(data).map(([k,v])=>[k,PRIVATE.has(k.toLowerCase())?'[REDACTED]':visit(v,seen)]));
  seen.delete(data);
  return output;
 };
 return visit(value,new WeakSet());
}
```

**Why this works:** Redact known secret-bearing keys recursively before logging and avoid mutating original request objects or emitting raw tokens.

</LessonStep>
