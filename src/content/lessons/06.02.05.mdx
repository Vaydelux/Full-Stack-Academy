## The problem we're solving

Switching between two people must not reuse the old person's in-progress draft. Giving every editor the same key retains the wrong record's local input state when switching profiles. The following exercise is React 19 and TypeScript 5 source checked into this repository, not a remote code runner.

## Build the mental model

React associates state with component identity and tree position; a deliberate key can reset a form for a new record. When a keyed component is replaced by a component with a different key at the same position. **Important boundary:** A pure-function test validates state transitions and static React rendering checks initial markup; neither alone simulates an interactive browser or verifies hydration and effect behavior.

**Predict before you run:** The editor key matches the current person ID, and the initial rendered field shows the selected person.
