## The problem we're solving

A course filter must remain shareable on reload, but a developer stores it only in ephemeral in-memory state, losing the filter after navigation.

**Broken behavior:** The starter's URL serializer always returns an empty string, so a selected filter cannot be linked.

## Build the mental model

Keep shareable filters in the URL as the source of truth and coordinate the visible Zustand UI state with parsed, allowlisted query parameters.

**Predict:** Valid active status can be serialized to a URL and restored; invalid status defaults safely.

**Evidence boundary:** The local test imports the real Zustand 5 `createStore` API and, where appropriate, the official middleware. The store is created afresh per test; it does not use a global request-scoped server singleton. Passing Node assertions does not prove browser hydration, cross-tab synchronization or HTTP authorization.

```ts
import {createStore,type StoreApi} from 'zustand/vanilla';
export type Status='all'|'active';
export type QueryState={status:Status;setStatus:(status:Status)=>void};
export function makeQueryStore(search:string){
 const status:Status=new URLSearchParams(search.startsWith('?')?search.slice(1):search).get('status')==='active'?'active':'all';
 return createStore<QueryState>()(set=>({status,setStatus:status=>set({status})}));
}
export function toQuery(store:StoreApi<QueryState>){
 const status=store.getState().status;
 return status==='all'?'':new URLSearchParams({status}).toString();
}
```
