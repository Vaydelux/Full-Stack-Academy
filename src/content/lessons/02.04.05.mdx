## The problem we're solving

An always-on scroll animation distracts motion-sensitive learners and does not support browser preference changes. A code review should require a reproducible symptom and realistic verification, not only a polished image. The local fixture is synthetic, deterministic and offline.

## Build the mental model

Scroll-driven animations can use view() timelines in supporting browsers, but progressive enhancement is required. Decorative motion should be disabled or greatly reduced under prefers-reduced-motion. Scroll movement should never hide essential content or gate access to information.

**Predict before running:** Reduced-motion mode has no running decoration; no-preference mode can animate without hiding reading content.

<LessonStep number={2} title="Repair the CSS and preserve user choice" file="labs/css-scroll-motion/starter/index.html" expected={"Reduced-motion mode has no running decoration; no-preference mode can animate without hiding reading content."}>

Apply the narrowly targeted instructor change. This is an educational repair, not a claim that browsers will use a particular GPU layer, font-loading timeline or screen-reader announcement.

```css
@keyframes float { 50% { transform: translateY(-0.35rem); } } .indicator { animation: none; } @media (prefers-reduced-motion: no-preference) { .indicator { animation: float 2s ease-in-out infinite; } @supports (animation-timeline: view()) { .scroll-highlight { animation: float 1s linear both; animation-timeline: view(); } } } @media (prefers-reduced-motion: reduce) { .indicator, .scroll-highlight { animation: none; } }
```

**Predict before running:** Reduced-motion mode has no running decoration; no-preference mode can animate without hiding reading content.

**Why this works:** Scroll-driven animations can use view() timelines in supporting browsers, but progressive enhancement is required. Decorative motion should be disabled or greatly reduced under prefers-reduced-motion. Scroll movement should never hide essential content or gate access to information.

**Proof:** Compare rendered values and interactions to the original starter using the same viewport and browser emulation.

</LessonStep>

## Explore and verify

Use DevTools to inspect computed styles and the Performance recording when making speed claims. Not every transform is composited; not every font loading strategy removes CLS; not every visually distinct control is accessible. The Node tests check instructor patterns; the isolated browser suite observes representative states. Manual assistive-technology and cross-browser checks remain outside the automated guarantee.
