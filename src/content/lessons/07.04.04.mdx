## The problem we're solving

A course includes user-supplied title text. Rendering JSON-LD in a script tag without escaping HTML-significant characters could break out of the script content.

**Defect:** The starter stringifies raw text without escaping a closing script sequence.

## Build the mental model

Generate schema.org data from validated content and escape `<` in JSON-LD before embedding in a script; never inject untrusted raw HTML.

**Predict before running:** An attacker-provided closing script sequence becomes escaped text while ordinary JSON remains parseable.

The academy exercises reviewed TypeScript/React logic locally. It does not automatically exercise the Next.js Metadata API, search crawler, browser page loading, network waterfall, Lighthouse or real-user field metrics. Those are separate qualification gates.

```tsx
 return JSON.stringify(value).split('<').join(String.fromCharCode(92)+'u003c');
}
```

```js
const result=mod.safeJsonLd({name:'</script><script>alert(1)</script>'});
assert.doesNotMatch(result,/<script>|<\/script>/i);
assert.ok(result.includes(String.fromCharCode(92)+'u003c'));
assert.deepEqual(JSON.parse(result),{name:'</script><script>alert(1)</script>'});
```

**Next.js 16 usage pattern (illustrative):**

```tsx
// Server Component (only after validating/escaping data):
const graph={ '@context':'https://schema.org','@type':'Article',headline:article.title };
const json=JSON.stringify(graph).replace(/</g,'\\u003c');
return <script type="application/ld+json" dangerouslySetInnerHTML={{__html:json}}/>;
```

**Production nuance:** The code example uses dangerouslySetInnerHTML for structured data, not arbitrary page markup. Escaping is essential; schema correctness and search result eligibility still require structured-data validation.

</LessonStep>
