## The problem we're solving

A workshop search accepts an arbitrary topic and displays it inside a list. Its developer used innerHTML because it seemed convenient. The code treats text as executable markup, and reviewers confuse the DOM with the rendered layout. We will keep the input as text, preserve native controls and inspect the result.

## Build the mental model

The browser parses HTML into a DOM; CSS contributes to style calculations, layout decides geometry and paint/compositing turn the result into pixels. These are related stages, not the same tree. A DOM change may trigger style or layout work, but the DOM is not itself a screenshot. When data is text, assign it to textContent. createElement plus append or replaceChildren constructs nodes explicitly, with no HTML parsing of untrusted strings.

**Predict before running:** If the user enters an angle-bracket tag, textContent displays those characters literally. innerHTML interprets them as markup.

<LessonStep number={1} title={"Select the real controls"} file="labs/web-dom/starter/index.html" expected={"A button click should be available to keyboard users, and the selectors should resolve to actual DOM nodes."}>

In the local HTML solution, find an input, action button and list by stable IDs. Use native HTML elements, not click handlers on divs.

```js
const input = document.querySelector('#topic');
const button = document.querySelector('#add-topic');
const list = document.querySelector('#topics');
```

**Predict before running:** A button click should be available to keyboard users, and the selectors should resolve to actual DOM nodes.

**Why it works:** A selector returns an element reference, not a copy of rendered pixels.

**Proof it works:** Open DevTools Elements and find each ID.

</LessonStep>


<LessonStep number={2} title={"Build a safe list item"} file="labs/web-dom/starter/index.html" expected={"Typing <img src=x onerror=alert(1)> should display text, not produce an image node."}>

Construct a list item as a node, set textContent and never concatenate input into innerHTML.

```js
const item = document.createElement('li');
item.textContent = input.value;
list.replaceChildren(item);
```

**Predict before running:** Typing `<img src=x onerror=alert(1)>` should display text, not produce an image node.

**Why it works:** textContent does not parse strings as HTML, so it prevents HTML injection in this rendering path.

**Proof it works:** Inspect the list child; verify its tag is LI and its text equals the input.

</LessonStep>


<LessonStep number={3} title={"Verify the event and the result"} file="labs/web-dom/starter/index.html" expected={"Blank input leaves the example unchanged; a nonblank topic updates one item."}>

Use an event listener, trim whitespace and provide a truthful local-only status.

```js
button.addEventListener('click', () => {
  const value = input.value.trim();
  if (!value) return;
  const item = document.createElement('li');
  item.textContent = value;
  list.replaceChildren(item);
  document.querySelector('#status').textContent = 'Local topic preview updated.';
});
```

**Predict before running:** Blank input leaves the example unchanged; a nonblank topic updates one item.

**Why it works:** Local DOM updates do not persist or send form data.

**Proof it works:** Tab to the button, press Enter, and verify one list item appears.

</LessonStep>
