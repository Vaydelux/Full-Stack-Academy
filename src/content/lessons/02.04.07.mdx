## The problem we're solving

A component looks correct in the default theme but its error state loses the expected red border after a CSS edit. A code review should require a reproducible symptom and realistic verification, not only a polished image. The local fixture is synthetic, deterministic and offline.

## Build the mental model

Visual regression compares a reviewed baseline and a new rendering at controlled viewport, browser, font and theme states. Pixel diffs can be noisy due to rendering environments; combine screenshots with semantic and computed-style assertions, then review intentional changes. This offline demo supplies deterministic state checks, not a full screenshot-diff engine.

**Predict before running:** Normal state stays teal, and toggling error state produces a red border and pale red background.

## Prerequisites and preflight

Continue from [the previous canonical CSS lesson](/learn/02.04.06). Open `labs/css-visual-regression/starter/index.html` in Chromium; use DevTools Styles, Computed and Performance where needed. Node.js 24 runs the local fixture tests. No cloud build, server credentials or external data is needed.

## Explore and verify

Use DevTools to inspect computed styles and the Performance recording when making speed claims. Not every transform is composited; not every font loading strategy removes CLS; not every visually distinct control is accessible. The Node tests check instructor patterns; the isolated browser suite observes representative states. Manual assistive-technology and cross-browser checks remain outside the automated guarantee.
