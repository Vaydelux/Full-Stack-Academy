## The problem we're solving

A copied tutorial targets a different major version and the build breaks. Updating random files won't help until you confirm which API version the project actually uses.

## Build the mental model

The manifest records an allowed version range; the lockfile records a resolved dependency version. Semantic Versioning gives a useful major/minor/patch convention, but real packages may not follow it perfectly. A major upgrade warrants migration review; even patch changes need tests. This lab deliberately supports stable X.Y.Z releases only, not ranges, prereleases or build metadata. Never use 'npm audit fix --force' without examining its proposed breaking changes.

**Predict before running:** A change from 1.9.7 to 2.0.0 should trigger migration review, even if a package manager can install it.

export function parseVersion(version){const m=/^(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)$/.exec(version);if(!m)throw new Error('Stable X.Y.Z required');const parts=m.slice(1).map(Number);if(parts.some(v=>!Number.isSafeInteger(v)))throw new Error('Unsafe version');return parts;}
```

<LessonStep number={3} title={"Classify upgrade risk without claiming compatibility"} file="labs/changelog-reading/starter/exercise.mjs" expected={"A major, minor or patch change is classified; downgrades are separate."}>

export function classifyUpgrade(from,to){const a=parseVersion(from),b=parseVersion(to);for(let i=0;i<3;i++)if(a[i]!==b[i])return a[i]>b[i]?'downgrade':['major-review','minor-review','patch-review'][i];return 'same-version';}
```
