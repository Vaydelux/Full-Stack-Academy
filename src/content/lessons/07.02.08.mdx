## The problem we're solving

A developer adds `'use client'` to a shared barrel file and accidentally pulls a server-only DB accessor into a client import tree.

**Symptom:** The starter treats imports under private server modules as safe for Client Components.

## Build the mental model

Keep the client module graph intentionally small and reject server-only or Node built-ins from client module imports.

**Predict first:** Known server-only modules and Node built-in imports are blocked; a shared UI module remains permitted.

The local fixture tests only an isolated TypeScript/React contract; actual Server Component compilation, network transport, streaming, Server Actions, security isolation and browser hydration require a separate compiled Next.js 16 application and integration tests.

<LessonStep number={2} title="Implement a minimal correct contract" file="labs/next-accidental-client-import/starter/solution.tsx" expected="Known server-only modules and Node built-in imports are blocked; a shared UI module remains permitted.">

```tsx
export function safeClientImport(specifier:string):boolean{
 if(!specifier.trim()||specifier==='server-only')return false;
 if(specifier.startsWith('node:'))return false;
 if(specifier.startsWith('@/lib/server/')||specifier.startsWith('@/db/'))return false;
 return true;
}
```

**Why it works:** Keep the client module graph intentionally small and reject server-only or Node built-ins from client module imports.

</LessonStep>

## Bug Hunt: reproduce, diagnose and repair
