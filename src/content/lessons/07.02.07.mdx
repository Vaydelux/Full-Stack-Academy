## The problem we're solving

A server integration has an API credential and user metadata. Only a public profile DTO is allowed into client render props.

**Symptom:** The starter copies the whole server record, including an API credential, to the browser.

## Build the mental model

Keep credentials in server-only modules, use narrow DTO projections, and audit the imported client dependency graph.

**Predict first:** Browser props contain only a user's public name and ID; no internal key field or value is present.

The local fixture tests only an isolated TypeScript/React contract; actual Server Component compilation, network transport, streaming, Server Actions, security isolation and browser hydration require a separate compiled Next.js 16 application and integration tests.

**Framework-oriented example (illustrative; needs real imports and infrastructure):**

```tsx
// lib/private-data.ts
import 'server-only';
export async function getPrivateCourse(id:string) {
 const token=process.env.COURSE_API_TOKEN;
 if(!token)throw new Error('Missing server token');
 return queryCourseOnServer(id,token);
}
// app/courses/page.tsx
const row=await getPrivateCourse(courseId);
return <CourseCard course={{id:row.id,title:row.title}}/>;
```

**Boundary note:** `NEXT_PUBLIC_` environment values are bundled for client use, so never prefix a secret. `server-only` is an import guard, not an authorization layer. Browser bundle scanning is a separate required check.

</LessonStep>
