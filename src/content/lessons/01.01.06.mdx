## The problem we're solving

Every link says 'Click here,' so a reader using a links list has no idea which resource each link opens. Another link uses `href=#` and jumps to the top instead of the intended section.

## Build the mental model

An `a` element with an `href` provides navigation. Its accessible name should describe its destination or action, even when the surrounding sentence is not read. Fragment links target elements with matching IDs. `nav` groups major navigation links; do not wrap every inline reference in a nav region. Avoid opening new tabs without reason. When a new tab is necessary, `target=_blank` and `rel=noopener` prevent the opened page from controlling the opener; `noreferrer` also suppresses referrer data. Modern browsers often apply implicit noopener, but being explicit communicates intent. Browser focus, not just CSS, determines keyboard usability.

**Predict before running:** Why is `href='#schedule'` broken if the target section has `id='sessions'`? The fragment ID does not match; the link is not connected to the intended content.

<LessonStep number={1} title={"Create navigation with useful link labels"} file="labs/html-navigation/starter/index.html" expected={"A links list clearly identifies two destinations."}>

Describe destinations using the link text, not generic 'read more' repeated everywhere.

```html
<nav aria-label="Page navigation">
  <a href="#schedule">Workshop schedule</a>
  <a href="#materials">Required materials</a>
</nav>
```

</LessonStep>

<LessonStep number={2} title={"Connect fragments and provide a skip link"} file="labs/html-navigation/starter/index.html" expected={"Clicking the schedule link reaches its actual section; the skip link reaches main."}>

Each link's fragment must match an actual section ID. Place the skip link first.

```html
<a href="#main-content">Skip to main content</a>
<main id="main-content">
  <section id="schedule"><h2>Workshop schedule</h2></section>
  <section id="materials"><h2>Required materials</h2></section>
</main>
```

</LessonStep>

<LessonStep number={3} title={"Provide external references safely"} file="labs/html-navigation/starter/index.html" expected={"The destination is meaningful and cannot receive a window.opener reference."}>

Use a real HTTPS reference and disclose that it opens in a new tab.

```html
<a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Element/a" target="_blank" rel="noopener noreferrer">HTML anchor documentation (opens in a new tab)</a>
```

</LessonStep>

## Bug Hunt: identify the actual source of the problem

An external reference uses `target=_blank` without explaining the new tab, and the skip link target is absent. Add an explicit notice, safe rel values and the actual main ID, then keyboard-test both links.
