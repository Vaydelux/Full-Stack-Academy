## The problem we're solving

Your README says run three commands to release, but the third runs even when tests fail. Worse, your commands depend on Windows-only shell syntax. A repeatable project gives everyone the same entry points and returns useful exit codes.

## Build the mental model

package scripts are named project commands. npm run adds local node_modules/.bin to PATH and runs scripts from the package root. Exit code zero signals success; nonzero signals failure. Use && to run a later check only when the earlier one succeeded (npm's default Windows cmd and POSIX shells support this). Prefer Node scripts for cross-platform filesystem and environment tasks instead of shell-specific syntax. npm ci validates the lock; it does not prove your application works. A separate verification script must run real tests. Do not make destructive or publishing actions implicit in a test script.

## Explore it yourself

Separate dev, build, start, lint, typecheck and test scripts in larger projects. The release command should not be the only way to test. For a new checkout the typical sequence is install locked dependencies, validate, test, build, and then deploy explicitly. This lab proves the first three pieces without a cloud service.

<Misconception claim={"If npm run followed by a command prints output, the check passed."} correction={"Exit codes and assertions—not the amount of console output—determine success."} />

## Bug Hunt: diagnose before you change code

A verify script is written as npm run check; npm test. In a compatible shell a semicolon does not require the preceding check to succeed. Use && or a programmatic runner that exits on the first failed step.

<KnowledgeCheck question={"Which script stops before testing if the syntax check fails?"} choices={["npm run check && npm test","npm run check; npm test","echo success","npm install"]} correctIndex={0} explanation={"&& runs the next command only if the earlier command succeeds."} misconception={"A semicolon generally sequences commands regardless of success."} lessonId="00.02.05" />
