## The problem we're solving

Reverse proxy and headers can create user-visible reliability or security failures. The starter trusts any nonempty Host header, enabling malicious password-reset or callback URLs.

## Build the mental model

Treat forwarded/Host headers as untrusted, use an explicit allowlist, and understand Next.js 16 proxy.ts executes in Node.js. **Expected result:** Only exact trusted hosts are allowed; lookalikes, ports and injected line breaks are rejected.

Offline tests verify small, deterministic policy models. They cannot establish real HTTP security, deployment compatibility, image loading, environment secrecy or network diagnostics.

 const host=request.headers.get('host')??'';
