## The problem we're solving

A dense workshop card overflows on mobile, ignores RTL and loses its focus indicator. Our task is to repair the actual style behavior, not just make a static screenshot look convincing. This workshop uses synthetic content in a standalone offline HTML file; it needs no account, cloud API or deployed preview.

## Build the mental model

A resilient component is a composition of constraints, not a hardcoded viewport screenshot: border-box sizing, fluid typography, logical padding, a narrow-first layout and explicit keyboard focus. Use a media query only where the content benefits from extra space; test zoom and RTL.

**Predict before running:** The card fits 320px, becomes a two-column component on wide screens and respects RTL.

## Prerequisites and preflight

Continue from [the previous CSS lesson](/learn/02.01.07). Open `labs/css-responsive-card/starter/index.html` in a browser and inspect the CSS rules using the Elements / Computed Styles panel. Have local Node.js 24 available for the test script and choose a 320px device viewport for the final check. The starter intentionally demonstrates the flaw, while the solution supplies the target behavior.


**Why it fails:** A resilient component is a composition of constraints, not a hardcoded viewport screenshot: border-box sizing, fluid typography, logical padding, a narrow-first layout and explicit keyboard focus. **Proof:** Open DevTools, select the target element, and confirm the failing computed property. Write the observed value before replacing the rule.

<LessonStep number={2} title="Apply the targeted CSS repair" file="labs/css-responsive-card/starter/index.html" expected="The card fits 320px, becomes a two-column component on wide screens and respects RTL.">

Replace the incorrect rule with the following CSS. Keep the native HTML controls and all semantic content unchanged.

```css
.card { box-sizing: border-box; inline-size: min(100%, 46rem); padding-inline: 1.5rem; border-inline-start: 4px solid #075e7b; } .card h2 { font-size: clamp(1.5rem, 2vw + 1rem, 2.25rem); } .action:focus-visible { outline: 3px solid #c44804; outline-offset: 3px; } @media (min-width: 42rem) { .card { display: grid; grid-template-columns: minmax(0, 1fr) auto; align-items: center; gap: 1rem; } }
```

**Predict before running:** The card fits 320px, becomes a two-column component on wide screens and respects RTL.

**Why it works:** A resilient component is a composition of constraints, not a hardcoded viewport screenshot: border-box sizing, fluid typography, logical padding, a narrow-first layout and explicit keyboard focus. Use a media query only where the content benefits from extra space; test zoom and RTL.

**Proof:** At 320px, check no horizontal overflow; at 1100px, grid columns; Tab focus ring; RTL border right.

</LessonStep>

<LessonStep number={3} title="Verify responsiveness and interaction" file="labs/css-responsive-card/starter/index.html" expected="The repaired solution works at narrow and wide viewports without hiding keyboard focus or producing horizontal overflow.">

Use DevTools Responsive Design Mode: select a 320px width, then a wide desktop width. Inspect the relevant computed style again. Where the lab includes a button or writing-direction toggle, test it using Tab and Enter.

```js
const target = document.querySelector('.card');
console.log(getComputedStyle(target).boxSizing);
console.log(document.documentElement.scrollWidth <= innerWidth);
```

**Predict before running:** A visible computed property changes as described, but the document remains scrollable normally with no unwanted horizontal overflow.

**Why it works:** Browser-computed styles and measured dimensions describe actual rendered rules, rather than assuming the presence of source text is enough.

**Proof:** Compare the computed result with the instructor solution and record one failing case from the original starter.

</LessonStep>
