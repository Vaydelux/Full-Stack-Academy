## The problem we're solving

A button changes a heading, while another button saves a shared record. Both feel like one application, but different processes perform the work. Confusing the environments makes developers try to access the DOM in Node.js, or expose private credentials in the browser.

## Build the mental model

A browser runs downloaded JavaScript and renders HTML and CSS. A server receives requests, applies business rules, and returns data or documents. Both can use JavaScript, but their APIs and trust boundaries differ: the browser has the DOM, while Node has server APIs such as filesystem access. The user controls the browser and can inspect any data it receives. Authorization therefore belongs on the server.

**Predict first:** Does every button click need a network request? No. A local DOM update needs no additional server communication; a shared database update normally does.

Install Node.js 24 and Git, clone the repository, and confirm `node --version`. No account or API key is needed.

<LessonStep number={1} title="Serve an HTML document" file="labs/browser-server/starter/server.mjs" expected="A local server returns the Runtime boundary heading.">

Keep the starter's import and direct-execution block; replace the request handler with this stage:

```js
export function createApp() {
  return createServer((req, res) => {
    if (req.method === 'GET' && req.url === '/') {
      res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
      return res.end('<h1>Runtime boundary</h1>');
    }
    res.writeHead(404);
    res.end('Not found');
  });
}
```

Run `node labs/browser-server/starter/server.mjs` and open `http://127.0.0.1:3101`. The terminal is the server process; the browser is a client. Stop it with Ctrl+C before restarting after edits.

<LessonStep number={2} title="Deliver browser code separately" file="labs/browser-server/starter/server.mjs" expected="The button changes text without another network request.">

Replace the root response body with this document:

```html
<!doctype html>
<html lang="en">
  <meta charset="utf-8">
  <title>Runtime lab</title>
  <body>
    <h1>Runtime boundary</h1>
    <button id="action">Try browser code</button>
    <p id="result"></p>
    <script src="/app.js" defer></script>
  </body>
</html>
```

Insert this route before the fallback:

```js
if (req.method === 'GET' && req.url === '/app.js') {
  res.writeHead(200, { 'Content-Type': 'text/javascript; charset=utf-8' });
  return res.end("document.querySelector('#action').addEventListener('click', () => { document.querySelector('#result').textContent = 'Browser code ran'; });");
}
```

The server sends the JavaScript as text, and the browser executes it. The defer attribute waits for document parsing. In Network, reload and inspect the HTML and script response. Click the button and observe that no new request is necessary.

</LessonStep>

<LessonStep number={3} title="Protect a server-side value" file="labs/browser-server/starter/server.mjs" expected="The status endpoint returns a boolean without revealing the synthetic private value.">

Add `const PRIVATE_VALUE = 'server-only-demo-value';` at module scope. Add this route before the fallback:

```js
if (req.method === 'GET' && req.url === '/api/status') {
  res.writeHead(200, { 'Content-Type': 'application/json' });
  return res.end(JSON.stringify({ ready: PRIVATE_VALUE.length > 0 }));
}
```

Visit the status endpoint and inspect its response. A boolean exposes the status without the underlying value. Never put real credentials in course fixtures; production secrets must be provided by protected configuration.

</LessonStep>

## Bug Hunt: A hidden value

A developer adds the private value to a JSON response because a debugging panel needs it and hides the panel with CSS. Inspect the Network response: the value is still disclosed. Remove the extra field, return only the boolean and run your boundary tests. CSS is not access control.
