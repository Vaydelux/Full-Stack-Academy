## The problem we're solving

A code review says looks wrong without explaining the failure, impact or actionable correction. The lesson uses synthetic local data; passing its test does not configure actual branch protection or trigger a release.

## Build the mental model

Useful review comments connect an observable symptom to an impact and a specific repair or question, while distinguishing required changes from suggestions. An actionable review note does not need inflammatory language or subjective style preferences, and tooling alone cannot certify collaborative quality.

**Predict before running:** A review comment cites a precise location, observed behavior, risk and proposed remediation.

<LessonStep number={2} title="Implement the explicit review or release contract" file="labs/team-review-rationale/starter/solution.mjs" expected={"A review comment cites a precise location, observed behavior, risk and proposed remediation."}>

Prefer an explicit result and a narrow, auditable policy; do not invent remote approvals or call an external API.

```js
export function solve(change){if(!change||typeof change.file!=='string'||!change.file.trim()||!Number.isInteger(change.line)||change.line<1||typeof change.symptom!=='string'||!change.symptom.trim()||typeof change.impact!=='string'||!change.impact.trim()||typeof change.proposal!=='string'||!change.proposal.trim())return null;return {location:change.file+':'+change.line,comment:'Observed: '+change.symptom+' Impact: '+change.impact+' Suggested change: '+change.proposal};}
```

**Predict before running:** A review comment cites a precise location, observed behavior, risk and proposed remediation.

**Why the repair works:** Useful review comments connect an observable symptom to an impact and a specific repair or question, while distinguishing required changes from suggestions. An actionable review note does not need inflammatory language or subjective style preferences, and tooling alone cannot certify collaborative quality.

**Proof:** Run the same independent test after editing; a green result demonstrates this local policy only.

</LessonStep>

<LessonStep number={3} title="Test both positive and negative outcomes" file="labs/team-review-rationale/solution.test.mjs" expected="Passes a precise expected-output contract and rejects a misleading or invalid case.">

```js
const reviewed=solve({file:'src/api.ts',line:14,symptom:'timeout not handled',impact:'request hangs',proposal:'abort at 3s'});assert.deepEqual(reviewed,{location:'src/api.ts:14',comment:'Observed: timeout not handled Impact: request hangs Suggested change: abort at 3s'});assert.equal(solve({file:'src/api.ts',line:14,symptom:'',impact:'bad',proposal:'fix'}),null);
```

**Predict before running:** The corrected policy distinguishes reviewable, unreviewed and invalid inputs.

**Why it matters:** Branch protection, reviewer permissions, remote signatures and provenance are external guarantees; local policy simulation cannot establish them.

**Proof:** Run `npm run lab:team-review-rationale` and inspect the failure messages when targeting the starter.

</LessonStep>
