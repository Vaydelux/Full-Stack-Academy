## The problem we're solving

A small internal profile directory requires a reusable card that handles an empty skill list and status changes. Copy-pasting hardcoded cards leads to mismatched names and inaccessible empty states. This lesson uses local React 19 / TypeScript 5 fixtures; the website does not execute learner-provided code.

## Build the mental model

Compose typed props, conditional badges and stable lists into one accessible feature. Explicit props and predictable composition, not hardcoded strings or hidden DOM edits. A React element is a description of UI; server rendering verifies initial markup but cannot, by itself, prove a browser interaction, reconciliation, or a DOM commit.

**Predict before you run:** The profile card renders unique data, online/offline state, stable skills and an empty case.

<LessonStep number={2} title="Implement the smallest correct React contract" file="labs/react-profile-capstone/starter/solution.tsx" expected="The profile card renders unique data, online/offline state, stable skills and an empty case.">

Replace the starter's implementation with the reviewed approach below. Keep its public exports stable.

```tsx
export type Profile = {id:string; name:string; role:string;online:boolean;skills:readonly {id:string;label:string}[]};
export function ProfileDashboard({profile}:{profile:Profile}) {
  return <article aria-label={`Profile of ${profile.name}`}>
    <h2>{profile.name}</h2><p>{profile.role}</p>
    <p role="status">{profile.online?'Online':'Offline'}</p>
    {profile.skills.length ? <ul>{profile.skills.map(s=><li key={s.id} data-id={s.id}>{s.label}</li>)}</ul>
       : <p>No skills listed.</p>}
  </article>;
}
```

**Predict before you run:** The profile card renders unique data, online/offline state, stable skills and an empty case.

**Why the repair works:** Compose typed props, conditional badges and stable lists into one accessible feature.

</LessonStep>
