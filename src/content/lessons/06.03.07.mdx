## The problem we're solving

A searchable directory briefly shows outdated matches when a query changes because its filtered list is stored and synchronized separately. The starter returns every item and ignores the query, demonstrating incorrect derived output. The goal is to learn the React runtime contract rather than memorize hook names.

## Build the mental model

Derive search results directly from props and current query rather than syncing duplicate state with an Effect. Remove the Effect and compute the value during rendering from the authoritative inputs. **Distinguish source-level correctness from runtime evidence:** Pure helpers can be tested without a browser, but an SSR output assertion cannot prove that an Effect ran, a ref focused an actual input or a global listener was removed after unmount.

**Predict before you run:** Search ignores casing and whitespace, preserves record order and returns an empty list for no matches.

Make the smallest correction that addresses the causal defect while keeping the fixture's exported API stable:

```tsx
export type DirectoryItem={id:string;name:string};
export function filterDirectory(items:readonly DirectoryItem[],query:string) {
 const term=query.trim().toLocaleLowerCase();
 return items.filter(item=>item.name.toLocaleLowerCase().includes(term));
}
export function Directory({items,query}:{items:readonly DirectoryItem[];query:string}) {
 const filtered=filterDirectory(items,query);
 return <ul>{filtered.map(item=><li key={item.id}>{item.name}</li>)}</ul>;
}
```
