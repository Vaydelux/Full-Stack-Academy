## The problem we're solving

A teammate reports 'the site is broken' with no URL, environment, steps or status code. The next developer cannot reproduce it and may waste time rewriting unrelated components.

## Build the mental model

An actionable issue includes a title, environment, deterministic reproduction steps, expected behavior, actual behavior, and sanitized evidence. State uncertainty rather than inventing observations. A simple redactor cannot guarantee privacy: manually review every log and screenshot before sharing. Never include real tokens, private account data, or an unredacted production HAR.

**Predict before running:** A two-step report that reproduces GET /api/projects returning 404 is more useful than 'API broken' because it provides a falsifiable claim.

## Bug Hunt: isolate and repair

A developer copies their full Authorization header into a report. Remove it, rotate any exposed real credential, and include only a synthetic request ID and the status instead.
