## The problem we're solving

A preview helper takes a user path and concatenates it into a URL. Special characters break query strings, repeated query keys disappear and an untrusted external URL can become an open redirect. We will parse and validate before presenting a generated link.

## Build the mental model

A URL object normalizes paths, percent encoding and query parameters. URLSearchParams.append retains repeated keys whereas set replaces previous values. An absolute attacker-supplied URL overrides the base, so compare the parsed origin to an explicit allowlisted origin before using it. The demo previews a URL as text; it never navigates.

**Predict before running:** Appending tag twice yields two entries, but set would replace the first. An input such as https://outside.example/ is rejected.

<LessonStep number={1} title={"Parse relative input with a trusted base"} file="labs/web-url/starter/index.html" expected={"A relative /workshops path resolves inside the tutorial origin."}>

Use an explicit HTTPS base so file:// tutorial hosting never controls the validation policy.

```js
const base = new URL('https://academy.example/');
const url = new URL(input.value, base);
```

**Predict before running:** A relative /workshops path resolves inside the tutorial origin.

**Why it works:** new URL handles relative resolution and percent encoding; concatenating strings does not.

**Proof it works:** Preview /workshops and inspect the normalized URL.

</LessonStep>


<LessonStep number={2} title={"Reject external or unsafe destinations"} file="labs/web-url/starter/index.html" expected={"An external HTTPS origin or javascript: path is rejected."}>

Check parsed origin before displaying or using a constructed link.

```js
if (url.origin !== base.origin) {
  status.textContent = 'Rejected: origin outside the local tutorial policy.';
  return;
}
```

**Predict before running:** An external HTTPS origin or javascript: path is rejected.

**Why it works:** A base URL is not an allowlist; validation must follow resolution.

**Proof it works:** Enter https://outside.example/ and verify the rejected result.

</LessonStep>


<LessonStep number={3} title={"Handle repeated query keys"} file="labs/web-url/starter/index.html" expected={"Both tag values are retained and correctly encoded."}>

Use append for multiple values, and getAll to inspect each one.

```js
url.searchParams.append('tag','web security');
url.searchParams.append('tag','DOM & CSS');
const tags = url.searchParams.getAll('tag');
```

**Predict before running:** Both tag values are retained and correctly encoded.

**Why it works:** Query parameters form a multimap, not a single-value dictionary.

**Proof it works:** Confirm two tags appear and the URL is printed as text only.

</LessonStep>
