## The problem we're solving

A fetch returns status 404, but the application reports 'Network unavailable.' Another request takes far longer than expected, yet no one captured timing. A useful diagnostic separates HTTP status, transport errors and elapsed time.

## Build the mental model

The Console records JavaScript errors and selected application logs. Network shows requests, statuses, payload metadata and waterfall timing. Performance profiles main-thread activity and marks. An HTTP error response is not a failed connection; fetch normally resolves for 404/500. Timings need a monotonic clock for elapsed durations: performance.now() is preferable to Date.now(). Logs should contain route templates, status and duration but not bearer tokens, cookies or sensitive bodies. This local lab makes a reusable probe with a fake clock so CI is deterministic.

**Predict before running:** If fetch resolves with status 404, should a probe classify it as transport failure? No. It is an HTTP response with ok:false.

<LessonStep number={2} title={"Record a bounded timing measurement"} file="labs/network-observation/starter/exercise.mjs" expected={"The probe reports status, type and elapsed milliseconds without revealing response contents."}>

Use an injected clock so tests simulate elapsed time without waiting; do not treat Date.now clock changes as reliable latency measurements.

```js
export async function probeRequest(request, now = () => performance.now()) {
  const start=now();
  try {
    const res=await request();
    return {kind:'http',status:res.status,ok:res.ok,
      durationMs:Math.max(0,Math.round(now()-start)),
      contentType:res.headers.get('content-type')};
  } catch {
    return {kind:'network-error',status:null,ok:false,
      durationMs:Math.max(0,Math.round(now()-start)),contentType:null};
  }
}
```

</LessonStep>

<LessonStep number={3} title={"Verify an HTTP error and a transport error"} file="labs/network-observation/starter/exercise.mjs" expected={"HTTP 404 remains an HTTP response; a thrown request becomes network-error."}>

Pass a fake response and then a throwing function. Use a monotonic fake clock for predictable output, and add the results to your issue's diagnostic evidence.

```js
let t=0;
const clock=()=>t;
const result=await probeRequest(async()=>{t+=15;return new Response('missing',{status:404});},clock);
console.log(result); // kind=http, status=404, ok=false, durationMs=15
```

</LessonStep>
