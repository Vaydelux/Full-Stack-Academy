## The problem we're solving

A service counts UTF-8 chunks using JavaScript string length and therefore underestimates multibyte payloads, allowing the maximum byte limit to be bypassed.

**Deliberate defect:** The starter counts Unicode code points rather than byte length and never throws at the byte limit. This exercise runs under Node.js 24 using built-in modules—no paid service, hosted data source or arbitrary learner-code runner.

## Build the mental model

Use Node Readable and Buffer.byteLength for true UTF-8 byte budgets, collecting bounded chunks and cancelling oversized input.

**Predict before writing code:** A UTF-8 euro sign consumes three bytes, and streams beyond the limit are rejected.

The exact Node.js API documentation is linked below. These exercises model concrete runtime behavior, not a screenshot of a server. They must not be interpreted as proof of container permission boundaries, a production reverse proxy or multi-process request isolation.

<LessonStep number={2} title="Repair the standard Node API usage" file="labs/node-stream-buffer-limit/starter/solution.mjs" expected="A UTF-8 euro sign consumes three bytes, and streams beyond the limit are rejected.">

```js
import {Readable} from 'node:stream';
export async function collectBytes(input,maxBytes){
 if(!Number.isSafeInteger(maxBytes)||maxBytes<0)throw new RangeError('Invalid byte limit');
 const chunks=[];let size=0;
 for await(const value of Readable.from(input)){
  const chunk=Buffer.isBuffer(value)?value:Buffer.from(String(value));
  size+=chunk.byteLength;
  if(size>maxBytes)throw new RangeError('Body too large');
  chunks.push(chunk);
 }
 return {size,content:Buffer.concat(chunks).toString('utf8')};
}
```

**Causal reasoning:** Use Node Readable and Buffer.byteLength for true UTF-8 byte budgets, collecting bounded chunks and cancelling oversized input.

</LessonStep>
