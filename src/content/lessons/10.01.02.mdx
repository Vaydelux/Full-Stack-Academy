## The problem we're solving

A missing or malformed PORT environment variable is silently accepted, then the server fails to bind a listener.

**Deliberate defect:** The starter converts PORT with Number but never rejects NaN, zero, out-of-range ports or an invalid NODE_ENV. This exercise runs under Node.js 24 using built-in modules—no paid service, hosted data source or arbitrary learner-code runner.

## Build the mental model

Parse environment variables as unknown strings into bounded runtime configuration and treat termination signals as requests for graceful cleanup.

**Predict before writing code:** Missing PORT uses a documented default; malformed values raise a clear configuration error.

The exact Node.js API documentation is linked below. These exercises model concrete runtime behavior, not a screenshot of a server. They must not be interpreted as proof of container permission boundaries, a production reverse proxy or multi-process request isolation.

```js
export function readConfig(env){
 const raw=env.PORT??'3000';
 if(!/^[0-9]+$/.test(raw))throw new Error('Invalid PORT');
 const port=Number(raw);
 if(!Number.isSafeInteger(port)||port<1||port>65535)throw new Error('Invalid PORT');
 const mode=env.NODE_ENV??'development';
 if(!['development','test','production'].includes(mode))throw new Error('Invalid NODE_ENV');
 return {port,mode};
}
```

**Causal reasoning:** Parse environment variables as unknown strings into bounded runtime configuration and treat termination signals as requests for graceful cleanup.

</LessonStep>
