## The problem we're solving

The starter reflects arbitrary Origins with credentialed CORS and approves state changes from any site. Real services must establish who can request a resource, constrain how the request is interpreted, and prevent unexpected data disclosure.

## Build the mental model

CORS governs browser read access; for cookie-authenticated state changes, independently verify Origin and use CSRF protections.

**Expected outcome:** Only a configured exact origin receives credentialed CORS and a cross-origin write is rejected.

**Production boundary:** For browser form posts also consider SameSite cookies, CSRF tokens and Origin/Referer checks; nonbrowser clients and cross-site resource policies have separate constraints.

 const accepted=typeof origin==='string'&&allowed.includes(origin);
 return {corsOrigin:accepted?origin:null,allowCredentials:accepted,allowWrite:accepted};
}
