## The problem we're solving

A counter handler schedules two updates but both reuse the same render-time count snapshot, losing one increment. This local fixture isolates a concrete failure before we introduce any external state or deployment.

## Build the mental model

Each render has a state snapshot. Calling a setter schedules another render; reading the state variable in the current handler does not magically change it. Functional setters are safer when several updates depend on the previous state.

**Predict before running:** The repaired implementation respects its documented contract.
