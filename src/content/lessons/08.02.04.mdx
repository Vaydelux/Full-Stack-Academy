## The problem we're solving

A dialog cycles focus past its last control and into the inert background on Tab, while Shift+Tab can leave it through the first control.

## Build the mental model

Modal keyboard focus must remain inside the active dialog and be returned to the trigger on dismissal. Use the browser's actual focusable elements, not an assumed static list; hidden/disabled controls must be excluded. The local contract models only wrap-around index arithmetic.

**Predict first:** Tab wraps from the last valid focus index to the first, and Shift+Tab wraps in the reverse direction.

<LessonStep number={2} title="Fix the policy and verify edge cases" file="labs/ui-focus-traps/starter/solution.ts" expected="Tab wraps from the last valid focus index to the first, and Shift+Tab wraps in the reverse direction.">

```ts

export function solve(current:number,length:number,backward:boolean):number{if(!Number.isInteger(length)||length<1||!Number.isInteger(current)||current<0||current>=length)throw new TypeError("Invalid focus sequence");return (current+(backward?-1:1)+length)%length;}

```

**Why it works:** Modal keyboard focus must remain inside the active dialog and be returned to the trigger on dismissal. Use the browser's actual focusable elements, not an assumed static list; hidden/disabled controls must be excluded. The local contract models only wrap-around index arithmetic.

**Proof:** Run `npm run lab:ui-focus-traps` and inspect the instructor test output.

</LessonStep>

## Production library pattern

```tsx
"use client";
import * as Dialog from "@radix-ui/react-dialog";
function AccessibleModal(){return <Dialog.Root><Dialog.Trigger>Open</Dialog.Trigger><Dialog.Content><Dialog.Title>Update settings</Dialog.Title><input aria-label="Setting"/><Dialog.Close>Close</Dialog.Close></Dialog.Content></Dialog.Root>;}
```

Prefer a tested focus-management primitive; the lesson solver is deliberately only a focus-index model, not browser focus control.
