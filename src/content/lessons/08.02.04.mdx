## The problem we're solving

The starter lets Tab move outside the focusable element range. Advanced UI interactions need a robust identity and focus model so the component works with touch, keyboard and screen readers rather than only a mouse.

## Build the mental model

Keep focus inside an active modal and restore focus after closing; use a vetted primitive for real DOM edge cases. **Expected behavior:** Tab cycles forward and Shift+Tab backwards; empty content has no focus target.

**Evidence boundary:** The local test checks a pure data or interaction-policy function. It does not prove DOM focus, ARIA announcements, actual event sequences, animation timing or a third-party library's mounted behavior. Use a real local browser and accessible component primitives for those claims.
