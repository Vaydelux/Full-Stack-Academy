## The problem we're solving

A monorepo runner builds the web app before its shared contracts package, so the application can consume stale output. This offline workshop is part of the Git/monorepo track; no workspace installation, external package query or Vercel build runs when reading the lesson.

## Build the mental model

A task graph expresses which package jobs depend on which other jobs. Turborepo's ^build dependency runs build tasks in upstream workspace packages before dependent builds. Cycles and missing tasks should fail explicitly rather than being silently reordered; this test models topological order without invoking turbo.

**Predict before running:** The contracts package builds before the dependent web and API projects, and cycles are rejected.

```js
export function solve(nodes){if(!Array.isArray(nodes))throw new TypeError('Tasks required');const map=new Map(nodes.map(n=>[n.name,n]));if(map.size!==nodes.length)throw new Error('Duplicate task');const out=[],active=new Set(),done=new Set();function visit(name){if(done.has(name))return;if(active.has(name))throw new Error('Cycle');const n=map.get(name);if(!n)throw new Error('Unknown dependency: '+name);active.add(name);for(const dep of n.dependsOn)visit(dep);active.delete(name);done.add(name);out.push(name);}for(const n of nodes)visit(n.name);return out;}
```
