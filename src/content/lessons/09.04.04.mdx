## The problem we're solving

A cart's total becomes stale because a developer stores a duplicated total separately and forgets to recompute it after adding an item.

**Broken behavior:** The starter always returns a zero total despite changes to the real store's quantities.

## Build the mental model

Keep one source of truth in Zustand and compute lightweight derived data from selected state; subscribe to stable slices rather than duplicating caches.

**Predict:** Totals change when quantities change, the previous state stays immutable and subscriptions observe updates.

**Evidence boundary:** The local test imports the real Zustand 5 `createStore` API and, where appropriate, the official middleware. The store is created afresh per test; it does not use a global request-scoped server singleton. Passing Node assertions does not prove browser hydration, cross-tab synchronization or HTTP authorization.

```ts
import {createStore} from 'zustand/vanilla';
export type QtyState={quantities:number[];addQuantity:(quantity:number)=>void};
export function makeQuantityStore(){return createStore<QtyState>()(set=>({
 quantities:[1,2],addQuantity:quantity=>set(state=>({quantities:[...state.quantities,quantity]})),
}));}
export const totalOf=(state:Pick<QtyState,'quantities'>)=>state.quantities.reduce((sum,x)=>sum+x,0);
```

**Reasoning:** Keep one source of truth in Zustand and compute lightweight derived data from selected state; subscribe to stable slices rather than duplicating caches.

</LessonStep>
