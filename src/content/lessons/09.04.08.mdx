## The problem we're solving

A course search UI needs a shareable query, optional type filter, and display density. A broken store ignores query updates and the result count never changes.

**Broken behavior:** The starter ignores query and kind actions and returns all items regardless of the selected filter.

## Build the mental model

Create a request-isolated Zustand 5 vanilla store with typed actions, stable selectors and derived visible rows; do not persist or duplicate server-owned catalogue data.

**Predict:** Search and kind filter real catalogue rows, density remains independent, and reset restores the defaults.

**Evidence boundary:** The local test imports the real Zustand 5 `createStore` API and, where appropriate, the official middleware. The store is created afresh per test; it does not use a global request-scoped server singleton. Passing Node assertions does not prove browser hydration, cross-tab synchronization or HTTP authorization.
