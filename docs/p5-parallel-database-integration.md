# P5 parallel database qualification

Six independent hosted runners provision a fresh loopback-only PostgreSQL 17 container each and execute the existing real acceptance commands: authorization SQL (14 checks), database-role RLS (14), synthetic authenticated HTTP to RLS-protected PostgreSQL, search SQL (15), inbox SQL (16), real pg inbox adapter (11). Role creation is permitted only for the two suites that deliberately create temporary roles, only within their disposable cluster. Other roles are restricted, never superuser or BYPASSRLS. The optional inbox driver is resolved from the already locked distributed runtime workspace via a temporary ignored node_modules symlink; no root dependency mutation. Each runner audits its installed workspace, masks random credentials, checks Git integrity and removes its own container. HTTP uses synthetic identity and the inbox uses synthetic signatures, not an actual identity provider or billing/webhook vendor. No topic-level publication is claimed.
