# Academy commit-bound local qualification — operator handoff

**2026-11-24 | source-only merge candidate; no publication/deployment**

## Why this work matters

Prior P5 milestones added many targeted tests but did not provide a single commit-bound workflow for qualifying the Academy and advancing the next publishable modules. The existing root and React-client package locks are present on the audited main commit `43b5150020cf8f235bd8b25eb23e3d6ab8b30148`. The NestJS example `examples/nestjs-vertical/package-lock.json` is absent; this is a genuine full-profile blocker, not a reason to generate synthetic npm integrity records or prevent an independent P1 attempt.

## Implemented

- `scripts/qualification-coordinator.mjs` exposes read-only `--plan` and `--plan-p1` commands and explicit `--run` and `--run-p1` commands.
- Preflight checks stable Node 24.9+ (24.x), Git root/HEAD and clean tracked/untracked worktree, selected tracked npm locks and SHA-256 hashes, npm CLI, required scripts and Playwright resolution.
- All-profile sequentially runs dependency advisory audit, existing Academy/P1 full qualification (root/nested npm installs, offline source and runtime tests, Next build and browser smoke), dedicated RHF and Query browser gates, then installed NestJS architecture tests. P1-only omits the final Nest runtime and its lock prerequisite.
- Each gate records starting/ending timestamps, exit status, signal/error code and result in a temporary receipt outside Git. It verifies commit and lock hashes and worktree cleanliness before/after steps; blocked, failed and invalidated runs never report automated success. Interrupted runs may retain a running receipt; discard as incomplete and rerun from clean checkout.
- Actual PostgreSQL, other infrastructure, manual accessibility and editorial approval remain separate not-run entries; `publicationApproved` is always false.
- The P5 matrix audit now rejects named substeps without a corresponding nonempty npm script and direct recursive invocation of the P5 bundle; new tests are included in the existing `test:release-gate-coverage` step. The 20 P5 groups and existing offline matrix are preserved.

## Run on your Windows workstation (PowerShell)

Use a clean trusted checkout, Git, Python (required by the existing validate script), Node 24.9+ stable in the 24.x line, and npm with registry access. Install Playwright outside the repo using a reviewed version, then set `ACADEMY_BROWSER_ROOT` to that package root (the directory whose node_modules contains Playwright). Install Chromium via that Playwright installation. Avoid writing evidence and browser downloads into tracked source.

```powershell
# First see blockers; does not execute qualification steps.
npm run qualify:academy:local -- --plan-p1

# Run only when plan prerequisites are satisfied.
npm run qualify:academy:local -- --run-p1
```

Review the output receipt path. A passing P1 receipt establishes only the listed automated steps. Perform manual keyboard/zoom/screen-reader and editorial reviews before even considering module-atomic promotion.

For the all-profile, the missing NestJS lock must first be generated by real npm with a trusted registry and audited against the example package manifest, on a development branch. Use `npm install --package-lock-only --ignore-scripts` from `examples/nestjs-vertical`, then review the resolved tree, integrity values and lock guard. Do not commit generated content if dependency resolution fails. Commit a genuine reviewed lock, then use a clean checkout for:

```powershell
npm run qualify:academy:local -- --plan
npm run qualify:academy:local -- --run
```

The runner checks all necessary selected prerequisites before running any commands; it is not a dependency installer or lockfile generator. Npm audit and installs contact the npm registry. Timeouts and failed processes may require manual cleanup. Receipts are local unverified reports, not cryptographically signed provenance or remote CI attestation; keep the exact tested checkout and evidence.
